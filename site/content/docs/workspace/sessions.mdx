## What a session is

A session is one conversation with its settings: the model and reasoning effort, the working directory it was started in, an optional project label, and the agent's full transcript. Every session has a UUID (shown by **Copy id** in the desktop app and in the `/sessions` picker in the terminal) and a title that the model writes for you after the first finished turn and refreshes now and then. Subagents spawned from a session are sessions of their own, nested under the parent — see [Delegation](/docs/automation/delegation).

Everything is stored in `~/.theuth/sessions.sqlite`: messages, compaction epochs, errors, cost meters. A session survives restarts, model switches and compactions; nothing is thrown away unless you ask for it.

`/new private` starts a **private** session: a memory-only tree that is closed when you leave it and never written to disk, knowledge or search.

## Finding and resuming

**Desktop.** The sidebar lists sessions under **Pinned**, then by day (**Today**, **Yesterday**, **Previous 7 days**, **Older**) — or, once any session carries a project label, under collapsible project headers with **Ungrouped** last — and **Archived (N)** at the bottom. The row menu (**Chat options**) offers **Rename**, **Pin**/**Unpin**, **Archive**/**Unarchive**, **Move to project**, **Open in new window**, **Copy id** and **Delete**. Archived sessions leave the sidebar but stay searchable. `/sessions` in the composer opens [Search](/docs/workspace/search) limited to sessions; `/resume <id>` opens one by id.

**Terminal.**

| Command | What it does |
|---|---|
| `/sessions` | Picker: `⏎` switches, `Esc` closes — the one you leave keeps running |
| `/resume <id>` | Open a session by id |
| `/new [private]` | Start a new session |
| `/project <label\|off>` | Label the session's root for grouping in `/sessions` and `/artifacts` |
| `/agents` | Pick one of this session's subagents; `/parent` goes back up |

`t --resume <id>` opens a session directly from the shell. The terminal has no rename, pin, archive or delete commands; use the desktop app for those.

**Titles.** Titles are generated by the session's own model unless you set a cheaper one: `agent.title_model: anthropic/claude-haiku-4-5` in `config.yaml`, `/title <model>` (persists), or Settings › Agent loop. `/title off` goes back to the session's model. To set a title by hand use **Rename** in the desktop app.

## Durability and who runs the session

theuth runs **one engine per data dir**. Whatever starts first — `t`, `t --headless`, the desktop app's daemon — takes `~/.theuth/engine.lock` and becomes the engine; a later `t` attaches to it as a client (the terminal status line shows `attached · pid N · desktop`, where the last word names which frontend started the engine: `tui`, `headless` or `desktop`). This matters for what happens when you quit:

- **Attached terminal.** `/quit` or `Ctrl+C` closes only your view; the engine, its sessions and any running turn carry on. Reopen with `t` or `t --resume <id>`.
- **Terminal that is the engine.** Quitting stops the process. Messages already written are safe; a turn that was mid-reply stops with the process and is not re-sent when you come back — a dangling tool call is repaired on resume so the next turn works.
- **Daemon.** `t --headless` (or the installed service, `t --install-service`) keeps sessions running with no UI attached; phones, Slack, Signal and Telegram talk to it (see [Channels](/docs/automation/channels)).

A second engine on the same data dir is refused with:

```text
engine already running (pid N, tui, since HH:MM, ws://127.0.0.1:P) — run `t` to attach, or set THEUTH_DATA_DIR for a separate store
```

With several engines in a [mesh](/docs/automation/mesh), every session is readable everywhere but has one **owner** engine that writes it. The `/sessions` picker and the desktop sidebar show an engine chip on sessions owned elsewhere; **Continue here** (desktop) or `/take` (terminal) moves ownership to the engine you are on. Typing into a session owned by another engine takes it over automatically when that engine is reachable.

## Rewriting the conversation

All of these work on **turns** — a message you sent and everything the agent did in reply. Turn numbers are the 1-based order shown in the pickers.

| Command | Effect |
|---|---|
| `/undo` | Hide the last turn; `undone: … — /redo restores` |
| `/redo` | Bring back the last undone turn |
| `/edit [n]` | Put turn n's message back in the editor; `⏎` sends it, replacing that turn and everything after it. Without `n`, a picker |
| `/regen [n]` | Regenerate the reply to turn n, replaying your message as sent |
| `/fork [n]` | New session containing the conversation through turn n; the original is untouched |
| `/clear` | Drop the whole conversation but keep the session, its id, title, model and settings |

Undo is reversible until you send something: the next message commits the cut and the hidden tail is deleted for good. **Edit** and **regenerate** are the same cut followed by a new turn, so they also destroy the old tail — fork first if you want to keep both branches. Fork is allowed while a turn is running (the in-flight reply is not copied); undo, edit and regenerate are refused with `turn in flight` until it finishes or you `/cancel`.

In the desktop app the same actions sit on the bubbles: **Edit** and **Fork from here** on your messages, **Regenerate** and **Fork from here** on replies, and **Undo**/**Redo**/**Clear** in the session menu (`⋯`). `/edit` is terminal-only; the desktop uses the bubble's **Edit**.

`/clear` is recorded as a compaction whose head says the context was cleared; the earlier transcript is still on disk and shows under a `── context cleared (epoch n) ──` divider when you scroll back. `/new` makes a fresh session instead.

## Removing content from context

`/shake [images|documents|messages|tools|summary]` removes specific items from what the model sees while keeping the transcript and everything said afterwards. Bare `/shake` opens a picker over the current context with nothing ticked; naming a category pre-selects it. Confirm with **Remove from context**. No model call is made and nothing is summarised; removed rows show a collapsed "Removed from context" marker in the transcript, and the next request simply omits them (which can miss the provider's prompt cache once).

Use it when a screenshot, a pasted document or a noisy tool result is eating the window but the rest of the conversation is fine. It is refused while a turn is running and on sessions run by an external ACP harness. Desktop: **Shake context…** in the session menu, or the small remove buttons on attachments and messages.

## Compaction

When the context approaches the model's window, theuth **compacts**: it folds older history into a head and keeps the recent tail verbatim. The transcript on disk is untouched — a compaction only changes what the model is sent — and a `── context compacted (epoch n · style) ──` divider marks the point.

Automatic compaction fires at `agent.compact_at` × the model's window (default `0.8`; `0` disables it). On demand:

| Command | Effect |
|---|---|
| `/compact` | Fold now with the default style |
| `/compact summary` | Cache-hot model call writes a summary head (the default) |
| `/compact cut` | Drop the folded span; keep the tail. No model call |
| `/compact snap` | Rasterise the folded span into images in the head. No model call; needs a vision-capable model, otherwise `snap needs a vision model (this one is text-only)` |
| `/compact style` | Show the default; `/compact style <name>` writes `agent.compact_style` to `config.yaml` |

```yaml
agent:
  compact_at: 0.8          # compact when the context is this full; 0 disables
  compact_style: summary   # summary | cut | snap
```

Automatic `snap` on a text-only model falls back to `cut`. Right before a cut the harness also runs a knowledge harvest in the background so durable facts are not lost — see [Knowledge](/docs/workspace/knowledge). The folded turns are kept verbatim in `~/.theuth/spill/<session>/epoch_<n>.txt` (and the summary in `epoch_<n>.summary.md`), which the agent can `read_file` if it needs something that was folded.

**The context gauge.** The terminal header shows `ctx 123k / 200k (61%) · cache 87%`; the desktop header pill shows `123k/200k · 61% · cache 87%` with a `≈` while the number is an estimate (before the provider reports). It turns amber above 75 % (`context filling up`), red above 90 % (`start a new session or summarise`) and pulses above 95 % (`next prompt may fail`). `t session context <id>` prints where the tokens go (head, tail, system prompt) for a session on a running daemon.

## Costs and tokens

The terminal header shows a running `cost`; `/cost` lists the returned cost, an estimate where providers return none, history coverage and one row per child session. The desktop header has a **Cost** pill that opens the same breakdown (**Direct**, **Descendants**, **Total**, a **Harness tokens** table and per-child **Inclusive total**). Costs are what the providers reported; `~$` marks an estimate, and sessions that started before the cost ledger did say `Historical cost unknown`.

## Subagents

A session that spawned subagents shows them nested under its row in the desktop sidebar, with state, cap (`read-only`), cost and age; the terminal's `/agents` picker opens one and `/parent` returns. Deleting a session deletes its subagents too. Details: [Delegation](/docs/automation/delegation).

## Errors in the transcript

A failed model call or tool is recorded as an error row anchored to the message it followed. It stays in the transcript on resume (red text in the terminal, an alert in the desktop app) and is purely informational: there is no retry button on it. Send your next message, `/regen` the turn, or `/undo` to drop it with the turn it belongs to. A message that could not be *sent* at all is different — the desktop composer keeps it with a **Retry** button.

## Not available

- **Exporting a session** as Markdown, PDF or JSON. Export exists for notes and boards (see [Documents](/docs/workspace/documents)) and for artifacts (`/artifacts`, key `e`), not for transcripts.
- **Share links** are for documents, not sessions.
- Renaming, archiving or deleting from the terminal.

## Troubleshooting

**"turn in flight" when I `/undo`, `/edit`, `/regen` or `/compact`.** Wait for the reply or `/cancel` first. `/fork` works while running.

**`/redo` says `nothing to redo` after an undo.** You sent a message in between; sending commits the cut and deletes the hidden turn. Fork before editing when you may want both branches.

**`session <id> is owned by <engine> (epoch n)` / `session:<id> is owned by <engine>, not here`.** The session belongs to another engine in your mesh. Use **Continue here** / `/take`; if that engine is offline the take waits for `sessions.takeover_secs` (300 s) unless you confirm the prompt to continue now, in which case any turns that engine had not shipped are set aside and listed once in the transcript.

**`engine already running (pid N, …)`.** You tried to start `t --headless` or a second engine on the same data dir. Run plain `t` to attach, stop the other process, or point `THEUTH_DATA_DIR` at a separate store.

**The gauge is red right after a compaction.** The model's window is too small for the fixed part of the frame (system prompt and tools), so no fold can help; theuth tells the model once (a `context_pressure` note) and stops auto-compacting that session. Switch to a model with a larger window or start a new session.

**A snap compaction was refused.** `snap` needs a session model that accepts images (`agent.vision_model` does not count here); use `/compact summary` or `/compact cut`, or switch the session to a vision-capable model with `/model`.
