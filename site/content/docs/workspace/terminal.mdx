## Starting `t`

Run `t` in any terminal to open the full-screen UI on a fresh session. The first transcript line shows the version. Useful starts:

```bash
t                         # new session in the terminal UI
t --resume <session-id>   # reopen an existing session
t -p "summarise this repo"   # print mode: stream the reply to stdout and exit
cat notes.md | t -p       # print mode with the prompt on stdin
t --headless              # no UI: run the engine as a daemon for the desktop app, phones and other t processes
t --acp                   # Agent Client Protocol on stdio, for editors
```

One engine runs per data directory. If an engine is already running (the desktop app's daemon, a `t --headless`, or another `t`), a new `t` attaches to it over its local WebSocket instead of starting a second one, and the status line shows `attached · pid <N> · <frontend>`, where the frontend (`tui`, `headless` or `desktop`) is the kind of process that started the engine. If the engine you attached to goes away, your `t` takes over and becomes the engine itself.

Logs go to `~/.theuth/logs/theuth.log` (daily files), because the UI owns the screen. The data directory follows `--data-dir` or `THEUTH_DATA_DIR`. Subcommands such as `t mesh`, `t tasks`, `t session`, `t sandbox` and `t mcp` (an MCP server on stdio that needs a running engine) are covered in [CLI](/docs/reference/cli), with every flag.

### Print mode (`-p`)

`t -p "<prompt>"` submits the prompt, prints the streamed reply and events to stdout and exits when the turn finishes. With `-p` and no text, the whole of stdin is the prompt. Tool approvals are answered on stdin with `y` or `n`; once stdin is closed (a piped prompt), pending approvals are denied with `denied: stdin closed`. `t -p "/search <query>"` prints search results and exits once they settle.

The same line printer is used whenever stdout is not a terminal, so `t` inside a pipe never tries to draw the full-screen UI.

## The screen

From top to bottom:

- **Transcript**: your turns, the agent's replies, tool cards, artifact cards, advisor notes and file cards. It stays pinned to the bottom until you scroll. While the agent works, a trailing activity row shows the one-line status the agent reports with `set_status`, or `thinking…` while it waits on the model.
- **Queued cards**: a message you send while a turn is running is queued as a steer and shown as a `◇ queued · ⌥↑ edit` card until the agent picks it up.
- **Header line**: `model  ·  effort  ·  ctx 12.3k / 200k (6%)  ·  cache 94%`, then tags when relevant: `cost`, `advisor <cost>`, `approvals off`, communication, link and node counts, and an available update. The line turns amber at 75 % of the context window and red at 90 %. In a subagent it reads `↳ <name>  child · model`; in a watch-only child of an external harness it reads `◎ <name>  watching · <model>`. An ACP session shows the harness and the model it reported (`omp · <model>`).
- **Composer**: a multi-line box. While dictating or in the talk view the header line is replaced by a dictation meter or talk status.
- **Status line**: short session id, `idle` or the current activity (the agent's `set_status` line wins over generic words such as `streaming…`), the last turn's token counts (`1.2k↑ 300↓`), idle subagents, `N queued`, `N job(s)`, loaded skills, and hints such as `↑ history · PgDn follows` while you are scrolled up or `editing #N` during `/edit`. After a restart, an update or a takeover by another node, a resume note says what happened and when, and `resumed · N replayed` names any tools skipped (effect unknown) and jobs lost. Then `◎ advisor: idle|reviewing…|paused|halted` while an advisor is on, and `● LIVE <n> · <domain>` while public shares are live. MCP status is on the right.

## Keys

| Key | What it does |
| --- | --- |
| `Enter` | Send. While a turn runs, the message is queued as a steer. |
| `Shift+Enter` | New line in the composer. |
| `Ctrl+Enter` / `⌘Enter` | Interject: cancel the running turn and start a new one with this message now (`⌘Enter` needs a terminal that reports the Cmd modifier, such as kitty-protocol terminals). |
| `⌥↑` (`Alt+Up`) | Pull the newest queued message back into an empty composer to edit it. |
| `Esc` | Cancel the in-flight turn or compaction of this session only; its subagents keep running. Otherwise cancel an open prompt or a pending `/edit`. |
| `Esc` ×3 within 1 s | Stop the turn and every running subagent of the session (`stopped N agents`). |
| `Ctrl+C` | Quit immediately (no second press). `/quit` or `/exit` do the same. |
| `PgUp` / `PgDn` | Scroll the transcript a page. `↑`/`↓` scroll a row while the composer is single-line; terminals without mouse capture send the wheel as these keys. |
| `Ctrl+O` | Expand or collapse the newest tool card or advisor note; on an artifact card it renders the file inline (`ctrl+o expands` / `ctrl+o collapses` hints appear on the card). |
| `o` | On an empty composer: open the newest artifact's file with the OS default handler. |
| `Ctrl+V` | Attach the image on the OS clipboard (see below). |
| `Tab` | On a path token, open path completion; in the `/` menu, complete the command name. |
| `F2` | Show or hide the plan (todo) card; while it has focus `↑↓` scroll it, `Esc` closes it, `Tab` returns to the composer. |
| `Ctrl+D` | Start dictation at the caret; press again to stop and keep the text, `Esc` to discard. |
| `Ctrl+T` | Stop a running talk from anywhere. |
| `y` / `n` / `Esc` | On an approval prompt: allow, deny, deny. `o` opens the subagent that asked, when the request came from a child. |

Answering a model question (an ask card, titled `question 1/N`): `↑↓` move, `1` to `9` or `Enter` pick, `s` or `Tab` skip, `Esc` dismisses and ends the turn. The recommended option is preselected and marked `(recommended)`. The last row, `type your own…`, takes a free-text answer: `Enter` on it opens the composer, `Enter` sends, `Esc` goes back to the options.

Mouse capture is deliberately off, so your terminal's native selection and copy work as usual. Links in artifact cards are emitted as terminal hyperlinks where the terminal supports them.

### Watch-only subagents

When an external harness (an ACP agent such as Claude Code or omp) spawns its own subagents, they appear in `/agents` as watch-only children. Opening one shows its transcript live with the `◎ … watching` header and a status hint naming the harness that runs the subagent, ending in `Esc stops it` or `cannot be stopped here` depending on whether the harness accepts a per-child cancel. Messages you type are not sent; the hint is shown instead.

## Slash commands

Type `/` at the start of the composer to open the command menu (`↑↓ move  ⇥ complete  ⏎ run  esc close`); a prefix narrows it (`/mo` → `/model`). `/<skill-name> [words]` hands a loaded skill to the model. In an ACP session the menu also lists the harness's own commands, tagged with its name. An unknown `/word` is sent as ordinary text. Argument syntax: `<x>` required, `[x]` optional.

Most commands open a picker when run without an argument. Every picker shows its keys in its title row; `↑↓` move and `Esc` closes unless noted.

### Watching and typing into a terminal job

`/terminals` lists the PTY jobs of the session tree. `⏎` opens a read-only observer that refreshes every half second: `↑↓ PgUp PgDn history  ←→ pan  r refresh  i type  esc close`. While the job is running, `i` (or `⏎`) hands the keyboard to the program: every key, including `Ctrl+C` and `Esc`, goes to the process, and the title reads `typing · Ctrl-] to stop`. `Ctrl+]` returns to the observer; `Esc` in the observer closes the overlay and leaves the job running.

## Images, files and paths

- **Clipboard image**: `Ctrl+V` reads the image on the OS clipboard, downscales it so its long edge is at most 1568 px, stores it as `~/.theuth/attachments/<hash>.png` and attaches it to your next message. This is `Ctrl+V` even on macOS: `⌘V` is handled by the terminal and pastes text only, so an image-only clipboard pastes nothing.
- **Dropped files**: dragging a file onto the terminal pastes its path. A single pasted path to a `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp` file up to 5 MB, or a `.pdf` up to 32 MB, is attached as a file; anything else is treated as text.
- **Long pastes**: multi-line text you paste becomes a paste token in the composer and is expanded back when you send.
- **Path completion**: press `Tab` on a token that starts with `/`, `./`, `../` or `~` to list matching paths; `Tab` accepts (a directory keeps completing), `Esc` closes. The engine answers, so in a session owned by another node you complete that node's filesystem.

## What the terminal cannot do

- **Run apps.** Interactive apps the agent builds run in the desktop app and the browser; `/apps` in the terminal opens the app's source file with the OS, shows it inline or exports it. See [Apps](/docs/workspace/apps).
- **Record meetings.** Meetings are a desktop feature; see [Meetings](/docs/workspace/meetings).
- **Boards, notebooks and rich document editing.** The terminal renders artifacts inline (text, CSV, diffs) but notes, boards and notebooks are edited in the desktop app; see [Documents](/docs/workspace/documents) and [Notebooks](/docs/workspace/notebooks).
- **Mouse interaction.** Scrolling and selection are your terminal's; there are no clickable controls.

Voice *does* work here: `/talk` and `/dictate` need the speech models to be present (dictation reports `model missing` with the expected path under `~/.theuth/models` until they are). See [Voice](/docs/workspace/voice).

## ACP mode for editors

`t --acp` speaks the Agent Client Protocol on stdio, so an editor that supports ACP can use theuth as its agent. It attaches to a running engine when there is one. When it has to start its own engine it runs a reduced one (tools, secrets, documents, knowledge, web, browser, scraping, code index, computer control, artifacts, apps, notebooks, autoresearch, dreaming and the agent loop) without schedules, mesh, roster, tasks, sandboxes, meetings, voice or Talk; run `t --headless` first if the editor session should see those. Configure theuth in the terminal first (model, logins, MCP servers); the editor is for turns. Zed, for example:

```json
"agent_servers": {
  "theuth": { "command": "t", "args": ["--acp"] }
}
```

`--acp` cannot be combined with `--headless`, `--serve` or `-p`. The reverse direction (theuth driving other ACP agents as subagents) is `/acp` and is covered in [Delegation](/docs/automation/delegation).

## Troubleshooting

**Pasting an image does nothing.** Use `Ctrl+V`, not `⌘V`; the UI reads the clipboard image itself. If you see `paste: …` in the transcript, the clipboard could not be read. On Linux this usually means no clipboard provider is reachable from the terminal's session.

**`⌘Enter` sends instead of interjecting.** Your terminal does not report the Cmd modifier. Use `Ctrl+Enter`, or a terminal with the kitty keyboard protocol.

**`Shift+Enter` sends instead of inserting a newline.** Same cause: the terminal must distinguish Shift+Enter from Enter (kitty protocol or an equivalent keymap).

**`Esc` stopped the turn but subagents keep working.** That is intended: a single `Esc` stops only the session you are in. Press `Esc` three times within a second to stop its subagents too.

**`t` says another engine is running and exits with status 3.** A `--headless`/`--serve` engine refuses to start twice for the same data directory. A plain `t` attaches instead; if it could not connect, the engine record under `~/.theuth/engine.json` points at a listener that is gone. Check `~/.theuth/logs/theuth.log`, or start `t --headless` again.

**Dictation says `model missing`.** The speech model is not under `~/.theuth/models`; see [Voice](/docs/workspace/voice) for how models are fetched.

**Approvals keep appearing.** `/approvals off` turns prompts off for this session, `/approvals off always` writes it to `config.yaml`; human-only approvals still appear. The policy itself is explained in [Tools and permissions](/docs/reference/tools-permissions).
