theuth is one process with one data directory. Every plugin reads its own
top-level section of `config.yaml`; a section that is missing means that
plugin's defaults. This page lists the layout, the precedence rules and the
keys with the defaults the code falls back to.

## Data directory

Resolution order: `--data-dir <path>`, then the `THEUTH_DATA_DIR` environment
variable, then `~/.theuth`. If no home directory can be determined the binary
exits with `cannot determine data dir; pass --data-dir`. `--config <path>`
points at a different `config.yaml`; the default is `<data_dir>/config.yaml`.

On every start (`first_run`) the binary creates `mcp/`, `acp/` and `skills/`,
writes `config.yaml`, `prompt.md` and `acp/agents.yaml` if they are missing,
and rewrites the eleven binary-owned skills (`harness.md`, `visualize.md`,
`pdf.md`, `loops.md`, `routines.md`, `apps.md`, `board.md`, `decide.md`,
`double.md`, `native-apps.md`, `cells.md`) whenever their content differs.
The dreaming plugin writes its own `skills/dreaming.md` and
`sensors/dreaming.py` the same way, and `schedules/dreaming.md` once.
Nothing else is ever overwritten.

Deleting `knowledge.sqlite` is safe; it is a derived index and is rebuilt.
Deleting `artifacts.sqlite` orphans the blobs it named, which are swept at
the next start. Deleting `secrets.key` (or the keychain item) loses the
vault.

## How config.yaml is read

The binary builds one configuration from two layers, later wins:

1. `<data_dir>/config.yaml` (or `--config`).
2. Environment variables prefixed `THEUTH_`, with `__` separating nesting
   levels: `THEUTH_<SECTION>__<KEY>`.

Each plugin then extracts its section by name. Every config struct is
`#[serde(default)]`, so an absent key or section means the Rust default
listed below. There is no third layer: CLI flags do not map onto config keys,
except that `--install-service --relay <url> --name <n>` writes `link.enabled`,
`link.relay` and `link.name` into the config file before starting the unit.

Examples:

```sh
THEUTH_RPC__LISTEN=127.0.0.1:7799 t --headless      # rpc.listen
THEUTH_AGENT__COMMUNICATION=true t                  # agent.communication
THEUTH_TOOLS__POLICY__DESTRUCTIVE=deny t            # nested: tools.policy.destructive
```

An environment value wins over the file on every start; the `/communication`
status reports whether its value came from `env`, the file, the default or
the mesh rule. Scalar coercion (booleans, numbers) follows figment's `Env`
provider; arrays and objects are better kept in the file.

Some state is deliberately not configuration. The **Allow public sharing**
switch and the sharing edge are stored per machine in `share.sqlite`; a
`share.enabled` or `share.edge` key in `config.yaml` or a `THEUTH_SHARE__*`
variable is ignored with a warning. See
[Public sharing](/docs/automation/sharing).

## Startup, live and restart

The rule: **`config.yaml` is read once at startup and is not watched.** A hand
edit takes effect at the next start. What makes some settings feel live is
that specific commands rewrite one line of the file *and* swap the value in
memory at the same time:

| Command | Key written |
|---|---|
| Settings › Models › Defaults (desktop); `/model <id>` on Slack, Signal or Telegram outside a thread | `agent.model`, `agent.effort`, `agent.subagents.model`, `agent.subagents.effort`, `roster.theuth_model`, `roster.theuth_effort` |
| Star a model in any model picker | `agent.favorite_models` |
| Settings › Models › Helpers; `/vision <model\|off>`, `/title <model\|off>`; desktop `/subagent <model>` | `agent.title_model`, `agent.vision_model`, `agent.escalate_model` and their `*_effort`; `agent.subagents.model` |
| Settings › Models › Providers (AWS); `/aws <profile\|clear>` | `agent.aws_profile` |
| `/communication on\|off always` | `agent.communication` (unset = on once a machine is paired, off otherwise; an explicit value wins) |
| `/compact style <summary\|cut\|snap>`; Settings › Agent › Context | `agent.compact_style` |
| Settings › Agent › Context; `/fractal model <id>` | `agent.endless.*` |
| Settings › Agent › Loop (desktop) | `agent.max_tool_rounds`, `agent.stream_idle_secs`, `agent.max_salvages`, `agent.status_every`, `agent.status_tool`, `agent.auto_title`, `agent.suggestions`, `agent.knowledge.hint_limit`, `agent.subagents.max_runtime_secs`, `knowledge.peek`, `knowledge.peek_threshold`, `tools.pty_idle_secs`, `schedule.run_timeout_secs` |
| Settings › Agent › Advisor; the advisor picker | `advisor.*` |
| `/approvals on\|off always` | `tools.approvals` |
| Settings › Tools › Builtins **Off always** | `tools.builtins.disabled` |
| Settings › Tools › Serve over MCP | `mcp_server.enabled`, `mcp_server.port` |
| Settings › Tools › Web search (desktop) | `web.*` read/budget keys, `search_providers.<provider>.*` |
| Settings › Network and Settings › Learning switches | `web.allow_private_network`, `browser.allow_private_network`, `a2a.enabled`, `computer.enabled`, `decision.enabled`, `double.enabled` |
| Settings › Learning › Dreaming, Double, Decision models | `dreaming.*`, `double.*`, `decision.families.*` |
| Settings › Agent › Autoresearch | `autoresearch.*` |
| Settings › Meetings, Settings › Calendar | `meeting.*`, `meeting.detect.*`, `meeting.calendar.*` |
| Settings › Voice › Dictation | `voice.polish_enabled`, `voice.polish_model`, `voice.polish_effort`, `voice.stt_engine`, `voice.shape`, `voice.end_commands`, `voice.input_devices` |
| `/link on\|off`, `/link relay <url>`, `/link name <n>` | `link.enabled`, `link.relay`, `link.name` |
| `t mesh hub <mode>`; Settings › Network › This machine | `mesh.hub`, `mesh.name`, `mesh.nearby` |
| `t --slack-setup`, `t --link-signal`, `t --telegram-setup` | `slack.owner`, `slack.enabled`, `signal.owner`, `signal.device_name`, `telegram.owner`, `telegram.enabled` |
| Telegram pairing (`/start <code>`, `telegram_link`), `/telegram allow\|rm\|group add\|group rm`, Settings › Channels › Telegram | `telegram.owner`, `telegram.allowed`, `telegram.groups` |

The rewrite is line-level: it replaces the first `key:` line inside the
section, keeps any trailing comment, and appends the key or section if it is
missing. Only `<data_dir>/config.yaml` is written; a file passed with
`--config` elsewhere is read but not written back.

Caveats:

- Directories, not the config file, are watched: `mcp/`, `schedules/`,
  `knowledge/`, `agents/`. Changes there apply within about a second.
- `agent.status_tool`, `agent.auto_title`, `agent.suggestions` and
  `knowledge.peek` apply to sessions started after the switch. The other
  Settings switches in that row (`decision`, `double`, `a2a`, `computer`,
  `web` and `browser` private network) are written at once and apply at the
  next start; the desktop shows a restart banner.
- `a2a.listen` and `a2a.enabled` need a restart even through the UI.
- `rpc.listen` is bound at start. The desktop app passes its own
  `THEUTH_RPC__LISTEN` to the daemon it launches, so the file's value does
  not apply there.
- A session-scoped `/approvals off` or `/communication off` without `always`
  is memory only and ends with the process.

## Other configuration files

- `providers.yaml`: named OpenAI-compatible gateways, `name: {base_url}`;
  the key is the vault secret of the same name. `/provider add` writes both
  and fetches `GET {base}models` into `models.json`.
- `models.json`: optional; the bundled models.dev catalog shape, adds or
  overrides models (local `ollama/...`, private gateways).
- `prompt.md`: read verbatim into every system prompt. Text between
  `<!-- root-only -->` and `<!-- /root-only -->` reaches only sessions a
  person reads; subagents and scheduled runs get the file without those
  spans.
- `acp/agents.yaml`: one entry per external harness,
  `name: {command, args, env, description}`; `/acp` lists, probes, adds from
  the registry and removes. See [Delegation](/docs/automation/delegation).
- `a2a/peers.yaml`: owner-edited peers and exports; `/a2a reload` validates
  the whole file and installs all of it or none.
- `schedules/<name>.md`: `cron:` / `every:` / `at:` front matter and the
  prompt as body; `until:`, `max_runs:`, `cwd:`, `approvals:`, `agent:`,
  `project:` and `run_timeout:` refine a run. A `when:` sensor turns the
  file into a watcher, with `fire:` (`on_change`, `while_true`, `once`),
  `for:`, `cooldown:`, `mode:` (`skip`, `queue`, `restart`), `memory:`,
  `expires:` and `timeout:`. The desktop app calls these Routines. See
  [Schedules](/docs/automation/schedules) and
  [Watchers](/docs/automation/watchers).

## Security scope

See [Security and privacy](/docs/reference/security) for the whole model.

- `rpc.listen` defaults to loopback and the token is required on every
  connection; nothing listens on other interfaces unless you change it.
  Phones and browsers reach the harness through the outbound link uplink,
  not an open port. `mcp_server` binds loopback only and is off by default.
- `a2a.listen` must be loopback; publish it only behind an HTTPS reverse
  proxy with `a2a.public_url` set.
- `web.allow_private_network` and `browser.allow_private_network` are on by
  default so the agent can reach dev servers on `localhost` and your LAN; set
  them to `false` on machines where that reach is not wanted. Cloud metadata
  endpoints are always refused.
- `browser.import_cookies` hands real browser credentials to the model;
  leave it off unless you need it. `browser.profile: off` stops the shared
  signed-in profile from syncing across your machines.
- `tools.approvals: false` removes every prompt for `ask` actions but never
  rewrites `deny`. Prefer `tools.policy.destructive: deny` on unattended
  machines. Public sharing stays owner-approved either way.
- The desktop app launches `t --headless` through your login shell, so the
  daemon has the same environment a terminal would, including any provider
  keys exported there.
