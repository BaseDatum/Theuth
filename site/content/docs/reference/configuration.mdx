theuth is one process with one data directory. Every plugin reads its own
top-level section of `config.yaml`; a section that is missing means that
plugin's defaults. This page lists the layout, the precedence rules and the
keys with the defaults the code falls back to.

## Data directory

Resolution order: `--data-dir <path>`, then the `THEUTH_DATA_DIR` environment
variable, then `~/.theuth`. If no home directory can be determined the binary
exits with `cannot determine data dir; pass --data-dir`. `--config <path>`
points at a different `config.yaml`; the default is `<data_dir>/config.yaml`.

On every start (`first_run`) the binary creates `mcp/`, `acp/` and `skills/`,
writes `config.yaml`, `prompt.md` and `acp/agents.yaml` if they are missing,
and rewrites the six binary-owned skills (`harness.md`, `visualize.md`,
`pdf.md`, `loops.md`, `apps.md`, `board.md`) whenever their content differs.
Nothing else is ever overwritten.

| Path | What | When it is read |
|---|---|---|
| `config.yaml` | every plugin's section | startup; slash commands rewrite single lines (below) |
| `token` | bearer token for the JSON-RPC server (64 hex, owner-only mode) | startup; created on first serve |
| `engine.lock`, `engine.json` | one running engine per data dir: pid, bound address, version | startup |
| `logs/theuth.log.<YYYY-MM-DD>` | the process log, daily rotation, no ANSI; `RUST_LOG` raises the level | live |
| `logs/service.log` | stdout of the `--install-service` unit | live |
| `prompt.md` | standing instructions prepended to every model call | every call |
| `skills/` | markdown skills; see [Skills](/docs/reference/skills) | every call |
| `mcp/*.json`, `mcp/config.yaml`, `mcp/repos/` | MCP servers, risk gates, cloned server repos; see [MCP](/docs/reference/mcp) | watched (300 ms debounce) |
| `oauth/mcp/<server>.json` | MCP server login tokens, mode 0600; provider `/login` grants live in the vault as hidden `oauth/<provider>` rows (legacy `oauth/<provider>.json` files are migrated and renamed `.migrated`) | on use |
| `secrets.sqlite`, `secrets.key` | the encrypted vault and, without an OS keychain, its key (0600); see [Secrets](/docs/reference/secrets) | on use |
| `providers.yaml`, `models.json` | named OpenAI-compatible gateways; catalog additions and overrides | startup |
| `acp/agents.yaml` | external ACP harnesses runnable as subagents | startup |
| `a2a/peers.yaml` | remote A2A peers and exports; `/a2a reload` re-reads it | startup, `/a2a reload` |
| `nodes.yaml` | paired remote harnesses (`/nodes`) | live |
| `schedules/*.md`, `schedule.sqlite` | scheduled runs and loops, run history; see [Schedules](/docs/automation/schedules) | watched |
| `sessions.sqlite` | every session's history | live |
| `attachments/`, `spill/` | pasted images; tool output over the cap and the verbatim text folded by each compaction (`spill/<session>/epoch_<n>.txt`) | on demand |
| `knowledge/`, `knowledge.sqlite` | the knowledge bundle (markdown with git history) and its derived index | live, watched |
| `documents/`, `index.sqlite` | Yjs documents behind the editor and their index | live |
| `artifacts/`, `artifacts.sqlite`, `artifacts.owners/` | content-addressed blobs shown with `show` or published with `app`, their index, per-process owner locks | live |
| `codeindex/<slug>-<hash>.sqlite` | per-repository symbol indexes | live |
| `agents/`, `decisions/`, `models/`, `sandbox/`, `signal/`, `telegram/`, `link/` | roster agents, decision logs, local speech and decision models, sandbox VM state, Signal linked-device state and inbox, Telegram thread bindings (`threads.json`) and inbox, link identity | plugin-specific |
| `*.sqlite` (`mesh`, `replica`, `link`, `mcp`, `skills`, `tasks`, `roster`, `schedule`) | replication and plugin state | live |

Deleting `knowledge.sqlite` is safe; it is a derived index and is rebuilt.
Deleting `artifacts.sqlite` orphans the blobs it named, which are swept at
the next start. Deleting `secrets.key` (or the keychain item) loses the
vault.

## How config.yaml is read

The binary builds one configuration from two layers, later wins:

1. `<data_dir>/config.yaml` (or `--config`).
2. Environment variables prefixed `THEUTH_`, with `__` separating nesting
   levels: `THEUTH_<SECTION>__<KEY>`.

Each plugin then extracts its section by name. Every config struct is
`#[serde(default)]`, so an absent key or section means the Rust default
listed below. There is no third layer: CLI flags do not map onto config keys,
except that `--install-service --relay <url> --name <n>` writes `link.enabled`,
`link.relay` and `link.name` into the config file before starting the unit.

Examples:

```sh
THEUTH_RPC__LISTEN=127.0.0.1:7799 t --headless      # rpc.listen
THEUTH_AGENT__COMMUNICATION=true t                  # agent.communication
THEUTH_TOOLS__POLICY__DESTRUCTIVE=deny t            # nested: tools.policy.destructive
```

An environment value wins over the file on every start; the `/communication`
status reports whether its value came from `env` or the file. Scalar coercion
(booleans, numbers) follows figment's `Env` provider; arrays and objects are
better kept in the file.

## Startup, live and restart

The rule: **`config.yaml` is read once at startup and is not watched.** A hand
edit takes effect at the next start. What makes some settings feel live is
that specific commands rewrite one line of the file *and* swap the value in
memory at the same time:

| Command | Key written |
|---|---|
| Settings › Chat › Models (desktop); `/model <id>` on Slack, Signal or Telegram outside a thread | `agent.model`, `agent.effort`, `agent.subagents.model`, `roster.theuth_model` |
| `/aws <profile\|clear>` | `agent.aws_profile` |
| `/communication on\|off always` | `agent.communication` (unset = on once a machine is paired, off otherwise; an explicit value wins) |
| `/compact style <summary\|cut\|snap>` | `agent.compact_style` |
| `/vision <model\|off>`, `/title <model\|off>`; desktop `/subagent <model>` | `agent.vision_model`, `agent.title_model`, `agent.subagents.model` |
| Settings → Agent loop (desktop) | `agent.max_tool_rounds`, `agent.stream_idle_secs`, `agent.max_salvages`, `agent.escalate_model`, `agent.subagents.max_runtime_secs` |
| `/approvals on\|off always` | `tools.approvals` |
| `/link on\|off`, `/link relay <url>`, `/link name <n>` | `link.enabled`, `link.relay`, `link.name` |
| Settings → Search (desktop) | `web.*` read/budget keys, `search_providers.<provider>.*` |
| `t mesh hub <mode>` | `mesh.hub` |
| `t --slack-setup`, `t --link-signal`, `t --telegram-setup` | `slack.owner`, `slack.enabled`, `signal.owner`, `signal.device_name`, `telegram.owner`, `telegram.enabled` |
| Telegram pairing (`/start <code>`, `telegram_link`), `/telegram allow\|rm\|group add\|group rm`, Settings › Channels › Telegram | `telegram.owner`, `telegram.allowed`, `telegram.groups` |

The rewrite is line-level: it replaces the first `key:` line inside the
section, keeps any trailing comment, and appends the key or section if it is
missing. Only `<data_dir>/config.yaml` is written; a file passed with
`--config` elsewhere is read but not written back.

Caveats:

- Directories, not the config file, are watched: `mcp/`, `schedules/`,
  `knowledge/`, `agents/`. Changes there apply within about a second.
- `a2a.listen` and `a2a.enabled` need a restart even through the UI.
- `rpc.listen` is bound at start. The desktop app passes its own
  `THEUTH_RPC__LISTEN` to the daemon it launches, so the file's value does
  not apply there.
- A session-scoped `/approvals off` or `/communication off` without `always`
  is memory only and ends with the process.

unset.

| `telegram.owner` / `allowed` / `groups` | unset / `[]` / `[]` | owner's numeric user id (written by `--telegram-setup` or pairing); more user ids; chat ids where mentions and commands are honoured (empty = private chats only) |
| `telegram.tools` / `reasoning` / `approvals` | `all` / `true` / `all` | activity cards per tool batch (`all`, `errors`, `none`); reasoning text in the expandable quote; where approvals for unbound sessions go (`all` = owner chat, `threads` = nowhere) |
| `sessions.takeover_secs` / `release_wait_secs` / `orphan_keep_days` | `300` / `10` / `7` | transcript replication across mesh engines |

## A compact config.yaml

Everything below is optional except `agent.model`. Values shown are the
defaults, so this file changes nothing; uncomment and edit what you need.

```yaml
# <data_dir>/config.yaml — env overrides: THEUTH_<SECTION>__<KEY>
agent:
  model: anthropic/claude-sonnet-4-5
  communication: false          # /communication on always → true
  # effort: high
  # vision_model: anthropic/claude-haiku-4-5
  # subagents: {max_depth: 1, max_concurrent: 8, max_runtime_secs: 600}
  compact_at: 0.8
  compact_style: summary

tools:
  policy: {read_only: allow, mutating: ask, destructive: ask}
  # approvals: false            # /approvals off always → never prompt

rpc:
  listen: 127.0.0.1:7777

# secrets: {key_store: auto, tools: true}
# knowledge: {enabled: true}
# web: {engines: [google, brave, qwant, duckduckgo, wikipedia, arxiv, github]}
# browser: {allow_private_network: false, import_cookies: false}
# link: {enabled: false, relay: wss://relay.example.com}
# schedule: {enabled: true, run_timeout_secs: 1800}
# update: {enabled: true}
# a2a: {enabled: false, listen: 127.0.0.1:7780}
```

Keep API keys out of this file: provider keys live in the
[secrets vault](/docs/reference/secrets), MCP credentials in `mcp/*.json` as
`{{secret:NAME}}` or `$(cmd)`, AWS credentials in AWS's own files.

## Other configuration files

- `providers.yaml`: named OpenAI-compatible gateways, `name: {base_url}`;
  the key is the vault secret of the same name. `/provider add` writes both
  and fetches `GET {base}models` into `models.json`.
- `models.json`: optional; the bundled models.dev catalog shape, adds or
  overrides models (local `ollama/...`, private gateways).
- `prompt.md`: read verbatim into every system prompt. Text between
  `<!-- root-only -->` and `<!-- /root-only -->` reaches only sessions a
  person reads; subagents and scheduled runs get the file without those
  spans.
- `acp/agents.yaml`: one entry per external harness,
  `name: {command, args, env, description}`; `/acp` lists, probes, adds from
  the registry and removes. See [Delegation](/docs/automation/delegation).
- `a2a/peers.yaml`: owner-edited peers and exports; `/a2a reload` validates
  the whole file and installs all of it or none.
- `schedules/<name>.md`: `cron:` / `every:` / `at:` front matter and the
  prompt as body; `until:`, `max_runs:`, `cwd:`, `approvals:`, `agent:`,
  `project:` and `run_timeout:` refine a run. A `when:` sensor turns the
  file into a watcher, with `fire:` (`on_change`, `while_true`, `once`),
  `for:`, `cooldown:`, `mode:` (`skip`, `queue`, `restart`), `memory:`,
  `expires:` and `timeout:`. The desktop app calls these Routines. See
  [Schedules](/docs/automation/schedules) and
  [Watchers](/docs/automation/watchers).

## Security scope

- `rpc.listen` defaults to loopback and the token is required on every
  connection; nothing listens on other interfaces unless you change it.
  Phones and browsers reach the harness through the outbound link uplink,
  not an open port.
- `a2a.listen` must be loopback; publish it only behind an HTTPS reverse
  proxy with `a2a.public_url` set.
- `browser.allow_private_network` and `browser.import_cookies` widen what the
  agent can reach as you; leave them off unless you need them.
- `tools.approvals: false` removes every prompt for `ask` actions but never
  rewrites `deny`. Prefer `tools.policy.destructive: deny` on unattended
  machines.
- The desktop app launches `t --headless` through your login shell, so the
  daemon has the same environment a terminal would, including any provider
  keys exported there.
