An agent is a standing role on your roster: a name, a title, a charter, a manager it reports to, and optional settings for model, effort, tools, MCP servers, monthly spend and memory. Every active agent has a **desk**: one pinned session that receives work (tasks, routines, mentions) and gets it done through child sessions. You hire one when a kind of work keeps coming back and you want a consistent owner for it, rather than re-explaining the role in every chat. The built-in `theuth` agent is always there and routes anything unaddressed.

## Prerequisites

- theuth running: the desktop app, `t` in a terminal, or a `t --headless` daemon. The roster is always on; there is no switch to enable it.
- Desks do their work in child sessions via `spawn_subagent`, which exists only while agent messaging is on. `agent.communication` unset means on once a machine is paired in a [mesh](/docs/automation/mesh) and off otherwise; an explicit `true` or `false` in `config.yaml` always wins. Change it with `/communication on always` in the terminal UI, or the **Let sessions message each other** switch in Settings › Network › Messaging. Without it an agent can still be hired, but its desk cannot delegate work.
- The **Agents and peers** builtin category (Settings › Tools › Builtins) must not be off: it holds `spawn_subagent`, `agents_list`, `agent_draft`, `agent_put` and `agent_propose`. **Off here** in a chat removes them from that chat and its subagents; **Off always** writes `tools.builtins.disabled` and removes them everywhere.
- At least one model provider configured: see [Models and providers](/docs/getting-started/models). An agent's `model:` must be a catalog id for a configured provider.
- Each machine runs its own agents' desks. In a [mesh](/docs/automation/mesh) an agent file lives on the machine whose `~/.theuth/agents/` holds it, and theuth is on every machine; a task is worked only by the desks of its **home** machine (see [Tasks › Machines](/docs/automation/tasks#machines)). Every machine in the mesh must run the same theuth version: an older one still dispatches every task to its own desks.
- Hiring and removing need no special permission: the Hire, Approve hire and Remove buttons are the consent. Tool calls made at a desk follow the ordinary permission model: see [Tools and permissions](/docs/reference/tools-permissions).

## How it works

### One file per agent

Each agent is a Markdown file, `~/.theuth/agents/<name>.md`: YAML front matter for the record, body for the charter. The file is the source of truth; theuth watches the directory, hot-reloads changes, and mirrors parsed files into `roster.sqlite`. You normally never write this file by hand (chat and the Agents view write it for you), but it is plain text and you may.

Names are `[a-z0-9-]{1,32}`. `theuth` is reserved: a file `agents/theuth.md` is ignored with a warning; the built-in agent's charter is `~/.theuth/prompt.md`.

### Hierarchy

Agents form a tree by `reports_to`, rooted at `theuth` (which reports to you). The manager is who gets the escalations, the budget tasks and the review of work an agent cannot sign off itself. An unknown manager, or a `reports_to` chain that loops, falls back to the root in the org chart. There is no limit on how many agents you can have. In a mesh the org chart also shows the agents of your other machines, each machine's `theuth` under the root and its agents beneath it.

### Desks

For every agent that is active (not paused, not an unapproved proposal) theuth keeps one session titled `<name> · desk` open on that agent's machine. theuth's own desk opens on first use. No desk opens before the machine's first sync with the mesh. The desk is the agent: its system prompt is its identity (`You are <Title> (<name>), an agent on this theuth roster; you report to …`), its charter, its capabilities, its journal and an operating manual. Observable rules of that manual:

- A desk never does the work in its own session: no files, shells or browsing there. It spawns a child session with a complete brief and the `model` and `tools` from its file.
- On an `assigned` or `reassigned` wake it runs a **fit check** against the roster's capabilities and hands the task to a better-matching agent with `task_reassign` if there is one. theuth's desk is the router by default.
- Every turn woken for a task must end with a disposition: `done` (by the reviewer), `review`, `blocked`, `delegated` or `continuing`. A turn that leaves its task unmoved gets one nudge; a second miss sets the task `blocked: "no continuation"` and wakes the manager.
- At most `roster.max_rounds` (3) child rounds per task per episode.
- A role missing from the roster is a proposal, not a hire: the desk calls `agent_propose` (see [Approving a proposal](#walkthrough-approving-a-proposal)).

A desk's work is grouped into **episodes**. An episode closes when the desk is idle for `roster.episode_idle_secs` (21600 s = 6 h), reaches `roster.episode_context_pct` (60 %) of its context window, the thread ends, or theuth shuts down. The closing turn writes a journal (Done / Open / Next / Notes, capped at `roster.journal_max_bytes` = 8192) to `~/.theuth/roster/journal/<name>.md`, which the next episode reads back. Before the journal it asks the desk to record what it learned with `knowledge_put` and to share team-relevant items with `knowledge_share`. Tasks still checked out at close without a `continuing` disposition become `blocked: no continuation`. A pause closes the episode too, but without the journal turn and without blocking anything (see [Pausing](#pausing)).

Desks and the task board are tightly coupled; [Tasks](/docs/automation/tasks) covers wakes, checkouts and dispositions in detail.

### Model and effort

| Session | Model | Effort |
|---|---|---|
| A hired agent's desk | its `model:`; unset = the default for new sessions | its `effort:`; unset = `agent.effort` |
| Native children of that desk that name no model | its `model:`; unset = `agent.subagents.model` | its `effort:`, then `agent.subagents.effort` |
| theuth's desk and the work it starts for tasks | `roster.theuth_model`; unset = the default for new sessions | `roster.theuth_effort`; unset = the default for new sessions |

Set the defaults in Settings › Models › Defaults (**Subagents**, **theuth agent**; every picker carries effort chips). theuth's model and effort can also be set on its **Runtime & Access** tab; they are written to `config.yaml` and an open theuth desk switches at once. A changed `model:` or `effort:` in an agent file applies to its open desk too. An effort the model does not offer is dropped. A `model:` the catalog no longer resolves does not keep the desk shut: the default stands in and a warning is logged. External harness children keep their own model unless one is named.

### Context of a desk

Desks run with fractal context by default (`agent.endless.default_desk: true`, the **Desks use fractal context** switch in Settings › Agent › Context): old turns become summary lines the desk can zoom back into, and a word-for-word tail of recent turns is kept. Per agent you can override that:

- `memory: epochs` turns fractal context off for this agent's desk; `memory: fractal` (or `endless`) turns it on.
- `view_bytes`, `tail_mode` and the `tail_*` marks size the summary view and the verbatim tail; `profile` picks the compactor profile.
- `memory_model` and `memory_effort` pick the model that writes the summaries for its desk; a chat's own pick wins.

A desk already running in the other mode switches at its next idle moment. The Hire wizard and the **Runtime & Access** tab expose **Context summary model**, **Context tail** and **Compactor profile**; each defaults to Settings › Agent › Context.

### Isolated memory

By default an agent's sessions read and write the main knowledge store as `agent:<name>`. With `isolated_memory: true` (the **Isolated memory** switch in the wizard and on **Runtime & Access**, or `isolated_memory` on `agent_draft` / `agent_put` / `agent_propose`) the agent gets its own knowledge store instead:

- Its desk and every session under it use `~/.theuth/agent-memory/<name>/`, with the same knowledge tools and search. Notes there are owned by `agent:<name>` and private; they cannot be shared, never appear in the main memory or its search, and the agent sees none of the main memory.
- It fails closed: when the store cannot be selected, knowledge tools refuse with `isolated memory unavailable here: …` instead of falling back to the main memory.
- Nightly dreaming skips every session of an isolated agent.
- The agent page shows an **Isolated memory** badge and a read-only **Memory** tab: a searchable list of its notes with a preview. The draft card shows `Memory: isolated`.
- Turning it on for an agent that already has notes in the main memory is refused (`isolated_memory: <name> already has N notes in the main memory; …`): hire a new agent with isolated memory instead. Moving notes is not supported.
- Switching it on or off retires the current desk (archived, its journal moved to `roster/journal/.parked/`); the next desk starts fresh. Removing the agent moves its store to `agent-memory/.removed/`.
- `theuth` cannot be isolated.

This keeps memory separate. It is not a security boundary: a session with file or shell tools can still read files on disk, including either store.

### Status

Each agent shows one **Active / Paused** switch and an activity chip:

| Chip | Meaning |
|---|---|
| `idle` | Active, nothing in flight |
| `working` | Its desk is handling a wake right now (green dot on its Desks tile) |
| `waiting on <child>` (`+N`) | Its desk's current wake waits on child sessions |
| `blocked` | Every open task it owns is blocked |
| `invalid file` | `agents/<name>.md` does not parse; the error is shown on the card; the agent takes no wakes |
| `Paused · N wakes held` | Switch off, or auto-paused by budget; `· suspended mid-turn` when a turn was cut short (see [Pausing](#pausing)) |

A proposal awaiting approval appears only in the **Hiring** strip and the Inbox, not as a chip. There is no "retired" state: removing an agent deletes its file.

### Pausing

Switching an agent off (or hitting its budget cap) suspends it the way quitting theuth does. Its desk's turn and every subagent turn under it stop at the next safe point (a model call in flight gets `durability.drain_secs`, default 10 s, to finish); the journal records where each stood and how long it had run. While it is paused nothing of it runs:

- wakes are still raised but not delivered; the task thread says `queued for <name> (paused)`;
- a routine with `agent: <name>` records its fire as `skipped: agent paused` and creates no task;
- a child's result or a peer's message sent to one of its sessions is accepted and waits (across a restart too); its reminders wait and fire after the un-pause;
- text you type into one of its sessions is refused with `<name> is paused`, asking you to un-pause it to send;
- checked-out tasks stay checked out: no "presumed lost", no `blocked: no continuation`;
- restarting theuth resumes nothing; removing a paused agent closes its suspended turns instead of resuming them.

Switching it back on resumes those turns where they stopped (a subagent keeps the run time it had used against `agent.subagents.max_runtime_secs`), delivers what waited, and once the resumed desk turn ends the queued wakes arrive in priority order. A wake the desk was serving when it was paused is not delivered a second time. Saving the agent's file from another window or the budget card never changes `paused`; only the switch does.

## Walkthrough: hiring in chat

Describe the role to theuth in any chat (desktop or terminal UI):

```text
› hire a research assistant who turns a topic into a sourced one-page brief,
  reads-only, max 40 USD a month
```

theuth checks the roster, then draws an **agent draft** card rather than writing anything: title and name, the first 600 characters of a charter it wrote for the role, then manager, model, effort, tools ceiling, budget, MCP, isolated memory and context summary model when set, and *Hand off to it when:* with the capabilities. One call can draft several agents, one card each. Each card has three buttons:

- **Hire**: creates the agent active (shows as **Replace** when an agent with that name already exists).
- **Hire paused**: creates the file with `paused: true`; nothing runs until you flip the switch in the Agents view.
- **Discard**: nothing is written.

Your press arrives as your next message (`[app agent-drafts …]` with `agent draft a1-…: hire`) and theuth calls `agent_put`, which writes `~/.theuth/agents/<name>.md` at once. The receipt reads `hired agents/research-assistant.md (active)` or `… (paused: un-pause from the Agents view when ready)`; `replaced …` when the name existed. A new tile appears under **Desks** in the sidebar, and the agent is on the org chart.

To change an existing agent, ask in the same way ("give the research assistant a 60 USD budget", "let it use mutating tools"): the card comes back with **Replace** and the file is overwritten with the new fields.

If an agent's desk drafts a hire, its cards say so, **Hire** and **Hire paused** both lead to `agent_propose` (the agent lands paused and waits for your approval) and a desk cannot draft a name that is already taken.

## Walkthrough: the Hire an agent wizard

Open **Agents** in the desktop sidebar and press **Hire an agent** (route `/agents/new`). The wizard is seven steps; a half-finished draft resumes if you leave and come back.

| Step | Heading | What you set |
|---|---|---|
| Identity | *Meet your next agent* | Title; a name is suggested from it |
| Role | *Where does it sit?* | **Reports to** (any roster agent or `theuth`), **Capabilities** paragraph |
| Runtime | *How does it run?* | **Model** with effort chips (default *Node default*), **Context summary model**, **Context tail**, **Compactor profile**, **Tools ceiling**, **Runs in** (*anywhere*, *its own VM* or a named VM), **Isolated memory** |
| Access | *What may it reach?* | MCP: **All servers**, **None** or **Only these** (per server, optionally narrowed to `server.tool` entries) |
| Budget | *What may it spend?* | **No budget**, or **Monthly budget** with an amount and 3-letter currency |
| Charter | *Its charter* | A document editor pre-filled with a starter (a title heading, "You are …, reporting to …", *What you own*, *How you work*, optional *When to hand off to you*), with a chat to theuth beneath it to draft together |
| Review | *Review and hire* | **Hire** (labelled with the title) or **Hire paused** |

Validation before the final step: name matches `[a-z0-9-]{1,32}`, is not `theuth` and is not taken; title present; manager exists and is not the agent itself; tail marks in range; budget amount greater than 0 with an uppercase 3-letter currency; charter non-empty.

## Walkthrough: approving a proposal

Agents cannot hire. When a desk decides a role is missing it calls `agent_propose`: the file is written with `paused: true` and `proposed_by: agent:<proposer>`, and a task `Hire agent <name> (<Title>)` is filed up the proposer's reporting line (to you, when the proposer is theuth). You see it in three places:

- the **Hiring** strip at the top of the Agents view (*Hiring · N proposed hires await your approval*),
- the **Inbox** as a `hire` item, with **Hire** and **Decline** buttons,
- the task board's Queue strip.

Open the agent and press **Approve hire**: the proposal flags are cleared, the hire task is cancelled with the comment `approved`, the desk opens, and a toast says `Hired <name>`. **Decline** (with an optional note) deletes the file and cancels the task with `rejected: <note>`; toast `Declined <name>`. Until you decide, a proposal receives no wakes, has no desk, and is hidden from `agents_list` (unless `all: true`), from chat routing and from the org chart.

## Walkthrough: talking to an agent

**Desktop.** The **Desks** group in the sidebar has one tile per agent that is not a proposal or invalid, `theuth` first. Click a tile (or **Open desk** on its detail page): the chat that opens *is* the agent's desk session. It answers as the agent, with its charter and journal in context. If no desk is open yet, the click opens one. The open desk's subagents are listed below the tiles under a line with its live and finished counts (5 per parent, then *Show more (N)*). A tile can be dragged into a split pane or opened in a new window, and the megaphone button next to **Desks** broadcasts one message to several desks. Desk sessions never appear in the ordinary chat list. Desks also show as nodes on the Inbox's agent graph.

**Charter tab.** The agent's detail page has a **Charter** tab: a document editor with a chat to theuth below it. Edits land in `agents/<name>.md` once you pause typing. theuth's own charter is shown read-only here (edit `~/.theuth/prompt.md`).

**Slack and Signal.** The first word of a message routes it: `research-assistant: compare these two vendors` goes to that agent's desk and binds the thread to it; `theuth …` addresses the default explicitly; anything else is theuth's. Matching is case-insensitive and the trailing `:` or `,` is optional. Only active, approved agents are routable. There is no `@` syntax and no per-agent channel. **Telegram does not route by first word**: every message in the bot's chats goes to theuth, and a leading `name:` reaches the model as ordinary text. The desktop and terminal composers do not use this routing either; open the desk instead. See [Channels](/docs/automation/channels).

**Task threads.** Writing an agent's name as a word in a task comment wakes it on that task.

**Other sessions and machines.** While agent messaging is on, a desk answers to `<name>@<machine>` from any machine of your mesh.

**Contacts.** You can share any agent that has a desk with a [contact](/docs/automation/contacts) in Settings › Sharing › Contacts (**Access**). The contact's agent can then message it; it answers within its own `tools:` ceiling. Settings › Sharing › **Chats and agents** lists everything you share.

## Reference

### Agent file

```yaml
---
title: Research Assistant
reports_to: theuth
model: anthropic/claude-sonnet-4-5
effort: medium
tools: read_only
mcp: [github, slack.search]
budget: 40 USD/month
capabilities: Turns a topic into a sourced one-page brief. Hand off literature and market research.
runs_in: any
isolated_memory: true
paused: false
---
# Research Assistant

You are Research Assistant, reporting to theuth.
…
```

| Key | Default | Meaning |
|---|---|---|
| `title` | the name | Display title |
| `reports_to` | `theuth` | Manager; must be `theuth` or an existing agent |
| `model` | the new-session default | Catalog id for its desk; native children that name no model start on it |
| `effort` | `agent.effort` | Effort for its desk and for native children spawned without one; dropped when the model does not offer it |
| `tools` | none (no cap) | Risk ceiling `read_only` \| `mutating` \| `destructive`; children inherit the lowest ceiling in their ancestry |
| `mcp` | every server | Allowlist of `server` or `server.tool`; `[]` = no MCP at all |
| `budget` | `none` | `<amount> <CUR>/month`, e.g. `40 USD/month`; currency uppercased, no spaces around `/` |
| `capabilities` | none | One paragraph: when to hand work to this agent; other desks see it during the fit check |
| `paused` | `false` | No desk, no wakes |
| `proposed_by` | none | `agent:<name>`; set only by `agent_propose`, cleared by approval |
| `runs_in` | `any` | `vm` or `vm:<name>` pins its work sessions to a [sandbox](/docs/automation/sandboxes) |
| `isolated_memory` | `false` | Its own knowledge store (see [Isolated memory](#isolated-memory)) |
| `memory` | `agent.endless.default_desk` | `fractal` (or `endless`) \| `epochs`: whether its desk uses fractal context |
| `view_bytes` | `agent.endless.view_bytes` (128000) | Summary view size, 16000 to 256000 |
| `tail_mode` | `agent.endless.tail_mode` | `fixed` \| `scaled`: how the verbatim tail is sized |
| `tail_low_bytes`, `tail_high_bytes` | Settings › Agent › Context | Fixed tail: kept after a trim (8000 to 256000) and trim point (16000 to 512000, above the low mark); whole bytes |
| `tail_low_share`, `tail_high_share` | Settings › Agent › Context | Scaled tail: shares of the model's window, 0.02 to 0.40 and 0.05 to 0.60, high above low |
| `profile` | `agent.endless.profile` | Compactor profile `auto` \| `standard` \| `small` |
| `memory_model` | `agent.endless.model` | Model that writes its desk's summaries |
| `memory_effort` | none (thinking off) | Effort of `memory_model`; cleared with it |

Any other key makes the file invalid. An empty body is the error `empty charter`. Files whose stem starts with `.` or that are not `.md` are ignored.

### Tools the model calls

| Tool | Risk | Arguments | Notes |
|---|---|---|---|
| `agents_list` | read-only | `{ all?: bool }` | One line per agent: name, title, manager, status, open tasks, budget use, capabilities. Default lists only agents that take work (hides paused, proposed and invalid); `theuth` is never listed |
| `agent_draft` | read-only | `{ agents: [{ name, title, reports_to, charter, model?, effort?, tools?, mcp?, budget?, capabilities?, memory_model?, memory_effort?, isolated_memory? }] }` | Draws one Hire / Hire paused / Discard card per agent; writes nothing |
| `agent_put` | mutating | `{ name, title, charter, reports_to?, model?, effort?, tools?, mcp?, budget?, capabilities?, memory_model?, memory_effort?, isolated_memory?, paused? }` | Creates or overwrites the file; `reports_to` defaults to `theuth`; refused from any desk other than theuth's |
| `agent_propose` | mutating | same as `agent_put` minus `paused` | Writes the file paused with `proposed_by`, files the hire task; `reports_to` defaults to the proposer; refuses a taken name |

There is no model tool to pause, approve, remove or rename an agent: those are yours alone, through the UI or RPC.

### `roster:` config

```yaml
roster:
  decision_wait_secs: 120     # escalate waits this long for a live answer before parking
  episode_idle_secs: 21600    # desk idle → episode closes, journal written
  episode_context_pct: 60     # …or at this % of the context window
  journal_max_bytes: 8192     # ceiling on roster/journal/<name>.md
  max_rounds: 3               # child rounds per task per episode
  theuth_model: null          # theuth's desk model; null = the new-session default
  theuth_effort: null         # theuth's desk effort; null = the new-session default
```

Every key has a default; an absent section is the defaults. `theuth_model` and `theuth_effort` change live from the UI; the others need a restart.

## Budgets

`budget:` is a money cap per calendar month (UTC). There are no token caps and no per-day caps; `budget: none` is never checked.

- Every cost reported by the agent's desk or any of its child sessions is added to its month.
- At **80 %** the manager receives a task `Budget: <name> at 80 % (x of y CUR)` and a `budget` item appears in the Inbox.
- At **100 %** theuth pauses the agent (writes `paused: true`, suspends its work as in [Pausing](#pausing)) and files `Budget override: <name> spent x of y CUR in <month>` for the manager.
- Flipping the switch back to **Active** (or **Un-pause** in the Inbox) while spend is at or over the cap records an **override for the rest of the month**: the cap will not re-pause it until the next month starts.

The Overview's Budget card shows *Healthy*, *Warning*, *Hard stop* or *Paused by budget*, with observed, budget and remaining amounts. Spend is counted on the engine that charged it; in a mesh, work done on another engine is tallied there.

## Safety and permissions

- **Hiring is consent.** Pressing Hire, Approve hire or finishing the wizard is the approval; `agent_put` only works from your own chats or theuth's desk. A desk that tries it is refused: `agent_put is the user's approval; as agent <name>'s desk, propose with agent_propose`. Proposals land paused and wait for you.
- **Tool ceiling.** `tools:` installs a risk cap on the desk; children cannot exceed the lowest cap among their ancestors. A call above the cap is denied outright (`denied: subagent is capped at <risk>`), never asked. Inside the cap, the usual `tools.policy` applies (`read_only` allowed, `mutating` and `destructive` ask by default), and approval cards from a desk's children reach you wherever you are (desktop card, TUI `[y]/[n]`, Slack or Telegram buttons, a thumbs-up or thumbs-down reaction on Signal). The timeout is `tools.approval_timeout_secs` (300 s, then deny). `/approvals off` and Settings › Agent › Approvals apply to desks like any other session; there is no per-agent "always allow". The built-in `theuth` runs with `destructive`, every MCP server and no budget.
- **MCP allowlist.** `mcp:` limits which MCP servers and tools a desk and its children can see at all. Omitted means every configured server.
- **Secrets** are never agent-scoped. `{{secret:NAME}}` in a tool call resolves on the executing engine and raises the call to at least *ask*: see [Secrets](/docs/reference/secrets).
- **Knowledge scope.** An agent's sessions read and write knowledge as `agent:<name>`, private by default, with its reporting line as the team; you and theuth see everything in the main memory. An agent with isolated memory keeps its notes in its own store (see [Isolated memory](#isolated-memory)); that separates memory and is not a security boundary.
- **Removal.** **Remove** on the detail page is an alert dialog: "Deletes `agents/<name>.md`. Its desk closes; its tasks stay on the board unowned until you reassign them. Agents reporting to it move under theuth." Its charter document goes to the trash. No model tool can remove an agent.

## Limits and lifecycle

| Item | Value |
|---|---|
| Agent name | `[a-z0-9-]{1,32}`, `theuth` reserved |
| Number of agents | no cap |
| Desks per agent | 1 per machine that has the agent (theuth: one on every machine) |
| Desk episode closes | idle 21600 s, or 60 % of context, or thread end / shutdown |
| Episode closing turn grace | 10 min |
| Journal | at most 8192 bytes, `~/.theuth/roster/journal/<name>.md` |
| Child rounds per task per episode | 3 (`roster.max_rounds`) |
| Nudges before `blocked: no continuation` | 1 |
| Escalation wait for a live answer | 120 s (`roster.decision_wait_secs`) |
| Budget thresholds | 80 % task; 100 % auto-pause; manual un-pause overrides the month |
| Charter preview on the draft card | 600 characters |
| `view_bytes` | 16000 to 256000 |
| Subagents shown per parent under Desks | 5, then *Show more (N)* |
| Desk housekeeping tick | 60 s |

Lifecycle: **draft card** → (Hire) **active** ⇄ **paused** → (Remove) **deleted**; or **proposed** (paused, `proposed_by` set) → (Approve) **active** / (Decline) **deleted**. A file that stops parsing becomes **invalid** until fixed; its desk closes and it takes no wakes.

| Symptom | Cause | Fix |
|---|---|---|
| Activity chip `invalid file` | Front-matter parse error, unknown key, bad `tools` / `budget` / `runs_in` / `memory` / `view_bytes` / `tail_*` / `profile`, or empty charter | Read the error on the card; fix the file or re-hire with **Replace** |
| Agent paused on its own | Hit 100 % of its monthly budget | Read the *Budget override* task; flip to **Active** (or **Un-pause** in the Inbox) to override for the month, or raise the cap on the Overview's Budget card |
| A task shows `on <machine>` and its agent here never picks it up | The task's home is another machine; only that machine's desk works it | Open the task's **⋯ › Move to ▸** to move it here: see [Tasks › Machines](/docs/automation/tasks#machines) |
| `agent is a proposal awaiting approval` | Trying to open a desk for an unapproved hire | Approve or decline it in the Hiring strip or the Inbox |
| `agent is paused` | Opening a paused agent's desk | Flip the switch to **Active** |
| `desk is closing; try again in a moment` | Episode is in its closing turn | Wait up to 10 minutes and retry |
| `agent_put is the user's approval; as agent X's desk, propose with agent_propose` | An agent's desk tried to hire | Expected; the proposal arrives in your Hiring strip and Inbox |
| `reports_to "x": no such agent (see agents_list); use theuth or an existing name` | Manager is not on the roster | Use `theuth` or an existing name; hire the manager first |
| `agent <n> exists; pick another name or create a task for it` | A desk proposed a name already in use | Choose another name, or assign the existing agent a task |
| `isolated_memory: <name> already has N notes in the main memory; …` | Turning on isolated memory for an agent that already wrote to the main memory | Hire a new agent with isolated memory |
| `isolated memory unavailable here: …` | An isolated agent's store could not be selected; knowledge tools refuse rather than use the main memory | Retry once theuth has finished starting; check that `agents/<name>.md` still has `isolated_memory: true` |
| Task set `blocked: no continuation` | The desk ended two turns without moving its task, or its episode closed mid-task | The manager was woken; **Unblock** on the task detail re-queues it |
| `agents/theuth.md` ignored (warning in the log) | `theuth` is reserved | Edit `~/.theuth/prompt.md` for theuth's charter |
| Desk opens but never delegates | Messaging is off (no machine is paired and `agent.communication` is unset, or it is explicitly `false`), or the **Agents and peers** builtins are off, so `spawn_subagent` is missing | `/communication on always`, or Settings › Network › Messaging; check Settings › Tools › Builtins |
