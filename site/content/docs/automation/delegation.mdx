title: Delegation and subagents
description: How theuth hands work to child sessions — native theuth subagents, external coding harnesses over ACP (opencode, codex, claude), and theuth on other machines — and how results, approvals, cost and limits flow back to you.
---

Delegation is theuth spawning a **child session** to do part of a job: a research fan-out across several native children, or a repository task handed to an external coding harness such as opencode in a given directory. The parent keeps the conversation with you; the child gets only a written brief and reports back once with its final message. You use it whenever a task splits into independent pieces, needs a tool you have installed elsewhere, or should run on another machine.

## Prerequisites

- **Communication switched on.** Model-to-model communication is on by default once this machine has a paired machine in a [mesh](/docs/automation/mesh), and off by default on a single machine (`agent.communication` absent in `~/.theuth/config.yaml`). While it is off, `spawn_subagent`, `discover_peers` and `send_message` are not offered to the model at all, and no child result is delivered. An explicit `agent.communication: true|false`, the env var or `/communication on|off always` always wins and is never moved. To turn it on from any chat:

  ```text
  › /communication on always
  ```

  This writes `agent.communication: true`. Alternatives: edit `config.yaml`, or set `THEUTH_AGENT__COMMUNICATION=true` in the daemon's environment (an env value wins over the file on every start; `/communication` tells you where the value came from).
- **A model provider** for native children — a child runs on a model you have credentials for ([Models and providers](/docs/getting-started/models)).
- **For external harnesses:** the harness installed and logged in, plus an entry in `~/.theuth/acp/agents.yaml` (added with `/acp add …` or Settings › Harnesses, below). Anything that speaks ACP v1 over stdio works.
- **For other machines:** a paired node or mesh engine — see [Mesh](/docs/automation/mesh).

No special mode is needed: delegation works in the desktop app, the terminal UI, and in `t --headless` behind Slack, Signal and Telegram.

## How it works

When delegation is available, theuth is instructed to delegate by default: external harness (`agent:`, with `cwd`) for anything in a code repository; native theuth children for research, review and fan-out. It writes each child a complete brief, because **a child sees nothing of your conversation** — only the `task` text.

A spawn returns immediately. The parent reads:

```text
Spawned `quiet-otter` (session:0192…). Its result will arrive as a <message from="session:0192…">
when it finishes; message it with send_message to `quiet-otter` or `session:0192…`.
```

The child is a real session: it appears in the sidebar under the parent, you can open it, read its transcript, answer its approvals, and `/cancel` it. Its lifecycle states are `idle`, `running`, `awaiting` (waiting on a peer reply), `approval` (blocked on an Allow/Deny card), `error`, `cancelled`.

When the child finishes, its final assistant message is queued on the parent as a user-role input wrapped as:

```text
<message from="session:<child-uuid>" id="<uuid7>" at="HH:MM">
…the child's final text…
</message>
```

The parent's turn then continues (or a new one starts) with that text. If the child failed, the error text *is* its final message and arrives the same way. Three kinds of child exist:

| `agent` argument | What runs | Where |
|---|---|---|
| omitted | A native theuth child on `model`/`effort` | This engine |
| `<harness>` | An external ACP harness from `acp/agents.yaml`, started as a subprocess in `cwd` | This machine |
| `<node>` or `<harness>@<node>` | A theuth child, or that node's own harness, on another machine | The node, over the link |

**Verification is yours and the parent's, not automatic.** theuth does not check a child's claims; the parent model is instructed to verify them (re-read the file, run the test) before passing them on. If a child says "tests pass", treat that like any other model claim until the parent — or you — has confirmed it.

## Walkthrough: a research fan-out

With communication on, ask for something that splits naturally:

```text
› compare how tokio, async-std and smol handle task cancellation — one short section each,
  then a recommendation for our use case

  ⠋ thinking…
  ▸ spawn_subagent  task: "Research cancellation semantics in tokio…"  name: tokio-research
  ▸ spawn_subagent  task: "Research cancellation semantics in async-std…"
  ▸ spawn_subagent  task: "Research cancellation semantics in smol…"
```

The three children show up in the desktop sidebar under this chat as a small tree (live rows first), each with a glyph for its state and, once known, a cost. In the terminal, `/agents` opens a picker of this session's subagents — running, awaiting, then newest finished first; ⏎ opens one. Each child reads docs and source on its own; reads need no approval under the default policy, so a research fan-out usually runs without interrupting you.

As each finishes, its report arrives in the parent transcript as an incoming message from that child (`tokio-research`, …), and the parent synthesises once all three are in. A child turn that runs longer than `agent.subagents.max_runtime_secs` (600 s of run time; a restart does not reset it, downtime does not count) is cancelled and its partial text is delivered prefixed `[timed out after 600s, stop=…]`; a child turn that failed says so (`[child turn ended: error — …]`, `[child turn cancelled]`, `[child turn ended with no reply]`).

## Walkthrough: a repo task through opencode

First, register the harness once. In the terminal:

```text
› /acp add opencode
```

or in the desktop app: Settings › **Harnesses** › pick it from the registry list and **Add**. The entry lands in `~/.theuth/acp/agents.yaml`. Press `p` in the `/acp` menu (desktop: **Probe**) to check it: the status is `ok`, `login required: <cmd>`, or `spawn failed: <why>` (the probe runs `initialize` + `session/new` with a 10 s limit; a hang reads `spawn failed: timeout`).

Then ask, naming the directory:

```text
› in /Users/me/src/relay, use opencode to make the reconnect backoff configurable
  (config key relay.backoff_secs, default 5) and add a test

  ▸ spawn_subagent  agent: opencode  cwd: /Users/me/src/relay  task: "…"
```

What happens:

1. theuth starts `opencode acp` in that `cwd`, sends `initialize`, authenticates if the harness asks, and opens a session. The harness's stderr goes to `~/.theuth/logs/acp-opencode.log`.
2. If you gave a `model`/`effort`, theuth applies them through the harness's own option menu when it offers one; otherwise the harness keeps its default. The chat header of the child shows the harness's live model picker and thought level, if it exposes them.
3. The harness gets a small theuth MCP server inside its session (`list_skills`, `load_skill`, `send_message` back to the parent, plus `read_file`, `edit`, `move_text`, `copy_text`, `indent` and `clip` run in the child's session: its working directory and approvals), and any `skills` you asked for are written into `<cwd>/.agents/skills` for the run and removed when it stops.
4. **Every permission the harness asks for comes to you** as a normal approval card on the child session (and surfaces in the parent transcript as "subagent `opencode-…` is waiting on you · open"). Allow/Deny there is forwarded as the harness's `allow_once`/`reject_once`.
5. When opencode finishes, its final message (or, if it ended with no text after a rejected permission, its last tool output) arrives in the parent as the `<message from="session:…">` input; the parent verifies and reports to you.

If the child stops and you want to continue in the *same* harness context — for example after denying something by mistake — open the child and run `/resume` with no argument (desktop: **Resume** in the child's header). This restarts the harness and reloads its session when the harness supports `loadSession`.

## Reference

### `agent.communication` and session scope

| Command / setting | Effect |
|---|---|
| `/communication` | Show global, session, inherited blocker, effective and network state |
| `/communication on\|off` | This session and its descendants, in memory, gone at daemon restart; cannot override a global off or an ancestor's off |
| `/communication on\|off always` | Writes `agent.communication` in `config.yaml` |
| `THEUTH_AGENT__COMMUNICATION=true` | Env override; wins over the file at start |
| `/peers` | Who this session may message, and peer requests waiting for your answer (⏎ opens, `i` inspects, `a` answers) |
| `/peers scope owner\|isolated [alias]` | Promote or isolate a root (owner only; no model tool does this) |
| Settings › Communication | Desktop switches for the same global and per-chat state |

Scope: roots you open from the desktop or terminal are `owner` scope and may also reach other owner roots; roots created by a routine, an ACP client (`t --acp`), or a non-owner Slack/Signal/Telegram contact are `isolated` to their own tree. Children always belong to their parent's tree. The model never sees another root's title, cwd or transcript.

### `spawn_subagent` arguments

| Argument | Meaning | Default |
|---|---|---|
| `task` (required) | Complete, self-contained brief; the child sees nothing else | — |
| `name` | Stable peer name used with `send_message` | Generated `adjective-noun`; `-2`, `-3` on collision |
| `agent` | `<harness>` from `acp/agents.yaml`, `<node>`, or `<harness>@<node>` (a mesh engine may be named by its id prefix) | Native theuth child |
| `cwd` | Absolute working directory for an external harness | theuth's cwd |
| `model` | `provider/model` (see `list_models`); checked against catalog and credentials for a native child; applied to a harness if it offers a `model` option, else kept. The agent passes it only when you ask for a specific model | For a native child: the desk agent's model when the parent is a desk, else Settings › Chat › **Subagents**, else the new-session default |
| `effort` | `low\|medium\|high\|off\|default` or a token budget; for a harness, applied when it lists that value (omp: `low\|medium\|high\|xhigh\|max`; opencode: the model's variants) | `agent.subagents.effort`, else configured |
| `tools` | Risk ceiling `read_only\|mutating\|destructive`; enforced by the tool registry for theuth children and on nodes; for an external harness only prepended to the brief as `Limits: tools <cap>` | No ceiling |
| `skills` | theuth skill names written into an external harness's cwd; error on a native child, on a node target, or when the entry has `skills: false` | none |

Errors the parent reads back: ``unknown agent `x`; configured: a, b`` (or ``unknown agent `x`; none configured - add one with /acp or in acp/agents.yaml``), `subagents are not available at depth N`, `remote agents are unavailable in a private session`, ``provider `p` has no credentials; list_models shows what is available``, ``unknown effort `e`; use low|medium|high|off|default or a token budget``.

Companion tools: `send_message{to, message, await_reply?, reply_to?, request_id?}` (`to` is `session:<uuid>`, `peer:<name>`, `parent`, a child's name, or a list of up to 16; body up to 32 KiB; `send_message` is a mutating tool and asks under the default policy), `discover_peers{query?, cursor?, limit?}` (25 per page, max 100), `peer_message{id}`, `list_models`.

### `agent.subagents` limits

```yaml
agent:
  subagents:
    model: null             # preferred child model
    effort: null
    max_depth: 1            # children at this depth cannot spawn further
    max_concurrent: 8       # simultaneous child spawn turns; extra spawns queue
    max_runtime_secs: 600   # run time per child turn (resumes continue it)
    reply_timeout_secs: 120 # send_message{await_reply} deadline
```

| Key | Default | Where to change it |
|---|---|---|
| `model` | `null` | Settings › Chat › **Models › Subagents**; desktop `/subagent <provider/model>` / `/subagent off`; `config.yaml`. When set, the parent's system prompt names it as the subagent default model. External harnesses keep their own model. |
| `effort` | `null` | `config.yaml` |
| `max_depth` | `1` | `config.yaml` (restart). At the limit `spawn_subagent` is hidden from the child and rejected at call time. |
| `max_concurrent` | `8` | `config.yaml` (restart). The parent still receives "Spawned …" at once; the 9th child waits for a slot. |
| `max_runtime_secs` | `600` | Settings › Agent loop › **Subagent timeout**; `config.yaml`. Per child turn, run time only (see Limits). Applies to turns from now on. |
| `reply_timeout_secs` | `120` | `config.yaml` |

Other caps: a child's result text is bounded by `agent.max_tool_output_chars` (32 000) with the remainder spilled to `~/.theuth/spill/<parent>/<child>.txt`, and vault values are redacted from it. A recipient with 32 pending unread peer inputs answers `busy`.

### `~/.theuth/acp/agents.yaml`

Read at every spawn and every `/acp`; no restart needed. One entry per harness:

```yaml
opencode:
  command: opencode
  args: [acp]
  description: OpenCode, local install     # shown to the model in the tool description
  env: {}                                  # merged over theuth's environment
  skills: true                             # default; false = no theuth skills written into the child's cwd
  skills_dir: .agents/skills               # default; .claude/skills for Claude Code
  mcp: true                                # default; false opts out of the theuth MCP shim
  steer: interrupt                         # default; queue = a message waits for the harness's turn to end
  steer_window_ms: 1500                    # default; messages inside the window share one interrupt
  nudge_after_secs: 20                     # default; 0 = no nudge when a message draws no activity
  max_nudges: 1                            # default; then an error is shown, nothing more is sent
codex-acp:
  command: npx
  args: [-y, "@agentclientprotocol/codex-acp"]
```

The generated file ships these two entries commented out. `/acp add <registry id>` fills one in from the public ACP registry (fetched from `cdn.agentclientprotocol.com`, cached in `~/.theuth/acp/registry.json` for 24 h; offline, the cache is used): `npx` packages become `npx -y <pkg>`, `uvx` packages `uvx <pkg>`, binaries use the one on your PATH or are downloaded to `~/.theuth/acp/bin/<id>/` with a sha256 check. `/acp remove <name>` deletes the entry and that directory.

Exercised in this repo as of this writing: **opencode 1.18.30 and 2.0.22**, **omp 18.3.1**. `codex-acp` and `claude-agent-acp` (`npx -y @agentclientprotocol/claude-agent-acp`) are template and registry entries. With opencode before 2.0, usage is reported per request rather than cumulatively, so its cost shows as "(last request only)".

## Safety and permissions

- **Nothing about spawning is a privilege by itself.** `spawn_subagent` is a read-only tool and does not ask. The gate is `agent.communication`: off hides the whole family of tools and blocks delivery; `/communication off` on a session opts that tree out underneath a global on. Session opt-outs are memory-only.
- **Children ask you, not the parent.** A native child's mutating/destructive calls go through the normal `tools.policy` and surface as Allow/Deny cards on the child session (TUI `[y]`/`[n]`, desktop card, Slack or Telegram buttons, Signal 👍/👎 or `/approve <code>`); unanswered cards deny after `tools.approval_timeout_secs` (300 s). The parent transcript shows a pointer card to the waiting child.
- **Harness permissions are forwarded through the same gate.** Every `session/request_permission` from an external harness becomes a theuth approval with the harness's tool title and arguments, classified by the kind the harness reports. Allow maps to the harness's allow option, Deny to its reject option; a cancelled turn answers `cancelled`.
- **`/approvals off` is inherited.** A session that opted out of prompts passes that to its children; `/approvals off always` writes `tools.approvals: false` for everyone. There is no per-tool "always allow". Details in [Tools and permissions](/docs/reference/tools-permissions).
- **`tools:` ceilings are hard for theuth children only.** A native child capped at `read_only` is refused anything higher with `denied: subagent is capped at read_only`, and so are its descendants. An external harness only *reads* the cap as the first line of its brief — its own permission prompts are still forwarded to you, but the cap is advice, not enforcement.
- **Secrets stay in the vault.** Child results are redacted of vault values before the parent sees them.
- **Private sessions cannot delegate to external agents.** `spawn_subagent{agent}` is refused in a private tree (`remote agents are unavailable in a private session`).
- **No model can kill a child.** There is no `cancel_subagent`, `list_subagents` or `wait` tool; cancelling is a human action (`/cancel`, Slack `/theuth cancel`).

## Limits and lifecycle

| Limit | Value |
|---|---|
| Nesting | `max_depth` 1: a child cannot spawn by default |
| Concurrent spawn turns | `max_concurrent` 8; further spawns queue silently |
| Child runtime | `max_runtime_secs` 600 per child turn (spawn, follow-up, human-opened, resumed) → turn cancelled, result prefixed `[timed out after 600s, stop=<reason>]`, child state `cancelled`. Only run time counts: a turn resumed after a restart continues its own cap (at least 60 s left to land); time the engine was stopped or the machine slept is not counted |
| Failed child | Result prefixed `[child turn ended: error — <reason>]`, `[child turn cancelled]`, or `[child turn ended with no reply]`; nothing is retried automatically |
| `await_reply` wait | `reply_timeout_secs` 120 |
| Result size | `agent.max_tool_output_chars` 32 000, rest spilled to `spill/<parent>/<child>.txt` |
| Peer intake | 32 unread inputs per recipient → `busy` |
| Message body | 32 KiB; up to 16 recipients per `send_message` |
| Harness probe | 10 s |
| Busy harness | `session/prompt` refused as busy is retried at 5, 10, 20, 30 s… until the runtime deadline |
| Message to a busy harness | After `steer_window_ms` (1.5 s) the turn gets `session/cancel` and is re-prompted at once with the message(s) and a note to resume; the parent still gets one result for the turn. No streaming within `nudge_after_secs` (20 s) of a message prompt → one nudge, then an error. `steer: queue` waits for the turn instead |
| Harness tail work | Output after the harness returned its prompt is a "continuation turn", closed after 120 s quiet and never delivered to the parent |
| Cancel grace | ACP child: `session/cancel`, process killed after 5 s |

Lifecycle: `spawn` → child `running` → (`awaiting` / `approval` as needed) → final message delivered as `<message from="session:…">` → child `idle`. A failure ends the child in `error` with the error text as its message; a timeout or `/cancel` ends it in `cancelled`. A finished ACP child can be resumed in its harness context; a native child can be messaged again with `send_message` to its name.

Cost rolls up: each child's spend (returned by the provider, or an estimate shown as `~$…`, or `—` when unavailable) is summed into the parent's **Descendants** figure in `/cost` and the desktop CostPill; the sidebar tree shows each child's own total. An ACP harness that reports a cumulative meter that later goes *down* is flagged as a suspected delta rather than silently accepted.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| theuth answers that it cannot delegate / `spawn_subagent` never appears in tool cards | Messaging is off: `agent.communication` is `false`, or unset with no paired machine, or this session is opted out | `/communication` shows the exact blocker; `/communication on always` turns it on globally |
| A child finished but the parent never reacted; log says `child result not delivered: communication off` | Communication was turned off between spawn and finish | Turn it back on and ask the parent to re-run; suppressed results do not revive |
| ``unknown agent `opencode`; none configured - add one with /acp or in acp/agents.yaml`` | No entry in `~/.theuth/acp/agents.yaml` | `/acp add opencode` or Settings › Harnesses |
| `subagents are not available at depth 1` | A child tried to spawn; `max_depth` is 1 | Ask the parent to do the fan-out itself, or raise `agent.subagents.max_depth` and restart |
| ``provider `openai` has no credentials; list_models shows what is available`` | `model:` named a provider without a key or login | Add the key or pick a configured model ([Models](/docs/getting-started/models)) |
| Probe shows `login required: <cmd>`, or the child fails with ``not logged in — run `<cmd>` in a terminal, then retry`` | The harness needs its own login | Run the quoted command in a terminal, then probe again |
| Probe shows `spawn failed: <why>` or `spawn failed: timeout` | Command not on PATH, wrong args, or the harness hung before `session/new` | Check `~/.theuth/logs/acp-<name>.log`; fix `command`/`args` in `agents.yaml` |
| Result arrives as `[timed out after 600s, stop=…]` | The child ran past `max_runtime_secs` | Raise Settings › Agent loop › Subagent timeout, or split the task |
| Parent gets `result of subagent session:… is missing; inspect its transcript` or `subagent result not delivered: <reason>` | The hand-off failed internally | Open the child from the sidebar or `/agents` and read its last message |
| An opencode child "finished" right after you denied a permission, with a tool output as its result | opencode ended the turn with no assistant text; theuth delivers the last tool output instead | Open the child, `/resume` to continue in the same context, and allow the step if intended |
| A harness child ignores `model:`/`effort:` | The harness exposes no such option, or not that value | Check the child's header picker for what the harness offers; otherwise set it in the harness's own config |
| `` `skills` is for an external harness; a theuth subagent loads skills itself with load_skill `` | `skills:` given on a native child (or a node target / an entry with `skills: false`) | Drop it; native children use `load_skill` themselves |
| Sidebar tree shows only 5 children | The tree caps at 5 rows per parent | Click **Show more (N)**; live children are always shown |
| Cost pill reads "(last request only)" | opencode before 2.0 reports usage per request | Upgrade opencode, or treat the figure as a lower bound |
