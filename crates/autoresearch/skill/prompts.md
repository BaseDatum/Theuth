
## Prompt and skill studies

A **prompt study** (159 §7) optimises a text artefact — a prompt file in the user's app, a skill, a learned sidecar — whose effect is measured by running it over cases and scoring each case. There is no benchmark command: the engine's case runner renders the artefact as the target model's system prompt (or fills `{{artefact}}` in `cases.render`), answers every case, scores it with the case's own check or with a 0–1 judge that sees the ideal, and decides with a paired per-case gate on the **val** cases only.

When it fits: the user has, or can write, a case set — at least 10 val cases after the split, so about 25 cases in all — with a checker (`exact`, `regex`, `contains`, or a command that reads the answer on stdin and prints `METRIC score=`) **or** an `ideal` per case for the judge. A judged per-case score with references and a holdout is allowed here; the judge-only warning above is about scalar studies with no cases.

The interview adds three rows and changes two:
1. **Cases** — `cases: {source: file, path: <repo-relative JSONL>, artefact: <repo-relative text file>}`. A `file` line is `{"id", "input", "ideal"?, "check"?: {"kind": "exact"|"regex"|"contains"|"command", "value"}, "tags"}`. Write the case file into the user's repo only if they ask; otherwise generate it in the drafts directory, have them commit it, and list it in `evaluator_paths` (custody hashes it; a changed case set is refused). `cases.split` defaults to `40/40/20` train/val/holdout; `cases.repeats` (calls per case per sample) defaults to 1.
2. **Skill studies** — `cases: {source: dreaming, skill_hint: <name>, artefact: skills/learned/<name>.md}` reads dreaming's case store for that skill (open, reopened and closed cases; the ideal reaches only the judge). The repo is a scratch git repo seeded with the sidecar; landing goes through dreaming's write path so `dreaming_undo` reverts it.
3. **Target and scoring** — `models.target` is the model the artefact runs on (default: the session model; pick the cheap one the prompt is for); `models.judge` the judge (default: another vendor than the target). Say the cost in numbers: val cases × repeats × (one target call, plus one judge call when judged) per experiment, plus the session; with 40 val cases on a $0.002 target that is about $0.10 of calls per experiment.
4. **Metric** becomes `metric: {name: score, unit: "", direction: higher, min_effect: "0.05"}` and `axes: {scoring: cases, artefact: file}` — the draft's kind reads `prompt study`. `bench: {command: cases, repeats: 2}`: the word `cases` names the engine's case runner (no script runs) and `repeats` is the baseline's passes; `holdout: {every: 3}` with no command runs the holdout split every 3 keeps and at the end.
5. **Scope** is the artefact; **off-limits** the case file and anything that generates it.

The study session sees failing **train** cases only — input, the model's answer, the checker's diff or the judge's reason, never an ideal and never a val or holdout case. A candidate that repeats eight consecutive words of any val or holdout input or ideal is refused before any call is made: tell the user the loop cannot win by pasting answers, and that a holdout drifting away from val raises the overfit flag like any other study.
