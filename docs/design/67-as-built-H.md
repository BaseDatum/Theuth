### `feat(tasks): escalate — up the line, wait, then park` (06006e9)
- `crates/tasks/src/escalate.rs` (new): `Escalations { pending, answered }` — `subscribe(decision) -> oneshot::Receiver<String>` (answers already given resolve at once), `answer(decision, text)` resolves every waiter and remembers the answer; `wait(rx, dur) -> Option<String>`; `set_wait`/`wait_secs()` over a `OnceLock<Duration>` (default 120 s) filled at plugin start from `roster.decision_wait_secs` (read as `rt.section::<serde_json::Value>("roster")` — tasks does not depend on roster).
- `crates/tasks/src/ledger.rs`: `escalate` now resolves the **caller's** agent's manager (`actor` = `agent:<n>` → `manager_of(n)`; `user`/`system` → `Err("you are the top of the line; decide it")`), wakes the manager with `WakeReason::Answer` (was `Review`), and the thread note ends with how to answer (`decide { task, decision, answer }` or `escalate` the same task further); returns `(decision, manager)` internally. New `answer_decision(decision, answer, actor, session)`: finds the task blocked on `decision` (`store.blocked_on`), writes `**decision** (…): answer` to the thread, removes the blocker through `update` — the existing last-blocker rule puts the task back to its previous state and wakes the owner with `Answer`. New `mention(id, text, actor)` = `say` + `wake(owner, Mention)`.
- `crates/tasks/src/lib.rs`: messages `Mention { id, text, actor, session }` → `Result<(), String>`, `MarkAnswered { sender, timestamp }` → `Result<bool, String>` (true = first), `AnswerDecision { decision, answer, actor, session }` → `Result<(), String>`, `AwaitDecision { decision, wait }` → `Option<String>` (DelegatedReply + timeout, the `approval.rs` idiom). The `Escalate` handler keeps its `Result<String, String>` reply; when the manager is the user it spawns the **user path**: `tools::AskUser` (`ASK_ACTOR`) is asked a `Request { session: the calling session, questions: [Question { id: decision, question + "(task <id> — <title>)", options as choices }] }`; the answer (option text or typed text) becomes `AnswerDecision { actor: "user" }` whenever it comes — `AskRequested` is already rendered by the desktop card, Slack and Signal (the "bound chat thread"), and `PendingAsks` replays it to late subscribers. `answered` added to the `replica::attach` list.
- `crates/tasks/migrations/0002_answered.sql`: `answered(id TEXT PRIMARY KEY, sender, timestamp, hlc)`; `store.mark_answered` = `INSERT OR IGNORE`, `rows_affected() == 1`.
- `crates/tasks/src/tools.rs`: `escalate` waits `AwaitDecision { wait: wait_secs() }` after filing: `Some(answer)` → `decision: <answer>` (the blocker is already gone); `None` → `parked: task … is blocked on decision:…; the answer re-wakes you. End your turn.` New tool **`decide`** (`DecideTool`, Mutating, `{ task, decision, answer }`) → `AnswerDecision` in the caller's name — how a manager desk answers. Eight tools registered.
- Outside the crate: `crates/tools/src/ask.rs` — `struct Request` and `struct Outcome` made `pub` with `pub` fields (two lines; nothing else).

## Deviations
1. **Duties default on.** `Follower::default().holding == true`: desks, dispatch, the Slack socket and Signal answering behave exactly as before the mesh (or when it never answers); the first `Lease` naming another holder turns them off. Two engines starting together may both be hub for a few seconds (§4.4 tolerates it).
2. **Chat crates follow the lease themselves** (no roster → slack/signal messages; a dependency cycle otherwise). Three `Follower`s, one implementation.
3. **First chat message = `CreateTask`, no extra `Mention`.** The task's `assigned` wake carries the brief; later messages raise `Mention`. Two wakes for one message would cost the desk two turns.
4. **Tasks from chat have no project** (`project: None`): a Slack/Signal thread carries no project label; theuth can `task_update` it.
5. **Manager answers with a tool**: the design's "manager replies" needed a way for a desk to answer; `decide { task, decision, answer }` is it. "Manager replies escalate" = the manager calls `escalate` on the same task; the chain ends at the user through the ask path.
6. **The user path is the `ask_user` actor**, not the approval actor: an escalation has a question and options, `Approval` is Allow/Deny. Its 1800 s timeout outlives `decision_wait_secs`; the task stays parked until answered.
7. **`escalate` by `user`/`system` is refused** ("top of the line").
8. **Budget override approval = `agent_pause false`** (RPC / Agents view) on the paused agent, which records the month's override. The "approval up the line" is the task filed for the manager (visible in the queue/board); an agent manager cannot approve an override (no tool) — the user does. Likewise `hire_agent`: the approval is a task for the proposer's manager; `agent_approve` resolves it.
9. **`answered`, `budget`, `budget_override` have single-column primary keys** (replica requirement) — `MarkAnswered { sender, timestamp }` and the store signatures are as the contract says.
10. **Signal `Thread.session` is `Option<SessionId>`** (an agent-bound contact with no desk yet); legacy `threads.json` still loads.
11. **Slack: one desk session, many threads.** Replies from a desk go to the agent's most recently active thread; `ponytail:` in `Threads::by_session`.
12. **Cost currency**: only the budget's currency is summed; other currencies in a session's bucket are ignored.
13. **Commits 1 and 4 are one compile unit** (`lib.rs` in commit 1 already references `budget`/`proposals`); the branch tip is what compiles.

## Not built
- **Tool approvals routed to a manager** (`approvals: ask`, §11 last sentence): no tool lets an agent resolve an `Approval`, the approval actor answers `Deny` after its own 300 s timeout, and the registry has no interception point. Approvals stay user-only as today.
- **42 push** for escalations to the user: design 42 has no implementation in the repo (no push op in `link`/`relay`); the user gets the ask card on the desktop and in the bound Slack/Signal thread.
- The `Unreachable` agent status, thread-entry deltas in wakes, placement (other workers).
