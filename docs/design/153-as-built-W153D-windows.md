## 3. Deviations (each the closest faithful variant; none silent)
1. **Secure fields follow the design, not the brief.** The brief said "IsPassword → refuse"; §13.1/§7.4/§16.1 #24–25 say secure → editable, delivered by the lease, never Return (Mac parity, R6). Built as the design: lease, no verification (bullets only), "send it" → "not sent — secure field". Read-only and disabled text controls are unknown since H3-D1 (live round 2 still showed the older refusal).
2. **Direct read-back looks three times** (150/350/1000 ms, early exit on landed) instead of once at 150 ms: SendInput and the target's UIA tree are asynchronous; a late read must never re-deliver words that landed.
3. **The lease is the Windows default delivery; paced direct typing (15 ms per character, ≤ 60 characters) only with `directInsertion` on.** Measured on build-B: a batch of KEYEVENTF_UNICODE events into Win11 Notepad (XAML/TSF) kept the first characters and turned every later one into the batch's last character; a Ctrl+V queued behind that backlog arrived as "v"; at 8 ms per character a 107-char run still came out mangled (round 4). Deliveries also wait for a quiet field (two equal reads 60 ms apart, ≤ 900 ms), and a run that does not read back goes to the card. Round 5 dropped characters from a 33-char run even so — injected KEYEVENTF_UNICODE keystrokes are not reliable in XAML/TSF text surfaces (the Mac's direct write is an AX insertion, which Windows has no equivalent for: UIA can set a whole value, not insert at the caret), so the lease (4/4 → 3/3 landed and restored in rounds 2 and 5) carries every utterance by default.
4. **Held keys take the lease** (`Method(keysHeld)`): during a hold of Ctrl+Alt+D paced typing cannot stay atomic against the chord's auto-repeat; the lease's single burst can.
5. **Role table, Windows form**: the certainly-not set adds the Windows forms of the macOS column (radio, menu, menubar, toolbar, table row/cell) and their kin (split button, tree/tab items, hyperlink, scrollbar, progress, status/title bar, separator, tooltip, header); `Text` WITH a TextPattern is unknown, not refused (Windows Terminal's control reports Text); a writable ValuePattern is editable on any role outside the certainly-not rows (H3-D1; DataItem is not one); ComboBox is a text role (AXComboBox twin); elevated targets are unknown and their paste is reported `pasteCommandFailed — elevated window` (UIPI drops SendInput silently).
6. **A refusal with words already in hand** (the probe's fixture, or the lock mid-gesture) shows the failure card (kind `noEditableTarget` / `targetUnavailable`) so no words are lost; a refusal at a real key press shows the hint only (nothing was said yet).
7. **The failure card and the rewrite panel sit where the one AnswerCard sits** (top-centre of the pointer's display, W153C's placement) rather than "at the pointer" (§3.2), because D12 makes them that card.
8. **Switch out of dictation** hands back every word heard in the gesture (words already typed stay in the target) — §3.5's "the destination changes at release" cannot un-type delivered utterances.
9. **Leases are serialised until their settle** (no chaining of writes under one snapshot): a next write before the previous Ctrl+V was consumed could paste the wrong words.
10. **Terminal defaults**: Windows Terminal, conhost/OpenConsole, cmd, PowerShell/pwsh, WezTerm, Alacritty, mintty, PuTTY, ConEmu, Hyper, Tabby are terminals unless a user profile says otherwise (their surfaces take the lease, `AppProfile.terminal` goes to the engine's stage 9).
11. **The pill is the island's voice view** (`IslandController.SetVoice`, 149 §P placement), no second pill window.
