### Deviations from the design (and the brief)
1. **`crates/a2a/src/lib.rs` is touched** (two lines, not E1a's `Ctx::pass`): the `PeerRoute` literal in the route commit gains `full_access: p.full_access`, and the test helper's `config::Peer` literal gains `full_access: false`. A struct literal must name every field, so the Contract's `PeerRoute.full_access` and `Peer.full_access` cannot land without them. The design's "200 does not touch `lib.rs`" holds for every function 200-E will edit.
2. **`full_access_eligibility` is a method on `Agents`** (defined in `access.rs`): both halves need the supervisor's store, policy and owner check, and D17's caller in `rpc_messaging.rs` reaches the supervisor anyway. `row_eligibility` is the free function the Contract names. An unreadable row reads not visible (`-> bool`, fail closed) rather than an error.
3. **`session_route` takes only the canonical UUID spelling** (36 characters, lowercase, hyphenated): `uuid` would also parse braced, URN, simple and uppercase forms, and D2 wants one spelling for a scope, a path and a conversation export. `PeerAddress::parse` uses it for the suffix, so `peer:maya/session:<not a uuid>` is now malformed (it parsed as a remote name and failed later in `peer_by_name`); the sender's `not a session id` text is 200-E's mapping.
4. **`ListedSession.title` is `Option<String>`** (a session without a title yet); `kind` and `state` are the existing `PeerKind` / `PeerState` (so `"native"`, `"running"` as in the Contract's JSON); the activity is `PeerActivity` (its `stalled_secs` stays optional).
5. **`parse_request`**: `limit` is required (1..=200); `after` is any UUID `uuid` parses; an empty `query` is no query; `kind` is a `DirectoryKind` in its snake-case wire name; `active_only` is `1` or `0` (anything else is a 400); unknown keys are ignored.
6. **`merge` keeps the first answer's row on a duplicate id** (members in the order asked; stable sort), and a member that answered exactly `limit` rows keeps the cursor even when nothing follows (the next page is empty with `null`), as D8's rule reads.
7. **`ContactPatch.full_access` answers `not available yet`** rather than being ignored: a client that sends it learns at once that nothing was written. The desktop `NO_PATCH` is unchanged (the generated `ContactPatch` field is optional); 200-UI adds `full_access: null` with the switch.
8. **Markers, not bodies, in 199's hot functions**: `full.rs` (`full_shape`, `full_return`) and `rpc_messaging.rs` `contact_file_notice` (199-E1b's) carry no edit; their 200-E hooks are listed in `access.rs`'s module doc. Every other hook is a one-line `// 200-E:` / `// 200-UI:` comment right above its function; only two bodies changed: the header strip in `server.rs` `dispatch` (one call beside the principal strip) and the `NOT_YET` refusal at the top of `network.rs` `network_send` (200's alone).
9. **`offers::settled` sets `SettledCards.full_access` already** (one line, 200's function per the design's Phases): it reads `Cached.full_access`, which nothing sets yet, so the result is always false. It saves a dead-code allowance on the new field.

- **Setting (D1)**: `contact_update` with `full_access: Some(b)` writes `full_access = b` on every record of the group (single-column `RecordWrite`s in the one `commit_records`); the staged `Peer` changes, so `same_grant` rotates the epoch. `Contact.full_access_from` is `full-access/v1` on the card that counts (`offers_eid`).
