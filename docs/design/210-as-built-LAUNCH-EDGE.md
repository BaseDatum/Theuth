## 1. Rate limit of `GET /v1/names/{name}`

- Order: per tunnel (engine key, `lookups_per_tunnel_min`, default 30/min), then for a direct path the tunnel's network
  (`Tunnel::net` = IPv4 address or IPv6 /64, `lookups_per_net_min`, 30/min) and its wide network (IPv4 /24, IPv6 /48,
  `lookups_per_wide_min`, 120/min). A relayed (`relay:…`) or `unknown` path has only the per-tunnel limit.
- Refusal: `429 rate_limited {scope: tunnel|net|net_wide, retry_after_s}` (GCRA wait rounded up, ≥ 1 s), no `limit`.
- Counted: `is_limit_refusal` now accepts `rate_limited` when it carries a `scope`, so these refusals land in
  `share_edge_refusals_total{code="rate_limited",scope="…",limit="none"}` and in the brake's `refusals_per_min`.
  `/v1/info`'s scope-less `rate_limited` stays uncounted (unchanged).
- Limiters are governor keyed limiters (`IpAddr` / `PublicKey` keys, no allocation per request), swept every minute
  with `ip_rate`/`info_rate`. Sized at start: `admin reload` reports them in `restart_required`.

## 2. Offline standby key (§13)

- `theuth-share-edge keygen --out <path>`: no config read. Writes 32 raw secret bytes (the `iroh.key` format) with
  `create_new` + 0600 (refuses an existing file), prints the public key in hex on line 1 (what `standby_public`,
  `PublicKey::from_str` and the logs use) and `z32: <z-base-32>` on line 2; a note on stderr.
- `standby_public: <hex>` (top level, optional). Set: start never creates `iroh.standby.key`; `status.standby`,
  `ticket --standby` (live relay + `public_addrs`) use it; a standby secret file on the volume with the same public key
  → warning at start; with a different key → start refused (`share_edge::standby_key`). `standby_public` equal to the
  live key (forgotten after a retire) → warning. Unset: old behaviour (file created at first start).
- `retire`:
  - `retire --standby-key S --edge-key E` (offline, launch procedure): config read only if the `--config` file exists
    (then `standby_public` must match S's key and a live admin socket refuses). Signs `Retire {v:1, edge: S, retired:
    E's key, issued_ms: now}` with S and writes beside E: `retire.json`, S's secret as E (0600), old E as
    `<E>.retired`. S is left in place.
  - `--config C retire --standby-key S`: the same with E = `<data_dir>/iroh.key`.
  - `retire` (no flags): the pre-launch path, only when `standby_public` is unset (else refused with a pointer to
    `--standby-key`); promotes `iroh.standby.key` and now removes it after the copy.
  - Shared `promote`: the new key is written to `<E>.new` and `retire.json` written before `E` moves, so a failure
    never leaves the dir without a live key (a missing `iroh.key` would make `run` create a random one).

## Deviations

- `rate_limited` carries no `limit`: share-proto's `LimitKind` has no lookup kind and share-proto is not this
  phase's file. Metrics label it `limit="none"`. A `LimitKind::Lookups` would be additive (TODO(210-M4) share-proto).
- A lookup refused at the net or wide tier has already spent a per-tunnel token (checks are sequential, governor has
  no multi-key atomic check); likewise a wide refusal spent the net token. Tolerable for a 30/min limit.
- `--edge-key` is a path only; "or config" is `--config` without `--edge-key`. The offline form with no config file
  cannot check `standby_public` or a running edge (documented in the README).
- `retire.json` is now overwritten atomically (`write_private`) instead of `create_new`: a second rotation of the
  same data dir works; the old notice is replaced (it named a key that is now itself retired).
- The on-volume `retire` removes `iroh.standby.key` after promotion (before: renamed into `iroh.key`); same end state.
- `retire` no longer creates a missing live key (`read_key` instead of `load_or_create_key`).

## Not built

- TODO(210-M4): a share-proto `LimitKind` for lookups (see above); clients show `rate_limited` from the code alone.
- No CLI flag to give `standby_public` to the config-less offline `retire` (use `--config` with a copy of the config).
- The release-side pinning of the new standby after a rotation is the release process, not the edge.

## Doubts

- Default per-tunnel 30/min equals the per-net limit, so for one direct engine per address the tunnel limit only binds
  for relayed tunnels and several engines behind one address hit the net limit first. That matches "per tunnel when
  asked over the tunnel"; raise `lookups_per_tunnel_min` if engines legitimately share an address.
- The `rate_limited` lookup refusals now feed `brake.refusals_per_min`; an operator with a tight threshold may see the
  brake hold on lookup floods (arguably intended: they are enumeration attempts).
