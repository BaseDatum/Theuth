## Deviations (decisions; nobody to ask)

- **`VmConfig.loopback_mesh: bool` (default `true`)** added to K's §2.2 type per S1 finding 4 ("A keeps the UDP port publish + `addrs` injection behind a config flag"). `false` → no UDP port published, pairing string untouched (relay path).
- **Host ports are picked by theuth for both TCP 6080 and UDP 7800** (bind-and-release on `127.0.0.1`) and passed explicitly — the runtime never reports a `0` host port (S1 finding 4), and `VmHandle` has no port field to read back from.
- **`Computer.engine` became `Option<EngineId>`** (contract §2.2 has `SandboxInfo.engine: Option<String>`; a creating VM has none). Old docker/ssh YAML (`engine: <string>`) still loads (test `old_docker_record_loads_and_projects`).
- **Vault row `sandbox/<name>/vnc` is written with `Vault::set_if_version`** through `secrets::handle`, not the `Set` message: `Set` → `Vault::set` rejects every `/` name; reserved families are `set_if_version`-only by design (37 §11). `writable_name` now accepts `sandbox/<a>/<b>` (each segment a `valid_name`); `oauth/`/`mesh/` unchanged.
- **`Retry` re-runs from the failed step** by writing `creating{step}` and letting `run_vm` start at that index; `Create` writes `creating{create}` (index 0) — the same path.
- **Guest commands run as the `engine` user**: `runuser -u engine -- env THEUTH_DATA_DIR=/data PATH="/usr/local/bin:$PATH" t …` (`t mesh pair` must read the engine's `engine.json`/token under `/data`). Assumes `runuser` (util-linux, in `debian-systemd:12`) and user `engine` (B's image). `--local-t`/bootstrap `t` goes to `/usr/local/bin/t`.
- **`tools.policy` is copied only when the host has one** (`tools.policy` absent → no `tools:` key in the guest config), so the guest never sees `policy: null`.
- **Restore** keeps `init: Auto` and the record's ports/mounts through `vm_spec` (S1 finding 2, issue #1676); the mock enforces "as_name must be free", so alternation `lab` ↔ `lab~` is asserted twice in the test.
- **`Snapshot { full: true }` → `Err`** naming S1 finding 3 (systemd guests, disk only).
- **Busy-session check for `Stop`** counts `agent::ListSessions` rows with `running && owner == <vm engine>` — on the host, `running` is the supervisor's *local* view, so sessions running *inside* the VM are invisible here (gap, see follow-ups); in a guest (`engine == ""`) every local running session counts.
- **`Takeover` steers only sessions this engine owns** (`SessionSummary.here`); sessions owned by the VM are announced via `SandboxEvent::Takeover` only. The remote steer path (`rpc::forward::route`) lives in `crates/rpc` and needs the connection's `Extensions`; not reachable from `sandbox`.
- **Reconcile pacing**: `HostSide.verify_every = min(10 s, step_timeout / 6)` so tests with a 2 s step ceiling do not sleep 10 s; production stays at 10 s.
- **Handlers run runtime I/O on the mailbox** (`stop`, `resize`-settle, `restore`) — ponytail: one VM operation at a time; `Create`/`Retry` bring-ups and `InstallRuntime` are the long ones and `Create`/`Retry` are spawned. `resize` settle polls every ≤ 2 s bounded by `resize_settle_secs`.
- **`sandbox_create` (tool) waits by polling `List` every 2 s** rather than subscribing to the bus (a tool has no actor); the card still gets `Progress` from the actor by `(session, call_id)`.
- **`#![allow(missing_docs)]`** on `actor.rs`, `record.rs`, `tools.rs` (contract-shaped fields; K's precedent), `#[allow(clippy::result_large_err)]` on `tools.rs` (`Result<_, ToolOutput>` tool-body idiom).
- **`preflight` without a runtime**: blocker code `runtime_missing` with message = the `vm::runtime()` error (today `vm runtime not built`), or `vm_disabled` when `vm.enabled: false`; `HostFacts.cores` from `available_parallelism`, memory/disk 0 (S owns the real facts).
- **CLI asymmetry** (brief note): `--ssh`/`--docker` still bring up inside the CLI process and join over RPC (`make_engine` + `RpcJoin`); only `--vm` is an RPC client of the actor. `Target` has no `Vm` variant and `MakeEngine` is docker/ssh-only.
- **`t sandbox rm --keep-snapshots BOOL`** (clap `ArgAction::Set`, default true) instead of a bare flag — a bare `--keep-snapshots` could not express "drop them".
