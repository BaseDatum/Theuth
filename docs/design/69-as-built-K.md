## What was built, per commit

### `feat(relay): forward HUB_MOVED; devices re-park like HARNESS_GONE` (48884bf)
- `crates/relay/src/frame.rs`: `reason::HUB_MOVED = 5` loses its `#[allow(dead_code)]`; new `reason::reparks(r) -> bool` (`HARNESS_GONE | HUB_MOVED`). Test `hub_moved_reparks_like_harness_gone`.
- `crates/relay/src/relay.rs` (`online`, the device loop's "harness closed my conn" arm): `if reason::reparks(r) { return true }` where it was `r == HARNESS_GONE`. The device gets `CLOSE 5`, its socket stays and goes back to `parked` for the next registration of the same id — exactly the 4 path. Nothing else: the relay already forwarded whatever byte the uplink sent (`frame::CLOSE` arm → `close_conn(conn, r)`) and counted it (`COUNT = 6`).
- **Flap avoidance, as the relay sees it.** `Relay::register` (`relay.rs:230`) *replaces*: `uplinks.insert(id, up)` and the old uplink is `kill`ed (its conns drop with `HARNESS_GONE`). So two hubs registering the same mesh id race and the latest wins; the only thing that stops a ping-pong is the loser **not dialing again**. That is link's side (below): on lease loss `MeshUplink::stop` flips `serve=false` before cancelling, `supervise` checks `serve` before every redial, and the loser's devices are told `5` so they park for the winner. The relay keeps "register replaces" unchanged — it is what makes the *new* hub's registration land immediately instead of waiting for the old socket to time out.

## Deviations
1. **Pending rows are consumed at the handshake, not at commit.** The contract's chooser is `Pending::take` (which deletes the row) for the hint path; I also `take` in the `single_live` fallback so both paths behave alike and commit has nothing to clear (the brief's "commit … clears the pending row" is already done by then). Consequence: a device that presents the right pending id but the wrong PSK (cannot read msg2) burns the row — the user rescans a fresh QR. Both are in the same QR, so nothing is gained by an attacker who has one and not the other.
2. **Every hub loads/creates `mesh/device_key` on lease gain** (contract §2 duties), not only "the first engine that pairs a device" (decision 1 wording). A hub with zero devices therefore holds one idle extra registration at the relay. Cheap; keeps `LinkStatus.mesh` populated on the hub.
3. **The mesh uplink is gated on `link.enabled`** as well as the lease (69 §8: `link.relay` applies to both uplinks; `enabled: false` means "nothing dials out"). `Enable` re-runs the reconcile.
4. **Registry following is a 3 s poll** of `link.sqlite` (the replica has no change feed; the contract says poll). Reload is one-directional: only when the table has something the mirror lacks, so the ordered local writer never gets clobbered by a stale read — except a content change (rename/revoke) queued locally and re-read before it lands, which is self-healing at the next tick. Marked `ponytail:` in `follow.rs`.
5. **Replicated revoke publishes `DevicesChanged` only** (no `LinkRevoked`), and closes the device's conns with `CLOSE 0` like a local revoke. `LinkRevoked` stays the originating engine's event.
6. **Mesh conn tokens are not children of the uplink token** (they are for the engine uplink) so `CLOSE 5` is sent deterministically; `Revoke`/replicated revoke still cancel them individually. On plugin shutdown (`serve` still true) mesh devices hear `HARNESS_GONE` from the relay, not 5.
7. **`run` → `serve` split in `conn.rs`** removes the handle on every exit path (see above) — engine path included; behaviour otherwise identical.
8. **`STABLE_AFTER` backoff reset** added to `mesh_uplink::supervise` (as the engine loop has); the contract's loop and gate are otherwise as C wrote them, with `serve` passed to `run_once`.
9. No `LinkPaired` on the mesh path (contract §6: `DevicePaired` there, `LinkPaired` on the engine path). Brief item 3's "`LinkPaired`/`DevicePaired`" read as engine/mesh respectively.
10. **Identity load is off the actor** (a spawned task + `MeshIdentityLoaded` message) so `secrets::handle`'s 10 s wait at boot never blocks `Status`/`Enable`; `DevicePairStart` still awaits it inline as C wrote it.
