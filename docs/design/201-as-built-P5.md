# 201 as built — P5 (in-turn trim)

§4.3 "In turn", F3, D12 "refuse rather than remove", §11.

## Landed

- **`endless/tail.rs`**: `round_starts(history)` — turn starts plus every assistant message that opens a round (not preceded by another assistant message), capped at the current round's start = the last assistant message (not the turn-start inference, so a recovery note after a partial reply is never a cut point). `trim_rounds(history, low) -> Option<Trim>`: the first position whose suffix ≤ low, else the current round's start; `None` when nothing precedes the current round. A tool row is never a position, so a call keeps its results.
- **`loop_.rs`**:
  - `Turn::trim_in_turn(why)`: marks from `tail_marks(view_allowance())`, `trim_rounds` to the low mark, `start_generation(first_seq, allowance − high)` (ingests the cut rows; their units have drafts), `describe_left` for the rows leaving, drains `history`, `tail_gen`, `since = len`, `hint_since` shifted, `generation_reset()` (the per-generation sets, extracted from `endless_start`), `turn_opened` again (compactor context and status follow the new generation), and swaps `self.view` to the new frozen render (`trimmed`, `logged = false`, `reset_this_round`). Log `endless: in-turn trim` (`why`, `cut_bytes`, `kept_bytes`, `generation`, `low`, `high`, `view_bytes`).
  - `round()`, after `prepare_images`, before the 07 §8.1 block: when `in_turn_trim_on()` (chat, endless frame up, no head, not meeting, service `active`, not the test hook) and view + tail > 90 % of `view_allowance()`, `trim_in_turn("pressure", Some(allowance))`; it refuses (changes nothing) when the kept rounds beside the view would still pass the allowance. If the frame is still over the allowance and the turn has not used its 07 §8.5 cut (`overflowed`), the classic cut runs once over the untouched tail (log `endless: in-turn trim cannot fit the frame; 07 §8.5 cut`).
  - `Abort::Model` overflow: an endless chat runs `trim_in_turn("refusal")` once (`Turn.refusal_trimmed`) before `shrink_view` and the §8.5 compaction; a trim → `Round::Retry`.
  - Tools (§11): `Turn.endless_listed` = `endless_tools_on() || stored_endless()` (stored memory mode `endless`, attached or not), set in `rebase` and used for listing and dispatch. Dispatch: not `served` → one-line refusal `"<tool>: nothing to search yet — this session's memory has no lines."`.
- **Tests** (`loop_/endless_tests.rs`, real loop + real service, paused compactor): `a_long_turn_completes_through_in_turn_trims_without_the_classic_cut` (200 rounds × 6 KB: no `Compacted`, every request's calls = its results, the previous round always sent, generation ≥ 3, the last request carries the newest frozen view); `one_round_too_large_for_any_trim_falls_back_to_the_classic_cut`; `a_turn_boundary_trim_through_the_loop_starts_a_generation` (item A for the boundary trim); `endless_tools_are_listed_from_creation_and_refuse_without_a_tree` (epochs: none; endless unattached and attached: identical `tools`). `endless::tail::tests::a_round_trim_keeps_calls_with_results_and_the_current_round`. Test model ids `inturn`, `onebig`, `listed`, `boundary` added to the harness catalog.

## Deviations

- "Allowance" = `view_allowance()` (turn target less system prompt and reserve), the same figure the tail marks are computed from; the frame measure is the frozen view's bytes + `tail::bytes(history)`.
- The fallback cut runs proactively when a trim cannot get the frame under the allowance (previously the endless path cut only on a provider refusal). The trim is skipped in that case, so the classic cut sees the whole turn (the first version cut the rounds first and then cut classically; the one-big-round test then saw no `Compacted` and the turn ended on the preflight refusal — cause not traced further).
- In-turn trims reset `state.used` like a boundary trim (the 07 trigger is off for endless turns anyway).
- The tool list reads the stored memory mode once per `rebase` (one store read).
- Meetings and `epochs`: `in_turn_trim_on` is false (no `view`, or `meeting_filter`); the test-hook view (`Shared::test_view`) also keeps the old D11 path, so `overflow_in_an_endless_turn_cuts_with_the_view_as_head` is unchanged.

## Follow-up (B, T, the 600 KB question)

- **B — trim now.** `Endless::{request_trim, take_trim_request, meeting}` (`Inner.trim_asked`, `pump::Handle::meeting`). `endless_tail(…, asked)`: `asked || take_trim_request` trims with the cold rule (down to the low mark when over it, whole turns, the last turn kept). `Turn::trim_now`: `compact_now` in an active, non-meeting endless chat runs `endless_tail(asked = true)` at once (the `CompactNow` mini-turn is idle by construction) and `generation_reset`; no new generation → `Err("Nothing to cut: the tail (N bytes) is already at or under the low mark (L bytes) or holds a single turn.")`. `CompactNow` while a turn runs: `request_trim` and `Err("turn in flight: the tail will be trimmed at the next turn boundary")`. Supervisor `EndlessFold` (now a `DelegatedReply`): an active non-meeting chat → the session actor's `CompactNow` off the mailbox, then `memory`; meetings, backfilling and unattached sessions → the old `Endless::fold`. A chat whose actor is not loaded is loaded by `Agents::actor`.
- Supervisor tests changed to the new contract: `compact_in_an_endless_session_folds_without_a_model_call` → `compact_in_an_endless_session_trims_without_a_model_call` (rows appended to the store only, so the tail is empty: "Nothing to cut", epoch 0, no model line); `an_endless_session_reports_its_view_not_its_raw_history` makes its mechanical lines with `endless.fold` directly instead of `/compact`.
- **T.** `a_too_long_refusal_trims_in_turn_and_retries`: 5 rounds, call 6 refused ("prompt is too long: 300000 tokens > 128000 maximum") → one in-turn trim (generation 2), the retry carries the current round and the new frozen view, the turn ends without `Error` and without `Compacted`.
- **Tests B:** `compact_in_an_idle_endless_chat_trims_now` (3 turns of 20 KB, under the high mark: `CompactNow` → generation + 1, tail ≤ 24,000 B; the next request carries one assistant reply, turn 2's); `compact_with_nothing_to_cut_says_so`.
- **600 KB.** With the round at 600 KB the fit check works as meant (no trim, the classic cut runs once: one `Compacted`), but the turn does not complete: only one main call reaches the provider (observed: 1 `Compacted`, 1 main call). Inferred, not traced in that run: after the cut the request still holds the 600 KB round (the 07 cut keeps the current round), the G1 preflight refuses it as over the window (≈150k tokens > 117,708) before sending, the refusal trim is off (the head is in place), `shrink_view` has no view, and the one 07 §8.5 compaction per turn is spent, so the turn ends with `model: prompt is too long … (theuth preflight, not sent …)`. That is the limit: a single round larger than the window cannot be carried by any cut; the test stays at 300 KB (over the allowance, under the window), where the fallback cut runs and the turn completes.
