## What each test establishes

**S1.** Model `evals1` (128k), tail marks 8 KB / 20 KB, 30 turns of one `todo` round (2.4 KB arguments) plus a 1.5 KB reply, an `Echo` compactor refining drafts in the background. Asserted for all 60 main calls: system and `tools` identical in every request; the round call extends the turn's first call; within a generation (from `Endless::generation` after each turn) each turn's first request extends the previous turn's last one byte for byte (per message, serialised JSON); at a trim the system message is kept; calls equal results in order in every request; the previous turn's input, reply and tool call id are in the next request; ≥ 2 trims; ≥ 1 `<recall>` prefetch note (inputs name an older turn's rare word) without breaking the prefix; drafts refined (`quality = model` nodes) and a refined line is in the last generation's view.

**S2.** Three turns on a compactor that never answers (tail under the low mark), then `stop_actor`, `detach`, drop the service; a new service over the same store `attach`es (what `resume_all` does per row; `resume_all` itself was not called — it resolves the session model through the configured-auth chain the harness does not set up), a draft is refined by the new compactor, a fresh actor is built from `store.frame`. The next request extends the last pre-restart request byte for byte; same generation number, same frozen view text, same system and tools. (A restart counts as a cold cache: with the tail over the low mark the first turn would trim; not exercised.)

**S3.** Hung compactor, 10 turns of 4 tool rounds + a long reply, marks 8 KB / 16 KB. First main call of each turn < 500 ms after the input; ≥ 2 trims; each generation's view ≤ `view_bytes × (1 + slack)` (16,000 → 18,000 B); after the run every unit has an l0 node; none is `model`.

**S4.** One script (plain turn, a `todo` round, `/compact` style `cut`, plain turn) run in three set-ups: `epochs` without the service, `epochs` with the service in the process, a meeting desk (memory `endless`, filter `meeting`, attached, `meeting_filter` on). Every main request is normalised (scratch dir, session id, uuids, timestamps, `<time now>`, `Date:`, `Working directory:`) and compared line by line with the same module run at `5b88548ff` (a detached worktree; captured with `EVAL_S4_CAPTURE`, committed as `loop_/eval_golden_s4.json`: 4 requests per set-up, plus the count of `Compacted` events of the `/compact` — 1 for both `epochs` set-ups, 0 for the meeting one, at base and head). "Before" is the base code's actual output, not an invariant. Result: identical in all three set-ups; the only difference before masking was the process working directory in the system prompt (the base ran from another checkout). Caveat: the base binary was built in the shared target dir, where the base and head `agent` crates share artefact names; the head was rebuilt after `cargo clean -p agent` before the head runs that count.

**S5.** Model `evalimg` (images on), a describer compactor (`accepts_images`, fixed answer). The user photo (input file) and the `read_file` screenshot are sent as `image_url` parts while in the tail (both in the screenshot turn's request); after trims no request carries them; two generations after they left, the view has `user: [image: evalphoto.png] — a red square on white` and an `echo: [image: …] — a red square on white` line; `zoom(<tool-picture unit>, 1)` called by the model through the loop answers `id+1|…` and the next request carries the screenshot again as an image; the unit rows stored before the images are unchanged. Service test: rows stored as the base derivation stored them (an empty caption unit, `[image]`, a tool response with images as one `echo`, a vision note as `user`; text from `git show 5b88548ff:crates/agent/src/endless/units.rs`) load with no index shift: rows 0–5 unchanged, the next row is unit 6, `zoom(i,1)` of each old index opens its own message, old `[image]` re-derives as `[image: old.png]`, every unit gets a line.

Observation (no verdict change): a tool picture's unit is named by the binary's own name, which `read_file` sets to a content hash (`echo: [image: 9d0f4f200155e4c6.png]`), not the file name; the path is only in the `echo` text unit before it. §8 asks for "a name"; a reader of the view cannot tell which file the picture was without zooming the neighbouring line.

**S6.** No product seam: the harness gets a real python worker pool (`repl::open_pool` over `$THEUTH_WORKER`, else `monty`/`t` on `PATH`; on this machine `/opt/homebrew/bin/t`, theuth 2.20.0), so `rebase` builds the `## Runtime` index and `batch_tools` pins. Registry tools registered by the test (`EvalTool`). Asserted: a direct and a runtime-only tool registered mid-generation leave `tools` and system unchanged and the request a byte extension; one `<tools>` note after the input names both; a tool unregistered mid-generation stays in `tools` and its call answers "eval_alpha is no longer available in this session …"; a per-chat `SetHidden` removes the tool from the next request at once while the addition and the removal still wait; after a trim the added tool is listed, the removed one is gone, the index names the runtime-only tool; an `epochs` session sees an addition and a removal at the next turn, with no note. Without a worker the test prints a line and returns (as `runtime_bridge_tests` do).

**S7.** Why the builders' setup built nothing: `fold_cfg_for` clamps `view_bytes` to 16,000..=256,000, so `view_bytes: 4_000` was 16,000 and 24 × ~640 B units never passed the fold's high mark. Here: 60 free user lines (~420 B, pairs need the model), `view_bytes` 16,000, `merge_at` 0.5, `Echo`; generation 1 is cut once the view fits on built merges (no hard-cap prefix line). A unit inside a merged line is zoomed: with `age_by_use` it is alone in generation 2 and merged again in 3; with it off, merged in 2 and 3.

**S8.** Compactor on a local endpoint with a 2,048-token window: `profile` resolves `Small`. Every recorded call: context ≤ 2,000 B and without `<chat>`; exactly one "Write one line about this message" or one "Join these two lines"; no batch; step body ≤ the window's chunk (`small_chunk_bytes`); whole request ≤ prompt + 2,000 + chunk + 200. A guard-tripping unit keeps its draft (`quality = draft`, the ungrounded reply never stored anywhere); a 12 KB unit goes in more than 12,000 / chunk calls.

**S9.** Marks 8 KB / 16 KB, `ledger_bytes` 1,000. Three user lines with cues ("you must never…", "let's go with…", "make sure…") are suggestions in the first trimmed generation's snapshot; the `todo` list is mirrored into Open tasks. In one turn the model accepts the postgres suggestion and drops the fridays one (ids read from the request's snapshot), closes two tasks, adds seven goals. Asserted per generation (snapshot as frozen): the unconfirmed suggestion is still listed one trim later and gone two trims later; the next snapshot after that turn has postgres under Decisions, no fridays, all seven goals and the open task, is ≤ 1,000 B, and the two closed tasks are the entries that left it (with them it would be 1,036 B); `recall("migrate schema")` still finds the closed task; within each generation every turn extends the previous request (the `<ledger>` notes come after the input). Prefetch bytes: S1.

**S10.** One `todo` round carrying 600 KB of arguments (≈ 150k tokens against a 128k window), then a plain turn. What the user sees, in both modes: turn 1 ends `stop_reason: error` with one `Compacted` event and the error `model: prompt is too long: ~159,000 tokens > 117708 maximum (theuth preflight, not sent: …)`; turn 2 runs one `Compacted` and completes (`stop`). Difference: provider calls in turn 1 — endless 1 (the call that returned the round), `epochs` 3. The base, same module (`eval_s10_base_epochs_only` in the base worktree, `epochs` only — the base's endless mode waits up to `settle_secs` on a hung compactor and times the harness out): `epochs` identical to head (1 error, 1 compaction, 3 calls, then 1 compaction and `stop`). So a single round over the window is not recoverable within its turn in either mode, and the build did not change the classic outcome.
