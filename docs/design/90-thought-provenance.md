# 90 — Thought-signature provenance: switching providers mid-session

Status: v0.1, 2026-10-03, orchestrator draft (theuth main 88305477, genai fork main e85c58ab). Extends 07 (frames), 36 §2 (model-call failures), 70 (thinking traces), 85 (Zen/OpenRouter targets).

## 0. The bug

Switching a session from an OpenAI model to an Anthropic one fails every call with

    400 {"type":"invalid_request_error","message":"messages.7.content.0: Invalid `signature` in `thinking` block"}

Mechanism (verified in the fork at e85c58ab):

- Every reasoning provider returns an opaque token next to its reasoning: Anthropic `thinking.signature`, OpenAI Responses `reasoning.encrypted_content`, Gemini `thoughtSignature`, Bedrock `reasoningContent.signature`, OpenRouter `reasoning_details[].signature/data`. genai normalises all of them into the same untyped `ContentPart::ThoughtSignature(String)` (and the reasoning text into `ContentPart::ReasoningContent(String)`); theuth persists the assistant `ChatMessage` as JSON (`messages.body`) and replays it on every later call.
- Each adapter's request builder treats every `ThoughtSignature` in history as its own: `anthropic/adapter_shared.rs:264-304` zips reasoning texts with signatures into `thinking` blocks when the counts match (an OpenAI turn has exactly one summary and one encrypted blob → counts match → a `thinking` block carrying an OpenAI Fernet token as its `signature`); `openai_resp/adapter_impl.rs:551-575` emits every blob as a `reasoning` item with `encrypted_content` (an Anthropic signature → `invalid_encrypted_content`); Gemini puts every blob on a `thoughtSignature`; the Anthropic builder also forwards every `ContentPart::Custom` verbatim (`:251,:342,:370`), so OpenRouter `reasoning.text` custom parts reach Anthropic as unknown block types.
- Provider rules (platform.claude.com thinking + thinking-troubleshooting, developers.openai.com reasoning guide, 2026-10): a signature is readable only by the provider that issued it; Anthropic drops blocks a *different Claude model* cannot read but 400s on a signature that does not verify (`Invalid signature in thinking block`, message ending there); OpenAI omits reasoning from another OpenAI model family but 400s (`invalid_encrypted_content`) on content it cannot decrypt, including content from another org/deployment (Azure vs openai.com, so also Zen or OpenRouter vs direct). Thinking blocks are only *required* within a tool-use turn; dropping all of a turn's thinking blocks is Anthropic's documented recovery ("strip every thinking and redacted_thinking block … and retry once").

## 1. Decisions

1. **A thought signature carries its issuer.** In the fork `ContentPart::ThoughtSignature` wraps a struct `ThoughtSignature { signature: String, origin: Option<ThoughtOrigin> }` with `ThoughtOrigin { adapter_kind: AdapterKind, model_name: ModelName, connection: Option<String> }`. Every capture path (stream and non-stream, all adapters that read a signature) stamps `adapter_kind`/`model_name` from the request's `ModelIden` and `connection` from the new `ChatOptions::with_thought_connection(label)` (the caller's name for the account/gateway the request went to). Serde: serialises as an object; deserialises from the object **and** from the legacy bare string (origin `None`), so every stored session still loads.
2. **An adapter replays a signature only to its issuer.** On the request path a `ThoughtSignature` is sent iff `origin.adapter_kind == this adapter` and `origin.connection == options.thought_connection()` (both `None` is equal; one side `None` is not). Anything else — another adapter, another connection, or an untagged legacy signature — is dropped together with the reasoning text paired with it; nothing of a dropped block is sent as text. Same rule for `ContentPart::Custom` parts that carry a `model_iden` (OpenRouter `reasoning_details`): forwarded only by the adapter kind that produced them; an untagged custom part is the caller's and is forwarded as today. `ToolCall.thought_signatures` (the untyped mirror) is no longer a replay source. Model name is recorded but not filtered on: Anthropic and OpenAI both drop what another of their own models cannot read, and dropping it ourselves would lose continuity on same-provider switches.
3. **Pairing is positional, not count-based.** The Anthropic builder walks an assistant message's parts in order and pairs each `ThoughtSignature` with the `ReasoningContent` that immediately follows it (the order `From<InterStreamEnd>` writes); a `ReasoningContent` without a preceding same-origin signature is never a `thinking` block. Replaying an all-Anthropic message produces byte-identical bodies to today (existing tests stay green).
4. **theuth names the connection.** `backend.rs` sets `with_thought_connection(label)` on every genai call, `label` = the theuth provider id of the resolved model (`anthropic`, `openai`, `opencode`, `openrouter`, `amazon-bedrock`, a gateway's name …), falling back to the adapter kind's lower-case name for an id without a provider. Direct-OpenAI and Zen-OpenAI blobs therefore never cross.
5. **The loop recovers from a rejected replay anyway.** New `compact::is_reasoning_rejected(err)` recognises the provider messages that mean "a replayed reasoning block was refused" (Anthropic: `invalid \`signature\` in \`thinking\` block`, `thinking blocks cannot be modified`, `bound to a different conversation`; OpenAI: `invalid_encrypted_content`, `encrypted content … could not be verified/decrypted`; Gemini: `thought_signature` validation failures). `Session::call` resends the same frame **once** with `Frame.strip_reasoning = true` — `Frame::request` then removes every `ThoughtSignature`, `ReasoningContent` and reasoning-typed `Custom` part from history and clears `ToolCall.thought_signatures` — immediately, as a further attempt of the same logical request (51 §6.1), with a `warn` log naming the provider message. A second rejection is the deterministic error it is today. This covers legacy rows, the prefix-binding check Anthropic enforces for accounts created after 2026-08-31, and any format we have not met yet.
6. **Legacy rows are not migrated.** Untagged signatures in existing sessions are dropped by rule 2; the only loss is thinking continuity on the already-stored turns of the same provider (allowed outside tool use; within an in-flight tool loop the documented recovery). No schema change.

## 2. Out of scope / follow-ups

- `thinking-binding-controls-2026-08-01` + `block_binding.prefix_mismatch_behavior: drop_block` for Anthropic (the prefix check is enforced for new accounts; theuth rewrites the tail with `<time>` stamps and compaction). Rule 5 makes the failure self-healing; the header is a later, measured decision.
- Gemini 3's requirement that function-call parts of the *current* turn carry a thought signature (dummy `skip_thought_signature_validator` when the turn came from another model). Noted, not built.
- `redacted_thinking` capture in the fork (check and report, do not build unless trivial).
