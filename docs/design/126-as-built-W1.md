### §6 labels → `crates/double/src/labels.rs`
- Weights (labels.rs:25-39): direct 1.0, override 3.0, rewind 0.5, interrupt 0.25 (within 30 s), timeout 0.25, correction `0.5 × P(true)` only when `P(true) ≥ 0.8`.
- `label()` writes the `(example, source)` row and `rescore()` re-marks every prediction row's `outcome` (labels.rs:47-83; `ladder::outcome` — override wins over direct, a timeout is not a label).
- **Bus path (works with no `questions` table):** `ApprovalResolved.decision` → direct/override; `timed_out` → timeout on `Deny`. Asks: `AskResolved` carries no answer, so the chosen label comes from the `ask_user` tool's rendered output (`<id>: <label>`, `ask_choice_from_output`, labels.rs:205), paired through `AgentEvent::ToolCallStarted { name: "ask_user", call_id }` → `AskRequested` → `ToolCallFinished { call_id, output }` (actor.rs:1062-1081, 838-895). `dismissed` → no label (the owner cancelled the turn).
- **Table path:** `Journal` (labels.rs:104) opens `<data_dir>/sessions.sqlite` read-only and reads `questions (state, answer, asked_at, answered_at, answered_by)`; `question(id)` is `None` when the table does not exist (the running pre-0033 engine). Used first for an answered ask (`ask_choice` parses `[{"kind":"choice","index":n}]`, labels.rs:191); the bus path is the fallback. Logged once at start when the table is missing.
- Hindsight (`Turns`, labels.rs:227; `Double::hindsight`, actor.rs:613): per session, the decisions of the turn in flight and of the previous turn (kept for two user turns). `ContextChanged { reason: "rewind" }` → the rewound turn's decisions (the one in flight, else the previous); `TurnFinished { stop_reason: "cancelled" }` → those asked within 30 s; `TurnStarted` → the previous turn's decisions when the `double.correction` Bool says `P(true) ≥ 0.8` on the new message (≤ 600 chars). Never on an overridden decision, never without a direct label, never across sessions. The negative names the owner's choice; `predict::memory` nets it (direct 1.0 − rewind 0.5 = +0.5 for Allow — "the owner did say yes").
- `pause` (actor.rs:1117): predictions and rungs continue, no label is written.
- **No bootstrapper** (Revision 1 ruling 8): nothing reads `messages`; no `bootstrap.rs`, no flag. §6.5's sqlite volume queries were not run (sessions.sqlite is the live engine's; W1 was told to use fixtures only).

- `memory()` (predict.rs:451): the class's newest ≤ 1,000 examples with an embedding and a positive net label.

### §9 ladder → `crates/double/src/ladder.rs`
- Thresholds as constants (ladder.rs:20-42). `next_rung` (ladder.rs:110) over the class's last-30-days ledger (`ledger`, ladder.rs:328: non-`baseline` predictions joined to labels, time order), one step per evaluation, never above the cap: L0→L1 n ≥ 20, acc ≥ 0.90, ECE ≤ 0.05; L1→L2 n ≥ 50, acc ≥ 0.97, ECE ≤ 0.05, zero overrides in the last 20; L1→L0 three wrong in the last 20; L2→L3 30 days at L2 (`stats.l2_since`) with no strike, cap permitting (default 2 → never in v1). `demote` (ladder.rs:103) is the immediate one-rung drop on an override. A strike = override, or a hindsight negative ≥ 0.5 on an acted row (`summarise`, ladder.rs:402).
- `hard_cap` (ladder.rs:83): destructive ≤ 1 always (`Caps::for_risk`); mutating ≤ 1 without the per-class opt-in (reason `mutating — opt in to allow L2`), the configured `read_only` cap with it; every other kind `read_only`. Applied at class creation, on every card, in `reladder` and in `SetCap`.
- Metrics (ladder.rs:154-262): prequential accuracy, multi-class Brier, ECE over 10 equal-width bins of `p_top`, coverage@2 % (largest descending-`p_top` prefix with error ≤ 2 %), asks avoided (`acted`), minutes saved (acted × (median answer + 30 s)), overrides/100 acted, undo rate (graced-and-not-acted)/100 acted. `curve` (ladder.rs:298) groups by ISO-week Monday. Every number is computed twice on the same rows: the live version(s) and `baseline` (§7.4).
- Evaluation runs after every direct/override/hindsight label (`reladder`, actor.rs:570), writing `stats.last_30d`, `l2_since`, the histogram and the median time-to-answer.

## Deviations from the design / brief

1. **Only approvals and asks are subscribed.** The tree has no bus event for an attention item, a packet or a draft being raised (`rt.publish` in roster/tasks/app publishes none; packets are RPC pulls, draft presses are chat messages). The keyer supports those kinds; the actor does not subscribe to anything that does not exist. Capture switches for them are read but idle.
2. **Time decay is a true 30-day half-life** (`0.5^(age/30)`, brief and §15.1), not §7.1's `exp(−age/30)` (half-life 20.8 days).
3. **k-NN ranks neighbours by decayed similarity, not raw cosine.** The §15.1 burst test showed why: 500 identical month-old `cargo test` cards fill the k = 15 neighbourhood before decay is applied to the vote; ranking by `cos × decay` keeps this week's decisions in it. Per-class retrieval already separates classes.
4. **No-head blend** is this wave's own: `w = n_eff/(n_eff+3)`, memory 0.8 / prior 0.2 inside `w`; the design leaves the pre-head blend unspecified. The double's gate thresholds (0.6 / 0.2) are constants until W2 fits temperatures.
5. **Multi-question ask sets are observe-only** (the contract's `DoublePredicted` carries one `choice`/`index`); the design only names freeform. A text answer to a single-question set is not a label (it is not one of the options).
6. **Asks: label source order** is journal first, tool output second; the design says "read the answer from the journal row" and the brief requires the event path alone — the output pairing is the event path.
7. **`DoubleAnswered.undo_until` is `None`** at L2: the grace precedes the act, so there is no undo window after it; the undo affordance is the in-grace inbox row (`detail` = grace end) plus `double_take_over`.
8. **Override demotion has no "contrary answer within the same turn"** detection; only take-over-then-different-answer counts.
9. `settings_set` stays a W2 stub (C's hand-off assigns it there, the stub said W1).
10. `Turns` and the pause flag are in-memory (`ponytail:` marker in labels.rs): a rewind right after a restart finds no turn.
