### Deviations from the design (and the brief)
1. **Type names follow the design, not the brief's list.** The brief named `FileState, FileDirection, IntakeState`; the design (rounds 3–5) has `InState`, `OutState`, `FileDirection`, `NoticeState`, and `FileState` = "`InState` or `OutState`, tagged by `direction`". `IntakeState` went with the held intake (round 3). The brief's `contact_files` RPC is the design's `contact_file`.
2. **`ContactFile.direction` and `.state` are one flattened field** `state: FileState` (`#[serde(flatten)]`, adjacently tagged): the wire still carries `"direction": "in", "state": "saved"`, and an `out` state under `in` cannot be expressed. `FileState::direction()` reads the tag.
3. **Sizes in error texts are exact bytes**: `files: <path> is 5000000001 bytes (over the 5 GB limit per file)`, `read_file: <path> is 300000000 bytes; too large to read whole (limit 256 MB). …` (the design leaves `<size>` unformatted).
4. **Gate refusals**: a socket does not open (`ENXIO` on Linux, `EOPNOTSUPP` on macOS); a failed open on an existing non-regular file reports `not a regular file`. `Refusal::Changed` (`files: <path> changed since it was offered`) is the reopen's mismatch; the route turns it into `410 changed`.
5. **`FileMeta` ignores unknown keys** (a later v1 field does not refuse a message); the receipt body is strict (anything else is a 400, as the design says).
6. **`ContactFileChanged` is an `AgentEvent` variant** as the design says, so the exhaustive matches in `crates/slack/src/channel.rs` and `crates/tui/src/model/agents.rs` gained an arm (slack ignores it; the TUI arm is `199-UIT`).
7. **The quarantine timestamp is 8 hex digits** (`{:08x}`), as Safari and curl write it.
8. **`notice_id`** is `Uuid::new_v5(NAMESPACE_OID, "theuth/contact-file/<holder>/<id>")`.
9. **`Store::notice_committed`** is frozen here (round 5's shared predicate), with a test; nothing calls it yet.
10. **ProtoJSON makes `size` a double.** Part metadata is a `google.protobuf.Struct`, so a `FileMeta.size` of `2516582` comes back from `a2a_pb::protojson_conv` as `2516582.0` (found by the round-trip test). `FileMeta.size` therefore deserialises a `u64` or a non-negative whole double up to 2^53 (exact; `FILE_MAX` is far below); a fraction or a negative is refused. Senders still write an integer.
11. **The receipt parser is a flat struct** with `deny_unknown_fields`, not the tagged enum: serde's internally tagged enums let unknown keys through on unit variants (`{"state":"received","x":1}` parsed). `Receipt` itself only serialises.

## 199-E2 as built (P2: access from another of our machines)

Built on `feat/199-e2` from `c5d0895af`. No frozen shape changed (types, RPC signatures, events, migration 0067, `Req`/`Reply`).

### What landed
- **Holder** (`agent/src/communication/files.rs`, the P2 seam): `impl Message<HeldContactFile> for Agents` reads `contact_files` by local id (`files::held`): only `direction='in' AND state='received'` with `path`, `dev`, `inode`, `size`, `blake3` all set; anything else (an `out` row, unfinished, failed, unknown) is `None`. `artifact::mesh::answer` `Req::GetContactFile { id }` asks it (`held`), reopens through `disk::egress_reopen` (the full gate plus the recorded `(dev, inode)` and size) and streams exactly `size` bytes by `pread` in `CHUNK` frames, each `send` under `FILE_IDLE` (no whole-transfer budget); otherwise `Missing`. Paired-only is the transport's property: `theuth/artifacts/1` streams exist only between paired engines (`mesh::net`, a stream of an unpaired one fails).
- **Fetcher** `artifact::mesh::fetch_contact_file_via(t, data_dir, holder, id, &ReceivedNotice) -> Option<PathBuf>` (beside `fetch_attachment_via`): asks the named holder only; opening and every frame under `FILE_IDLE`; bytes stream into `files/partial/cache-<uuid>` (0600), counted against the notice's `size` and BLAKE3-hashed as they arrive; at `End` size and digest must equal the notice's, else `verification failed`. Then `disk::publish` (quarantine, no-clobber `hard_link`, no row to record) into `files/cache/<holder>/<id>/<name>` (dirs 0700) and `disk::finish`. Every call first re-hashes the entries of `<id>/` (`verified`, on the blocking pool) and returns the first that matches; there is no exists-shortcut. `Ok(None)`: the holder answered `Missing`.
- **Expected values** `files::received_notice(store, session, holder, id) -> Option<ReceivedNotice { name, size, blake3, machine }>`: `Store::notice_committed(session, notice_id(holder, id))` first, then the text of either form: the `messages` row at the `at_seq` of the `input_accepted` step with that `input_id` (body → `loop_::text_of`), or the `errors` row with that id. The first `<message_file …/>` is parsed and unescaped; it must say `state="received"` and name the same `holder` and `file`, with a 64-hex `blake3`.
- **RPC** `contact_file_fetch(session, holder, id)`: `authorize` (a replica's own copy is enough), the notice (`no notice for <id> in this chat`), then: this engine is the holder (`mesh::self_id()`) → the held path (`no such file on <machine>` if none); no transport or holder not connected → `<machine> is offline`; else the hook → the cache path, `Missing` → `no such file on <machine>`, any other failure verbatim (`verification failed`, `<holder> sent nothing for 60 s`, `<holder> closed mid-answer`). `<machine>` is the notice's `machine`.
