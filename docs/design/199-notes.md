### a2a ↔ agent seams (E1a ↔ E1b, commit "199-C: E1 split seams")
`crates/a2a` depends on `crates/agent`, never the reverse, so every trait both builders share lives in `agent::communication::files` (a2a re-exports `Gone`, `Receipt`, `REASON_MAX` from `a2a::contacts::files`). Each side registers its implementation in a process-wide slot; an unregistered slot answers a no-op.
- **Sender side, E1b implements, E1a calls** (`a2a` route → agent):
  ```rust
  #[async_trait] pub trait FileOffers: Send + Sync {
      async fn open(&self, contact: &str, id: &str) -> Result<OfferHandle, OfferError>;
      async fn receipt(&self, contact: &str, id: &str, receipt: Receipt) -> Result<(), OfferError>;
  }
  pub struct OfferHandle { pub file: std::fs::File, pub len: u64, pub blake3: String, pub deadline: DateTime<Utc> }
  pub enum OfferError { Unknown /* 404 */, Gone(Gone) /* 410 expired|missing|changed */ }
  pub fn set_offers(Arc<dyn FileOffers>);  pub fn offers() -> Arc<dyn FileOffers>;  // default NoOffers: 404
  ```
  `contact` is the caller's immutable record id (`ContactFacts.id`), `id` the sender's local id from the path. The `(dev, inode, size)` re-check (`disk::egress_reopen`) happens inside `open`. Registered at agent start (`supervisor::start`, now `NoOffers`, marked `199-E1b`).
- **Receiver side, E1a implements, E1b calls** (agent queue → a2a client):
  ```rust
  #[async_trait] pub trait FileFetch: Send + Sync {
      async fn download(&self, fetch: &Fetch, progress: &mut (dyn FnMut(u64) + Send)) -> Result<Fetched, TransferError>;
      async fn send_receipt(&self, contact: &str, member: &str, id: &str, receipt: &Receipt, timer: Timer) -> Result<(), TransferError>;
  }
  pub struct Fetch { pub contact: String, pub member: String, pub id: String, pub size: u64, pub partial: PathBuf, pub have: u64, pub timer: Timer }
  pub struct Fetched { pub bytes: u64, pub blake3: String }  // the whole partial; the caller verifies
  pub enum TransferError { Unknown, Gone(Gone), Changed, Idle, Deadline, Cancelled, Transport(String), Disk(io::Error), NotYet }
  pub struct Timer { pub deadline: tokio::time::Instant, pub idle: Duration }  // Timer::until(d) = FILE_IDLE; at(last) -> (Instant, Expiry::{Idle, Deadline})
  pub fn set_fetch(Arc<dyn FileFetch>);  pub fn fetch() -> Arc<dyn FileFetch>;  // default NoFetch: NotYet
  ```
  a2a's implementation is `a2a::contacts::files::ContactFetch(Weak<Ctx>)`, registered in `Ctx::attach` beside `reach::Gate`; it calls the free functions `download(net, cut, fetch, progress)` and `send_receipt(net, cut, member, id, receipt, timer)` (both `NotYet`, marked `199-E1a`). `Changed` covers every Range or length mismatch and a `416` (`check_answer`); `Idle` requeues and resumes, `Deadline` fails the file; `progress` gets the partial's size.
- **Cancellation**: `a2a::contacts::files::Transfers` (field `Ctx.transfers`): `token(contact) -> CancellationToken` for every route GET/receipt and every download/receipt POST of that record id; `cut(contact)` cancels them all and the next transfer starts with a fresh token. `ContactFetch` takes the token itself; the cut goes in `Ctx::pass` right after the live snapshot swap (marker `199-E1a`), for every contact whose members or block state changed.

### Deviations from the design (and the brief)
1. **Type names follow the design, not the brief's list.** The brief named `FileState, FileDirection, IntakeState`; the design (rounds 3–5) has `InState`, `OutState`, `FileDirection`, `NoticeState`, and `FileState` = "`InState` or `OutState`, tagged by `direction`". `IntakeState` went with the held intake (round 3). The brief's `contact_files` RPC is the design's `contact_file`.
2. **`ContactFile.direction` and `.state` are one flattened field** `state: FileState` (`#[serde(flatten)]`, adjacently tagged): the wire still carries `"direction": "in", "state": "saved"`, and an `out` state under `in` cannot be expressed. `FileState::direction()` reads the tag.
3. **Sizes in error texts are exact bytes**: `files: <path> is 5000000001 bytes (over the 5 GB limit per file)`, `read_file: <path> is 300000000 bytes; too large to read whole (limit 256 MB). …` (the design leaves `<size>` unformatted).
4. **Gate refusals**: a socket does not open (`ENXIO` on Linux, `EOPNOTSUPP` on macOS); a failed open on an existing non-regular file reports `not a regular file`. `Refusal::Changed` (`files: <path> changed since it was offered`) is the reopen's mismatch; the route turns it into `410 changed`.
5. **`FileMeta` ignores unknown keys** (a later v1 field does not refuse a message); the receipt body is strict (anything else is a 400, as the design says).
6. **`ContactFileChanged` is an `AgentEvent` variant** as the design says, so the exhaustive matches in `crates/slack/src/channel.rs` and `crates/tui/src/model/agents.rs` gained an arm (slack ignores it; the TUI arm is `199-UIT`).
7. **The quarantine timestamp is 8 hex digits** (`{:08x}`), as Safari and curl write it.
8. **`notice_id`** is `Uuid::new_v5(NAMESPACE_OID, "theuth/contact-file/<holder>/<id>")`.
9. **`Store::notice_committed`** is frozen here (round 5's shared predicate), with a test; nothing calls it yet.
10. **ProtoJSON makes `size` a double.** Part metadata is a `google.protobuf.Struct`, so a `FileMeta.size` of `2516582` comes back from `a2a_pb::protojson_conv` as `2516582.0` (found by the round-trip test). `FileMeta.size` therefore deserialises a `u64` or a non-negative whole double up to 2^53 (exact; `FILE_MAX` is far below); a fraction or a negative is refused. Senders still write an integer.
11. **The receipt parser is a flat struct** with `deny_unknown_fields`, not the tagged enum: serde's internally tagged enums let unknown keys through on unit variants (`{"state":"received","x":1}` parsed). `Receipt` itself only serialises.

## 199-E1b as built (P1, the agent layer)

On `feat/199-build` from the seams commit `201c7939a`; `crates/agent` (plus the regenerated OpenRPC fixture and one TUI call site). The seam signatures are used exactly as committed; none changed.

### What landed
- **Store** (`store/contact_files.rs`): `FileRow` over `contact_files`, every transition conditional on the expected state(s), `settle_files` (the States rules in one transaction: `saved` → `received` with the notice once the exchange reads `consumed`/`replied`; a failed file's waiting notice; every non-terminal file of a `failed`/`suppressed`/`unknown` exchange failed with its reason, no notice), the outbox (`notice_outbox`, `notice_to`), `file_published` (step 6), contact lookups by binding/alias (merges followed) and `share_live` (D17's re-check: not removed or blocked, and a granted export of the chat with no member refusing, or a live `contact_threads` conversation into it).
- **Sending** (`files/send.rs`): `send_message(files)` resolves the recipients, requires each to be a contact (`files can go to contacts only; <addr> is not a contact`), then gates every path once (`disk::egress_open`; its texts), clones it into `files/outgoing/` with `fclonefileat` (macOS; else the original is served after `egress_reopen`), hashes the clone (or the handle) with BLAKE3, checks the 64 KiB envelope estimate, and writes one `out` row per file per recipient (local id, `OFFER_TTL`). A repeated `request_id` must carry the same `(blake3, size, name)` list. `structured.files` and the `N files offered (…); offers expire <date>` line are added to the receipts.
- **FileOffers** (`FileService`, registered with `set_offers` from `supervisor::start`): `open` re-checks the contact (record ids, merges followed), the deadline (`410 expired`; the card fails "expired before <contact> fetched it"), then serves the clone or the original re-opened through `egress_reopen` (`410 changed` / `missing`; the offer fails); the first GET moves the card to `sending`. `receipt` applies the first terminal receipt only (`sent`, or `failed` with the receiver's reason) and drops the clone; past the deadline `410 expired`.
- **Receiving**: `deliver_full` and `full_return` write one `in` row per reference part before the record is read (`files/intake.rs`; the sender's `peer:<binding>` names the contact record); `exchange_record` fills `PeerRecord.files`; `peer_wrapper` writes the `state="receiving"` placeholders and the hint after `</message>`.
- **The queue** (`files/service.rs`, one task, a pass on every `kick()` and once a second): at most 2 downloads per sending member, none engine-wide; `Idle` back to the end of the queue (resumed from the partial's bytes), transport errors and `NotYet` on D8's backoff (5 s doubling to 10 min); every other error fails the file (ENOSPC: `disk full on <machine>`); a size or BLAKE3 mismatch fails it at once ("the file changed before it was fetched"). Progress events at most twice a second. Local deadline `min(declared expiry, arrival + OFFER_TTL)`.
- **Publication**: partial 0600, dirs 0700, `disk::publish` with the `record` callback writing `publishing` + target + inode, then `file_published` (received with its notice when the exchange was read, else saved), then `finish`. A file that failed meanwhile is unlinked by inode.
- **Receipts**: the terminal receipt follows the terminal state (`received` once received, `failed` with the reason), POSTed through `fetch().send_receipt`, retried on D8's backoff until the sender answers or the deadline.
- **Notices (D17)** (`files/notices.rs`): the outbox sends `contact_file_notice` through the front door (`forward::route` with no marker: here, or `theuth/rpc/1` to the chat's current owner); `accepted` → `sent`; then `contact_file_notice_status`: `committed` → `delivered`, `unknown` re-sends; errors (offline, `NOT_OWNER`, method-not-found) retry on the backoff with no deadline; never `send_input`. On the owner: the RPC refuses any call without the `Forwarded` marker; strict ownership (`NOT_OWNER`); dedup (pending here, or `notice_committed`); share re-check (ended: `record_error_once` + `AgentEvent::Error`, no turn); else `Agents::input(…, InputOrigin::Automatic, Delivery::NextTurn)`. At consumption (`Turn::take_notice`) the share is checked again (ended after admission: the engine-state row, the ticket dropped), and `append_input` (source `contact_file`, `input_id` = the notice id) refuses, inside its write transaction, a copy whose step or ended-share row already exists (`NoticeCommitted`). Every path clears the pending id.
- **RPCs**: `contact_file`, `contact_file_thumbnail` (≤ 64 MB read, `images::fit(…, 512)`, the fitted MIME; `not an image` / `too large for a thumbnail` tell the card to show an icon), `contact_file_export` (no-clobber copy, `<dest> exists`); each carried to `holder` with `forward::to_engine` (`<machine> is offline`). `answer_peer_request` gained the optional 4th `files` (D15): on the chat's owning machine only (`attach on <machine>` elsewhere, and for a forwarded call), to a contact's request only; the same gate and offers as the tool, `Deliver(reply_to)`, the human's provenance kept.
- **`ContactFileChanged`** on every state change the service makes (start, progress, saved/received, failed, sending/sent, expiry, settle).
- **Startup** (`pause::boot_accounting`, after `fail_interrupted_except`): staged offers dropped, every `publishing` row resolved by inode (`Finish` commits step 6, `Republish` links under the next name, `Requeue`), then `files/partial/` emptied and unfinished downloads requeued from byte 0, clones of settled offers removed. The service starts after it; its first pass fails the files of the exchanges failed at restart; terminal files within their deadline get their receipt again.

### Deviations
1. **Offers reach the a2a client through `exchange_record`.** `Deliver` has no `files`: the send path stages its rows under `pending:<session>:<request_id>`, and `exchange_record` adopts them for the outbound exchange of that `(sender, request_id)` (one per pair), so `OutboundPeerMessage.record.files` carries them (`holder`, `id`, `name`, `media_type`, `size`, `blake3`, `deadline`: the reference part). A send with files always has a request id (the caller's or a fresh one; `<id>#<n>` per recipient of several). Rows nothing adopted are dropped after the `Deliver`s, and at startup.
2. **Outside the ownership map, unavoidable**: `network.rs` `inbound_text` skips `iroh://` URL parts (it refused every non-text part, so no message with files could be admitted); `supervisor.rs` `Agents::input` is `pub(crate)` (the notice admission's automatic input); `crates/tui/src/components/peers.rs` passes `None` as `answer_peer_request`'s new 4th argument (the generated client is positional).
3. **The loop knows a notice by the pending set** (session + exact text), not by a new `Input` field; a notice row carries no clock stamp.
4. **Publication runs on a blocking thread** (`spawn_blocking` + `Handle::block_on`): `disk::publish`'s `AsyncFnMut` callback yields a future rustc cannot prove `Send` for every argument lifetime, so it cannot sit inside a spawned task's future. The seam is unchanged.
5. **A notice's `from` is `peer:<alias>`** (the contact record's alias); for a `~return` answer the wrapper's `peer:<alias>/<export>` keeps its export, the notice does not.
6. **"<contact> cannot receive files" is the a2a client's** (this crate never sees card extensions): the send fails on its receipt, and the service fails its offers with that reason.
7. **No receipt column**: receipts are retried in memory, and re-sent at startup for every terminal file within its deadline (the sender applies the first).
8. **Only full shares carry files** (`deliver_full`, `full_return`, as D3 names them): a cautious-share message's references are ignored by the agent. `<root>` is always the data dir (a private chat never receives a contact's message: `contact_owned` refuses it).
9. **A file already on disk never expires**: the deadline fails only `queued`/`receiving` downloads and unsettled offers; a `saved` file waits for its exchange.

## 199-E3 as built (P3: foreign A2A peers and public HTTPS)

Branch `feat/199-e3` from the merged 199 tree `deeba3a83`. `crates/agent`, `crates/a2a`; `web::fetch::download` (199-W) is used as merged, unchanged.

### What landed
- **Admission** (`a2a/src/server.rs` `validate_send`): from an HTTP peer (`caller == None`, no files extension needed) inline `raw` parts (inside the unchanged 64 KiB `BODY_LIMIT`) and `url` parts that pass `agent::communication::files::foreign::https_url` (absolute `https`, no userinfo); any other URL is `invalid_params` `message.parts[i]: the url is not https` / `the url carries credentials` / `the url does not parse`. `data` parts stay `content_type_not_supported`, and so do `raw`/`https` parts from a contact (a theuth sends references). Exactly-one-content (`exactly_one`), text, status and artifact text bounds unchanged. Non-public hosts are not judged here: they fail at fetch time with a failed notice (Failure modes).
- **Intake** (`files/foreign.rs` `in_rows`, `admit`): one `in` row per foreign file part, in message order, beside the exchange and before the text is delivered, so `PeerRecord.files` carries the `state="receiving"` placeholders: `start_task` (an HTTP peer's new task, from the snapshot's first message), `resume_task` (an answer on a task), and `import_reply` (an answer's file parts: a `Completed` task's artifacts, or a `Message` answer's parts). `contact_id` is the sender's binding `peer:<uuid>`; `source` is the URL, or the inline bytes as `data:;base64,…` (restart-safe); name from `filename`, else the URL's last path segment, else `file`, sanitised; type declared, else `mime_guess`; size known only for inline; deadline `now + OFFER_TTL`. `inbound_text` skips these parts (they carry no text).
- **Download** (`service.rs` `download` → `foreign`, `foreign::fetch`): a foreign row never resumes: the partial is removed, then `web::fetch::download(url, partial, opts)` with `max_bytes = FILE_MAX`, `idle_timeout = FILE_IDLE`, `deadline` = the row's (public-only, HTTPS on every hop, no whole-request timeout, BLAKE3 while streaming, unknown length allowed), or the `data:` bytes decoded into a new 0600 partial. `Store::file_measured` records size and BLAKE3 while `receiving`, then the same `publish` (quarantine, no-clobber link by inode, States, the notice) as a contact's file. Outcomes: an address the guard or the scheme check refuses (directly or by a redirect) fails `not a public HTTPS address`; a stall goes to the back of the queue, a transport error, 429 or 5xx after D8's backoff, each restarting from byte 0; a foreign row still queued at its deadline fails `no response`; anything else fails with the download error's text (`too large: over 5 GB`, `failed: HTTP 404`, `disk full on <machine>`). No receipts (there is no sender route). The queue slot (D7, 2 per member) of a foreign file is its sender.
- **Notices**: `alias_in` names a `peer:<uuid>` row by its binding's alias (cards, `files/received/<alias>/…`, the notice's `from="peer:<alias>"`); `Store::share_live` (D17's re-check, admission and consumption) for `peer:<uuid>` is "the binding is not revoked".
- **Answers** (`a2a/src/client.rs`): `Retained::of` and the `ArtifactUpdate` path (`artifact_parts_ok`) keep text, `raw` and `https` file parts; `data`, other URLs and userinfo are refused. The item and serialized-byte accounting is unchanged (inline bytes count in the snapshot bytes, a URL's file never; the 1 MiB text bound counts text only); the fingerprint also counts parts, so a file-only artifact change is reported. `accepted_output_modes` is `["text/plain", "*/*"]`.
- **Inline sends** (D16, toward an HTTP peer): `send::stage` resolves a non-contact `peer:<alias>` with a live binding as a foreign recipient (`contact_id = peer:<binding>`) and refuses, before anything is staged or sent, with `foreign::inline_fit`'s design text `<peer> takes files only inside the message, and <name> (<size> bytes) does not fit in 64 KiB` (base64, escaped text, part keys and a 1 KiB request envelope). The client (`inline_message`, `Link::Http` with files) re-checks the same estimate, reads each file through `FileOffers::open` (the gate's reopen checks; the card moves to `sending`), compares the offered BLAKE3 (`disk::blake3_of`), sends text + `raw` parts with no extensions, and on acceptance settles each offer `sent` through `FileOffers::receipt`. A refused send fails the exchange and with it the offers (States).
