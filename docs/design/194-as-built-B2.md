## Decisions where the contract was silent
- **Chat effort vs inherited model (row 12).** The chat's own effort applies over whichever link chose the model. Other links' efforts travel with their own model only. R1: the panel's chips show only beside the chat's own model, at `SessionMemory.effort_override` (the chat's own); the Default chip clears it.
- **Pickers with `none` selected show no chips** (Compactor, Summary model ×2, Memory summary model, dreaming tiers): `none` means "use the fallback, effort included" (D4d), and `current` (the selected `ModelInfo`) is undefined.
- **D4c vs D4b on whole-struct setters**: a whole-struct write whose model changed drops an incompatible effort; with the model unchanged it refuses. This lets a single picker write (`{...s, model}`) succeed.
- **Meeting summary** is a session model switch, not a side call, so row 14 did not need S1.
- **Dreaming tiers that run nowhere.** `triage` and `propose` models run in the night's own turn in v1 (no separate call); their efforts are stored and validated like their models, and apply where those models are honoured (nowhere yet, as for the models). `target` is `agent.model` (no setting).
- **Tidy effort → routine `effort:`** (quoted). `update_routine_file` gained `effort` in `ROUTINE_KEYS`; a cleared effort removes the line. The routine parser (`schedule::file::FrontMatter`, `deny_unknown_fields`) learns `effort:` in C's row 18: **on this branch alone a set tidy effort makes the routine file unparseable until C merges.** Nothing writes the line while the effort is unset.
- **`memory_effort:` is written quoted** in agent files so a budget (`"8000"`) stays a string.
- **Tool descriptions (D7)**: `memory_effort` is named in the param doc of `agent_propose`/`agent_put` (`AgentProposeArgs`) and `agent_draft` (`AgentDraft`), beside `memory_model`. The tool description texts do not list `memory_model` either, so they were left unchanged. The draft card shows `memory effort \`x\`` after `memory model`.
- **Migration number 0063** (`0063_endless_efforts.sql`). If another branch adds a 0063, Z renumbers one.
- **`localFirst`** was removed from settings/Memory.tsx and chat/MemoryPanel.tsx. The two 177 U4 assertions that pinned `localFirst === true` were deleted (D5 removes the ordering); the Local-tag assertions stay.

## R1 (review fixes, worker 194-B2-R1, on fe0cf447)

1. **Compactor cache key — fixed.** `pump::compactor_for` keys on `{id}|{effort:?}|{chosen}|{limits:?}`: a listed `low` is both the thinking-off default (`chosen: false`, `anthropic_off`) and an explicit pick (`chosen: true`), so Default ↔ Low now switches the compactor in force. 2. **Thinking budget vs `max_tokens` — fixed.** `ModelCompactor::cap(anthropic_off, lines)` is the reply (one unit: 600, local 2048; a batch: 600 a line, at most 16k) **plus** the effort's budget beside it, saturating, at most `carry()` = min(output limit, half the window — what `tokens::ceiling` keeps for a reply). `ModelCompactor::with_pick` clamps a numeric budget above `carry() − 600` to `Budget(carry − 600)` with a `warn!` ("thinking budget clamped …"), so `max_tokens` stays above it. A named level is sent as picked, not turned into a budget (on non-Anthropic transports it is no budget at all); its genai budget (High: 24k, Anthropic budget thinking only) needs an output limit above it (the known ceiling, a `ponytail:` note in `with_pick`). `Compactor::out_tokens(lines)` (was `out_tokens()`) is the same cap, so the pump's prompt fitting reserves what the request asks. Test `loop_::thinking_tests::compactor_thinking_budgets_fit_the_request` (Sonnet 4.5, budget thinking: High and `Budget(u32::MAX)` at 1, 2 and 40 lines; 2 lines at High = `budget_tokens 24000`, `max_tokens 25200`).
3. **Explicit Off keeps the transport-safe thinking off — fixed.** `with_pick` treats `Zero` (and `Budget(0)`) as no pick: an Off compactor is the Default one, byte for byte (same key too). Local OpenAI-style: the kwargs (`enable_thinking: false`), no effort keyword; Anthropic: `disabled`; Fable: adaptive `low`. A positive level rides as picked. `pump::model_compactor` builds the thinking-off compactor and calls `with_pick`. Tests: `loop_::thinking_tests::compactor_off_is_thinking_off_and_a_pick_rides_on_the_wire` (Haiku 5.5 and Fable 5.1 at Default, Off, Low: Off body == Default body), `local::tests::local_compactor_off_is_the_kwargs_and_a_pick_rides` (omlx-like local server at Default, Off, Low).
4. **Meeting summary effort — fixed by a guarded mutation, not a per-turn override.** The turn path has no per-turn reasoning override and cannot cleanly take one: `agent::Steer` has 17 struct literals outside the agent crate, the input rides `Held::Routed` and the session queue, and `Current.effort` is read per round. So: `Restore` now records `(prior, summary value as the session stores it)` for the model and the effort; `restore_session` puts the session back **only while it still holds the summary's value** (`restore_plan`: a pick the user made during the summary stands), and it is awaited in the releasing handler, never detached. Every exit runs it: a failed queue (`queue_summary`), the turn's end (finished, error, cancelled), a withdrawn form, and the watchdog (`SummaryTimeout` now goes through `take_summarizing`). Known ceiling: a turn the agent opens from its own queue in the instant between the summary turn's end and the Meeting's `TurnFinished` handling can run its first round on the summary effort; the upgrade path is a per-turn override on the queued input. Tests: `the_put_back_keeps_a_pick_made_during_the_summary`, `every_summary_exit_puts_the_session_back` (queue failure, watchdog, withdrawn, turn end; test seam `RESTORED`).
