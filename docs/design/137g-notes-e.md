## Decisions
- **TS name `EndlessBacklog`** (deviation, names only on the TS side): `dreaming::Backlog` (136 §2.7) already exports `bindings/Backlog.ts`, and a second `Backlog.ts` overwrote it. The Rust type is `agent::Backlog` as contracted; its binding is `ts(rename = "EndlessBacklog")` → `bindings/EndlessBacklog.ts`, and `SessionMemory.backlog` / `EndlessProgress.backlog` are typed `EndlessBacklog | null`. The JSON shape is unchanged.
- **"guard of mechanical"**: `endless_nodes` has no guard column and `endless_calls` rows are model attempts (they feed `stats.calls` and the guard-trip counts). The flag is the node's own `mechanical` column instead; a mechanical node has `tries = 0`, `model = NULL`, `free = false`. No `endless_calls` row is written, so `stats.calls` keeps counting model calls only.
- **Fold of a unit that fits `node_bytes`**: its node is the ordinary free node (verbatim, `free = true`, not flagged) — it is exact, not an excerpt.
- **Excerpt**: `tree::mechanical_unit` — the tagged unit, whitespace runs collapsed to one space, then head ⅔ + ` … ` + tail ⅓ of the room, at char boundaries, ≤ `node_bytes` bytes.
- **Fold and calls in flight**: if a level-0 call runs, the State's token is cancelled (no failure; a merge in flight restarts with it). A model reply that raced the cancel and landed first wins over the excerpt (better text); the fold only fills nodes that are still unbuilt.
- **Pause on an epochs session**: unchanged, like fold (nothing is persisted).
- **Pause and settle**: `settle` returns `false` at once while paused (no call can land).

## Decisions (phase B)
- **G1 one policy** (`agent::tokens`): `budget(kind, model, Limits) -> Budget { target_tokens, ceiling_tokens }`; `preflight` at `Backend::stream` (the one choke point; turn, side calls and compactor all pass it). Its refusal text is Anthropic's "prompt is too long: N tokens > M maximum (theuth preflight, not sent: …)", so `compact::is_overflow` / `overflow_numbers` and every existing overflow path read it; the degrade hooks are the callers' overflow paths (turn: G5 re-render; compactor: G5 ctx shrink). Learner: per-model EWMA (α 0.3) of request bytes ÷ provider `prompt_tokens`, clamped 1.8..=4.0, fed by every usage and by a provider's overflow count; persisted since R1 (below).
- **Side calls** get the preflight ceiling only; they cap their own inputs already (recon c/d). No side-call sizing was changed.
- **Turn budget**: allowance = target bytes − last system prompt − min(48 KB, target/4) (tools and input reserve). `view_bytes` and `raw_bytes` scale by the same factor when they exceed it (floors 2 KB / 1 KB); the live fold is untouched (a scaled fold is rebuilt for that render).
- **G2 hard cap (beyond the brief)**: the raw budget alone does not bound a tree whose *built* lines cannot merge (merges not built, e.g. after `endless_fold` with settling paused: the live run showed 1.17 MB of built excerpts). `Fold::size` therefore also folds the oldest lines, built or not, into one prefix line `(N older lines folded to fit the view — recall reaches them)` while the view is over `high + raw_bytes`. `fit()` still decides merges on the raw-folded size (D5 unchanged).
- **G3**: E8's window trim is now the G1 target (it uses the learned bytes/token, not 3 B/token); `ctx_budget` = min(`compactor_ctx_bytes`, local: `local_ctx_bytes`, target − fixed).
- **G4**: all text kinds capped at `cap_chars`; map-reduce chunks split at a newline in the second half of 16 KB, else a char boundary; the reduce input is the chunk lines joined. The job's outer bound grows with the chunk count.
- **G5**: compactor: one retry at ctx × M/N × 0.85 (strictly smaller). Turn: once per turn (`EndlessView.shrunk`), before the D11 compaction.
- **G6 batching**: the scan walks from the frontier; built, running or backed-off units are skipped (they do not break a batch, units are independent); free units and G7 units are instant jobs (no slot). A batch is one call slot. The reply cap is 600 tokens per line (+ thinking), ≤ 16k. A batch writes one `endless_calls` row (under its first unit); a refused line is not a failure, the unit goes solo (`Live.solo`) and runs the single-unit prompt with the in-call retries. A failed batch call is a failure of each unit. Merges are unchanged. ETA = lines × measured call-seconds per built unit ÷ parallel calls (cloud `jobs`, local 1).
- **G6 numbers**: 5,000 unbuilt non-free units = ⌈5000/16⌉ = 313 batch calls (+ solo retries), not ~2,600 serial calls. Measured live (local fake, one batch at a time, 0.4 s/call): 16 units per batch, ~19 units/s, 432 units in 24 s, so 5,000 ≈ 4.4 min at 0.4 s/call; at 5 s/call ≈ 26 min serial local, ≈ 3.3 min with 8 cloud jobs. Batch prompts ≤ 46.6 KB (ctx ≤ 24 KB local + 16 units).
- **G7**: `failures ≥ 3` makes a level-0 unit due at once whatever its backoff, and `spawn_build` writes the mechanical node instead of calling. (R1-2 narrows this, below.)
- **G11**: the day check runs before every call (one `model_calls` sum + one meta read). The cost check uses the prompt without its context (`COMPACT` + step) at the learned bytes/token; over `max_usd_per_call` the unit folds mechanically (a merge over it backs off as a failure). Resuming a spend pause records the UTC day in `sessions.endless_spend_override`. (R1-3/R1-4 refine this, below.)
- **G9**: `/compact` in an endless session folds before the tool-registry rebase (no model, no registry needed) and persists a `<memory>` note; the epoch is unchanged (the RPC returns the current epoch).
- **Mechanical flag**: not set on free merges of mechanical children.
- **`set_session_compactor_model`**: the catalog accepts any `provider/model` id, so the RPC also requires a reachable provider (a configured gateway, or a catalog model of a configured provider). The agent default (from its file) is not validated; it falls back at run time.

## Fix round R1 (Theuth's review, 18:54)
- **R1-1 preflight never blocks on the guess**: `tokens::UNLEARNED_REFUSE_BPT = 4.0` — with no learned ratio a request is refused only if it is over the ceiling even at 4.0 B/token (the clamp's optimistic end); sizing keeps 2.2. Learned ratios persist in `<data dir>/token_ratios.json` (`tokens::init` at engine start, temp-file + rename, written when a ratio moves > 0.02). The refusal text names the data dir's `models.json` for a stale catalog window.
- **R1-2 mechanical fold**: a unit folds only after `hard ≥ 3` non-transient failures in a row (`compact::classify` ≠ Transient) **and** ≥ 10 min since the first of the run (`Retry.since`); 429/5xx/network only back off. A mechanical-due unit waits its backoff like any failure (a store error no longer hot-loops). (R2-2 widens "hard" and adds the success gate.)
- **R1-3 cost**: the check prices the largest single call (`compactor::largest_call_bytes`: one map-reduce chunk, or the whole batch). A batch over `max_usd_per_call` sends each unit solo (no failure); a unit whose own call is over folds at once, with one `pending_error` notice per session state "summary model too expensive for max_usd_per_call; lines folded as excerpts".
- **R1-4 spend**: a failed call settles its `model_calls` row with the answered attempts' usage plus the estimate of the failing prompt (`compactor::Failed { error, calls }`); failed attempts also write `endless_calls`. Within one `max_usd_per_call` of the day cap (`Live.near_cap`, set until the first spend check) the pump runs one call at a time, so the overshoot is at most one call. (R2-1 / R2-3 narrow both, below.)
- **R1-5**: the hard-cap line says "recall reaches them" (it is no tree node; `endless_zoom` refuses it).
- **R1-6 overflow**: a retry that would not shrink is skipped (compactor ctx, turn re-render); an overflow refusal without numbers shrinks to 0.5. `compact.rs` reads Gemini ("input token count (N) exceeds the maximum number of tokens allowed (M)") and xAI ("maximum prompt length is M but the request contains N") and recognises Bedrock's "input is too long".
- **R1-7**: `/endless off` writes its head within the session model's view allowance (`set_mode_within`); a bare `<memory>` note (G9/G10) is no unit, renders as an info line in the TUI and is a harness tag for the advisor.
- **R1-8**: `endless_fold` uses `Store::endless_nodes_put_new` (`ON CONFLICT DO NOTHING`): a model line that landed during the fold stays.
- **R1-9**: `Fold` keeps running built/open byte sums (O(1) `fit_size`); `batch_lines` takes the last of a repeated number and joins an unnumbered line to the numbered one before it.
- **R1-10**: the loop G5 scenario uses its own model id `openai/bounded`, so learned ratios from other scenarios cannot move its sizing.
- **Q1 thinking off**: every compactor runs with thinking off — `ReasoningEffort::Zero` for Anthropic and ollama, else the model's lowest listed effort (`none` → Zero, `minimal`, `low`), else none; the session's effort no longer reaches compactors and `max_tokens` is back to 600. genai at d2fd71e already maps `Zero` to `thinking: {type: "disabled"}` for the models that think by default (Haiku 5+, Sonnet 5, Opus 5: `ant_model.rs thinking_enabled_by_default`), so no fork change was needed. (R2-7: Anthropic is decided by the transport.)
- **Q2**: a reply whose only guard trip is size is cut at a word boundary with "…" (`guards::cut_words`) and accepted — no correction round.
- **Q3**: a unit sent solo after a refused batch line aims at 80 % of `node_bytes` ("in at most {aim} bytes").
- **Q4 eval**: `scripts/endless-eval/eval.py --thinking disabled|default` (default disabled; the header prints it), size trips cut as in Q2, batch parsing as in R1-9; `fake.py` answers empty for an Anthropic request with thinking on and a large prompt (the Haiku 5 empty-reply shape).

## Fix round R2 (Theuth's re-review, 19:54)
- **R2-1 charge only what may be billed**: a failed call's row carries its answered attempts' real usage; the failing prompt's estimate is added only when theuth dropped the call after dispatch (`pump::billed_drop`: "timed out", "stream idle"). Overflow, 4xx, 429/5xx, connect errors and the preflight's "not sent" cost nothing, so an outage cannot reach `paused_by: "spend"` or the desk budgets. A cancel after dispatch stays `Cancelled` with no usage (unchanged).
- **R2-2 (a)** `pump::hard_failure`: non-transient, or "compactor returned nothing", "timed out", "stream idle", "panicked", so a unit that always comes back empty or always times out still folds. **(b)** `Retry::mechanical(last_ok)`: the fold also needs a node built by the model (`Live.last_ok`, any level) after the unit's first failure; an error that fails every unit (401/403, no credit, unknown model) folds nothing and stays `stalled` for Retry or a model switch. Over cost is its own flag (`Retry.cost`) and folds at once as before.
- **R2-3**: near cap when `spent + jobs × max_usd_per_call ≥ cap` (every slot's call could cross it). Local compactors are still exempt.
- **R2-4**: `tokens::learn(model, bytes, flat, tokens)` takes out the request's flat image/PDF tokens before the ratio; the file write happens outside the ratio lock (snapshot under it, the `RATIOS` path lock serialises writers).
- **R2-5**: a blank line ends a batch line's continuation (also in `eval.py parse_batch`).
- **R2-6**: `Fold::is_folded_line(id, n)` — zoom refuses any folded-run line, aligned or not ("… is a folded run, not a summary line; recall searches it.").
- **R2-7**: `Zero` for Anthropic is sent by `ModelCompactor::request_lines` on `Transport::Anthropic` (with the 600-token cap); `thinking_off` no longer looks at the id, so a `claude-*` id behind an OpenAI-compatible gateway gets the catalog's lowest effort or nothing.
- **R2-8 Fable / Mythos**: Theuth's probes (claude-fable-5-1, 600 tokens) showed that sending nothing gives thinking-only empty replies and that `disabled` is a 400. genai d2fd71e marks Fable and Mythos as `thinking_enabled_by_default: false` with adaptive and effort support, so `Zero` sends nothing. `ReasoningEffort::Low` already maps to `thinking: {type: "adaptive"}` (plus `display: "summarized"`, because the compactor captures reasoning content) and `output_config.effort: "low"` (`ant_reasoning.rs insert_anthropic_reasoning`), so **no fork patch is needed**. `compactor::anthropic_off(slug)` returns Low for a slug containing `fable` or `mythos` (genai's own `legacy_is_fable_or_mythos` test) and Zero otherwise. It applies on `Transport::Anthropic` and, through `thinking_off`, to Bedrock's Anthropic models (`bedrock*::…anthropic.…`), which go through the same genai mapping (`bedrock/converse.rs`). The test `endless_compactor_turns_thinking_off_per_model` checks the body on the wire (wiremock): Haiku 5.5 gets `thinking: {type: "disabled"}`, Fable 5.1 gets adaptive with effort `low`, and both have `max_tokens` 600.
- No new live run: R2-2 changes when a failing unit folds, which run 3 did not exercise (its only fold was over cost, unchanged).
