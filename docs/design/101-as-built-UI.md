## Deviations from the brief / design

- **No manual `encodeURIComponent`** in links: TanStack Router 1.170 encodes path params itself (`router-core/path.js
  encodeParam`) and decodes on match; pre-encoding would double-encode `:`. Links pass the raw id; hrefs come out as
  `/attention/review%3A…` (verified).
- **`age` not moved**: `Hud.tsx` already imports it from `components/tasks/helpers`; the row imports it from there too.
- **`shared.tsx`** added (not in the brief's file list) to hold what the three screens share without an import cycle.
- **Review action bar** is a fixed footer below the scroll area rather than `position: sticky` — same result inside the
  pane's flex column, no scroll-container coupling.
- **`openExternal`** uses `openUrl` with a `window.open` fallback (BoardReader's pattern) rather than streamdown's `a` path,
  so url pointers also open in a plain browser (dev/screenshots).
- **`useResolved` also fires after Snooze** and after every PlainScreen resolving button (D11 names Answer / Approve / Send
  back / Dismiss; an item that left the list should not stay on screen in any case).
- **`usePacket` enabled on `typeof key === 'string'`**, not `key !== null`: items from an engine without 101 have no `packet`
  field at all (seen on the live daemon) and must not call `packet_get(undefined)`.
- **Sim task ids** reuse `tasks/mock.ts` ids 2 and 3 so `?mock=1` supplies the task title and `done_when`; `mock.ts` task 3
  gained a `done_when`. `useTask` gained an `enabled` parameter.
- **Screenshots** taken with the managed headless Chromium, not the Chrome CLI (see above).
