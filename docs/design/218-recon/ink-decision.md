# Whiteboard ink (design 218): the decision

Decided 2026-11-25. Every file, function and line named here was read at `b4a960243` (the checked-out branch `ui/send-eclipse` points at the same commit as `main`). I had no shell, so uncommitted edits in the working tree were not ruled out, and nothing was built or run.

## 1. The decision

**Web-only ink on every platform: iPad, macOS and the browser.** One input path (Pointer Events in `canvas/Canvas.tsx`), one renderer (perfect-freehand in `ink/render.ts`), one tool state (the zustand store in `canvas/store.ts`), one undo stack (`canvas/undo.ts`).

The PencilKit capture layer, the `PKToolPicker`, the stroke hand-over protocol and the `inkEngine` toggle are deleted. `tauri-plugin-ink` stays as a small crate with two stateless services that the web cannot provide:

- **Vision handwriting** (`recognize_text`, ruling R6).
- **A Pencil gesture forwarder** (`UIPencilInteraction` double-tap and squeeze). It reports the gesture and the owner's preferred action from Settings; JS decides what to do.

Neither service touches a stroke or holds tool state.

### Why

- **The owner's A/B settled the one open cost.** Both reports named the same test: draw with "Native Pencil ink" off on the real iPad. Report A said to measure before choosing web-only; report B said to choose it unless it felt sluggish. The owner ran it on 2.30.2 and reported "it honestly seems like there's no lag." That is a feel test, not the blind A/B with 240 fps video that design §6.2 specified, so section 4 keeps a tripwire.
- **The native layer failed its own exit gate.** `docs/design/218-whiteboard.md` §6.2 gate (4) requires that the owner prefers native in an A/B against pointer ink. He did not find a difference worth four bugs in one day.
- **The seam was the bug.** The tool dropping, Pencil taps turning into strokes, and capture switching on mid-stroke all came from two layers sharing input and tool state. Web-only removes the second layer; fixing the hybrid only narrows the races.
- **macOS must draw with mouse and trackpad.** PencilKit has no AppKit canvas or picker, so the web renderer exists regardless. Native-owned ink on iPad would mean two renderers and two tool UIs permanently.
- **Native-owned ink fights the document model.** Ink is anchored to a card and version in Yjs with one `Y.UndoManager`. A `PKCanvasView` brings its own scroll camera and undo stack, and needs camera sync against a web canvas.
- **PencilKit's extras are things 218 forbids or hides.** Principle 5 says ink is never interpreted, and the picker was already built without ruler, lasso or drawing-policy controls. What remained was latency, and the owner did not feel it.

### Effect on the owner's rulings

| Ruling | Effect |
|---|---|
| R2: fingers navigate, the Pencil inks | Unchanged. `routePointer` in `canvas/input.ts` already routes pen to ink and touch to pass; `fingerInk` ("Draw with finger") stays. |

## 3. What the web path must have to be the only path

Most of it is already there. Two things are missing; both are small.

| Need | State at `b4a960243` | Action |
|---|---|---|
| Pen-only rule (R2) | `routePointer`: pen inks in every mode except link and erase; touch passes unless `fingerInk` | None |
| Palm rejection while writing | `palmActive`: touches are ignored while the pen is down and for `PALM_MS` (500 ms) after; the `touch` listener (`Canvas.tsx:735-746`) stops palm and stylus touches before d3-zoom | None |
| **Palm that lands before the pen** | **Missing.** A resting palm routes as `'pass'`: it arms the 550 ms long-press mark menu (`press`, lines 566-583) and feeds `MultiTap`. `taps.cancel()` exists but nothing calls it, and `taps.up` runs undo/redo regardless of the palm window (lines 666-670). | **Build**: on pen-down, clear `press.current` and call `taps.cancel()`; do not feed `taps.down` while `palmActive`; ignore the result of `taps.up` while `palmActive`. |
| Coalesced events | `getCoalescedEvents()` with a fallback to the event itself (lines 643-644), de-duplicated by `StrokeSamples` | None |
| Predicted events | `getPredictedEvents()` drawn ahead for the frame, never committed (lines 650-661) | Keep; see next row |
| **One wet draw per frame** | **Missing.** With predicted events, `drawWet()` runs synchronously on every `pointermove`, and it re-runs perfect-freehand over the whole stroke (lines 401-404). iPadOS WebKit fires `pointermove` twice per sample, so a long stroke pays that twice per sample. | **Build**: keep the predicted tail on the `Wet` value and draw once per animation frame. |
| Pressure | `e.pressure` per sample; `hasPressure` picks real or simulated thinning (`freehandOptions`) | None |
| Tilt | Not captured (`Pt` is x, y, pressure, t) and no tool uses it | **Do not add.** No tool shades by tilt; adding it changes the packed stroke format for nothing. |
| Tool picker | `InkTools` in `Cluster.tsx`: Pen, Fine liner, Marker, Eraser, colours. A Pencil tap on it is a tap (`isControl`, line 545). | None. It is now the only picker and the only writer of the tool. |
| Tool latch | `pickInkTool` arms draw; nothing on pen-up changes mode | Keep the latch tests on the pointer path |
| Undo / redo | `createUndo` (one `Y.UndoManager`), two- and three-finger tap, cluster buttons, keyboard | None |
| Eraser | `mode: 'erase'` → `eraseAt` removes whole strokes | Pencil double-tap toggles it through the gesture forwarder |
| Stroke cut by the system | `pointercancel` commits what was drawn if it has two or more points (line 718) | None |
| Pencil over a live page card | `penRelay.ts` relays pen events from the sandboxed frame | None |
| Hover preview | None today, on either path | Not in scope |

What native code is still needed for:

- **Double-tap and squeeze.** The web never sees them. The forwarder gives the same Settings-following behaviour the picker gave. Mapping (taken from `native-ink.ts:112-119`): `switchEraser` toggles erase; `switchPrevious` swaps with the previous tool; the three palette actions raise the cluster (`timer.show()`); `runSystemShortcut` and `ignore` do nothing.
- **Palm rejection.** Nothing native. PencilKit's `.pencilOnly` policy is replaced by the pen-only route plus the palm rules above. I did not verify how many palm contacts iPadOS filters before WebKit sees them; the rules assume none.

|---|---|---|
| **Latency.** WKWebView is capped at 60 Hz on ProMotion (WebKit bug 294338). Re-measure on each iPadOS major version. | Tag `b4a960243` as `ink-hybrid-final` before deleting, so the native layer is one checkout away. Do not keep it in the tree. |

## 5. Implementation brief for the builder (omp Opus)

**Goal.** Make Pointer Events + perfect-freehand the only whiteboard ink path on every platform, delete the PencilKit capture layer and the `inkEngine` toggle, and reduce `tauri-plugin-ink` to handwriting recognition plus a Pencil gesture forwarder.

**Where.** Repo `/Users/sky/Develop/skymoore/theuth`. Work on a new branch `refactor/218-web-ink` from `main` at `b4a960243`, in its own worktree. Do not commit to `main` and do not push; the orchestrator merges. Before the first commit the orchestrator tags `b4a960243` as `ink-hybrid-final`.

**Constraints.**
- No new npm or cargo dependency. No version bumps.
- The store is the only writer of `mode`, `tool`, `colour`, `width`. Native code never sends tool state.
- Do not change the packed stroke format (`ink/pack.ts`) or `Pt`.
- cargo commands run under the machine's build lock as in earlier 218 rounds; one cargo job at a time, `--test-threads=4`.
- Commit per step with path-scoped commits.

### Steps, in order

**Step 1. Remove the native path from the UI.**
- Delete `components/whiteboard/native-ink.ts` and `native-ink.test.ts`.
- `canvas/store.ts`: remove `inkEngine` and `nativeInk`.
- `canvas/input.ts`: remove `RouteState.nativeInk` and the `s.nativeInk` branch in `routePointer`; fix the `Route` doc comment (`swallow` is the read-only pen).
- `canvas/Canvas.tsx`: drop `nativeInk` at lines 338 and 530; delete `commitCaptured`; reword the comment at 589.
- `canvas/api.ts`: delete `commitCaptured` from `WhiteboardCanvasHandle`.
- `WhiteboardView.tsx`: delete the import, the attach effect, the visibility effect, the `viewEnd` call and the "Native Pencil ink" toggle. Leave `recognize` for step 2.
- `canvas/input.test.ts`: remove `nativeInk` from `base` (line 4) and the loops (16-17); delete the test "native ink swallows pen events…" (22-25); fix lines 48-49.

**Step 2. Rewrite `lib/ink-native.ts` and wire the two services.**
- `lib/ink-native.ts` exports exactly:
  - `recognizeText(png: string): Promise<{ text: string; confidence: number } | null>` → `plugin:ink|recognize_text`; null outside Tauri, when the plugin is missing, or on any failure.
  - `listenPencil(on: (e: PencilEvent) => void): Promise<() => void>` → `plugin:ink|pencil_listen` with a `Channel`; the returned function calls `plugin:ink|pencil_unlisten`. Outside Tauri or on failure it resolves to a no-op.
  - type `PencilEvent = { kind: 'pencil'; gesture: 'tap' | 'squeeze'; action: … }` (the seven actions as today).
  - Keep the `loader` test seam. Delete the generation/owner-token machinery, `attachNativeInk`, `resetNativeInkOwner` and the stroke types.
- New `components/whiteboard/pencil-gestures.ts`: a pure `pencilAction(e, state, previous)` returning the store patch and whether to show the tools, with the mapping in section 3. Track `previous` from a store subscription (the tool and whether erase was on, updated whenever either changes), not from native events.
- `WhiteboardView.tsx`: when not `readOnly`, `listenPencil` on mount and unlisten on unmount; pass `recognize: recognizeText` to `sendWhiteboard` unconditionally.
- Rewrite `lib/ink-native.test.ts` for the two functions (null outside Tauri; missing plugin; failure swallowed; the exact command names).
- New `pencil-gestures.test.ts`: each action; `switchPrevious` twice returns to the start; `ignore` changes nothing; the tool stays latched after a gesture.

**Step 3. Move the latch tests onto the pointer path.**
- `pen-latch-canvas.test.ts`: remove the fake `Plugin`, `attach`, `connectNativeInk` and the `native` argument of `mount`. The "iPad + Pencil" block drives `pointerType: 'pen'` events only. Keep both describes and all four tests.
- Port two cases from `pen-latch.test.ts` into it: "picking the armed pen again keeps it" and "the cluster auto-hiding (4 s) and the popover closing do not change the tool". Then delete `pen-latch.test.ts`.

**Step 4. Harden the web path (`canvas/Canvas.tsx`).**
- Pen-down (both the pointer `down` handler and the `penRelay` `'down'` phase): clear `press.current` and its timer, call `taps.cancel()`.
- Do not call `taps.down` for a touch that starts while `palmActive`; discard a `taps.up` result while `palmActive`.
- Wet drawing: store the predicted points on the `Wet` value, schedule one `requestAnimationFrame(drawWet)` per frame, and draw committed points plus the predicted tail there. Predicted points are still never committed.
- New tests beside `canvas/one-stroke.test.ts`:
  - palm first, then pen: no mark menu after 550 ms, no undo, the view does not move during the stroke;
  - two touch contacts tapping during the palm window do not undo; a two-finger tap outside it still does;
  - a 600-sample stroke with doubled moves and predicted events draws at most once per frame and commits no predicted point.

**Step 5. Reduce the plugin.**
- Swift: move `PencilController` to `ios/Sources/PencilController.swift` with `@available(iOS 17.5, *)`; delete `CaptureSurfaces.swift`, `InkOverlay.swift`, `ToolPickerController.swift`; reduce `InkModels.swift` to `PencilEvent` and `ErrorEvent`.
- `InkPlugin.swift`: three commands. `pencilListen` (args `onEvent: Channel`) installs one `PencilController` on the web view and resolves `{ ok: true }`, or `{ ok: false }` below iOS 17.5 or off iPad; a second call replaces the channel. `pencilUnlisten` removes it. `recognizeText` unchanged.
- `Package.swift`: drop PencilKit.
- Rust: `build.rs` `COMMANDS` = `pencil_listen`, `pencil_unlisten`, `recognize_text`; `src/lib.rs` handler list and crate doc; `src/desktop.rs` stubs for the three (`pencil_listen` answers `{ ok: false }`); `src/models.rs` keeps `PencilAction`, `PencilGesture`, `InkEvent` with `Pencil` and `Error` only, `Recognized`, plus a `ListenResult { ok }`.
- Tests: delete `stroke_batch_serde_shape` and `attach_reports_desktop`; trim `ink_event_serde_shape` to the two variants; add `pencil_listen_reports_desktop`.
- `permissions/default.toml`: the three `allow-*`. Delete the seven stale files under `permissions/autogenerated/commands/` and let the build regenerate `reference.md` and `schemas/schema.json`; commit the result.
- `api-iife.js`, `guest-js/index.ts`: the three commands.
- Comments: `Cargo.toml` description; `crates/desktop/src/lib.rs:123`; `crates/desktop/Cargo.toml:60`.
