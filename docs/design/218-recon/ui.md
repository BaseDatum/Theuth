## 2. Document client

**`UI/lib/doc/provider.ts`** (501 lines):
- `class EngineProvider` (`#L117`). It has `readonly doc = new Y.Doc()` (`#L119`), `awareness`, `meta`, `status: DocStatus` (`#L32-L38`), and `queued`, `onStatus`, `onEvent`, `onAuthored`, `agentPresence`, `destroy`.
- Constructor: `constructor(client: RpcClient, api: Api, id: DocId, engine: string = LOCAL, guest?: GuestUser)` (`#L160`).
- Sharing: `export function acquire(client, api, id: DocId, engine = LOCAL): EngineProvider` (`#L486`) and `export function release(p)` (`#L496`). They are refcounted per `id`, so one provider serves several panes.
- React hook: `components/editor/useDocument.ts#L26`, `useDocument(target: DocTarget): LiveDocument`, returns `{ provider, status, error }`. `target = { doc: DocId }` skips `doc_resolve`.
- Constants: `ENGINE='engine'` (`#L16`) and `RESTORE='restore'` (`#L18`) are module-private, not exported. Updates with any other origin go to the engine.
- RPC sequence in `#sync` (`#L378`):
  - `doc_subscribe` first, then `doc_open(id, sv)`.
  - The state chunks are joined and applied under the `ENGINE` origin.
  - The queue is drained in batches, then a catch-all push follows.
- Local updates are sent by `#local` (`#L257-L280`) via `doc_update`. When not live they queue in `#queue`.
- Limits:
  - **One update may not exceed 48 KiB base64** (`MAX_UPDATE_B64`, `#L26`). A larger one hits `#refused` (`#L304-L310`), which closes the provider as `update too large (48 KiB); reload`. The offline replay merges updates into batches under that cap, but one single oversized transaction cannot be split.
  - The engine's document cap is 8 MiB (`document full (8 MiB)`).
  - `MAX_UNCONFIRMED` is 1 MiB of acked updates kept for resend.
- Offline storage in `lib/doc/queue.ts`:
  - `DB='documents'` with stores `state` and `pending` (`#L7-L9`).
  - `export const MAX_BYTES = 4 * 1024 * 1024` (`#L11`). Over it, the state blob is dropped but pending rows are kept (`saveState` `#L102-L112`).
  - `class DocStore { constructor(engine, doc); load(); enqueue(update): Pending; ack(items); saveState(state) }`.
  - **IndexedDB is used only for link devices.** `this.#store = engine === LOCAL ? null : new DocStore(engine, id)` (`provider.ts#L166`). On a local engine, `queue.ts` is bypassed and offline queueing is memory only. This matches the design's §3.1 and §9 wording.

**Using a non-BlockNote Y.Doc.** The provider is schema-agnostic. It touches only `doc.on('update')`, `encodeStateVector` and `applyUpdate`. `getXmlFragment(FRAGMENT)` (`FRAGMENT = "document-store"`, `packages/documents/src/schema.ts#L25`) is applied only inside `Editor.tsx#L194`. So a whiteboard can call `useDocument({ doc })` and then use `provider.doc.getMap('cards')`, `getMap('links')` and so on.
- For a local undo stack, mutate with `doc.transact(fn, OWNER)` and use `new Y.UndoManager([maps…], { trackedOrigins: new Set([OWNER]) })`. Engine updates carry origin `'engine'`, which UndoManager ignores.
- Awareness is always created (`#L164`). Cursor and presence fields are up to us.
- `readOnly` follows `meta.kind === 'source'` or a viewer (`#L407`).

- **Where `theuth/describe-point` goes:**
  1. Page side: `BOOTSTRAP_JS` (`#L72-L183`). Add a `window.addEventListener('message', …)` branch for the new method that does `document.elementsFromPoint`/hit-test and replies via `post({jsonrpc:'2.0', id, result})`. The bootstrap already has `post`, `notify` and the `message` listener (`#L75-L76`, `#L101-L105`).

  - The `message` listener is on `window` with `'*'` origin for replies, because the frame is an opaque origin.

## 9. Tauri invoke and snapshots

**Pattern:**
- `lib/tauri.ts` wraps each command: `isTauri() ? invoke<T>('name', args) : Promise.resolve(fallback)` (`#L40-L162`), for example `invoke<void>('island_show', { width, height })`.
- `lib/web-view-native.ts` is a "every invoke for web views lives here" module that tests mock (`#L1-L192`). It is the template to copy: one module per native feature, so vitest mocks one import.
- Rust side: `#[tauri::command]` functions in `crates/desktop/src/*.rs`, registered in `tauri::generate_handler![…]` (`lib.rs#L112` mobile, `#L359-L397` desktop). The `capabilities/default.json` file gates plugin permissions.

**Snapshots — what exists:**
- **No** `takeSnapshot` of the main webview exists.
- `apple_tile.rs#L270-L301` has `snapshot(view: &WKWebView, viewport, tx)`, which calls `takeSnapshotWithConfiguration_completionHandler`. It is for **child tile webviews only**, reached through `web_view_call(label, op, args)` with op `'snapshot'` (`webview.rs#L512-L523`).
  - `web_view_call` is checked against the caller's window and the tile label.
  - The TS wrapper is `web-view-native.ts#L174-L177`, which returns `{ png }` for snapshot.
- A DOM-to-PNG rasteriser exists for chat fences:
  - `lib/fence-snapshot.ts`: queue (`MAX_RUNNING=2`), `FAIL_MS`, `QUIET_MS`, and caps `MAX_PNG_BYTES = 4 MiB`, `MAX_SIDE = 8000`.
  - It uses DOM → SVG `<foreignObject>` → canvas (`components/chat/FenceSnapshot.tsx#L7`, via `rasterize` and `standalone` from `lib/diagram-export.ts`), with computed styles cloned inline.
  - Request/answer events: `artifact.fence-snapshot-requested` / `-resolved`, and `api.answer_fence_snapshot(id, answer)` (`fence-snapshot.ts#L130`).
  - Similar events exist for `page-preview-requested` / `-resolved` (hidden render in the app, 120 §11) and `web-view-call-requested`.
  - **This is the closest pattern to the design's "snapshot / describe-point for agents".** An agent-triggered `wb_snapshot` request can ride the same event pair.
- It does not capture sandboxed iframes, native webviews or canvas-sourced pixels from other origins. The design's P0 spike (whether `takeSnapshot` of the main webview includes `theuth-page` frames on iOS) therefore still requires a new Rust command and iOS plugin.
- iOS: the plain `WKWebView` is created in `ios_webview.rs` (commands at `#L834-L1039`), not a Swift plugin. `crates/desktop/ios/` holds only `Info.ios.plist`. A native PencilKit layer (P3) would be the first Swift in `crates/desktop`.

**Recipe for pointer ink:**
1. `<svg>` or `<canvas>` overlay with `touch-action:none`.
2. `onPointerDown`: if `pointerType === 'pen'` (or finger when the toggle is on), call `setPointerCapture` and start collecting `getCoalescedEvents()`.
3. Render with `perfect-freehand` `getStroke`; add the dependency at 1.2.3.
4. Commit one `Y.Map` entry per stroke in a small transaction, to stay under 48 KiB.
5. Test with synthetic `MouseEvent` plus pointer fields, as in `Desks.test.ts`.

## Risks and surprises versus the design

1. **Update size.**
   - A single `doc_update` over 48 KiB base64 permanently closes the provider (`provider.ts#L304-L310`). Only the offline replay merges batches.
   - A long ink stroke or paste must be written as several transactions, or points must be thinned. The design cites only the 4 MiB IndexedDB bound and a "2 MiB bake" (R8), not this 48 KiB per-update cap.
2. **Local engine has no IndexedDB** (`provider.ts#L166`); the offline queue is memory only. The design says this correctly. Link devices (iPad) get IndexedDB with the 4 MiB state-plus-pending cap, which matters because iPad is the target.
3. **`ENGINE` and `RESTORE` origins are not exported** (`provider.ts#L16-L18`). Design §4.6 cites `provider.ts#L15-L16`. A `Y.UndoManager` needs only its own origin, but any code that distinguishes engine-origin writes must either export them or use the literal `'engine'`.
4. **Live web cards are native webviews.**
   - A `WebFrame` child webview cannot be transformed, zoomed or shielded by a DOM layer. §4.4's shield works for sandboxed iframes (`HtmlPage`), not for `show_web` cards.
   - The live budget and snapshot demotion in §3.6 are therefore load-bearing for web cards.
   - This is one more reason for the P0 snapshot spike.
5. **Tiles are Trellis now, not `panes.ts` nodes.** The design's references (`tiles.ts#L58-L69`, `registry.tsx#L43-L61`) are accurate. Older knowledge about the "binary tree, `draft:` prefix" is stale.
6. **Sidebar:**
   - `GROUPS.library` is a tab list, and the rail popovers are session-oriented (`railSections`). A "Whiteboards" section means new rail and popover code, not just a data entry.
   - Both `AppSidebar.tsx` (expanded) and the rail variant (`#L172-L227`) need matching rows.
7. **`DocKind` is generated from Rust.** `useNotes.ts` hard-codes `['note','board']`. The whiteboard list needs the binding regenerated first, and `NotesList` should keep ignoring whiteboards (no existing filter on unknown kinds, so check what `doc_list('note')` returns).
8. **Marker kind.** `attach.ts` has the kind enumerated in a type, a const array and a regexp, plus `attach-picker`. A Rust-side parser in `crates/agent/src/attach.rs` must change in the same commit. I did not read the Rust side.
9. **Engine-side document handling.** The BlockNote schema and markdown conversion live in `packages/documents` (bundled into `crates/js-runtime`, with `just documents-bundle-check` gating it). A whiteboard Y.Doc with no `document-store` fragment must not be fed to that converter (export, markdown, snapshots). I did not verify this on the engine side. The `panelRequirements` list includes `doc_markdown` and `doc_export`.
10. **Attribution** is currently the library default everywhere. R3 means adding `proOptions.hideAttribution` plus a custom top-left element. Check that this complies with the free licence terms before shipping.
11. **React Flow and the stylus.**
    - No filtering of pen versus finger exists. P2's "stylus ahead of React Flow's pan" task is real.
    - React Flow handles gestures with d3-zoom. Use capture-phase handlers and `panOnDrag={[…]}`, or `noPanClassName`/`nodrag`/`nopan` on the ink layer.
12. **Glass, snapshot-in-current-theme and `data-snapshot-light`.**
    - No glass style exists, so the pill's CSS is new.
    - Design A1's "re-take snapshots on a theme switch" can use `useDark()` as the trigger.
    - The `data-snapshot-light` variant (`styles.css#L13`) suggests a way to render a subtree in light mode for a snapshot.
13. **Tests:** only `*.test.ts` runs (no `.tsx`), and there is no DOM environment. Canvas and gesture logic must live in pure `.ts` modules (like `attention/graph/elements.ts` and `tasks/graph/model.ts`), with `renderToString` for markup checks.
14. **Mic:** `MicButton` is coupled to the Composer's recorder state, so "holding the mic dictates" in the pill needs that logic factored out of `Composer.tsx` first.
15. **Status bar and safe areas:** a full-screen route must respect `--statusbar-h` and `--safe-*`, and size with `--visible-band`.
