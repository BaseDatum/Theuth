## Deviations

- **Transparency CSS moved out of `@layer base`** (`styles.css:509-518`). In the browser smoke `html` painted `#12100e` despite `html[data-overlay]` matching: `public/theme.css` sets `html { background }` unlayered, and an unlayered rule beats any `@layer` rule regardless of specificity (its `:where` note assumes specificity decides). The island's `html[data-island]` rule had the same flaw; both now live unlayered. For the overlay an opaque `html` would have painted every display dark, so this was not optional.
- **`since_ms` = `duration_ms`, not `0`.** The brief says `since_ms: 0`; DAEMON's generated `ScreenContextReq` documents `since_ms` as "Press-to-release duration" and the brief also says the generated bindings are the truth. The value is cast `as unknown as bigint` (ts-rs types u64 as `bigint`; the wire carries a JSON number, `JSON.stringify` throws on a real BigInt).
- **Failure paths call `point_cancel()`, not `point_done()`.** The brief/spec say `point_done()` on "Nothing recognized" / a send failure, but in SHELL's machine `Sending + PanelDone → Replying` (a second `PanelDone` would be needed to reach `Idle`), while `Sending + Cancel → Idle`. `point_done()` is used exactly where the machine expects `PanelDone`: once after a successful send (`Sending → Replying`) and once after the reply (`Replying → Idle + Conceal`).
- **Panel shows/hides the island itself.** The shell's `Start` effect emits events only (no `island_show`); the panel calls `islandPlace`/`islandShow`/`islandHide` like the meeting island.
- **A `hint` phase.** Refusals and cancel hints render in the listening slot for `HINT_MS = 2000` (the spec's 2 s; the brief's 1.5 s for cancel hints was not kept separate — one timer).
- **Reply end detection.** `speakBlock` → `enqueue` → `speak` is asynchronous, so "nothing to speak at `TurnFinished`" cannot be read from `speech.ts` synchronously (nothing is exported for it). The panel tracks the desk's `SpeechStarted`/`SpeechFinished` ids and treats 4 s after `TurnFinished` with no `SpeechStarted` as spoken (covers an empty block and a disabled voice plugin). `lib/speech.ts` untouched.
- **Desk entries for `speakBlock`.** Checked: `store/reduce.ts` `route()` creates an `empty()` slice for any session event, so `TurnStarted`/`TextDelta` in the island webview build the desk's entries without loading history; `speakBlock` finds the newest assistant entry. No history load, no `speak` from the panel's own text.
- **Settings › Voice key permission states.** The brief's three controls + Reset hints + disclosure + "Change the keys" are there; the spec's Accessibility/Screen Recording dots with the Open System Settings link are not duplicated — the row's description points at Settings › Computer, which already renders them.
- **"Click outside" → `point_cancel()`** is not implemented in the webview: a non-activating `NSPanel` webview gets no outside-click signal; Esc inside the panel is wired. The shell holds the global Esc between press and send (§0.2).
- **`DictatedText` not exported** from `Composer.tsx` (touching the composer for an export was avoided); the six-line muted/saturated rule is inlined in `VoicePanel.tsx`.
- **`speakerSource()` duplicated** from `routes/talk.$session.tsx` (12 lines) rather than editing a route outside this seam.
- **`steer` vs `send_input` reads the island webview's own slice** (`running ?? false`); a desk mid-turn that this webview has not seen yet reads as idle and gets `send_input`.
- **`point:refused` in main** toasts with a "Change the keys" action instead of a persistent Settings › Shortcuts badge.
- **`isOverlay()`** detects the label (`overlay-<n>`), matching the ADDENDUM's path routing (`/overlay?display=<n>`) in the browser fallback.
