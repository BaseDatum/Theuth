## Per commit

### 1 · `483f523` desktop: durable composer drafts per session
**Wrong:** the draft lived in `Composer`'s local `useState`, mirrored to a module-level in-memory `Map` (`lib/drafts.ts`) by an effect; nothing survived a relaunch, and a remount before the effect ran (pane/route churn) lost it. The message edit bubble (`MessageUser.EditBubble`) kept its own `useState`, so a virtualised row scrolling out cancelled the edit.
**Built:** `lib/drafts.ts` is now a zustand store persisted to `localStorage['composer-drafts']`: `by[key]` = one draft per session (`''` = new chat, `panel:<id>` = note panel) with `text` + `pastes` (Map serialised as entries); `edits[session]` = the in-progress message edit `{turn, text, refs}`. `Composer` renders `text`/`pastes` straight from the store (no local copy), `prefillDraft`/`slash.draftSkill` write to it. `MessageUser` drives `editing` from `edits[session]`; `beginEdit`/`updateEdit`/`endEdit` never touch `by`, so cancel trivially leaves the pre-edit draft intact and an edit survives virtualisation remounts and reload. Empty drafts are not stored. `useSkillDraft` unchanged.
**Tests:** `lib/drafts.test.ts` — draft → edit → update → cancel leaves text/pastes/attachments intact; one draft per session + new chat; `load()` after set restores drafts (Map) and open edit, omits empty; corrupt storage reads as empty.
