**Review of `docs/design/218-whiteboard.md` (rev 1)**

Reviewer: native theuth subagent `wb-review-fable`, 2026-11-24. Read against `main`'s working tree. Not done: no `git` access (branch contents unread), `file://` is disabled in the session browser so the mock was rendered with `page_preview` and measured by script, not looked at as a picture; nothing was built or run on a device.

## Verdict

**Needs revision — the idea is right, three load-bearing mechanisms are not.** The product argument (variants stay put, explicit links, ink is a picture and words carry intent, the agent reads structure) is sound and worth building, and the library facts check out. But (1) the PencilKit overlay as specified cannot route touches the way §6.1 says and its transform sync fights `PKCanvasView`; (2) nothing in the design can rasterise a card, yet snapshot LOD, ink crops, `wb_crop`, PNG/PDF export and the region captions all depend on it, and the caption mechanism is impossible against the 120 sandbox; (3) "a Yjs doc in the document store" buys far less than L215 claims — the store is BlockNote-shaped end to end, there is no offline persistence, and the in-document journal with a per-session cursor is wrong under concurrency and compaction. Separately, §1 as written will silt up with stale ink and near-duplicate cards inside one session, which is the gimmick risk Sky named. All four have concrete fixes below; none needs a rethink of the concept. Recommend rev 2 before P0, and a P1 that puts Pencil ink on the iPad through pointer events so the productivity test runs before any Swift is written.

## Blockers

**B1. The PencilKit overlay cannot work as §6.1 describes (L185–189).**
- **Touch routing.** "`hitTest` returning nil for non-Pencil touches" is not available: `hitTest(_:with:)` receives a point and an event whose touch set is still empty at hit-test time ([SO 67478111](https://stackoverflow.com/questions/67478111/allow-interaction-with-view-behind-depending-on-uitouch-touchtype-using-pointin): `event.allTouches` prints `Set([])`). The one pattern reported to work over a `WKWebView` is: canvas `hitTest` returns nil **always**, and the canvas's `drawingGestureRecognizer` is moved onto the web view with `allowedTouchTypes = [.pencil]` ([SO 66251895](https://stackoverflow.com/questions/66251895/overlaying-pkcanvasview-on-top-of-wkwebview); its author calls it "extremely hacky"). Consequences the doc does not handle: the web view is then the hit view for Pencil touches too, so the page receives `pointerType: "pen"` events for every stroke (cards get dragged, selected, text-selected under the ink) unless the web layer drops them; and the "Pencil starts on a handle = link" exception (L149) becomes a race between a stroke PencilKit has already begun and a web-side decision.
- **Viewport sync.** `PKCanvasView` is a `UIScrollView` whose supported geometry is `contentSize`/`zoomScale`/`contentOffset` ([Apple](https://developer.apple.com/documentation/pencilkit/pkcanvasview): "a scroll view… automatically scales its underlying content"). A `CGAffineTransform` on the view (L187) scales rasterised tiles — blurry committed ink and a wrong-resolution live stroke when zoomed in — and a scroll view has a bounded, non-negative content rect, so "world units" on an infinite canvas need an origin shift nobody specified. The doc's own mitigation (rasterise into PF and hide the overlay on every pinch, L187, L193) means committed ink swaps between two different renderers on every pan/zoom.
- **Stroke identity.** "Eraser and lasso edits map to stroke deletes/updates" (L189) needs to know which stroke changed. `PKStroke.id` is iOS 27.0+ ([Apple](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct/id)); the app targets 17.4 (`crates/desktop/tauri.ios.conf.json#L9-L10`). Before 27 it is a value diff of two drawings, and the pixel eraser splits strokes into new ones.
- **`pk` blob.** `PKStroke` is not `Codable` and has no data representation; only `PKDrawing` has `dataRepresentation()` ([Apple](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct/datarepresentation())). A per-stroke blob is a one-stroke `PKDrawing` each. Also `PKStrokePath` points are B-spline control points, so "points → portable form" must sample with the interpolation API, not copy the array (WWDC20 session 10148; from memory, not re-fetched).
- **Every non-iPad stroke has no `pk`.** Mac/agent/remote strokes must be rebuilt as `PKStroke`s for the overlay, and anchored strokes must be re-transformed natively whenever a card moves. None of that is designed.
- **Fix — make the overlay capture-only.** The `PKCanvasView` holds only the stroke in flight. On stroke end: convert with the viewport captured at stroke begin, write to Yjs, wait for the web layer's "painted" ack, then set `drawing = PKDrawing()`. The web Perfect Freehand layer is the single renderer of committed ink on every client. This deletes viewport sync during gestures (the overlay is empty whenever fingers move), the hide/rasterise swap, the `pk` blob, stroke-identity diffing, native undo, and native rebuild of remote strokes. Costs, to state honestly: the stroke's shape changes slightly at commit (PencilKit → PF), so restrict the picker to inks PF can match with `PKToolPicker(toolItems:)` (iOS 18+, [Apple](https://developer.apple.com/documentation/pencilkit/pktoolpicker/init(toolitems:))) — pen, marker, highlighter, no textured pencil/crayon; and eraser/lasso act on web-side strokes (when the picker's tool is eraser, pass pen events to the web layer and hit-test there). Drop the Pencil-on-handle exception; links are made with a finger or link mode.
- **Also specify:** first responder (the picker needs the canvas as first responder; the web composer's text field needs the web view — who wins when the sheet opens); the palm (ignore finger touches during a stroke and for ~500 ms after, else a resting hand pans the board or toggles chrome); and build the proof before P2: one screen, 100 strokes, pinch, measure.

**B2. No rasteriser exists for cards; crops, snapshot LOD, `wb_crop`, export and region captions rest on one (L99, L163, L198–199, L222, L226).**
- A `page` card is the 120 frame: `sandbox="allow-scripts allow-forms"`, never `allow-same-origin`, opaque origin (`crates/desktop/ui/src/components/chat/HtmlPage.tsx#L1-L5`, `#L169-L173`; `crates/desktop/src/pages.rs#L1-L8`, `#L134`). The host cannot read its pixels or its DOM from JavaScript. So "renders that region with the cards underneath … to a PNG" (L198) and "a cached PNG rendered when it last left live" (L99) have no implementation on any client, and **`elementsFromPoint` through the frame (L199) is impossible**. The only channel into a page is the `postMessage` bridge, which today carries size, open-link and console (`HtmlPage.tsx#L142-L158`; `crates/desktop/ui/src/lib/page-bootstrap.ts#L227-L249`).
- Native capture exists only for web view tiles, not the main webview (`crates/desktop/src/apple_tile.rs#L12-L14`, `#L270-L307`). The relay-served web client has no capture path at all.
- "Server-side from the stored model for headless reads" (L163) and P0's "headless crop renderer" (L222): the engine has no renderer for pages, mermaid or json-render (all client React).
- With B1's overlay as written, ink is not in the webview either, so even a native snapshot misses it. Capture-only ink fixes that: one snapshot has cards and ink.
- **Fix:**
  - Tauri (macOS, iOS): a `takeSnapshot` of a rect of the main `WKWebView` (the binding is already there, `crates/desktop/src/ios_webview.rs#L165-L166`); this is the crop renderer and the snapshot-LOD source.
  - Store each card's last snapshot as a blob beside the document, written by whichever client last had it live; say what a card shows before any snapshot exists (title chip).
  - Headless `wb_crop`: compose from stored snapshots plus vector ink in Rust; a card with no snapshot is a labelled box. Say so; do not promise more.
  - Web client: crops carry ink and card outlines only, flagged in the caption.
  - Region captions: add a bootstrap RPC (`theuth/describe-point {x,y}` → selector, role, label, rect) to `injectBootstrap` (`page-bootstrap.ts#L199-L218`), resolve it **at stroke end** while the card is live, store it on the cluster. Treat the answer as untrusted page text: length cap, quoted, never instructions — it is a prompt-injection channel from agent- or web-authored HTML into the next turn.
  - Move `wb_export(png|pdf)` behind this.

**B3. The substrate claim is wrong in scope; the journal and cursor design is wrong in kind (L69–78, L162, L215, L222).**
- **The store is BlockNote-shaped.** One `Y.XmlFragment` named `document-store` holds every document's blocks (`crates/document/src/lib.rs#L90-L91`). Export is unconditional `helper.markdown` → derived file (`crates/document/src/actor.rs#L744-L766`); the helper is BlockNote + linkedom in a JS thread (`crates/document/src/helper.rs#L1-L6`); search walks block kinds (`crates/document/src/index/mod.rs#L31-L38`); `doc_*` edits are block edits. `DocKind` has no whiteboard and its predicates (`free_standing`, `homed`, `movable`) enumerate kinds (`crates/document/src/meta.rs#L87-L147`). What a `whiteboard` kind inherits: the yrs doc, update log, snapshot, fan-out, relay. What P0 must build and the doc does not list: a kind and binding, a non-markdown export (or none), a yrs-side reader for the maps, an index adapter if "search" is meant, and every `match` on `DocKind`.
- **"Offline … comes with it" (L215) is false.** 59's provider queue is in memory; IndexedDB was deferred to a later step (`docs/design/59-documents.md#L1234`, `#L1673`), and there is no IndexedDB persistence anywhere in `crates/desktop/ui/src` (grep). An iPad on the couch that loses the engine keeps strokes only until the app is evicted. For an ink surface that is data loss; state it or build it.
- **"Undo comes with it" is false.** The only `Y.UndoManager` in the UI belongs to y-prosemirror and already needs a revive hack (`crates/desktop/ui/src/components/editor/reveal.ts#L252-L264`). A whiteboard needs its own manager and origin rules (S3).
- **Journal inside the Yjs doc (L78).** `seq` is assigned by whichever client writes; two clients offline both write `seq 41`. The array grows without bound and syncs to every client forever. The writer is the client, so a journal line is an unauthenticated claim about `actor`. Card ids like `c7` have the same defect: two clients mint `c8` offline and one card silently overwrites the other in the map.
- **Per-session cursor (L162).** After a compaction the agent no longer has the outline the deltas apply to; the cursor says it does. Forks and restarts repeat it.
- **Fix — copy the notebook mechanism, which already solved this.** The engine derives the baseline from the transcript itself: the last `<notebook …>` block resets it, each `<notebook_changes>` applies, a stale notice is ignored (`crates/agent/src/notebook_context.rs#L595-L612`); it injects a manifest after compaction and a changes note otherwise, as an engine-written message after the user's (`crates/agent/src/loop_.rs#L7503-L7513`; `notebook_context.rs#L852-L861`). Do the same: `<whiteboard id>` outline once per epoch, `<whiteboard_changes>` computed by diffing the yrs doc against that baseline. No journal map, no cursor state, correct after compaction, and the provenance is the engine's. Ids: engine- or ULID-minted, with short aliases assigned in the outline render.
- **"Attached exactly like a note" (L19, L73).** A note attachment is a per-message reference with no standing record — "a reference belongs to the message it came with" (`crates/agent/src/attach.rs#L39-L41`, `docs/design/66-attachments.md#L360`). The "attachment record" L73 calls the authority does not exist. What the doc wants (a session that stays bound and receives changes) is the notebook binding (`crates/agent/src/store.rs#L3666`). Pick it explicitly. The marker itself needs `Kind::Whiteboard` in `attach.rs#L49-L76`, the prompt table row (`#L17-L41`), the TS twin and shared fixture (`#L10-L11`), and the tasks tool's kind list (`crates/tasks/src/tools.rs#L168-L170`).
- **Packet lines 3–4 (L175–176) as bracketed body lines.** Parsing stops at the first non-marker line (`attach.rs#L3-L5`, `#L163`), so they are body text: shown in the user's bubble, and a first message with no words titles the session "[whiteboard changes since your last read]" (`attach.rs#L243-L256`). The engine-injected message above removes both.

**B4. §1 will not pass its own productivity test after the third variant — ink and cards only accumulate.**
- **Ink is an instruction, then it is litter.** The three marks in §1.1 step 3 are consumed when mock C lands, but stay on A and B. L36 presents "Sky's ink everywhere" as the end state. By variant 5 every mock is covered in answered marks and the next crop contains old ink the agent must not re-read.
- **Every change is a new card.** A page card's source is one artifact version (`attach.rs#L54-L55`: a `call_id` is one version), so "editing the source updates the card" (L95) cannot happen for pages: "make the header darker" yields card D. Twenty minutes gives fifteen cards for five ideas, and the row no longer reads as "the variants".
- **Fix (one mechanism for both):** a card holds a **version stack** (`versions: [call_id…]`, current on top, a small "v3 of 4" scrubber). `wb_update(card, source)` pushes a version; a new card is for a new direction. Ink anchored to a card belongs to **(card, version)**; ink in a sent batch goes to 30 % once sent and is hidden when the card moves to a new version or the agent marks the batch resolved; "show answered marks" brings it back; a mark can be pinned as a lasting annotation. Fresh ink is always the only full-strength ink on screen.
- Without this, the feature is a prettier scroll-back.

## Should fix

**S1. `tauri-plugin-glass` and design 198 are not on `main`.** No `crates/tauri-plugin-glass`, no `docs/design/198-*.md`, no Swift under `crates/desktop` except the macOS companion (glob); `docs/design/199-notes.md#L431` records the crate as "gone" after a merge of `origin/main`; only unmerged refs remain (`.git/packed-refs#L42-L47`). "Built exactly like `tauri-plugin-glass`" (L185) and "`UIGlassEffect` … 198's material" (L105) cite code this tree does not have. The iOS native layer that does exist is Rust/objc2 UIKit beside Tauri's webview (`crates/desktop/src/ios_webview.rs#L1-L5`). State the dependency (198 merges first) or build the ink overlay in the `ios_webview.rs` style; either way the CSS glass pill is the P1 composer on iPad.

**S2. Prior rulings forbid this canvas and the doc does not amend them.** 208 admitted `@xyflow/react` "for the Attention graph only" and lists the rulings against a second renderer and an infinite canvas as primary surface (`docs/design/208-attention-graph.md#L47`, `#L183`). 218 needs the same explicit amendment section.

**S3. Undo (L167, L120).** "Undo on the owner's device can undo [agent edits]" makes two-finger-tap undo remove something the agent did off-screen instead of the stroke just drawn. Rule: the owner's stack tracks the owner's origin only; an agent turn is one undo unit offered on its reply ("Undo this turn": the turn's inverse ops); edits inside a referenced source (a note, a file) are not board undo. With capture-only ink there is one stack; with B1 as written there are two (PencilKit's and Yjs's).

**S4. Using a live card versus moving the board (L21, L84).** One finger pans and selects; nothing says how Sky taps a mock's tab or scrolls its list — the reason a page card beats a screenshot. Also an iframe under the pointer swallows pan and pinch, so React Flow gestures die over every live card. Specify: every live frame sits under a shield; double-tap (or Enter) "enters" the card (accent border, touches go to the frame), tap outside leaves. Ink never enters.

**S5. Page cards have no viewport.** A phone mock must render at 390×844 and be scaled by the board, but `Card` has only `w,h` (L74) and the 120 frame sizes itself from the page's reported height (`HtmlPage.tsx#L148-L151`). Add `viewport {w,h}` with device presets and `wb_place(..., device)`; comparing variants at different widths is not a comparison.

**S6. Card sources that are session-scoped.** A terminal is `{session, job}` (`crates/desktop/ui/src/components/tiles/open.ts#L71-L79`); a diff is a `DiffSpec` of a session, fetched through the session's owner engine (`open.ts#L108-L111`; `docs/design/212-show-file-and-diff.md#L8`). L88–89 give `job id` and `commit / range / files`. Add the session, say what a card shows when the job or session is gone, and freeze diffs (a working-tree diff changes under the board). State whether a session attached to the board can read an artifact created by another session.

**S7. "Tap → `show_note` tile / web view tile" has nowhere to open (L86, L90).** A tile opens beside a chat pane and returns `null` without a workspace or a laid-out host (`crates/desktop/ui/src/lib/tiles.ts#L58-L69`); there are no tiles in the mobile layout (`tiles.ts#L137-L141`). A full-screen whiteboard has no chat pane. Define the drill-in: an in-board sheet, or the whiteboard is itself a pane host. Likewise `show_whiteboard` needs a kind in `crates/desktop/ui/src/components/tiles/registry.tsx#L43-L61`.

**S8. Crop budget (L198, L232).** At roughly w·h/750 tokens per image, a typical mark (≈500×320 px) is ~200 tokens, but the stated cap — 6 crops up to 1024 px — is ~8 k tokens, over three times one full-screen screenshot (~2.5 k). The check "≤ 25 % of screenshot-every-turn" is met only when marks are few and small. Budget total pixels per message (≈1.2 MP). Tight crops also lose "where on the card": default to **one image per inked card, the whole card with its ink**, plus a zoom only when the ink is small. And say what happens on a model without vision (the harness has a fallback model, `crates/agent/src/rpc_settings.rs#L74-L76`): crops go through it or the composer warns; otherwise ink is silently dropped.

**S9. Ink batches are per board, sends are per session (L77, L197).** A board attached to two sessions has one `batch` counter; ink sent to X is never fresh for Y, or is fresh twice. Derive freshness per session from the same baseline as B3. Also bound it to the viewport: a doodle made ten minutes ago off-screen should not ride the next message by default.

**S10. Anchor rule (L77).** "Bbox centre on a card" mis-anchors an arrow drawn from A to B (centre on empty canvas or on a third card) and a bracket beside a card. Anchor to the card containing most of the stroke's length, else free; and placement/re-layout must move free ink that touches a card with it, or refuse the move.

**S11. Agent presence while it works (L131, L105).** A mock takes a minute. `wb_place` should reserve a labelled placeholder at once (so Sky sees where it lands and placement is solved against the live document at write time), then fill it. `wb_remove` should archive, never delete, and the agent should not move or dim owner-placed cards unasked.

**S12. The reply bubble (L25, Q3).** Fading after 6 s loses answers that arrive while Sky is drawing elsewhere. Keep it until the next send or a dismiss, collapsed to one line after 6 s; a reply about one card pins to that card.

**S13. Chrome summon (L20, L123).** "Tap on empty canvas" fails when a card fills the screen at working zoom, and a palm tap toggles it. Add a grabber on the pill (always visible, so always reachable). The 4 s auto-hide needs an off switch (timing, WCAG 2.2.1).

**S14. React Flow specifics.**
- Its attribution link renders bottom-right (`208-attention-graph.md#L197`) — under the composer. Move it (`attributionPosition`) or decide on hiding.
- `onlyRenderVisibleElements` (used by both existing canvases, e.g. `crates/desktop/ui/src/components/attention/graph/Canvas.tsx#L309`) unmounts off-screen nodes; for a page card that reloads the page and loses its state. Use the doc's own LOD, not that flag.
- There is no shipped Yjs binding: the collaborative example is a Pro example under the xyflow Pro licence ([reactflow.dev](https://reactflow.dev/examples/interaction/collaborative)). Write the (small) binding; do not copy that code. Write positions on drag end, not per frame.
- Frames map to parent/group nodes; say so.

**S15. Naming (L18).** `DocKind::Board` serialises as `"board"` (`meta.rs#L101-L104`, `#L124`), the agent prompt has a `## Boards` block (`crates/document/src/tools.rs#L39-L44`), design 71's files are `71-whiteboard-*.md`, and its skill credits "dev.fast Whiteboard" (`tools.rs#L1313`). The doc itself says "the board" throughout, including text the agent will read. "Put it on the board" will route to `doc_create(kind="board")`. Add a disambiguating sentence to both prompt blocks, never write "board" in `wb_*` descriptions or packet text, and rename or annotate the 71 files.

**S16. Accessibility and phone are one fix.** The canvas is opaque to VoiceOver and keyboard; nothing is specified. The `wb_read` outline is the accessible representation: ship an **Outline view** (frames → cards → links, each openable) with Tab order by frame and row, honour Reduce Motion for settle/spotlight/Follow, and make that the phone's default instead of a pannable canvas (L141).

**S17. Security of live cards.** Up to eight agent-authored pages run scripts at once with no network policy beyond `sandbox` (`pages.rs#L134`); timers cannot be paused short of unmounting. State a CPU/memory budget, and that sharing a whiteboard (Q6) means running another agent's scripts. `added_by` (L74) is client-asserted; do not use it for trust.

## What is good

- The non-negotiables are right and stated as decisions: ink is never interpreted, links are explicit, the agent gets structure plus small pictures, chrome is one pill. These are what keep it from being a Miro clone.
- Cards as references to renderers theuth already has; no new content types.
- Library facts verified on registry.npmjs.org today: `@xyflow/react` 13.0.3 MIT (peer `react >=18`), `perfect-freehand` 1.2.3 MIT ([LICENSE](https://github.com/steveruizok/perfect-freehand/blob/main/LICENSE)), `yjs` 13.6.33 MIT, `tldraw` 5.6.2 "SEE LICENSE IN LICENSE.md" (production licence terms confirmed in its [LICENSE.md](https://github.com/tldraw/tldraw/blob/main/LICENSE.md)), `@excalidraw/excalidraw` 0.18.1 MIT. Rejecting tldraw and Excalidraw is correct for live React cards.
- React Flow fits: DOM nodes are the existing components, handles and edges are built in, the dependency is already in the bundle.
- "Viewport sync is the hard part" names the real risk, and Follow is off by default.
- A measurable productivity test and a token budget in §9, and open questions with defaults.
- Dimmed-with-reason rejected variants: the single best idea in the doc; it is what chat cannot do.

## Suggested changes to the experience

1. **Version stacks, not card sprawl** (B4): refinements update a card in place with a scrubber; only a new direction makes a new card. The row stays "the variants".
2. **Ink has a life** (B4): fresh = full strength; sent = 30 %; answered = hidden with the version it marked; pinned = permanent annotation.
3. **Enter a card to use it** (S4): double-tap makes a mock interactive; everything else is board navigation.
4. **Device-true mocks** (S5): page cards carry a viewport preset; variants are compared at the same size.
5. **Placeholders at once** (S11): the agent reserves the spot before the artifact exists; Sky keeps working and knows where to look.
6. **Replies stay until read** (S12), pinned to the card they are about.
7. **One image per inked card** (S8) so the agent sees where the mark is, within a pixel budget.
8. **Undo by owner; "undo this turn" for the agent** (S3).
9. **Outline view** (S16): the accessible, keyboard and phone representation, and the thing a brief is exported from.
10. **A grabber on the pill** (S13) so the controls are reachable when the screen is all card.
11. **Send from chat**: an artifact card in any normal chat gets "Add to whiteboard…"; today's content reaches the board without the agent.
12. **Phase order**: P1 ships Pencil ink on the iPad through pointer events + Perfect Freehand (pressure, and prediction on 18.2+), so Sky runs the productivity test on the couch before P2. P2 then replaces capture with the native overlay behind the same stroke interface, and is judged on latency alone.
