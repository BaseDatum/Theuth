## Decisions (do not re-litigate; record deviations in the as-built)

### W1 — sidebar Note button, pop-out `?new`, Meetings/Briefs column, portrait paper

- D1 Sidebar order: THEUTH mark · Chat · Talk · **Note** · Meeting (still only when `useCanRecord()`) · Attention · Agents · Library · Desks · Sessions · (footer Settings). Nothing else about the rows changes.
- D2 The Note row is a `SidebarMenuItem` > `SidebarMenuButton asChild` > `<button type="button" aria-label="New note" disabled={pending}>` with the same `h-9 rounded-[10px] px-2.5` classes as its neighbours and no `isActive`. Icon: lucide `StickyNote` (the Notes tab's icon in `lib/nav.ts`) `size-4` inside the same `relative inline-flex` wrapper the Meeting row uses; the badge is a lucide `Plus` at the top-right corner, `className="absolute -top-1 -right-1 size-2.5 text-success" strokeWidth={3.5} aria-hidden` (malachite `--status-success-fg`, the palette's green: #2f5d4a light / #4a8a6e dark; the Meeting dot is `bg-danger`). Label `<span>Note</span>`. Keep the plus a glyph, no disc; tune the offset/size by eye from a 2× screenshot so the plus reads at a glance without hiding the note's folded corner. Export the colour class as one constant (`NOTE_PLUS = 'text-success'`) so a one-token swap to `text-project-nile` (olive) is possible if Sky meant that by "green ochre".
- D3 Click = create then open: `createNote(api, queryClient, queryClient.getQueryData<DocSummary[]>(queryKeys.notes) ?? [])` in a `useMutation`; `onSuccess(n)`: if `!isMobile && canPopout()` → `void openPopout({ kind: 'note', doc: n.id, fresh: true })` and the main window stays where it is; else → `void navigate({ to: '/notes/$id', params: { id: n.id }, search: { new: true } })` (the sidebar sheet already closes itself on the href change, AppSidebar 154–156). `isMobile` is `useSidebar().isMobile`. `onError` → `toast.error(errorText(e))`. Button `disabled={create.isPending}`. Put the mode choice in a pure function `noteOpenMode(isMobile: boolean, canPopout: boolean): 'popout' | 'navigate'` in `lib/popout.ts` (or a new tiny `lib/note-open.ts`) with a vitest.
- D4 `lib/popout.ts`: the note target becomes `{ kind: 'note'; doc: string; fresh?: true }`. `pathOf` appends `?new=true` when `fresh`; `popoutUrl` joins `window=` with `&` whenever the path already carries a `?` (this replaces the `meeting-note` special case, same output for it). `popoutLabel`/`idOf` ignore `fresh` (so focus-if-open keeps working). `popoutTarget(href)` keeps ignoring everything but `window` — add tests: `popoutUrl({kind:'note', doc:'d1', fresh:true}) === '/notes/d1?new=true&window=popout-note-d1'`, `popoutTarget('tauri://localhost/notes/d1?new=true&window=popout-note-d1')` → `{kind:'note', doc:'d1'}`, and the meeting-note URL unchanged. The popped NotePage then sees `?new` (route `notes_.$id.tsx validateSearch`), selects the title and drops the flag — `POPOUT` was read once at boot so losing `?window=` from the address afterwards is harmless (already the case today).
- D5 Meetings and Briefs lists sit in the same centred column as Tools/Secrets/Notes: replace the `min-h-0 flex-1 overflow-y-auto px-6 pb-10` scroller in `MeetingList.tsx` (103) and `BriefSearch.tsx` (92) with `Column` from `components/library/Page.tsx` (export it already exists). The meeting `Row`'s absolute hover actions (`li.relative`) and `pr-32` stay as they are; check at 1600 px and at 390 px that nothing overlaps or clips. The Start form (`StartForm.tsx`, `max-w-2xl`) and the control center are untouched.
- D6 Portrait paper: in `styles.css` give the paper A4 proportions — `html .bn-editor, html .theuth-paper { aspect-ratio: 1 / 1.4142; }` next to the existing rule, and `html [data-paper="dense"] .bn-editor { aspect-ratio: auto; }` (the meeting pane is a box beside a transcript, not a sheet). Keep `flex: 1 0 auto` so a taller canvas is still filled; content longer than the sheet must still grow the sheet (an `aspect-ratio` box with `overflow: visible` has a content-based automatic minimum height — verify, do not assume: screenshot an EMPTY note and a LONG note and log `.bn-editor`'s `getBoundingClientRect()` width/height; expected ratio ≈ 1.41 for the empty one, taller for the long one). Under 768 px the sheet is edge to edge; the ratio may apply there too (a 390 px sheet → ~551 px, then flex fills) — confirm the phone screenshot still looks right. No change to `.bn-container`, the canvas, or Editor.tsx.
- D7 As-built: `docs/design/143-as-built-W1.md` — what landed where (file:line), the two screenshots' facts, the measured paper ratios, deviations. Also commit `docs/design/143-note-flow.md` (this file; copy it verbatim from the brief directory, do not edit it).

### W2 — the note chat is always there, in the popped window too

- D8 `NotePage.tsx`: mount `NoteChat` as `below` whenever `chat.open && !deleted` — popped windows included; keep the Chat action (toggle) in both shells (drop the two `!popped &&` guards at 155 and 161 only; the "Open in new window" action keeps its `!popped` guard).
- D9 `lib/note-chat.ts`: `EMPTY.open` becomes `true` — a note the user never touched opens with the chat under it (CharterDoc already defaults to open). A saved `open: false` still wins (the user closed it). `DEFAULT_HEIGHT` 320 and `MIN_HEIGHT` 160 unchanged.
- D10 `NoteChat.tsx` has two shapes, chosen by `state.session`:
  - **No session yet — the input bar.** A `shrink-0 border-t border-border-subtle bg-background` section with NO fixed height and NO `ResizeHandle`: a 32 px header row with the muted copy `Ask theuth about {about} — the first message starts a chat with it attached` (truncating) and the Close (X) button, then the `Composer compact pinned={doc}` exactly as today. No empty centred paragraph, no 320 px void. Target total height ≈ 90–110 px.
  - **Session — the mini session view.** Exactly today's panel: `ResizeHandle` on top, header (title · Open chat · New chat · Close), `Transcript compact`, `Composer compact`, `height: state.height`. Clamp: desktop as today (`pane − 120`); on `useIsMobile()` cap at 45 % of the pane and start at `min(320, 40 % of the pane)` when the saved height is the default.
  - The switch happens on `onCreated` (first message) — the section grows from the bar into the panel; the Composer remounts on its `key` as today (the draft was already sent).
- D11 In a popped window (`isPopout()`), the header's Open chat (ExternalLink) opens the chat in its own window — `openPopout({ kind: 'chat', session })` — because the popped note has no shell to navigate inside; elsewhere it navigates to `/c/$session` as today. New chat / Close unchanged. `theuth:note-ask` reseeding and `prefillDraft` unchanged.
- D12 CharterDoc keeps working with the same component (it passes `about="this charter"`); the bar shape applies there too. No change to CharterDoc, Composer, Transcript, Editor or routes.
- D13 Put the pure parts in `lib/note-chat.ts` with a vitest: `panelHeight(saved: number, pane: number, mobile: boolean): number` (the clamp rules of D10) and the default-open rule (`EMPTY.open === true`; a saved `{open:false}` wins through `set`'s merge).
- D14 As-built: `docs/design/143-as-built-W2.md` — file:line, screenshot facts (shell note with the input bar; popped note `?window=popout-note-<id>` with the bar; a note with a session showing the mini transcript if one exists on the engine; phone 390 px), deviations.
