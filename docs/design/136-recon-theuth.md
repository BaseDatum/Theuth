**One-screen summary for the dream design**
- Memory = one OKF bundle of 1,598 markdown concepts (87 % written by the automatic harvest), a derived FTS5 index, gix history; ids are free-form (namespaces are convention), `timestamp` is the only temporal field, no read/use counters, no dedupe/merge/expiry/staleness logic, design 41 (self-checking concepts) is unbuilt.
- Learning loops that exist in code: the harvest (every 3rd tool-using root turn + before every compaction, same model as the session, ≤ 8 docs, create/overwrite-by-id only); the desk journal (8 KiB Done/Open/Next/Notes overwritten per episode); the double (126, off by default; learns approval/ask answers, incl. a `double.correction` classifier on every user turn — the only correction detector).
- User-feedback signals in storage: approval deny/timeout, stop (`cancelled`), attention dismissals, `[app …]` presses as user messages, rewind (which deletes the corrected tail). No thumbs/ratings, no "why this went wrong" record, no lessons/retro store, no preferences slot other than `prompt.md`/always-skills and the per-session compaction `## Notes`.
- Routines: markdown files, one reused unattended session cleared (frame + Python runtime) before each fire, `model:` pin, no `effort:`, run cap 1800 s; a routine can read past sessions only one at a time (`session_read`, 64 KiB) and discover them only via `search` (≤ 50 hits/category) — no bulk session/summary reader and no sqlite without `shell()`.
- Skills: flat `.md` with `name/description/always` only; 9 of the 10 live skills are binary-owned and rewritten on every start (a dreaming routine must write under new names); no load counts; the index has no budget.
