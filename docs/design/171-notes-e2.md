## Decisions (design silent or ambiguous)

- **`auto` order is by family, not by directory**: the nearest `.venv` anywhere up the walk beats a nearer uv project (§0 D7 "nearest .venv/venv → uv project → pyenv/conda → python3"). Each family appears once in the menu.
- **Monty Stop = dead kernel.** monty-pool cannot resume a turn dropped mid-flight; Stop, Kill and the 60 s limit drop the checkout (its worker is killed) and the kernel is `dead` — the next run starts fresh ("names reset"). An exception or a type-check failure keeps the kernel.
- **Monty sufficiency without a check-only call** (monty-pool 1.4 has none): the code is fed indented as the body of a never-called `async def` on a throwaway checkout, so the type checker sees it and nothing runs. Known gap: a cell using names defined by an earlier cell of the scope may fail the check (unresolved reference) — such a cell is reported insufficient. The sufficiency checkout waits at most 5 s for a worker (kernels may hold all of them) and answers `None` (unchecked) otherwise.
- **Shim `status` carries an extra `cwd` field** (still nine frame types) so `live_cwd` follows a cell's own `os.chdir`. The shim exits (`os._exit`) when its stdin closes, so it never outlives a killed engine.
- **SystemExit / KeyboardInterrupt in a python cell end the run with an `error`, not the kernel.** Python error runs finish `exit: Code(1)`, ok runs `Code(0)`.
- **`input_reply` value** = the typed bytes minus one trailing `\n` / `\r\n`.
- **Note delivery wake**: the origin gets the full result with `wake = review`; bound notebook chats get `<cell_result run=… name=… exit=… in="note <doc> \"<title>\""></cell_result>` with `wake = false`. The `in=` attribute is inserted into E1's `deliver::cell_result` text before ` pass="` (L2 order); when E1's text is empty (stub) origin delivery is skipped.
- **`doc_read` annotations are synchronous** (the frozen trait): they read an in-memory map filled by `note::deliver` and, on a note's first `doc_read` after start, in the background from `Cells::runs` + `Cells::output`. The very first `doc_read` of a note after an engine restart can lack its run lines.
- **Hub routing is engine-wide**: `HubGate` has no doc parameter (one documents hub per mesh, 69), `route(doc)` ignores `doc`.
