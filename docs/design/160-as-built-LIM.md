### Behaviour as implemented
- Rows (§5.1): `anthropic:api_key` (headers), `anthropic:oauth` (headers + usage endpoint, only with a grant), `openai:oauth` (headers + usage endpoint), `openai:api_key` (headers), `amazon-bedrock` (`unavailable`, "Bedrock exposes no usage meter to theuth; quotas live in AWS Service Quotas"), `cursor` (`unavailable`), `google:api_key` (`unavailable`, only with a Gemini key), `openrouter:api_key` / `opencode-go:api_key` / `deepseek:api_key` (usage endpoint), `<gateway>:gateway` per `providers.yaml` gateway; any other provider that answers with limit headers gets a row lazily (`<provider>:<auth>`), dropped after 30 silent days. Unconfigured rows show as `not_configured` only when their provider had calls in the last 30 days, one per provider, never when another row of that provider is configured.
- Status precedence: `unavailable` → `not_configured` → `error` (hard poll failure) → `limited` (429 / rejected window until its time, or a window ≥ 100 % before its reset, or a source saying calls are refused) → `stale` (restored from disk; a transient poll failure; no observation yet; newest observation older than max(15 min if headers feed the row, 2 × poll cadence)) → `warn` (window ≥ 75 % or bucket ≤ 15 % left) → `ok`. A passed reset reads as full (bucket) / unused (window) until re-observed.
- Merge: key (row, scope, bucket); newest server `date` wins, tie → lower `remaining`; windows replace by id; fresh header data clears a poll failure and the restored flag; a 2xx with no limit headers lifts a 429.
- Persistence: atomic owner-only `<data_dir>/limits/snapshot.json` via `platform::files::write_private`, 2 s after the last change and once at shutdown; loaded at `start`, every row `stale` until refreshed.
- `kick(None)` wakes every poller and the local refresh; `kick(Some(p))` the pollers whose provider is `p`; it also stamps "someone is looking" for the probe. Before `start` (tests, ENG's RPC before boot) `kick` is a no-op and `snapshot` serves whatever headers were observed.
- Probe (`limits.anthropic.probe: true`, default off): one `max_tokens: 1` `claude-haiku-5-5` call with thinking disabled, at most every 10 min, only within 3 min of a kick and when no real Anthropic call refreshed the row for 5 min; its headers go through `observe_headers`.

## Deviations (and why)
1. **Pin in one place, by branch.** The design says "all three Cargo.toml places"; the code has one git line (`Cargo.toml` `[patch.crates-io] genai`, branch-based, `#L418`) — `#L200` is the crates.io version and `#L389` the section header. I switched the branch to `theuth-160-response-headers` (the file's convention: every patch names its fork branch) rather than a bare `rev`. When the fork merges the branch into `main`, flip it back.
2. **`mbx update -p genai` was not used.** It re-resolved unrelated crates (`windows-sys`, `syn` versions) under its own Rust 1.99 resolver; I reverted it and edited the one lock line by hand (verified with `cargo metadata --locked`).
3. **`reqwest` added to `crates/agent/Cargo.toml`** (outside the ownership list, one line + one lock line). The pollers need an HTTP client and the sink's `on_response` signature is reqwest's `StatusCode`/`HeaderMap`; reqwest 0.13.5 is already compiled into `agent` through genai/oauth/web, so no new crate builds. Closer: if ENG also touched `crates/agent/Cargo.toml`, keep both lines.
4. **SSE needed a second tap slot in genai.** In SSE mode `EventSourceStream` owns the `FrameTap` and the inner `WebStream` had none, so calling the hook "in `WebStream::poll_next`" alone would never fire for Anthropic/OpenAI/Responses. Added `WebStream.response_tap`, fed by `EventSourceStream::with_frame_tap`.
5. **Budgets read the ledger through a separate read-only pool**, not `Store`: `Store::pool()` is `#[cfg(test)]` and `store/**` is ENG's. Same SQL measure as `Store::budget_spent` (`returned ?? estimated`, USD). USD caps only (the ledger prices in USD); session-cap spend counts the capped session's own calls since its stamp (enforcement's measure), not its children.
6. **`supervisor` line passes only `rt` and `Auth`.** The data dir, shutdown token and config come from `rt`; no `Store` handle is needed (see 5).
7. **`start` is idempotent** (`started` guard) so a second engine in one test process does not double the pollers on the global hub.
8. **Rows with no data yet are `stale`**, with a message ("no calls observed yet; limits arrive with the next call" / "waiting for the first usage check"); §5.3 lists no status for "configured, never observed".
9. **Clippy gate run with `--no-deps`.** `mbx clippy -p agent --all-targets` stops in `crates/voice/src/history/mod.rs:465` (`clippy::chunks_exact_to_as_chunks`, a lint new in mbx's toolchain; pre-existing, not my file). `--no-deps` lints `agent` alone.
