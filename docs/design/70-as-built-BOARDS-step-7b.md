Design 71 v2 §5 row 7, reader half (7a shipped `codeindex::Locate` and the `code_locate` RPC). Branch `71/step-7b-live-anchors` (worktree of `feature/71-boards`, base `3398f626` = steps 1, 2, 3, 4, 7a). Mechanisms served: M11 (every anchor verified on open and on **Verify**; `Excerpt` chips `changed` / `moved → L88–L101` / `missing`, "show current"; `code:` spans carry the same state), M12 reader side (`N anchors · M stale` in the header chrome, **Verify**, **Ask to refresh** placeholder for step 8), M5 live window (the pane fetches the range when no `Excerpt` covers it), M3 (a link is never a dead end — a pin lands on the current lines, or on the reason there are none). ## What was built

- **`components/board/live.ts`** (new) — the reader's live model. `collectRequests(blocks)`: the batch for a board in document order, deduplicated — every top-level `Excerpt` (`excerpt:<blockId>` key, `start`/`end` from its lines, `symbol`, `text_sha` = SHA-256 of the lines joined by `\n`, computed with `crypto.subtle`), every `code:` link in prose and table cells, every `Graph` node / `Sequence` step `ref` (bare links: no hash, existence only). `createLiveStore(locate)`: one zustand vanilla store per open board — `results: Map<key, Located>`, `error` (a whole-batch failure), `pending`, `verifiedAt`; `ensure(reqs)` locates only the keys not cached and not in flight (open, each Yjs insert, a stray pin), `verify(reqs)` drops the cache and asks for everything (a generation counter drops a batch a Verify superseded). `staleOf`, `chipText` (`changed` · `moved → L88–L101` · `missing`, nothing for `same`), `langOf` (extension → shiki alias), `toLocate`, `LiveContext` / `useLiveStore` / `useLocated(key)`.
- **`BoardReader.tsx`** (additive hunks) — creates the live store per provider with `api.code_locate(root, anchors)`; an effect re-collects on every block change and calls `ensure`. Header chrome (mono 11 px, `.board-chrome`, `data-anchors`/`data-stale`): `N anchors · M stale` (`verifying…` until the first batch lands, `verify failed: <reason>` when the batch errors) · **Verify** (spinning while pending) · **Ask to refresh** (rendered when M > 0, disabled — step 8 wires the M10 message). `AnchorSpan` gains `data-live` and a `key · state` title (dotted decoration; `missing` strikes through). `BoardExcerpt` reads `useLocated(excerptKey(blockId))`, passes the chip into the excerpt header and implements **show current**: the live `text`/`start` replace the quoted ones; `mark` follows a `moved` range by its delta and is dropped on `changed`; "show quoted" swaps back. The excerpt's registered anchor stays the document's range.
- **`SidePane.tsx`** — `LiveChip` (chip + optional toggle) and `LiveWindow`: when no `Excerpt` covers a code anchor, the pane asks the store (`ensure` on demand) and renders `<Excerpt path text={loc.text} start={loc.start} lang={langOf(path)} full>` from the working tree with its chip and a "live from the working tree" line; `missing` → "`<anchor>` is missing: the file, range or symbol is gone." ; batch error → "Could not verify: …"; pending → "Fetching the current lines…"; each with **Open the file** on desktop shells. A bare-path pin renders the whole file capped at 18 rows (Show all). Block anchors get a one-line placeholder.
- **`Excerpt.tsx`** (step 3's file, additive) — `chip?: ReactNode` slot after the header meta, as its header comment reserved for step 7.
- **`crates/document/src/tools.rs`** — `Docs::check_excerpts(doc, markdown)` on the shared `Docs::edit` path (so `doc_insert` and `doc_replace` both go through it, after `check_fences`): `excerpt_anchors(markdown)` collects every `Excerpt` element of every valid `json-render` fence with the 7a hash convention; `frontmatter_root` reads `root:` from the document's markdown (`Markdown{annotate:false}` ask, plain or JSON-quoted); the `CODEINDEX_ACTOR` is looked up and asked `Locate{root, anchors}`; a non-`same` row is refused as `nothing changed: an Excerpt does not quote the tree — read the current lines and retry\njson-render block <n>:\n- /elements/<id>/props/text: not verbatim, current lines are <path> L<a>-L<b>:\n    <numbered lines>` (`moved` adds "`<symbol>` now starts at L<n> (quoted from L<m>)"; `missing` says so). Fails open: no `Excerpt` in the edit, no codeindex actor, no `root:` (not a board), or a `Locate` error (root not a git top-level, path escape) → the edit proceeds as before. `crates/document/Cargo.toml` gains `codeindex` (no cycle: codeindex depends on runtime/tools only).

## Deviations

1. **The reader's cache is keyed by anchor, not `(path, mtime)`.** §2.5/§6.1 say "cached per `(path, mtime)`"; the reader has no mtime source — `Located` (7a) carries none and learning one would be another RPC. What the cache is for (no re-fetch on every Yjs update, no duplicate in-flight requests) is met by caching per anchor key for the life of the open board: a Yjs insert locates only the anchors it added, **Verify** drops the cache. An mtime in `Located` would only let Verify skip unchanged files; the batch is one local call, so it was not added.
2. **`Excerpt`s are keyed `excerpt:<blockId>`, links and refs by the anchor string.** Two excerpts of the same range with different text have different hashes and therefore different states; a `code:` link to the same range has no hash and its state is existence only (7a deviation 1), so the two cannot share a key.
3. **`code:` spans show only `missing` in practice.** "`code:` links and unit `ref`s show the same states on hover" (M11) — a link has no embedded text, so 7a answers `same` for any range that still exists; the span's `data-live`/title carry whatever comes back (`changed` would show if a link ever carried a hash). Diagram units are step 5's; their `ref`s are in the batch and the count, and `useLocated(formatAnchor(ref))` is ready for the unit hover.
4. **"Ask to refresh" is a disabled placeholder** (the task names step 8 for the M10 message); it renders only when M > 0 so the chrome stays `N anchors · M stale · Verify` on a clean board.
5. **Header chrome lives inside `BoardReader`** (a mono bar above the column) rather than in `NotePage`'s shared bar where step 4 put Edit — the task assigns the counts to `BoardReader` as an additive hunk, and `board.css` is step 6's file, so the bar is styled with utility classes.
6. **The insert-time check fails open** on missing infrastructure. The design's refusal is for a real mismatch; a board whose `root` is not a git top-level (step 2 does not check that at `doc_create`), a disabled codeindex, or a `Markdown` read failure must not block writing. `Locate` errors are logged at `debug` on target `document`.
7. **Root comes from the document's markdown, not `DocMeta`.** Step 2 put `root` only in the frontmatter block; the check asks `Markdown{annotate:false}` for the whole document and parses the header — one helper round trip per edit that contains an `Excerpt`, nothing for other edits.
8. **The refusal echoes the current lines numbered**, up to the excerpt's own size (≤ 120 lines): the model needs them to write the corrected block without another read round, which is the budget step 2 ran out of.
9. **The live window lights no rows**: the whole window is the anchor. `full` (uncapped) for a ranged anchor, capped for a bare path.

## Findings for later steps

1. **The fixture board's excerpts were not verbatim against this tree** (all three `changed` on first open: `start` off by one/two against `fences.rs`, as step 2 found in run 1). The scratch repo was rewritten so the quoted rows match before the Done-when sequence; the fixture itself is unchanged (step 4's tests read its ranges). Step 9's `board-check` will flag the same rows on a real board; with this step's insert-time check the model can no longer land them.
2. **7a `moved` starts at the definition's `line_start`, not at the excerpt's start.** An excerpt that begins with a doc comment (`/// …` then `fn opening`) reports `moved → L77–L90` after two lines are inserted above, where the same-sized window would be L76–L89: the index's `Definition` starts at the `fn` line. One-line drift; a fix belongs in `locate.rs` (shift by the old definition start, which the request would have to carry) — recorded, not changed here.
3. **Excerpt headers wrap when the chip is long** at narrow pane widths (`moved → L92–L98 show current` beside `path · symbol · lang`); the meta span truncates, so nothing overflows, but step 6's typography pass may want the chip on its own line under 480 px.
