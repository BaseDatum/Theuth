## Defects found live, each with its fix and test (commits `140 P: …`)

2. **A study never fires when the dir watcher is blind.** `sort-a2` sat `running` for 15 min with `list_schedules` empty. `schedule::Reconcile` is public; `schedule_file::write` asks it after the atomic write. Test `schedule::fire_tests::reconcile_ask_reads_a_file_written_after_load`. (18aa28a0)
3. **Race exposed by 2: fire before `running`.** The fire followed the write while the study was `preparing`; the confinement resolver answered "toolset gone", the loop ended and deleted the file. `prepare` sets `started_at` + `running` before writing. Test `study_is_running_before_its_schedule_file_exists`. (6c19e4f9)
4. **The study session edited the user's checkout.** File tools resolve relative paths against the engine's process cwd (the frame header's "Working directory"); the schedule's `cwd:` seats only the shell. With relative scope paths in the brief, haiku read `sorter.py` (ENOENT), listed `.`, found `repo-sort/` and edited `/tmp/140/repo-sort/sorter.py` (user repo `M sorter.py`, twice) while the worktree stayed unchanged: empty `candidate.patch`, "no gain", then "duplicate of #1" ×3. Tests `run_refuses_an_unchanged_worktree_by_name`, brief fixture needle. Repo restored (`git checkout -- sorter.py`), manifest identical. (1d93d7ba)
5. **Reviewer vs Restore forever.** A user-restored keep was re-reviewed and could be reverted again by the same SUSPICIOUS. A restored keep is now `Flagged` (needs-eyes), never reverted. Test extended `review_reverts_a_suspicious_keep_and_restore_queues_it`. (1d93d7ba)
