## What was built

- **`lib/board-ask.ts`** (new, pure) — the §2.9 grammar. `BoardRef = {doc, block, at}` with `BoardAt` = `code {path, lines|null}` | `node {id}` | `step {n}` | `stale {count}`; `formatHeader` / `parseHeader` (`^\[board (\S+)((?: · [^\]]+)*)\]$`, fields optional, each at most once; a field that is not `block`, `node`, `step`, `stale` or a root-relative path makes the line body text); `composeAsk(ref, quote, question)` → header, `> ` quote lines (capped at `QUOTE_MAX` = 4 KiB, the question is not), a blank line, the question; `parseAsk(body)` inverts it. `step <n>` is **1-based** (the reader's `n. from → to` numbering). `board-ask.test.ts`: eight header shapes round-trip, eight non-headers stay body text, a full message round-trips through `attach.compose`/`parse` behind the pinned marker, the cap.

## Deviations

1. **Ask prefills; it never sends.** §2.9 says "running session → the steer path (`AppHost.tsx:430-452` pattern)". The composer already takes that path on send (`Composer.tsx` steers while `running`), and M10's check is "composer holds …" — a question needs the user's words after the quote, so the reader types and sends. Nothing is sent without a send.
2. **`askBoard` reuses NoteChat's "Ask theuth…" path rather than `prefillDraft(session, text, [noteRef], panel)`.** The panel composer is `pinned` to the board (`NotePage` builds the `AttachRef` with the live title and list meta), so passing the ref again would attach it twice. The `boardRef` is used only in a popped window, where there is no panel: a bound session gets `prefillDraft(session, text, [boardRef])` + `openPopout({kind:'chat', session})`; unbound → the new-chat draft + a toast. Not smoked (a popout needs the desktop shell).
3. **`step <n>` is 1-based.** The design leaves it open; the reader numbers steps `1.` … in `aria-label` and the tour badge, and the agent reads `steps[n-1]`. The skill text says `step <n>` without a base; the round-trip test pins the format, the as-built pins the base.
4. **A board create is a run breaker in `foldRuns`** (`ToolRunCard.tsx`, shared). Under TOOL-COLLAPSE every `doc_create` sits inside a run of many `doc_insert`s and would be hidden while drawing — exactly when §2.11 / M7 want the card ("drawing · Map … Open lands on the board while How it works is still arriving"). `show`/`app` cards keep folding as before.
5. **The card's section comes from the transcript, not the document.** `drawingSection` scans the session's `doc_insert`/`doc_replace` args for the last `## `; §2.8's badge reads the last inserted block's section from the document. Same answer for the agent's own inserts, no `doc_subscribe` per card. Python-wrapped calls count (child rows carry parsed `args`).
6. **The card binds only when no `note-chat` entry exists.** §2.11 says "the `note-chat` binding on create/open"; binding on every mount would undo a user's "New chat". `EMPTY` merges on `set`, so a cleared binding leaves an entry with `session: null` and the card leaves it alone. Read-only (inspection) transcripts do not bind.
7. **Boards in the notes list = two `doc_list` calls.** The RPC filters by exact `DocKind`; `doc_list(null)` would return knowledge/artifacts/charters too. One query key, so `DocumentChanged` invalidation is unchanged. `AttachPicker` and the composer's note browser see boards too (they are notes, 71 §2.1).
8. **The floating Ask covers selections in `.board-column` only.** Excerpts in the side pane and tour stops (portals) have no floating button; the pane has **Ask about this** and a pinned unit/row is what the tour shows.
9. **Prose selections carry the block, not a `path`.** A sentence with one `code:` span inside could add `path:a-b`; the block id is what `doc_read`/`doc_replace` need and the agent reads the span from the block. Not added.
10. **Excerpt rows quote the block's text, not the DOM selection.** A native selection across two gutter rows drags the gutter numbers along on some engines; the quote is `excerptLines(text).slice(a-start, b-start+1)` for the rows the selection's ends sit in, so a partial first/last line still quotes whole rows.
11. **Header chrome clears the TOC pill on narrow shells** (`padding-left` under ≤ 720 px). Not in the design; with a 44 px pill the `16 anchors` text sat under it at 390.

## Findings for later steps

1. **The scratch engine needs the documents helper beside `t`** (`target/debug/theuth-documents-59.5`; `just documents-helper` writes it to `packages/documents/dist/`). Without it `doc_read` fails with `documents helper not found` — the first agent turn of this smoke fell through to `knowledge_get`/`artifact_read` and answered from the code alone. Step 9's runs must copy it (or `just desktop` does).
2. **`doc_read(blocks=[…])` without `format="markdown"` returns the whole outline** — `blocks` only filters the markdown form (the tool's own description says so). The prompt block's `doc_read(doc, blocks=[…])` therefore costs the agent one extra call; either the outline form should honour `blocks` (small Rust change in `document`) or the prompt should say `format="markdown"`.
3. **`doc_*` are python-only tools in this config** ("`doc_read` is not a direct tool here; call it from python"): the agent's first direct `doc_read`/`read_file` attempts failed before it switched. The board skill's examples are python already; the prompt block's `doc_read(doc, blocks=[…])` reads as a direct call.
4. **The M13 in-place edit (`doc_replace` of the owning block) was not driven end to end here**: on this scratch tree the three excerpts are stale, so 7b's insert-time check would refuse a re-issued `Excerpt` until the agent re-reads the lines — the right behaviour, and step 9's steering prompts are where it is measured.
5. **The NoteChat panel at 390 takes its remembered 320 px** under the sheet pane; two bottom surfaces stack. A coarse-pointer rule capping the panel to the keyboard-free half would help, in NoteChat's file.
