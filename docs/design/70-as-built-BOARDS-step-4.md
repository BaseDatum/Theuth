# 70 — as-built BOARDS step 4: `BoardReader` with the anchor model and the split pane

Design 71 v2 §5 row 4. Branch `71/step-4-board-reader` (worktree of `feature/71-boards`, base `7697d23f` = steps 1, 2, 3, 7a). Mechanisms served: M3 (a `code:` link is never a dead end — it opens the side pane), M4 (one anchor model; hover / focus / click light the span, the covering `Excerpt` and its rows together), M5 (the code beside the sentence: 560 px pane, drag 360–920, bottom sheet ≤ 1080), M8 columns (860 / 720 / 1120, 1000 while the pane is open), M14 consumed (the units' `data-node`/`data-step` markup renders; wiring is step 5). ## What was built

- **`components/board/anchors.ts`** — the §2.3 model in code. `overlaps(a, b)` (same path and intersecting ranges; a bare path covers the file; blocks by id), `contains(outer, inner)` (an `Excerpt` is the code window for what its range contains), `intersect(a, range)` (the rows to light), `formatAnchor`, `activeOf(state)` = `tour ? tour.units[index] : pinned?.anchor ?? hover`. One zustand store per open board (`createAnchorStore`, handed down by `AnchorContext`): `{hover, pinned: {anchor, by, claim}, tour, registry}`; `register(id, {anchor, kind, blockId})` on mount. `useAnchored(entry, {claim, coarse})` wires an element: `data-anchor`, `data-anchor-id`, `data-anchor-active`, `data-anchor-pinned`, `mouseenter` → 120 ms → `hover` (fine pointer only), `focus` → `hover` at once, click / Enter / Space → `pinned`.
- **`components/board/blocks.ts`** — the headless read: `yXmlFragmentToBlocks(BlockNoteEditor.create({schema, links}), provider.doc.getXmlFragment(FRAGMENT))` over the shared `@theuth/documents/schema`; no ProseMirror view is ever mounted. `useBlocks(provider)` re-reads on `observeDeep`, so an insert is one new element on the page. `classifyCode(codeBlock)` → `excerpt` (root `Excerpt`) | `diagram` (`Graph`/`Sequence`: wide column) | `surface` (other catalog roots, prose width) | `invalid` | `mermaid` | `code`; `excerptsOf(blocks)`, `codeAnchor(href)`, `excerptAnchor(props)`, `rootOf(blocks)` (frontmatter `root:`), `plainText(content)` (the claim line).
- **`components/board/BoardReader.tsx`** — `[column | resizer | pane]` grid (`minmax(0,1fr) 0 0` → `minmax(0,1fr) 10px var(--board-pane-width)` when pinned), the block mapping of §2.2 (headings → `h1–h3` with the block id, paragraph/quote/lists (consecutive list items fold into one `ul`/`ol`, checklist boxes read-only) → `.board-prose`, table → mono 13 px, divider → rule, `json-render` → catalog or `BoardExcerpt`, mermaid → `MermaidFence`, other code → `pre`, frontmatter → nothing, unknown → `FenceFallback`). `code:` links → `AnchorSpan` (`<a href="code:…" tabIndex=0>`, kind `span`, claim = the paragraph's text); other links open outside (`openUrl`, `window.open` fallback). `BoardExcerpt` wraps the step-3 `Excerpt`: the frame is the keyboard target (`tabIndex=0`, Enter pins the whole range, focus lights it), rows are pointer targets by delegation (`closest('[data-line]')` → `path#L<n>`), lit rows = `intersect(active, range)`. `Escape` while pinned unpins and focuses `[data-anchor-id=by]`. Pane width persisted in `localStorage` (`board-pane-width`), clamped 360–920 by the 10 px resizer.

- **`components/board/fixtures/surface-fence-parsing.md`** — step 2's run-1 board (`agqoakh4mb4udakblwyre2shfa`), with four `code:` links added to "How it works" so the fixture carries every case the Done-when names (a ranged link covered by an excerpt, one that spills past every excerpt, a single-line link).

## Deviations

1. **The route switch lives in `NotePage`'s `Note`, not in `routes/notes_.$id.tsx`.** The kind is only known once `doc_open` returns `meta`, which arrives through the provider `Note` already owns; the route file has no meta. Same observable behaviour (`/notes/<id>` opens the reader for a board), and the bar (title, rename, snapshots, undo-agent, popout, delete, chat) is shared instead of rebuilt. The §2.2 header chrome list (`N anchors · M stale`, Verify, Tour, Ask, Copy link, ⋯) belongs to steps 5–8; only **Edit/Read** and a `board` chip were added.
2. **`code:` links did not survive `doc_insert` before this step** — the helper's BlockNote (0.54.2) drops any href whose scheme is not in tiptap's allowlist at markdown → HTML → blocks import, and the editor drops them again on paste/render. Fixed at the shared schema (`links.isValidLink`), consumed by the helper and `Editor.tsx` — three additive hunks outside `components/board/**`. Without it the reader would have had nothing to anchor (step 2's run-1 board carries its one `code:` link only in the derived `note.md`; its Yjs document holds plain text). `isAllowedUri` is declared in BlockNote's types but not exported at runtime, so the default list is inlined.
3. **`Excerpt.tsx` gained two additive props** (`active`, `full`) instead of DOM-poking rows from the wrapper: the rows are React-rendered, so lighting them in the same commit as the span needs the prop; `full` is the pane's `heightMode: content`. Step 3's row markup is otherwise untouched; row *events* are delegated from the board wrapper as its header comment intended.
4. **The bare-path code window.** §2.3 says a bare `path` "overlaps everything in that file" and an excerpt is the window "for every anchor its range contains"; a whole file is contained by nothing. The pane shows the file's **first** excerpt for a bare-path pin (a Map node's `ref` will be a bare path in step 5), and lights only excerpt frames, not rows.
5. **"Open the file" is `openPath(root/path)`** through the opener plugin (already in the capability set), desktop shells only; in a browser the placeholder is text. Step 7b replaces the placeholder with the live window.
6. **Sheet geometry**: the ≤ 1080 px sheet is `position: absolute` inside `.board-shell` (`position: relative`), not `fixed` — `container-type` no longer implies layout containment, so a fixed sheet covered the sidebar. The `ArtifactPanel` radix `Sheet` was not reused: it is modal (overlay, focus trap) and the pane must leave the prose interactive.
7. **Consecutive list-item blocks fold into one `ul`/`ol`**; the design's mapping table lists "lists" without saying how BlockNote's sibling items become one list. Checklist boxes are read-only.
8. **Nested `Excerpt`s** (inside a `Stack`/`Card`) render through the catalog without anchors; only a top-level `Excerpt` root is a code window. The skill inserts each `Excerpt` as its own block, so no fixture exercises the nested case.
9. **Typography beyond geometry left to step 6** (`--font-serif` on `.board-prose`, the chrome register test); h1/h2/h3 sizes and margins from §2.7 are applied because the reader is unreadable without a heading scale. Diagram units stay inert (`highlight`/`onSelect` are step 5's).
10. **`connecting` renders nothing** (an empty div) for every note until `meta` lands — previously an empty, non-editable BlockNote mounted for those few hundred milliseconds; for a board it would have flipped to the reader.

## Findings for later steps

- **Step 2's boards hold no `code:` links.** Runs 1–4 counted `code:` links from the derived markdown; the Yjs documents flattened them (deviation 2). Step 9's `board-check` must read `doc_read(format="markdown")` *after* this fix lands in the engine the boards are drawn with; the helper binary beside an older `t` still drops them.
- **The frontmatter block in Edit mode shows the knowledge form** ("Untitled · type?") for a board's `root:`-only header — `FrontmatterBlock.tsx`'s read view assumes the knowledge fields. Step 6 or 8 could give a board frontmatter a one-line `root` view.
- **The excerpt-row → link case needs a real single-line link.** The fixture's original `[opening()](code:…#L83)` sits inside a backtick run and is not a link in the document; the added `[search happens linearly](code:…#L38)` is the single-line case the row click exercises (row 38 → that span).
- **Hover clears eagerly.** Moving from span A to span B with the same anchor clears the light on A's `mouseleave` and re-lights after B's 120 ms; a shared "leave grace" would remove the blink if it shows up in step 5's unit hover.
- `useNotes()` (`doc_list('note')`) still lists no boards, so the fixture board is reachable only by URL or from the session's `theuth://notes/<id>`; step 8 owns the list glyph.
