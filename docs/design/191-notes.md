### Deviations from the doc
1. **When the import runs** (D2 "at the first reconcile after `contacts_ready`"): inside the first post-latch reconcile, before it stages (`crates/a2a/src/lib.rs`, `Ctx::http_file`), and again whenever `peers.yaml` holds contact or export entries (a crash before the rewrite, a hand edit). Running it after the flip would let that same first pass revoke the bindings the import keeps (`revoke_peer_bindings_except` sees no record for them). The import is still post-latch and pre-flip, so it cannot admit anything early.
2. **Removed records** do not go into the deny set but into `Staged.removed` (`crates/a2a/src/config.rs`): the gate never admits them as a contact, but they may pair again inside an open window (D2 "a re-pair therefore works"). A member removed through its root takes the root's removal time. A **live duplicate** whose anchors were all removed with another record and paired no later than that removal (made before the removal synced, or a re-pair under clock skew) is quarantined "removed on another machine": no route (its binding is revoked), its endpoints in `removed`, so a ceremony can re-pair it (`pin` then writes a fresh binding, since the old one is revoked here). Quarantined and blocked records' endpoints are in `deny`, refused before anything else, a ceremony included.
3. **Quarantine is per merge group**, not per record, in two kinds (`crates/a2a/src/contacts/records.rs`, `stage_records`). *Unsound* (a malformed alias, binding or anchor, a binding revoked here, no anchor, one of our machines, a loop or a chain past 16 hops): its binding falls out of the routes and is revoked. *Lag or a convergence in flight* (a pointer into a record this machine lacks, two unmerged groups sharing an anchor, an alias taken until the rename lands): its binding is **held** (`CommitPeerConfig.hold`: stepped out of its alias, kept live, unrouted, its inboxes capped and unmarked full), so the record comes back whole once the rows arrive. Both deny all the group's anchors. A grant naming an export row this machine lacks is skipped, never a quarantine.
4. **Alias collision**: until the reconcile's rename (`<alias>-2`) lands, the newer record is quarantined ("its name is taken by another contact (renaming)", held); the older keeps the alias.
5. **An answer without a grant** (a `first_contact` entry for an export the contact is not granted) is a grant row with `granted` NULL: it abstains on the grant and takes part in the strictest answer. `contact_update` decides "newly granted" (which starts on Always allow) from the group's rows, not from this machine's routes, so an Ask first on an export whose chat is not here is kept.
6. **Exports this machine cannot publish** (the chat's session not replicated here yet, or not native) are left out of this machine's routes with their grants; no contact is quarantined for it. `a2a_exports` lists such a chat export paused `"chat not on this machine"`; a deleted chat's export is tombstoned only by its home (`exports()`), since lag and deletion look alike elsewhere.
7. **One principal per exported chat** stays (§6.3): staging skips the later contact's grant (key order, the same on every machine); `contact_update` refuses it up front as before.
8. **Inbox marker** is set on every admission by `handle_inbox` (`ContactInbox.export_id`, from the export's id): in P1 the admitting machine is the inbox's home. The import marks inboxes through the file's names; every pass then marks every remaining local `inbox = 1` row of a session this machine owns (an export no longer known by name keeps its name in the marker: its presence is what caps a moved inbox).
9. **Before the latch** the records are staged for display only (`Live::display`: listed in `contact_list`, no binding, no route); **before `contacts_ready` the gate refuses everything**, a ceremony included, since the deny set is whole only after the first pass (`iroh_gate(…, ready)`).
10. **`Ctx::edit` is gone**: `peers.yaml` holds HTTP peers only and is hand-edited. A file that cannot be read or parsed, a failed import or a failed rewrite is a problem in status, never a reason to skip the tables (`Ctx::pass` returns `Ok(Some(problem))`; the HTTP peers then stay the last good ones). An HTTP peer that does not stage falls back to the last good HTTP peers (`reconcile_now`). A contact RPC answers `Err` only when the tables did not reconcile (its write is in; the next tick retries). A failed pass waits `RETRY_PAUSE` (20 s) before an unprompted retry.
11. **The reconcile's hash** is the hash of the snapshot the pass staged, never a later read: a write landing mid-pass is reconciled at the next tick (and the commit's own binding changes cause one extra idempotent pass).
12. **`gc_contact_threads`** forgets threads by staleness only: `contact_threads` replicates, so deleting the threads of a binding revoked here would delete them mesh-wide.
13. Not in P1, as the doc phases them: `paired_on`/`machines` on `Contact` (the column is written), `ContactPatch.modes`/`cap` and `Contact.cap` (W-40, P3), release of a hold on a replicated Allow (P3), votes (P2).

## P2 ROSTERS

Built on `feat/191-p2` from the P1 head a4915b97 with the final design merged (a7871515). Paths are at the P2 head.

### What landed
- **Migration `crates/agent/migrations/0060_contact_rosters.sql`**: `contact_rosters` (replicated; `id` = `<contact>|<chain>|<version>|<signer>`, immutable rows: `contact`, `chain`, `version`, `signer`, `hash`, `roster` = the signed copy as JSON), `contact_roster_heads` (replicated; `id` = `<record>|<machine>`, written only by that machine), `contact_roster_local` (local, never attached: `record` PK, `chain`, `version`, `hash`, `roster`, `history`), `contact_endpoints.pinned_by`, and `DROP TABLE contact_votes` (P1 had created it). `RECORD_TABLES` (`crates/agent/src/store/contacts.rs`) loses `contact_votes` and gains the two replicated tables.
- **`SESSIONS_WIRE_SCHEMA` stays 59**: no session-log table changes in P2 (the rule at `crates/agent/src/store.rs` near the constant is about the tables `capture::ATTACHED` replicates; the record replica is separate and a peer lacking a column skips it). The snapshot test is unchanged and passes.
- **Reconcile trigger** (D2): `Records.rosters` hashes as `(count, max hlc)` (`Rosters`' own `Hash`), the heads and local rows by content; a `Net.peers_gen` bump runs the pass too (`Ctx::tick`).
- **Pure rules** (`crates/a2a/src/contacts/rosters.rs`): the copy, its domain-separated signature (`theuth/a2a/roster/v1\n` + JCS of `{chain, version, members, signer}`), its content hash (SHA-256 of the JCS of `{chain, version, members}`), verification (1..256 sorted unique endpoint ids, the signer among them, the signature), the cap (`membership`: pins first, then oldest `added_ms`), `decide` (sign v+1, co-sign, or nothing; the 16-copy cap), `hops` (the greedy hop chain from a pin), `keep` (hop chains plus the last 8, recomputed before pruning), `carried` (the last 8 versions, each content once, ≤ 16 signatures: previous-version members, then pins, then the rest, oldest first), `path_answer` (≤ 64 hops, ≤ 256 KiB, `next` = `from=` continuation), and the contact side's `base`, `advance` (jump and replay; the equal-version switch from the roster before the head or the head's own, capped by a flip budget), `verify_path`, `adopt`, `compare`, `conflict`.
- **Our side** (`crates/a2a/src/contacts/members.rs`): `Ctx::sign_rosters` runs at the end of every reconcile pass once `contacts_ready` is set, for every live record (members of live groups; never a removed or broken one): sign at latest + 1 when the membership differs from the latest content, co-sign it when equal and not yet signed, then prune (rows of removed records go too). `Ctx::push_rosters` posts the members/v1 payload on `NOTICE_PATH` to every admitted machine of every live contact after a signing, and once to a contact newly admitted (at boot, after a bootstrap); 2 s doubling to 10 min, superseded per endpoint by a newer push. The card (`Ctx::contact_card`) carries the extension for the caller's own group; it is omitted while no chain exists (the JWS vector test is unchanged). `GET ROSTER_PATH?chain&pin&from[&to&head]` (`Ctx::roster_path`) serves the caller's own record from one of that record's pins (401 a stranger, 404 another record, 403 a pin that is not one). The inflation alert (`Ctx::observe`): a request `to` above our latest, or `head` a hash we never signed at a version we still hold, twice at least 5 s apart, raises `Contact.problem` and an Attention item `contact_roster:<record>`; nothing is denied.
- **The contact side**: `Ctx::ingest` (a card's extension, a push body) moves each record of the group the serving member is admitted for by the accept rule, or bases a record nothing has based yet on its pin's copy; `Ctx::roster_round` (every `ROUND` = 60 s from the 2 s tick, and by tests) refreshes the cards of every admitted member older than the TTL, bootstraps a record based elsewhere but not here (proof paths from the pins, dialled by the pins and the heads rows' untrusted hints, ≥ 2 sources when reachable, the highest verified head, adopted only when a live machine's head or history holds it or two sources agree; none at all: its verified path), and compares a record's head with every live machine's (`Seen`): merely behind for 3 rounds fetches a path; diverging fetches one path (`to` = the other head) and sets `conflict` only when it reached that version and the other hash is none of its contents there; the flag is re-written every round while it holds, cleared once heads agree.
- **Staging and the gate** (`crates/a2a/src/contacts/records.rs`): `admit_of` per record (`Pins` while nothing is based, `Roster` from this machine's own state, `Unverified` when a heads row or a local row exists but no readable state here, `Disagree` while a live machine's flag holds); a group admits the union of its records' rosters, never its pins once based; `Unverified`/`Disagree` quarantine the group (held binding, anchors denied, problem shown). Attribution, the merge proof (in `reconcile_writes`) and the deny lift as in D1/D2. `ContactFacts.eids` is the admitted set (dialled order: a pin still admitted first); refused endpoints never stay in it.
- **Dialing**: `PeerClient::contact` and `IrohTransport` take the contact's admitted members (updated in place on each pass: no epoch change, followers stay); a member that refuses before admitting anything (unreachable, 401, `NOT_OWNER`) moves the call to the next; any answer after admission is final.
- **`NOT_OWNER`** (S4): `full_return` (`~return` into a session another machine owns), `admit_send` (a contact's message into an inbox session owned elsewhere, before anything is accepted) and `full_intake` (guard) answer `NOT_OWNER` (-32013). A chat export owned elsewhere keeps W-40 until P3 deletes it.
- **Ceremonies** wait for `contacts_ready` at `contact_window` and `contact_pair` too ("waiting for your other machines").

### Deviations from the doc
1. **`contact_endpoints.pinned_by`** (0060): our side's pins of a record are `paired_on` plus every endpoint row's `pinned_by` (the machine whose ceremony wrote it). A second ceremony from another of our machines into the same record overwrites the row's `pinned_by`, so an older pin can be forgotten; a proof-path request from a forgotten pin is refused (403), and the contact tries another pin or machine.
2. **`contact_roster_heads` has two more columns**: `chain` (the chain the machine follows: an untrusted hint, like `members`, so a fresh machine knows which chain to ask a path of; a path is still verified from the pins, and our side serves only the caller's own records) and `at_ms` (when the row was written). "A flag not refreshed within 3 refreshes expires" is `now - at_ms > 3 × ROUND` (180 s); a machine re-writes its own row every round while its flag holds. ponytail: wall clocks across the contact's machines; a round counter in the row if skew ever matters.
3. **The 16-copy cap is per content of a version**, not per version; storage and the card use the same signature order (previous-version members, pins, the rest, oldest first), so a qualifying hop copy is never pruned first. A member ranked after 16 signers of a content does not co-sign it (no sign/prune loop).
4. **Dial order**: the member that last answered first, then one with a live connection, then the rest (the doc: live connection first). Until P3 names the machine in task ids, a follower's `GetTask` must reach the machine holding its task.
5. **`NOT_OWNER` for chats**: W-40 still forwards a chat export's message to its owner (its tests stay); P2's refusal covers the inbox session and the return route, as D3 lists them (`full_return`, `full_intake`, `deliver_full`'s path through `admit_send`).
6. **Pushes**: after a signing to all; else once per process to each contact not pushed to (boot, newly admitted after a bootstrap), so a co-signature written while the record was still unverified here is delivered. The notice is answered 204 at once; the body is read (≤ 192 KiB, 413 above) and ingested off the request.
7. **The inflation alert**: "synced" is `contacts_ready`; the replica exposes no count of parked rows, so that half is not checked (alert only, never a deny). "Two refreshes" is two observations at least 5 s apart. The alert lives in memory until restart; its Attention item uses the `Node` kind (no new kind, no TS change).
8. **Refresh round**: the contact side's round runs every 60 s (`ROUND` = `OFFERS_TTL`) from the 2 s tick; "still behind after 3 refreshes" is 3 rounds; a round's card refreshes fetch only members whose last card is older than the TTL.
9. **Bootstrap hints** come from every heads row of the record (a retired machine's included: they are only dial and chain hints); adoption compares with live machines' heads only, as the doc says.
10. **Dial hints** (D3): `Staged.addrs` is this machine's whole `contact_addrs`, so a roster member or a record still bootstrapping is dialled with its last direct addresses. A LAN-only mesh with relay `none` and discovery off has no address for a contact machine it never connected to: it cannot fetch a proof path and the record stays denied until it has one (fail-closed). The in-process tests and the rig give the address the way a relay or discovery would.
11. **A removed record's listed endpoints** (for the deny lift) are those of this machine's own state of that record; a machine that never had a state knows only its pins.
12. **Base among several chains** applies at the first base only; a machine already based never switches to a lower chain that appears later.
13. **The proof-path route also takes `to` and `head`**: the divergence fetch asks up to the other head's version, and that is where the inflation alert looks.
14. **`Records.me`** is set to this engine's mesh id by the a2a plugin (`Ctx::records`; the same value in production, and tests' stores have none).

### Fail-closed, path by path
| Path | How it stays closed |
|---|---|
| A roster that does not verify | Every copy is verified alone (`Copy::verify`): ≤ 256 sorted unique endpoint ids, the signer among them, the Ed25519 signature over the domain prefix; anything else is dropped before any rule sees it. Our own rows that do not verify are neither carried nor kept (pruned). |
| Another record's chain, a signer outside the roster, an equal or lower version | `advance` takes only the state's chain, only versions above the head, only copies a member of the current roster signed; the equal-version switch only a higher hash from the roster before the head or the head's own, at most one flip per record per round. |
| A version gap | Jump only to the lowest version a current member signed; with no such copy the state stays where it is (no timestamps, no skew rule). |
| A fresh machine that cannot bootstrap | Any heads row of the record (a retired machine's too) or an unreadable local row means "based": `Unverified`, the group quarantined (held binding, anchors denied), `Contact.problem` "cannot verify this contact's machines". The pins are never admitted again. A verified path is adopted only when a live machine's head or history holds it, or two of our machines agree; with live peers and none of these, nothing. |
| A divergence | `conflict` set only by a verified path that reached the other head's version without its hash; while any live machine's flag holds (re-written every round, expiring after 3), every machine denies the group (`Disagree`) with the problem. A path that stops short never flags. |
| A quarantined or removed record | Quarantined: no route, anchors denied, no push to it, no card for it. Removed: never signed (its rows deleted), never carried or pushed, its roster rows and heads rows ignored; its pins and listed endpoints stay in `removed` until a newer ceremony pins one in a live record, and then only what that record's own roster lists (its newer pins while it has none) is lifted. |
| A proof path from an unverified source | The serving machine is untrusted: the path is verified from the record's pins alone (`verify_path`), every copy on its own; dial and chain hints never count. Our side serves a path only to an admitted caller, of its own record, from a pin of that record. |
| A push or card with bad signatures | A card must verify against the endpoint that served it; then each carried copy is verified on its own; a push body that does not parse, or copies that do not verify, change nothing. A body over 192 KiB is refused (413). |
| An endpoint two contacts list | Admitted only for the one that pinned it or holds a copy it signed; neither (or both): for none. A refused endpoint is dropped from the dial list. |
| A rogue member of ours | The stated limit: the contact follows its roster; the remedy (remove it, remove the contact on both sides, pair fresh) gives a new record and chain; the old record's endpoints stay refused. A stale contact machine that took a rogue roster is flagged by the others once our chain reaches that version. |
| An inflated chain | Alert only (`Contact.problem` and Attention on our side); nothing is denied, so a partition cannot lock out an honest contact. |
| A contact message into a session owned elsewhere | `NOT_OWNER` before anything is accepted (inbox, return route); the client tries the next member; an answer after admission is never sent again elsewhere. |
| Signing from a stale view | Nothing is signed before `contacts_ready`; a ceremony is refused before it too. |
