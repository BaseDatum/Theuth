Built on `feat/191-p1` from main 10f651e1 (design at review round 2, f568f2bc). Paths are at the P1 head.

### What landed
- **Migration `crates/agent/migrations/0059_mesh_contacts.sql`**: `contacts`, `contact_endpoints`, `contact_votes`, `contact_grants`, `a2a_exports` (replicated: one key column, `hlc TEXT`, no NOT NULL/UNIQUE/CHECK/FK), `contact_addrs` (local), `sessions.contact_inbox`, and `contact_threads` rebuilt with `id` = `<binding>|<context_id>` (rows copied, index kept).
- **Attach**: `Store::replicate_records` (`crates/agent/src/store.rs:911-922`) attaches `contacts::RECORD_TABLES` beside `projects` and `cost_owners`.
- **`SESSIONS_WIRE_SCHEMA` = 59** (`crates/agent/src/store.rs:674`); the snapshot test (`sessions_wire_schema_tracks_the_replicated_columns`) takes `contact_inbox`.
- **Record store**: `crates/agent/src/store/contacts.rs` (`Records`, `content_hash`, column-only `RecordWrite`s, `contact_addrs`, the inbox marker and its backfill); agent messages `ContactRecords`, `WriteContactRecords`, `BackfillContactInboxes`, `SetContactAddrs` (`crates/agent/src/communication/network.rs`).
- **Staging, merge, import**: pure functions in `crates/a2a/src/contacts/records.rs` (`stage_records`, `reconcile_writes`, `import`, `analyze`).
- **Reconcile**: `Ctx::reload_as` (`crates/a2a/src/lib.rs`) is the one pass; `Ctx::tick` runs it on the 2 s tick when the file stamp, the records' content hash, or the first post-latch pass asks; every contact RPC runs it right after its write (`Ctx::commit_records` → `reconcile_now`).
- **Replicated binding id**: `bind_peer_in(…, Some(id))` (`crates/agent/src/store/communication.rs:904-995`) takes the record's id, renames a live row in place, refuses a revoked one (`BINDING_REVOKED`); `peer_bindings.endpoint` = `contact:<record id>` (`contact_record_endpoint`).

The a2a plugin holds the same `Arc` (`Ctx.ready`) and sets it at the end of the first successful pass after `mesh::synced()`; the agent only reads its `Agents.contacts_ready` copy, never asks the a2a actor.
- **Contact RPCs** (`crates/a2a/src/contacts.rs`): `contact_list`, `contact_update`, `contact_remove`, `a2a_exports`, `a2a_export_put`, `a2a_export_remove`, `contact_first_answer`, and the ceremony's pin write the tables; a write to a merged contact writes every record of its group that has a row (else the root).

### Deviations from the doc
1. **When the import runs** (D2 "at the first reconcile after `contacts_ready`"): inside the first post-latch reconcile, before it stages (`crates/a2a/src/lib.rs`, `Ctx::http_file`), and again whenever `peers.yaml` holds contact or export entries (a crash before the rewrite, a hand edit). Running it after the flip would let that same first pass revoke the bindings the import keeps (`revoke_peer_bindings_except` sees no record for them). The import is still post-latch and pre-flip, so it cannot admit anything early.
2. **Removed records** do not go into the deny set but into `Staged.removed` (`crates/a2a/src/config.rs`): the gate never admits them as a contact, but they may pair again inside an open window (D2 "a re-pair therefore works"). A member removed through its root takes the root's removal time. A **live duplicate** whose anchors were all removed with another record and paired no later than that removal (made before the removal synced, or a re-pair under clock skew) is quarantined "removed on another machine": no route (its binding is revoked), its endpoints in `removed`, so a ceremony can re-pair it (`pin` then writes a fresh binding, since the old one is revoked here). Quarantined and blocked records' endpoints are in `deny`, refused before anything else, a ceremony included.
3. **Quarantine is per merge group**, not per record, in two kinds (`crates/a2a/src/contacts/records.rs`, `stage_records`). *Unsound* (a malformed alias, binding or anchor, a binding revoked here, no anchor, one of our machines, a loop or a chain past 16 hops): its binding falls out of the routes and is revoked. *Lag or a convergence in flight* (a pointer into a record this machine lacks, two unmerged groups sharing an anchor, an alias taken until the rename lands): its binding is **held** (`CommitPeerConfig.hold`: stepped out of its alias, kept live, unrouted, its inboxes capped and unmarked full), so the record comes back whole once the rows arrive. Both deny all the group's anchors. A grant naming an export row this machine lacks is skipped, never a quarantine.
4. **Alias collision**: until the reconcile's rename (`<alias>-2`) lands, the newer record is quarantined ("its name is taken by another contact (renaming)", held); the older keeps the alias.
5. **An answer without a grant** (a `first_contact` entry for an export the contact is not granted) is a grant row with `granted` NULL: it abstains on the grant and takes part in the strictest answer. `contact_update` decides "newly granted" (which starts on Always allow) from the group's rows, not from this machine's routes, so an Ask first on an export whose chat is not here is kept.
6. **Exports this machine cannot publish** (the chat's session not replicated here yet, or not native) are left out of this machine's routes with their grants; no contact is quarantined for it. `a2a_exports` lists such a chat export paused `"chat not on this machine"`; a deleted chat's export is tombstoned only by its home (`exports()`), since lag and deletion look alike elsewhere.
7. **One principal per exported chat** stays (§6.3): staging skips the later contact's grant (key order, the same on every machine); `contact_update` refuses it up front as before.
8. **Inbox marker** is set on every admission by `handle_inbox` (`ContactInbox.export_id`, from the export's id): in P1 the admitting machine is the inbox's home. The import marks inboxes through the file's names; every pass then marks every remaining local `inbox = 1` row of a session this machine owns (an export no longer known by name keeps its name in the marker: its presence is what caps a moved inbox).
9. **Before the latch** the records are staged for display only (`Live::display`: listed in `contact_list`, no binding, no route); **before `contacts_ready` the gate refuses everything**, a ceremony included, since the deny set is whole only after the first pass (`iroh_gate(…, ready)`).
10. **`Ctx::edit` is gone**: `peers.yaml` holds HTTP peers only and is hand-edited. A file that cannot be read or parsed, a failed import or a failed rewrite is a problem in status, never a reason to skip the tables (`Ctx::pass` returns `Ok(Some(problem))`; the HTTP peers then stay the last good ones). An HTTP peer that does not stage falls back to the last good HTTP peers (`reconcile_now`). A contact RPC answers `Err` only when the tables did not reconcile (its write is in; the next tick retries). A failed pass waits `RETRY_PAUSE` (20 s) before an unprompted retry.
11. **The reconcile's hash** is the hash of the snapshot the pass staged, never a later read: a write landing mid-pass is reconciled at the next tick (and the commit's own binding changes cause one extra idempotent pass).
12. **`gc_contact_threads`** forgets threads by staleness only: `contact_threads` replicates, so deleting the threads of a binding revoked here would delete them mesh-wide.
13. Not in P1, as the doc phases them: `paired_on`/`machines` on `Contact` (the column is written), `ContactPatch.modes`/`cap` and `Contact.cap` (W-40, P3), release of a hold on a replicated Allow (P3), votes (P2).

## P2 ROSTERS

Built on `feat/191-p2` from the P1 head a4915b97 with the final design merged (a7871515). Paths are at the P2 head.

### What landed
- **Migration `crates/agent/migrations/0060_contact_rosters.sql`**: `contact_rosters` (replicated; `id` = `<contact>|<chain>|<version>|<signer>`, immutable rows: `contact`, `chain`, `version`, `signer`, `hash`, `roster` = the signed copy as JSON), `contact_roster_heads` (replicated; `id` = `<record>|<machine>`, written only by that machine), `contact_roster_local` (local, never attached: `record` PK, `chain`, `version`, `hash`, `roster`, `history`), `contact_endpoints.pinned_by`, and `DROP TABLE contact_votes` (P1 had created it). `RECORD_TABLES` (`crates/agent/src/store/contacts.rs`) loses `contact_votes` and gains the two replicated tables.
- **`SESSIONS_WIRE_SCHEMA` stays 59**: no session-log table changes in P2 (the rule at `crates/agent/src/store.rs` near the constant is about the tables `capture::ATTACHED` replicates; the record replica is separate and a peer lacking a column skips it). The snapshot test is unchanged and passes.
- **Reconcile trigger** (D2): `Records.rosters` hashes as `(count, max hlc)` plus the row ids (`Rosters`' own `Hash`; the ids since review r1: a prune plus an older row's late arrival can keep both stamp values), the heads and local rows by content; a `Net.peers_gen` bump runs the pass too (`Ctx::tick`).
- **Pure rules** (`crates/a2a/src/contacts/rosters.rs`): the copy, its domain-separated signature (`theuth/a2a/roster/v1\n` + JCS of `{chain, version, members, signer}`), its content hash (SHA-256 of the JCS of `{chain, version, members}`), verification (1..256 sorted unique endpoint ids, the signer among them, the signature), the cap (`membership`: pins first, then oldest `added_ms`), `decide` (sign v+1, co-sign, or nothing; the 16-copy cap), `hops` (the greedy hop chain from a pin), `keep` (hop chains plus the last 8, recomputed before pruning), `carried` (the last 8 versions, each content once, ≤ 16 signatures: previous-version members, then pins, then the rest, oldest first), `path_answer` (≤ 64 hops, ≤ 256 KiB, `next` = `from=` continuation), and the contact side's `base`, `advance` (jump and replay; the equal-version switch from the roster before the head or the head's own, capped by a flip budget), `verify_path`, `adopt`, `compare`, `conflict`.
- **Our side** (`crates/a2a/src/contacts/members.rs`): `Ctx::sign_rosters` runs at the end of every reconcile pass once `contacts_ready` is set, for every live record (members of live groups; never a removed or broken one): sign at latest + 1 when the membership differs from the latest content, co-sign it when equal and not yet signed, then prune (rows of removed records go too). `Ctx::push_rosters` posts the members/v1 payload on `NOTICE_PATH` to every admitted machine of every live contact after a signing, and once to a contact newly admitted (at boot, after a bootstrap); 2 s doubling to 10 min, superseded per endpoint by a newer push. The card (`Ctx::contact_card`) carries the extension for the caller's own group; it is omitted while no chain exists (the JWS vector test is unchanged). `GET ROSTER_PATH?chain&pin&from[&to&head]` (`Ctx::roster_path`) serves the caller's own record from one of that record's pins (401 a stranger, 404 another record, 403 a pin that is not one). The inflation alert (`Ctx::observe`): a request `to` above our latest, or `head` a hash we never signed at a version we still hold, twice at least 5 s apart, raises `Contact.problem` and an Attention item `contact_roster:<record>`; nothing is denied.
- **The contact side**: `Ctx::ingest` (a card's extension, a push body) moves each record of the group the serving member is admitted for by the accept rule, or bases a record nothing has based yet on its pin's copy; `Ctx::roster_round` (every `ROUND` = 60 s from the 2 s tick, and by tests) refreshes the cards of every admitted member older than the TTL, bootstraps a record based elsewhere but not here (proof paths from the pins, dialled by the pins and the heads rows' untrusted hints, ≥ 2 sources when reachable, the highest verified head, adopted only when a live machine's head or history holds it or two sources agree; none at all: its verified path), and compares a record's head with every live machine's (`Seen`): merely behind for 3 rounds fetches a path; diverging fetches one path (`to` = the other head) and sets `conflict` only when it reached that version and the other hash is none of its contents there. Since review r1 (MUST 2): the flag starts from the machine's own row and clears only when every live machine's head equals its own after the round's advance (a failed or short fetch keeps it); each round first stamps the machine's own standing flags (`at_ms` only) and ages the others' flags by its own round count, before and outside any fetch; the fetches run outside `roster_lock`, and their writes land under it only for a record whose state did not move meanwhile; a round due while another round's fetches run only stamps and ages.
- **Staging and the gate** (`crates/a2a/src/contacts/records.rs`): `admit_of` per record (`Pins` while nothing is based, `Roster` from this machine's own state, `Unverified` when a heads row or a local row exists but no readable state here, `Disagree` while a live machine's flag holds); a group admits the union of its records' rosters, never its pins once based; `Unverified`/`Disagree` quarantine the group (held binding, anchors denied, problem shown). Attribution, the merge proof (in `reconcile_writes`) and the deny lift as in D1/D2. `ContactFacts.eids` is the admitted set (dialled order: a pin still admitted first); refused endpoints never stay in it.
- **Dialing** (D3, "gate and dialing over the group's union"): `PeerClient::contact` and `IrohTransport` take the contact's admitted members (updated in place on each pass: no epoch change, followers stay), so a session on any of our machines dials the contact with its own key and the contact admits it from our roster (rig case 2). A member that refuses before admitting anything (unreachable, 401, 404, `not owner`) moves the call to the next, each member tried at most once; any answer after admission is final. When every member refuses and one said `not owner`, that error is returned to the caller (never "contact unreachable" nor an internal error, the call's deadline included); the sender records it as refused.
- **`NOT_OWNER`** (S4), with a strict owner predicate (design reviews, 21:46 and 22:45):
  - **Wire form**: the A2A JSON-RPC error `{"code": -32030, "message": "not owner"}` (`agent::communication::network::NOT_OWNER_CODE`, `NOT_OWNER_TEXT`). -32030 collides with nothing: theuth uses -32000..-32002, -32010..-32014 and -32020 (`rpc/src/api.rs`, `rpc/src/forward.rs`, `rpc/src/cells.rs`, `agent/src/communication/mesh.rs`), A2A -32001..-32009 and the JSON-RPC reserved range. The mesh-internal `NOT_OWNER` (-32013) is not reused.
  - **Predicate** (`Store::owned_here`, `Agents::contact_owned`): the session's row exists and reads here AND its owner is this engine. An unknown row, an unreadable row, another engine's, and an empty owner on a mesh engine are not ours. A lone engine (no mesh id, so `me` is `''`) owns its own `''` rows: that is the only reading of empty as "ours". None of today's lenient helpers is reused (`session_owner`'s `Ok(None)`, `here`'s "empty is local", `admit_forwarded`'s `_ => Ok(())`, `start_or_queue`'s insert-only `inboxes` short-circuit).
  - **Where**: in the a2a router's strict session resolve (`Handler::owned`, `SendMessage` and the streaming send, right after the export resolves its session, through the agent's `ContactOwned`), before any task exists, as the JSON-RPC error. As a backstop in `deliver_full` (the task fails `not owner`, never delivered), `full_intake`, and `full_return` (`~return` at a non-owner returns the error directly), and in `admit_send`. Through the router no contact message reaches W-40 any more: a chat owned by another of our machines is `not owner` there and the client reaches the owner. W-40's code stays until P3 deletes it (its agent-level test still drives it through `admit_send`).
  - **The inbox resolve** (P2 review SHOULD 1): the agent export's resolve (`handle_inbox`, which every contact request of an agent export runs first: the sends, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, the push-config and extended-card calls) looks up the contact's inbox and checks the strict predicate before anything else: before an inbox is opened (`new_root`), its row marked (`mark_a2a_inbox`, the marker) or its limits installed (`run_full_inbox`). An inbox here whose session is not strictly this engine's is `not owner` to a send and TASK_NOT_FOUND (`task not found: task`) to every other call, as an unknown task reads; only a send opens an inbox (`ContactInbox.send`, set by the router), so a read from a contact with no inbox here is TASK_NOT_FOUND too.
  - **A member's gate refusal** (P2 review SHOULD 4): a gate that refuses closes the connection with the reason `mesh::net::A2A_NOT_A_CONTACT` (`not a contact`), which can reach the client only after the request left (`send_request`). `reach.rs` (`gate_refused`) reads that close in the error chain as refused before admission (`UNSUPPORTED_OPERATION` "not a contact there"), so the next member is tried, each once, and `not owner` wins when all refuse. Any other broken stream after the request left stays an unknown outcome, never sent elsewhere. ponytail: a stream already admitted on a connection the gate then closes (the contact removed or blocked mid-request, or a second stream refused on the same connection) reads as refused too and may be sent to another member, which by then refuses it as well once the removal reached it; a per-stream refusal (an HTTP 401 instead of the close) if that ever matters.
  - **Not in P2** (as the doc's phases say): `a2a_forward` (forwarding to the owner), return-route forwarding, `contact_holds` and Attention everywhere, the W-40 deletion, the `INBOX_STAYS` lift.
- **Ceremonies** wait for `contacts_ready` at `contact_window` and `contact_pair` too ("waiting for your other machines").

### Deviations from the doc
1. **`contact_endpoints.pinned_by`** (0060): our side's pins of a record are `paired_on` plus every endpoint row's `pinned_by`. Since review r1 (SHOULD 6) the column holds a JSON array, a set: a ceremony writes the row's set plus its own machine (`records::pinned_by_with`), so a third ceremony into the same endpoint forgets neither earlier machine (their hop chains kept, their proof paths served). A bare id (P2's first builds) reads as one machine; a value that does not parse names none (that pin's paths refused, 403). 0060 is unchanged (the column stays TEXT; editing it would break the checksum of databases that already applied it). ponytail: two of our machines pinning the same endpoint within one replication delay can still lose one (column last-writer-wins); a row per pinner if that ever happens.
2. **`contact_roster_heads` has two more columns**: `chain` (the chain the machine follows: an untrusted hint, like `members`, so a fresh machine knows which chain to ask a path of; a path is still verified from the pins, and our side serves only the caller's own records) and `at_ms`. Since review r1 (MUST 2), "a flag not refreshed within 3 refreshes expires" counts rounds, never wall clocks: each machine remembers, per other machine's flagged row, the `at_ms` value it last saw (an opaque stamp, NULL included) and the round of its own when it changed; unchanged for 3 of its own rounds, the flag expires (`records::age_flags`; an expiry restages). A flag first seen (at boot too) counts as fresh, so a NULL or skewed stamp never lifts a deny early. A machine's own flag never expires on it.
3. **The 16-copy cap is per content of a version**, not per version; storage and the card use the same signature order (previous-version members, pins, the rest, oldest first), so a qualifying hop copy is never pruned first. A member ranked after 16 signers of a content does not co-sign it (no sign/prune loop).
4. **Dial order**: the member that last answered first, then one with a live connection, then the rest (the doc: live connection first). Until P3 names the machine in task ids, a follower's `GetTask` must reach the machine holding its task.
5. **`NOT_OWNER` for chats**: the router refuses a contact's message into a chat another of our machines owns (the client reaches the owner); W-40's code is left for P3 to delete, reachable only from its agent-level test.
6. **Pushes**: after a signing to all; else once per process to each contact not pushed to (boot, newly admitted after a bootstrap), so a co-signature written while the record was still unverified here is delivered. The body is read (≤ 192 KiB, 413 above) and, since review r1 (SHOULD 3), ingested inline under the contact's permit before the 204, so no ingest outlives the request or queues past the contact's rate and concurrency bounds. The sender trims a body to 192 KiB before posting (deviation 19).
7. **The inflation alert**: "synced" is `contacts_ready`; the replica exposes no count of parked rows, so that half is not checked (alert only, never a deny). "Two refreshes" is two observations at least 5 s apart. The alert lives in memory until restart; its Attention item uses the `Node` kind (no new kind, no TS change).
8. **Refresh round**: the contact side's round runs every 60 s (`ROUND` = `OFFERS_TTL`) from the 2 s tick; "still behind after 3 refreshes" is 3 rounds; a round's card refreshes fetch only members whose last card is older than the TTL.
9. **Bootstrap hints** come from every heads row of the record (a retired machine's included: they are only dial and chain hints); adoption compares with live machines' heads only, as the doc says.
10. **Dial hints** (D3): `Staged.addrs` is this machine's whole `contact_addrs`, so a roster member or a record still bootstrapping is dialled with its last direct addresses. A LAN-only mesh with relay `none` and discovery off has no address for a contact machine it never connected to: it cannot fetch a proof path and the record stays denied until it has one (fail-closed). The in-process tests and the rig give the address the way a relay or discovery would.
11. **A removed record's listed endpoints** (for the deny lift) are those of this machine's own state of that record; a machine that never had a state knows only its pins.
12. **Base among several chains** applies at the first base only; a machine already based never switches to a lower chain that appears later.
13. **The proof-path route also takes `to` and `head`**: the divergence fetch asks up to the other head's version, and that is where the inflation alert looks.
14. **`Records.me`** is set to this engine's mesh id by the a2a plugin (`Ctx::records`; the same value in production, and tests' stores have none).
15. **Landing**: P1 lands on main together with P2, not before it: P1 alone has no owner check on the contact paths.
16. **Attribution priority**: an endpoint two unmerged groups admit goes to the one that pinned it; only when none pinned it, to the one holding a copy it signed; two of either kind (or none), and neither admits it. The doc's "pinned it or holds a copy signed by Y" allowed both at once, and the rig showed a deadlock: a second ceremony's record (pinning n2) and the first record (holding n2's co-signature) both qualified, so n2 was admitted for neither and the second record could never base.
17. **Pair again through a roster member**: a ceremony with an endpoint a live contact's current roster admits (not only its anchors) adds a pin to that record (`pin()`), never a second record, and the ceremony no longer flags it as a lookalike "new key" (D1 "a ceremony with an endpoint that already belongs to a live record only adds a pin to it").
18. **Signing damper** (review r1, SHOULD 7): `decide` signs latest + 1 only when this machine's membership differs from the latest content AND from the content this machine last signed. Two of our machines with persistently different `members()` then sign one version each and stop (the latest is whoever signed last), never alternating versions pushed to every contact; a machine whose view changes signs again. If this machine's last copy was pruned (8 newer versions), it may sign once more.
19. **Payload size** (review r1, NITs): `rosters::trim` cuts a members/v1 payload to a byte budget, the carried order reversed: the oldest version entries first (from the chain carrying the most; each keeps its latest), then the last-ranked signatures (each content keeps its first), then whole chains from the end. The card trims to `CARD_BYTES_MAX` less its own bytes and 4 KiB (the extension wrapper and the JWS); a push to 192 KiB. Two 256-member chains of 8 versions (~290 KB) otherwise exceeded both. A contact missing a cut version asks a proof path.
20. **Version bound** (review r1, NIT): a copy above `VERSION_MAX` (`i64::MAX`) does not verify and our side never signs past it; the version columns saturate rather than wrap (a saturated row would disagree with its copy and be ignored).
21. **A roster drop closes connections** (review r1, SHOULD 2, D2 step 6): a pass that keeps a contact but drops one of its endpoints (rig 4a) closes that endpoint's `theuth/a2a/1` connections and streams (`close_a2a`), unless another live contact still admits it (and it is neither denied nor removed). Held first messages are released only when the whole contact ends, as before.

### Fail-closed, path by path
| Path | How it stays closed |
|---|---|
| A roster that does not verify | Every copy is verified alone (`Copy::verify`): ≤ 256 sorted unique endpoint ids, the signer among them, the Ed25519 signature over the domain prefix; anything else is dropped before any rule sees it. Our own rows that do not verify are neither carried nor kept (pruned). |
| Another record's chain, a signer outside the roster, an equal or lower version | `advance` takes only the state's chain, only versions above the head, only copies a member of the current roster signed; the equal-version switch only a higher hash from the roster before the head or the head's own, at most one flip per record per round. |
| A version gap | Jump only to the lowest version a current member signed; with no such copy the state stays where it is (no timestamps, no skew rule). |
| A fresh machine that cannot bootstrap | Any heads row of the record (a retired machine's too) or an unreadable local row means "based": `Unverified`, the group quarantined (held binding, anchors denied), `Contact.problem` "cannot verify this contact's machines". The pins are never admitted again. A verified path is adopted only when a live machine's head or history holds it, or two of our machines agree; with live peers and none of these, nothing. |
| A divergence | `conflict` set only by a verified path that reached the other head's version without its hash; while any live machine's flag holds, every machine denies the group (`Disagree`) with the problem. A path that stops short never flags. A standing flag clears only when every live machine's head equals this machine's (a failed, short or slow fetch keeps it); it is stamped at the start of every round, outside the lock and any fetch, and another machine's flag expires only after 3 of this machine's own rounds without a new stamp (no clock comparison; a NULL or skewed stamp is fresh when first seen). |
| A quarantined or removed record | Quarantined: no route, anchors denied, no push to it, no card for it. Removed: never signed (its rows deleted), never carried or pushed, its roster rows and heads rows ignored; its pins and listed endpoints stay in `removed` until a newer ceremony pins one in a live record, and then only what that record's own roster lists (its newer pins while it has none) is lifted. |
| A proof path from an unverified source | The serving machine is untrusted: the path is verified from the record's pins alone (`verify_path`), every copy on its own; dial and chain hints never count. Our side serves a path only to an admitted caller, of its own record, from a pin of that record. |
| A push or card with bad signatures | A card must verify against the endpoint that served it; then each carried copy is verified on its own; a push body that does not parse, or copies that do not verify, change nothing. A body over 192 KiB is refused (413). The ingest runs under the contact's permit before the answer (no unbounded queue on `roster_lock`). A copy above `VERSION_MAX` does not verify. |
| An endpoint two contacts list | Admitted only for the one that pinned it, else the one holding a copy it signed; two of a kind (or none): for none. A refused endpoint is dropped from the dial list. |
| A rogue member of ours | The stated limit: the contact follows its roster; the remedy (remove it, remove the contact on both sides, pair fresh) gives a new record and chain; the old record's endpoints stay refused. A stale contact machine that took a rogue roster is flagged by the others once our chain reaches that version. |
| An inflated chain | Alert only (`Contact.problem` and Attention on our side); nothing is denied, so a partition cannot lock out an honest contact. |
| A contact message into a session not strictly owned here | `not owner` (-32030: an unknown or unreadable row, an empty owner on a mesh engine, another engine's) at the router before any task exists, and again in `deliver_full`, `full_intake`, `full_return` and `admit_send`; a drained inbox still in `inboxes` never short-circuits it; the client tries each other member once and returns `not owner` if all refuse; an answer after admission is never sent again elsewhere. |
| A contact's request resolving an agent inbox at a non-owner | The strict predicate first in `handle_inbox`, before `new_root`, `mark_a2a_inbox`, the marker and `run_full_inbox`: `not owner` to a send, TASK_NOT_FOUND to a read, no inbox opened for a read, no cap lifted, nothing marked; a store error reading the inbox is an internal error (fixed text). |
| A member's gate closing the connection `not a contact` | Read as refused before admission only from that exact close reason in the error chain; the next member is tried once, `not owner` wins if any said it; every other failure after the request left is final (unknown outcome). |
| An unreadable session row on a contact path | Never read as ours: `admit_principal` refuses first (`internal error`, fixed text, never the store's), `full_intake` and `deliver_full` refuse `not owner` on their own, the router's `ContactOwned` and the inbox resolve answer `not owner`. |
| Signing from a stale view | Nothing is signed before `contacts_ready`; a ceremony is refused before it too. |
| An endpoint a roster dropped | Its open connections and streams close in the pass that drops it (unless another live contact admits it); the gate refuses it from the same swap. |
| A pin row whose `pinned_by` does not read | It names no machine: proof paths from it are refused (403); nothing is served on its behalf. |
| An oversized payload | Our side trims a card or push to the reader's cap (oldest versions first) rather than sending one the reader refuses; the reader's caps (256 KiB card, 192 KiB notice) are unchanged. |

- **Offline owner** (answer 4): not connected (`mesh::call`'s `peers()` check), the 10 s deadline, `OWNER_UNREACHABLE`, a malformed line: the contact hears `UNSUPPORTED_OPERATION` "the chat's machine is offline" (`ContactRefusal::OwnerOffline`). Nothing is queued.
- **Task ids name their machine** (`network::task_id`): `<first 16 hex of the engine id>-<uuidv7>`; a lone engine mints a bare UUIDv7. An id without a 16-hex prefix or this machine's own is served here; a prefix naming no paired machine is offline.
- **Not accepted yet** (D3): a member whose gate refused this machine closes the connection "not a contact"; `reach::gate_refused` reads that close reason from the failing call's own error (the dial, the handshake or the request; never another connection, so a stale closed one cannot turn a timeout into this), `IrohTransport` treats it as a refusal (another member is tried; nothing was served), and when every member refused that way the receipt is `failed` with "<contact> has not accepted this machine yet" (`reach::NOT_ACCEPTED`, mapped in `client.rs`). The converse (the owner's gate does not list the caller: 401 there) is the transient `UNSUPPORTED_OPERATION` "the chat's machine has not accepted this machine of yours yet; try again shortly" (`forward::NOT_ACCEPTED_THERE`).
- **Inbox home and adopt by marker** (D4; `Agents::inbox_of`, the first thing `handle_inbox` runs after the `contacts_ready` check, before any side effect). The a2a plugin stages `AgentExport.home` from `a2a_exports.home` as `InboxHome::Here` (this machine), `At(<engine id>)` (a live machine of the mesh) or `Left` (any other, or none: listed paused "its machine left the mesh", `PAUSED_HOME_LEFT`), and passes it in `ContactInbox.home`. Order: two or more sessions carrying the marker → `export unavailable … has more than one inbox`, logged with the ids, both capped here; the local row's strict owner check (owned here → it; owned elsewhere → `not owner` naming the owner; empty owner → plain `not owner`); the marker (owned here → adopt: `create_a2a_context`, then the usual `mark_a2a_inbox` with the live persona, which must be known; elsewhere → `not owner` naming it); none → `Here` mints, `At` answers `not owner` naming the home, `Left` refuses. Only a send gets past a refusal or opens/adopts; a read is TASK_NOT_FOUND. Store: `owner_strict` (`Owner::{Here, Elsewhere, Unknown}`, replacing `owned_here`), `inbox_rows`, `marked_inboxes`, `inbox_marked`; `a2a_inbox` went. No migration: the `sessions(contact_inbox)` index is p3-holds' 0062. `SESSIONS_WIRE_SCHEMA` unchanged (61 on main, from hides).
- **`INBOX_STAYS` lifted for marked inboxes only** (the last commit, `crates/sessionsync/src/owner.rs`): `move_to` and `answer_release` refuse an inbox unless `inbox_marked` (marker set, readable, naming a live `a2a_exports` row by id). A failed marker read refuses (`answer_release`: "could not tell whether this contact's inbox is marked, so it stays here"). `INBOX_STAYS`, `Msg::Refused` and both checks stay.

### Deviations from the doc
1. **Resolve, then forward, by the router itself.** The doc has the receiving machine read the method and ids and resolve the owner. Here it runs the request in its own router and forwards only when that router's strict resolve says `not owner` naming one of our machines: chat exports, agent exports (the marker and the home) and `~return` all resolve in one place (the agent), and nothing exists before the refusal (P2 put it before any task). Only the task id prefix of a `GetTask`/`CancelTask` is read by the layer itself. A call spends one rate token on the receiving machine whatever it resolves (review 1).
2. **`admit_contact` on the owner is its router's own bound.** The owner checks `gate(caller)` and `contacts_ready` itself, then its `dispatch` applies exactly `admit_contact`'s rate and concurrency bounds on the same principal; calling `admit_contact` too would spend two tokens per forward. (The receiving machine's own charge is separate: one token and one permit there, `Charged`.)
3. **Non-carried methods whose session is elsewhere** (a stream, push config, `ListTasks` of an agent export whose inbox is elsewhere) answer `UNSUPPORTED_OPERATION` with "streaming is not carried to contacts yet; poll GetTask", as the doc words it; a stream whose session is owned here is still served.
4. **Ambiguity caps the marked sessions owned here** (`unmark_a2a_inbox_full` + the fail-closed limits), so "both stay capped" holds even when one of them had been adopted.
5. **Rehoming an export** whose home left: the engine half is built (review 1): `a2a_export_put` of an existing agent export whose staged home is `Left` (neither this machine nor a machine of the mesh, or none) writes `home` = this machine; a home that is a machine of the mesh is kept, and without a mesh endpoint nothing is rehomed. The UI's "rehome" button, if any, is a re-share.
6. **Rig case 18** is driven by rewinding C's own roster state to version 1 (a data edit) and freezing n1 at C's boot: n2 must already verify C before it can send at all (P2's bootstrap), so a brand-new n2 cannot reach the send.
7. **Merged with main (P2 review fix b): the owner check comes first.** `handle_inbox` resolves through `inbox_of` before any side effect, and a local row whose session another machine owns is `not owner` (naming it) whatever its marker, so the D4 residual "the home unmarks its own row of an unmarked, pre-191 moved inbox and opens a new one" is not built: such a contact's sends end in `not owner` (fail-closed; only an inbox moved by a build before `INBOX_STAYS` is in that state). A read (`ContactInbox.send` false) resolves only an inbox owned here, else TASK_NOT_FOUND, and never opens, adopts, unmarks or caps one (the two-markers refusal writes nothing for a read). A gate's `not a contact` close is read only from the failing call's own error (main's `gate_refused`; this branch's `Net::a2a_refused` is deleted), and gives the "has not accepted this machine yet" refusal.
8. **An owner that is no machine of this mesh** (a row naming an engine removed from it, or one P2's real-router test stands in for) is plain `not owner`, never carried, so the contact's client tries its next member as in P2; only a machine of the mesh that is not connected is "the chat's machine is offline".

### Fail-closed, path by path
| Path | How it stays closed |
|---|---|
| A contact request for a session owned elsewhere | The receiving router refuses `not owner` before any task; the owner it names is used only to forward, never shown to the contact. An unknown row, an unreadable row or an empty owner on a mesh engine names no owner: plain `not owner`, never forwarded, never local. |
| A forward's owner | Re-checks the caller on its own tables: `contacts_ready` (else `OWNER_UNREACHABLE`), `IrohGate::Contact` (else 401: a blocked caller too), its router's rate and concurrency bounds, its own strict owner resolve (`NOT_OWNER`, never a second hop), its own 10 s deadline (a blocking call never holds the permit past it). |
| `a2a_forward` from outside the mesh | `UNAUTHORIZED` without the `Forwarded` marker (an internal connection included). |
| `a2a_forward` from a machine `mesh.messaging_off` lists | Refused before the plugin is reached, `-32000` with words that name no machine (the deleted `contact_deliver`'s check, review 1). |
| The receiving machine's own bound | One `admit_contact` per call (rate token + permit, held across the router run and every forward); a full bucket is 429, every permit taken is 503, before anything runs or is carried. `Charged` is a request extension: no HTTP client sets it. |
| A bare `/rpc` | Resolved to the first granted export before anything; none granted is 404 here, never carried. The owner side carries only `/agents/<[a-z0-9_-] or ~return>/rpc`. |
| A stale view | At most two resolves; the second `NOT_OWNER` goes back to the contact, whose client tries its next member once. Rig 16: two machines each reading the other as owner run nothing and end in `not owner`. |
| Owner offline or frozen | Not connected: refused at once; listed but silent: refused at the 10 s deadline, below the contact's 30 s. Nothing queued; the contact's retry carries the same `messageId` (admission dedups). |
| A stream, push config, the card, the notice, the proof path | Never carried: the contact-only routes are answered before the layer; any other method whose session is elsewhere is `UNSUPPORTED_OPERATION`. The owner side refuses any path or method outside the allowlist too. |
| An answer over 2 MiB | Fails on the owner (`Limited`) and again on the receiving machine; never cut. |
| A caller the owner does not list yet | 401 there, the transient refusal here; nothing ran, nothing stored. |
| One of our machines the contact has not accepted | Its gate closes "not a contact"; nothing was served, the next member is tried, the receipt is `failed` "<contact> has not accepted this machine yet"; no relay. |
| A task id naming another machine | Read only for `GetTask`/`CancelTask` (a `SendMessage` with a crafted `params.id` resolves its session); forwarded there (unary only); not connected is offline; a well-formed prefix naming no machine of the mesh is offline too (no tell of which machines are connected); an id without one is served here (pre-191 ids). |
| Agent export with no inbox | Only the home mints; another machine forwards to the home; a home that left mints nothing (paused). |
| Re-sharing an agent export | Its home moves here only when it left (neither this machine nor a machine of the mesh, or none); a mesh machine's home is kept; no mesh endpoint: nothing rehomed. An At ↔ Left move keeps the grant epoch; a move to or from `Here` rotates it. |
| A marked inbox that moved here | Capped (marker, no local row) until a contact message adopts it; adoption needs the agent's live persona (else `export unavailable`) and `contacts_ready`. |
| Two sessions carrying one marker | Refused, never chosen between; the ones owned here capped. |
| A name-valued or unmarked moved inbox | Never adopted, never routed (not the home: `not owner` naming the home, nothing opened); a name-valued marker still caps; a local row of a session owned elsewhere refuses (`not owner`) before anything happens here. |
| A read (`GetTask`, `CancelTask`) of an agent export | Only an inbox owned here by its local row; else TASK_NOT_FOUND. Two markers refuse it too, and a read writes nothing (no adoption, unmark or cap). |
| A move of an inbox (`move_to`, `answer_release`) | Only a marked inbox moves; unmarked, name-valued, a tombstoned or unknown export's, or a failed read: `INBOX_STAYS` (or "could not tell…"). |
