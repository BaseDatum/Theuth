## Correctness risks asked about (item 2)

- **48 KiB cap.** Client writers all go through `canvas/ops.ts` (no other `transact` in the tree) and bulk ones use `chunked`. One stroke is at most 24 000 bytes. The hole is undo/redo (M1) and byte-vs-character limits (m1). Engine writes call `apply` directly and are not capped locally (`wb/engine.rs#L414-L416`); a bake or an undo-turn is one update of unbounded size. I did not check whether an engine-to-relay hop caps it.
- **Helper/export bypass.** Every helper call site in `actor.rs` has a whiteboard guard: load `#L328`, apply `#L476-L477`, import `#L572`, `#L608`, edit `#L666`, export `#L783`, outline `#L1676`, headings `#L1753`, markdown `#L1832`, restore `#L2484`. Only `close` is unguarded (m4).
- **`doc_*` refusal.** Outline and Markdown return `wb::DOC_REFUSAL` before any helper call (`actor.rs#L1676-L1679`, `#L1832-L1835`); tests `doc_tools_refuse_a_whiteboard`, `create_never_calls_the_helper`, `export_writes_the_outline` exist. Not run by me.
- **Migration.** B2.
- **Composer recorder.** Behaviour identical; merge hazard M4.
- **describe-point.** Host matches reply by id and `ev.source`, strips `[ ] < >`, collapses whitespace, caps 120/24 (`lib/page-bootstrap.ts#L326-L374`); the engine quotes and prefixes it. Good. The page-side listener does not check the sender, but it can only describe itself and replies only to its parent.
- **Pen script.** `sandbox="allow-scripts allow-forms"`, listener only while capture is on, source-checked, points validated (`PageCard.tsx#L111-L125`, `#L142`). Remaining: m6.
- **Swift.** Overlay classes are `@available(iOS 26.0, *)` and `@MainActor`; every command hops to main (`InkPlugin.swift#L140-L149`); attach gates on iPad and iOS 26 (`#L65-L72`); timers re-enter with `MainActor.assumeIsolated` (`InkOverlay.swift#L203-L206`, `#L242-L245`); Vision runs off main (`HandwritingRecognizer.swift#L14-L24`). Ownership problem: M3.
