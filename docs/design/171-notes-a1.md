## What was built (brief items)

1. **Quiet delivery** (`crates/agent/src/supervisor.rs`, `loop_.rs`). `HarnessDeliver { wake: false }` → `Agents::inject_as(.., wake=false)` → `QuietInput(wrapped)` to the session actor. The actor parks it in `Session.quiet` (memory only) while idle; `start_turn` puts the parked items ahead of the opener (`Session::join_quiet`) whenever a turn opens through it — a human input, a waking harness input, leftover steers. While a turn runs, a quiet input is a *passive* steer: it joins the next tool batch; left over at the turn end it parks again (it never opens a turn). `wake: true` is unchanged.
   - Generalises 145's park at the same decision point (`inject`), but lives in the session actor: only the actor knows exactly when a turn opens "for any reason" (peer inputs, leftover steers and human inputs all pass `start_turn`), and 145's park is a talk-window timer (`Talk`), a different release rule. The talk park is untouched; a quiet result on a talk session parks quietly (the window opening does not wake it).
   - **No ledger ticket while parked**: a pending ticket would read as owed activity (`Ledger::activity`) and block A2A settlement and continuation decisions for as long as the result waits. The parked input carries `ticket: None` (like other inputs that bypass `Agents` routing).
   - **Order**: parked items first (arrival order), then the opener. The turn's `TurnStarted.channel` falls back to the first input that carries one, so a Slack message opening a turn behind parked results is still that channel's turn.
   - Not joined into a scoped (A2A) or peer-opened turn (50 §6.3): they wait for the next private one. E1 should therefore mark parked runs consumed only when a `TurnStarted` text contains the run id (the event carries the joined text), not on every `TurnStarted` — **relay to E1**.
   - **Turn-start event**: the existing `AgentEvent::TurnStarted { session, text, .. }`; no new event.
   - **Remote owner (139)**: `harness_outbox` rows and `Msg::Harness` have no wake field and A1 may add no migration. A quiet result for a session owned elsewhere is queued with `kind = "quiet " + kind` (`agent::supervisor::QUIET_KIND`); the owner's `HarnessDeliver` handler strips the prefix and parks it. `crates/sessionsync` untouched.
   - ACP-run sessions have no quiet input: a quiet result wakes them as before (documented fallback; also for queued children and draining sessions).

Rounds: `SessionState.cell_rounds` vs `cells.correct_rounds` (read from the `cells:` section, default 1). A surface and a cell correction in one reply persist both user messages and continue once.
   - `ValidateCtx`: this reply's names once per occurrence (so `name_duplicate` is within the reply) plus earlier assistant cells' names not re-presented here; `after_edges` from the newest version of each name; vault names via `Vault::list()` (names only); `monty_ok` from `agent::repl::monty_sufficient`.
   - `surface::cell_link::cells(text)` is the one "user-cell fences of a markdown text" helper (closed fences that `surface::cell::parse` accepts), used by the agent pass, the channel links and the skill test.
   - **`monty_sufficient(pool: Option<&Pool>, code) -> Result<(), String>`** is `async` and takes the pool (STUB-DEVIATION from the brief's `monty_sufficient(code)`): (a) `surface::cell::monty_scan`; (b) a check-only type check on a worker — the code is fed as the body of an `async def` that is never called, so Monty parses and type-checks it and nothing runs (a plain feed would run the cell when the check passes). `Typing`/`Runtime` errors of that feed = insufficient; no pool, a busy pool (10 s), or a worker failure = unchecked (fail-open, like the fence checkers).
