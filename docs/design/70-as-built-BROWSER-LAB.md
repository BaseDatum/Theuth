## 2. What changed in code (`b0ed1606` + this doc's commit)

- **`crates/decision/src/laya.rs`** — `pub struct Special { cls, sep, pad, mask, mask_text }` with `Special::MODERNBERT` (the old constants, kept as `CLS`/`SEP`/`PAD`/`MASK` for the test fakes in `engine.rs` / `browser/tests/live.rs`) and **`Special::from_tokenizer(&Tokenizer)`**: `[CLS]/[SEP]/[PAD]/[MASK]` else `<bos>/<eos>/<pad>/<mask>` via `token_to_id`, else an error naming both sets. `LayaConfig.special` (`#[serde(skip)]`, default ModernBERT); `build_sequence` uses `cfg.special` for the frame and blanks `special.mask_text` (`<mask>` on Gemma) from user text as laya does; `collate(rows, floor, pad)` takes the pad id.
- **`crates/decision/src/candle/mod.rs`** — `Loaded::open` sets `laya.special = Special::from_tokenizer(&tokenizer)?` right after loading the tokenizer; `run` collates with `self.laya.special.pad`. Header verification (`verify_header`) is unchanged and already strict per layout: the required names are the same in both checkpoints and `tok_embeddings` must be `[vocab_size, hidden_size]` from that dir's `encoder/config.json` — `[256000, 768]` for v17s, `[50368, 1024]` for root. No "layout detection" beyond the tokenizer was needed: the two checkpoints are the same file layout, the same architecture and the same head; the brief's "different backbone" is mmBERT = ModernBERT with other dims, which `candle/config.rs` + `model.rs` were already config-driven for (`layer_types`, per-kind `rope_parameters`, `norm_bias`, `intermediate_size`).
- **`crates/browser/src/systemone.rs`** — format v3: `TEXT_MAX` 1500 → **1200**, new `LABEL_MAX = 50` and `cut_label(&mut String, n)` (their `_cut`, char-counted, `→`-aware) applied to `"[i] {Open }label"` before the role / value / aria suffixes in `Element::option_text`. Module docs updated; `SELECT` and `PRESS_ENTER` deliberately **not** offered (see §4).
- **Scripts / docs / desktop** — `scripts/fetch-models.sh` REQUIRED comments + `origin_of` → `hf:cklxx/laya-browser/v17s/…`; `scripts/fetch-laya-browser.sh` → `REV=v17s` with the hub's byte sizes (643,835,524 / 1,939 / 561 / 34,363,188 / 624); `crates/desktop/ui/src/lib/labs.ts` hint "0.7 GB, cklxx/laya-browser v17s"; `decision/src/lib.rs` doc; `57-decision.md` §4.1 facts + §12.4 revision lines pointing here. `models.json` is not a checked-in file — `release-models.sh` rebuilds it from REQUIRED (not run: do not publish).
- **Tests** — `candle/config.rs::parses_root_and_v17s_checkpoint_configs` (fixtures `tests/fixtures/laya-root/` and `laya-browser-v17s/`: both `encoder/config.json` + `rl_agent_config.json`; asserts dims, RoPE bases, head budget 768/1024, temperature bucket); `laya.rs::special_tokens_follow_the_tokenizer` (Gemma-style word-level tokenizer → ids 2/1/0/4 and `<mask>` text blanked, `[MASK]` left as text; `tiny()` without specials → error; pad id reaches `collate`); `laya.rs::real_tokenizer_when_present` now asserts `Special::from_tokenizer == MODERNBERT`; `systemone.rs::labels_are_cut_like_format_v3` (five `_cut` cases with Python-computed expectations incl. a `→` option and non-ASCII, one through `option_text`, `TEXT_MAX == 1200`). ## 4. Deviations and what was not done

- **`SELECT` and `PRESS_ENTER` not added.** `PRESS_ENTER` would need Enter to submit the focused field; obscura's `browser_press_key` dispatches the key event only ("Enter does not submit", `tools.rs`), so offering it would give the head a no-op it likes for search boxes. `SELECT` needs the reader to expand `<select>` options into `[i:k] Field → Option` actions and a value channel to `browser_select_option`. Both are compatible omissions (criteria are per-page) and cost the same tasks as before (`internet-dropdown`). `cut_label` already implements the `→` rule so a later SELECT renders right.
- **No v2 compatibility path.** v10 is gone upstream; the bucket still holds its four files and they load fine (the tokenizer path is auto-detected), only rendered as v3 (1200 chars / 50-char labels) — which scored the same 9/16 as the recorded v2 run.
- `recent_actions` stays at the last 6 (their fine-tune saw 10); unchanged from step 5.
- `laya_fmt` is still not read by code: the renderer is v3 by constant. Reading it would need the format to flow from the engine's checkpoint to the browser crate for one extra constant pair — not worth it while there is one format.

## 5. Recommendation

Ship v17s as `decision-browser/`: it loads through the existing port with the tokenizer-id change, is the only checkpoint upstream still publishes, scores 62 % vs 56 % on the same suite under the same conditions, and runs ~35 % faster per step (smaller encoder). Next `release-models` run republishes the bucket copy (the fallback then also becomes v17s). Two follow-ups the numbers point at, for Sky: the `browser.target` gate τ 0.25 refuses a correct 0.19 on a 60-option page (`quotes-tag-love`) — v17s spreads probability wider than v10 over big windows, so τ 0.15 or a margin-based gate is worth a shadow-log look; and the suite should warm the engine before run 1 (the 2 s budget swallowed the cold load once).
