## What was built

- **`components/board/units.ts`** (new) — the pure derivations and the hook. `unitsOf(diagram)`: every unit in authored order (Graph: `nodes`; Sequence: `steps`, id = index, `detail` = `from → to` with actor labels), `anchor` parsed from `ref` (`null` when absent or failing the grammar). `highlightOf(units, active)`: ids whose anchor overlaps the active one — the view's `highlight` prop. `diagramStops(diagram, blockId)`: one `TourStop` per unit; a unit without a `ref` is an explanation stop (R §B.7). `boardStops(blocks)`: **Tour this board** — every anchored element in document order (spans, units, excerpts; children walked), sections opened by `#`/`##`; a span's or excerpt's stage is its section's first diagram, else the excerpt that covers the span (an excerpt stands on itself), else nothing. `unitBy(blockId, unitId)` = `unit:<blockId>:<unitId>` is the registry id and `pinned.by` / `tour.by`; `focusBy(root, by)` resolves a `data-anchor-id` or a unit's `<g data-node|data-step>` inside its block. `useUnits(diagram, blockId, coarse)`: registers the anchored units (`kind: 'unit'`), selects the active anchor (reference-stable) and memoises `highlight`, returns `onSelect` (pin, claim = `from → to: label` or the node label), `openTour(atUnit, by)`, and the wrapper handlers: `mouseover` delegation → 120 ms → `hover` (per unit, not per child element; fine pointer only), `mouseleave`/`blur` clear, `focus` → `hover` at once, `keydown` in the capture phase for ⌘↵ (tour at that unit; the unit's own Enter never runs) and `T` (tour at the focused unit, else stop 1). `useUnitPress(onPress)`: `pointerdown`/`pointerup` delegation — `DiagramFrame`'s pan/zoom surface takes pointer capture, so Chromium retargets `click` to the surface and a unit's own `onClick` never fires (see Findings).
- **`components/board/Tour.tsx`** (new) — `BoardDiagram` (the wide block: `data-block`, the wrapper handlers, a mono chrome row with **Tour · N stops** when ≥ 1 unit has a `ref`, `DiagramView`), `DiagramView` (`GraphView` / `SequenceView` with `highlight` by unit id, `onSelect`), `Tour` (the portal), `useTourBoard(blocks)` (the hook step 6's TOC calls), `useTourHotkeys(blocks)` (`T` outside a diagram, not in an input → Tour this board), `useTourPersist(docId, blocks)`, and the two pure rules `activeStopForScroll` and `tourKeyIndex`. The portal: `document.body`, `position: fixed; inset: 0`, `role="dialog" aria-modal`, `aria-label="Tour, stop n of N"`, grid `minmax(0,1fr) 10px var(--board-tour-pane, 594px)`, resizer 10 px, pane 360–760 and stage ≥ 480 (`clampPane`), width persisted in `localStorage['board-tour-pane']`. Stage = the stop's `stage` block re-rendered: the diagram with `highlight = [stage.unit]` (unit stops) or `highlightOf(units, anchor)` (span/excerpt stops on a section diagram), auto-scrolled to the lit unit (`scrollIntoView` center; `auto` under `prefers-reduced-motion`, else `smooth`); an `Excerpt` (`full`, rows from the anchor) when the stage is an excerpt; "No diagram in this section" otherwise. A press or Enter on a stage unit jumps to its stop. Feed = `<section class="tour-stop" data-stop data-anchor data-active aria-current>` per stop: badge · label · `from → to` (button, click activates) · code window = the covering `Excerpt` (`full`, `intersect` rows lit) / the placeholder (`No excerpt on this board covers these lines.`, step 7b's live window lands here) / `This unit has no code reference.`. Scroll-sync: `activeStopForScroll(tops, scrollTop, clientHeight)` = Whiteboard's `activeTargetForScroll` (first stop at or below the top; active if in the top half, else the previous); a programmatic reveal (`scrollTo` the stop's `offsetTop`) sets `revealing` so the intermediate scroll events of a smooth scroll do not step; a sync-chosen stop sets `fromScroll` so the reveal effect does not scroll back. Feed bottom padding `80vh` so the last stop can reach the top. Keys on `window` while open: `ArrowDown`/`j`, `ArrowUp`/`k`, `Home`, `End` (clamped), `Escape` → `closeTour()` + `focusBy(page, by)`. Prev / Next / Close buttons. `@media (max-width: 1080px)`: rows `minmax(180px, 40%) 1fr`, resizer hidden.
- **`components/board/anchors.ts`** (step 4's, additive) — `TourStop = {anchor: Anchor|null, kind, label, detail, stage: {blockId, unit}|null}`; `tour: {stops, index, by, blockId}` (was `{units: Anchor[], index, by}`); `activeOf` = `tour.stops[index]?.anchor ?? null` (an explanation stop lights nothing); `openTour(stops, index, by, blockId)` (index clamped, empty stops ignored), `stepTour(index)` (clamped), `closeTour()`. `anchors.test.ts` updated to the new shape (clamp both ways, explanation stop → `null`).
- **`components/board/blocks.ts`** (additive) — `Diagram = {type: 'Graph', props: GraphData} | {type: 'Sequence', props: SequenceData}`; `classifyCode` returns `{kind: 'diagram', diagram}` with the parsed root props instead of the fence text, so the reader mounts the view itself with `highlight`/`onSelect` (the catalog's `JsonRenderFence` cannot take them).
- **`components/board/BoardReader.tsx`** (minimal hunks) — `case 'diagram'` → `<BoardDiagram/>`; `<Tour/>` mounted while `tour` is set; `TourWiring` (a null component calling `useTourHotkeys` + `useTourPersist` under the store context); the pin's `Escape` handler yields while a tour is open and returns focus through `focusBy` (a unit's `by` has no `data-anchor-id`).
- **`components/board/board.css`** (additive) — `.board-diagram-head` / `.board-tour-button` (mono 11 px, `--marker-tint` hover), a focus ring for `[data-node]`/`[data-step]` (Whiteboard's ring, R §B.5), and the `.board-tour*` / `.tour-stop*` rules of §2.6 (tokens re-declared on `.board-tour` because the portal sits outside `.board-shell`).
- **`chat/surface/Graph.tsx`, `chat/surface/Sequence.tsx`** (step 3's, one attribute each) — the `<svg>` is `role="group"` when its units are interactive (Graph: when `onSelect` is given; Sequence: always — steps are always focusable). `role="img"` with focusable descendants is axe `nested-interactive`; a chat `Graph` without `onSelect` keeps `role="img"`.

## Deviations

1. **`tour.units: Anchor[]` became `tour.stops: TourStop[]` (+ `blockId`).** §2.3 types the tour as anchors only, but §2.6 wants a stop per unit including units without a `ref` (explanation stops), labels, `from → to`, and a stage per stop (Tour this board stands a span on its section's diagram); the persisted `{blockId, index}` also needs the toured block. `activeOf` keeps the precedence and returns `null` on an explanation stop.
2. **Click on a unit is delegated from `pointerdown`/`pointerup`, not `onClick`.** `DiagramFrame`'s surface calls `setPointerCapture` on `pointerdown`; Chromium then fires `click` at the capturing element, so `Graph`'s / `Sequence`'s `onClick → onSelect` never runs under the frame (the smoke's first node click focused the node — hover lit — but pinned nothing). `useUnitPress` (≤ 6 px slop, primary button) restores the press without touching the shared frame; Enter/Space still go through the views' own handlers.
3. **`T` outside a diagram opens Tour this board.** §2.3 lists `T` as a tour setter; §2.6 puts Tour this board in the TOC (step 6) and the header chrome (step 7b). Until those land, `T` on the page is the only reachable path; inside a diagram `T` tours that diagram (from the focused unit, else stop 1).
4. **`role="group"` on the diagram `<svg>` when its units are interactive** (Graph.tsx / Sequence.tsx, step 3's files). `role="img"` forbids interactive descendants (axe `nested-interactive`, the Done-when's "axe clean on units"). Chat `Graph`s without `onSelect` are unchanged.
5. **The stage is the in-flow view inside a scroller, not a `fullscreen` prop.** `GraphView`/`SequenceView` take no size prop; inside `.board-tour-stage` (`overflow: auto`) the svg fits the stage width (`max-width: 100%; height: auto`) and a tall diagram scrolls, with `scrollIntoView` on the lit unit doing the stage follow. Adding a `fill` mode to two shared views for one caller was not worth it; the 7-step fixture fits without scrolling at 1440.
6. **A stop without a covering excerpt shows the step-4 placeholder**, not a live window — step 7b owns `code_locate` in the pane; the tour's stop reuses the same rule (`coveringExcerpt`) so the live window slots in there too.
7. **Sections for Tour this board open on `#` and `##`** (step 6 owns sections proper; §2.2 says sections derive from `##`). A `#` title with content before the first `##` would otherwise share a section with it.
8. **Hover on units mutes the rest of a `Sequence`.** `SequenceSvg` mutes every non-highlighted step whenever `highlight` is non-empty (step 3's M4 treatment); so a prose hover that touches one step dims the other six. Graph nodes are not muted. Kept — it is the component's own rule.
9. **No focus trap in the dialog** (Whiteboard has none either, R §B.7); `Tab` can leave the tour. `Escape` and the pill are always reachable.

## Findings for later steps

- **`Excerpt`'s body is a scrollable region without a tab stop** (`overflow-auto` on the token list): axe `scrollable-region-focusable`, in chat and in the tour. A `tabIndex={0}` on the scroller (or only when it overflows) in `Excerpt.tsx` fixes it — step 7b touches that component.
- **`DiagramFrame` pointer capture swallows every click on diagram content**, in chat and apps too: `Graph`'s `onSelect` from a mouse click cannot fire anywhere the frame is used (apps pass `onSelect`, 65 §3.5). `useUnitPress` is the board-side workaround; the frame itself could dispatch a synthetic press when the pointer did not move.
- The Sequence's 7 steps fit the stage at 1440; a 40-step `Sequence` (the cap) is ~3 400 px tall in the stage and relies on the stage scroll-follow — worth a look in step 9's reference boards.
- Step 6's TOC: `const tourBoard = useTourBoard(blocks); tourBoard(byId)` where `byId` is the TOC entry's `data-anchor-id` so `Escape` returns focus to it.
