# 85 — OpenCode Zen and OpenRouter as first-class providers

Status: v0.1, 2026-10-03, orchestrator draft from two recons (theuth main bba5b5e2, genai fork a08e55d0; Zen docs/gateway source v2.0.22; models.dev api.json; OpenRouter docs + live /models). Extends 02 (catalog), 05 (credentials/resolver), 07 §3 (cache marks). Supersedes nothing.

## 0. Decisions in one screen
1. **Zen is a built-in provider with id `opencode`** (the models.dev id; model ids `opencode/claude-opus-5-5` as opencode itself uses), display name "OpenCode Zen", vault key `opencode`, env `OPENCODE_API_KEY`. Beat: a user-added gateway (cannot carry per-model protocols) and a new `zen` namespace (would diverge from models.dev and opencode's own ids).
2. **Per-model protocol dispatch happens in theuth, not in a new genai adapter.** For a Zen model theuth builds the genai `ServiceTarget` itself — endpoint `https://opencode.ai/zen/v1/`, `AuthData::Key(key)`, `ModelIden::new(kind, slug)` with `kind` chosen from the catalog's protocol: Anthropic → `AdapterKind::Anthropic` (URL `…/messages`, header `x-api-key`), OpenAI Responses → `AdapterKind::OpenAIResp` (`…/responses`, Bearer), Gemini → `AdapterKind::Gemini` (`…/models/{id}:…`, header `x-goog-api-key`), else `AdapterKind::OpenAI` (`…/chat/completions`, Bearer). This is exactly what the gateway branch in `backend.rs:95-103` does today with `AdapterKind::OpenAI` hard-coded. Beat: a `Zen` adapter in the fork modelled on `OpenCodeGoAdapter` — more code, a second place to keep the model→protocol table, and the existing adapters already produce the right wire format per kind.
3. **Protocol comes from the catalog**: `trim` keeps a new `Model.protocol` (from models.dev `provider.npm`: `@ai-sdk/anthropic` → `anthropic`, `@ai-sdk/openai` → `openai_responses`, `@ai-sdk/google` → `gemini`, absent/`@ai-sdk/openai-compatible` → `openai_chat`) and `Model.canonical` (`canonical_model_id`) for every ROUTABLE provider; `opencode` joins `ROUTABLE`. A small override table in theuth applies the Zen docs where models.dev disagrees (docs authoritative: `qwen3.7-max`, `qwen3.7-plus` → anthropic) and excludes `jev-*` (System One, not a chat model). Prefix fallback when a model has no protocol (e.g. a user models.json entry): `claude-*` → anthropic, `gpt-*|grok-*|muse-*` → openai_responses, `gemini-*` → gemini, else chat.
4. **Transport and default effort follow the chosen kind/model, not the provider.** `Backend::transport` for a protocol-dispatched target returns `Transport::of(kind)` (Zen Claude gets Anthropic `cache_control` breakpoints; Zen GPT gets `prompt_cache_key`); `frame::default_effort` treats a catalog model whose canonical id starts with `anthropic/` (or whose slug starts with `claude-`) and has `reasoning: true` as Anthropic for the medium default — under any provider (opencode, openrouter, bedrock).
5. **Billed cost is captured.** Zen injects `cost` (USD string, 8 dp): top-level on non-stream JSON; stream frame `event: ping` `{"type":"ping","cost"}` on the Anthropic and Responses formats, `{"choices":[],"cost"}` on chat. The genai fork lifts these into `Usage.cost{ProviderReported}` so `model_calls.returned_nanos` is exact. OpenRouter's `usage.cost` (always present) already lands there; the fork must also read `prompt_tokens_details.cache_write_tokens` and `completion_tokens_details.reasoning_tokens`.
6. **OpenRouter becomes first class on the existing genai `OpenRouter` adapter** (pass-through to OpenAI chat at `https://openrouter.ai/api/v1/`): credential name `openrouter` in the vault and `OPENROUTER_API_KEY` in the env (genai's `OPEN_ROUTER_API_KEY` still accepted); default headers `HTTP-Referer: https://theuth.io` and `X-OpenRouter-Title: theuth`; reasoning sent as OpenRouter's unified `reasoning: {effort}` when the model lists `reasoning` in `supported_parameters` (chat `reasoning_effort` otherwise — both are accepted); top-level `cache_control: {type: "ephemeral"}` (OpenRouter's automatic trailing breakpoint) when the model's canonical id is Anthropic; SSE keep-alive comment lines (`: OPENROUTER PROCESSING`) ignored; a mid-stream `error` chunk at HTTP 200 surfaces as a provider error with its `metadata.error_type`; `reasoning_details` round-trip stays as built. Optional `agent.openrouter.provider` config (JSON passthrough of OpenRouter's `provider` preferences: order, allow_fallbacks, data_collection, sort, only, ignore) sent when set. Beat: the `/responses` skin (stateless only) and the `/messages` skin (Bearer unverified) — chat is the most complete and already wired.
7. **Catalog source stays bundled** (02 §1 "no network at run time"): `just models` refreshes from models.dev; OpenRouter's live `GET /models` and Zen's `GET /zen/v1/models` are NOT fetched at runtime in this design (follow-up: a Settings "refresh catalog" action writing `<data_dir>/models.json`). Model ids stay as models.dev spells them (`openrouter/anthropic/claude-opus-5.5` with a dot; `opencode/claude-opus-5-5`).
8. **Reserved names.** `opencode`, `openrouter`, `open_router`, `zen` are refused as gateway names with the hint "built-in provider: set the `opencode` / `openrouter` secret". A gateway that answers Zen's `ModelProtocolUnsupported` gets the same hint in its error.
9. **Settings.** Connections lists the two built-ins with configured yes/no beside Accounts/Gateways (reuse the existing secret-set flow for the key); TUI `/provider` help mentions them. No adapter picker is added to gateways.

- OpenRouter: Bearer; `HTTP-Referer`/`X-OpenRouter-Title`; chat extensions `models`, `provider`, `reasoning{effort|max_tokens,exclude}`, `plugins`; `usage.include` deprecated — usage with `cost`, `cost_details`, `prompt_tokens_details{cached_tokens, cache_write_tokens}`, `completion_tokens_details{reasoning_tokens}` always returned; SSE comments, trailing usage chunk with a choice, mid-stream `error` at 200; `cache_control` passthrough (top-level or per block, ttl 1h); ids `author/slug[:free|:batch|:nitro|:floor|:exacto]`; errors 402 `metadata{reason, limit_source}`, 429 `metadata.error_type`.

## 2. Contract
- `models::Protocol { Anthropic, OpenAiResponses, Gemini, OpenAiChat }`; `Model.protocol: Option<Protocol>`, `Model.canonical: Option<String>` (serde default; absent in user files).
- `backend::ProtocolTarget { kind: AdapterKind, endpoint: Endpoint, auth: AuthData }` chosen by `backend::target_for(resolved, catalog, auth) -> Option<ProtocolTarget>`: built-in Zen when `resolved.provider == Some("opencode")` and a key exists; user gateways keep today's behaviour (kind OpenAI) — a gateway may later gain `protocol` per model from its models.json entries via the same function.
- `AgentEvent`/RPC unchanged except `ProviderInfo` gaining `builtin: bool` and `configured: bool` for the Connections view (serde default).
- Config: `agent.openrouter.provider: <json>` optional; `agent.openrouter.referer`/`title` optional overrides of the default headers.
- Credentials: vault names `opencode`, `openrouter`; env `OPENCODE_API_KEY`, `OPENROUTER_API_KEY` (+ `OPEN_ROUTER_API_KEY`); `configured("opencode")` true when either exists.

## 4. Rejected
- New `Zen` genai adapter (decision 2). — Runtime fetch of models.dev / OpenRouter `/models` (02 §1; follow-up). — OpenRouter `/responses` or `/messages` skins (decision 6). — An adapter picker on user gateways (keeps the gateway concept simple; Zen/OpenRouter are built-ins). — A `models-dev` crate dependency (stale).
