## Deviations

1. **`root` is required for a board** (the design writes `doc_create(kind?, root?)`). A board without a root cannot verify a single anchor (M11/M12), so the tool refuses `kind="board"` without an absolute, existing directory, and refuses `root` on a note. The board's `root` is not checked to be a git top-level (that is `code_locate`'s rule, step 7).
2. **Boards keep `Binding::Note`**; the kind is set on `DocMeta` by `create_doc` when a root is given. No `Binding::Board`: a board has no other owner, gets a fresh id and a `note.md` like a note, and every `Binding::Note` gate (store uniqueness, group listing) already does the right thing. `Binding::kind()` therefore says `Note` for a board's binding; only `create_doc` and `Store::bind` (never called for boards) consult it.
3. **`kind` is a string with two values in the tool schema**, not `Option<DocKind>`: the enum would show the model five kinds it may not create.
4. **The check refuses on the whole markdown of the call**, for every document kind, not only boards: a broken `json-render` fence is broken in a note too, and the model's correction round is the same. The error text is the tool's own (`nothing changed: a block does not validate — fix it and retry`), not the reply-side `<surface_error>` envelope; the located pointer is the full fence pointer (`/elements/e/props/mark/0`), which contains the design's `/props/mark/0`. **Two refusals the design does not name** were added after run 3: a fence whose language is a catalog component name exactly (` ```Excerpt `; the 38 names come from `surface::catalog_compact()`, exact case so ` ```text ` stays a language) and a `[label](path#L<n>…)` link with no scheme — both are what the model writes when it means a block or a `code:` link, and both land as dead text on the reader's page (M3 "a link is never a dead end"). Each is one line of the tool error naming the shape to write instead.
5. **One prompt block for the plugin.** `ToolRegistry` keeps one block per plugin name, so `## Boards` is appended to the Documents paragraph in the same `RegisterPrompt{plugin:"document"}`. Two sentences were added to the §3.1 text: `load_skill("board")` first (the skill is on-demand via the skills index; without the line the model never reads it), and that a refused block names its path.
6. **Skill additions beyond §3.2**, all from the three runs: `start` and `text` must come from the same `read_file(offset=start, limit=n, numbers=False)` call (run 1's off-by-one); `ref` carries no `code:` prefix and is fixed, never dropped, when refused (run 2 lost every `Sequence` ref this way); the `Graph`/`Sequence`/`Callout` enum values are listed (eight of the refusals were guessed enums); the read-back needs four or five tool rounds and is budgeted; a heading and its first paragraph may share one `doc_insert` while a diagram or an `Excerpt` is always its own call — a 6-section board otherwise spends the 32-round default on inserts and the read-back never runs. `lines()`/`block()` helpers in the recipes strip `read_file`'s header/footer, which §4's `read_file(...)` one-liners would have pasted into `Excerpt.text`.
7. **Callout variants are `note|tip|question|important`** (the crate's enum), not `info|warning|danger`.
8. **Notes search includes boards** (`search.rs`): finding the board again is part of "the reader will come back to it". The desktop notes list (`doc_list('note')`) does not show boards yet — step 8 owns the list glyph/badge; a board is reachable by `theuth://notes/<id>`.
9. **`Rename` skips the frontmatter block** to find the `# h1` — a one-line fix the board test exposed.
10. **Not done here**: the `[fm]` outline line prints only `type/title/tags` (helper `convert.ts`, not this step's files), so `root` is visible in `doc_read(format="markdown")` but not in the outline. The RPC `doc_create(title, markdown)` is unchanged (design §2.1 changes the tool only).

## Findings for later steps

- **Excerpt fidelity is the weak point, and it is a machine check, not a rule.** In four runs the model produced 8 `Excerpt`s; 4 were verbatim, 4 were not (one `start` off by one from slicing an earlier read, one dedented, one hand-edited, one re-read from the wrong window). The skill says "verbatim from one `read_file` call" three ways and the read-back names the comparison; the model still retypes, and the 32-round default (`agent.max_tool_rounds`) ends the turn before the read-back's `doc_replace` in three of four runs (run 4 said so in chat). Step 7's `code_locate` will mark these `changed` on open and step 9's `board-check` will fail them; a cheaper place is insert time — `doc_insert` on a board could read `root/path` lines `start..start+n` and refuse a non-verbatim `Excerpt` with the first differing line, the same shape as the fence refusal. Not done here because 71 §2.1 scopes the insert-time check to `surface::check` and the tool does not know the board's root without a meta read; proposed as a step 7 or step 9 addition.
- **Enum guessing costs a round each** (`kind`, `style`, `direction`, `state`, `mark` shape: 11 of 13 refusals). The compact catalog line in the prompt block carries names, not enum values; the skill now lists the `Graph`/`Sequence`/`Callout` values. If step 9's steering runs show the same, the `visualize` skill's `## Catalog` could print enum values in `Props:`.
- **`code:` links are rare** (1, 0, 0, 0 per run) although `ref`s are plentiful (13, 5, 6, 10): the model anchors diagrams, not sentences. The prompt block and skill both state the prose grammar; step 9's `board-check` "≥ 1 anchored claim per paragraph in How it works" (M3 check) is the lever.
