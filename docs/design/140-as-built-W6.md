## Deviations (and why)

1. **`autoresearch_draft` is registered by `app`, not `autoresearch`.** The card is an OpenUI app and only `crates/app` can commit one under the tool's own call id (`commit_source` is `pub(crate)`); the two crates had no edge, so `app` now depends on `autoresearch` (acyclic: only `rpc` and `theuth` depended on `app`). `autoresearch::tools::DraftTool` keeps C's type and description but `tools::register` no longer registers it (two tools of one name would collide); its `call` says the tool is served by `app`.
2. **The press path is a tool `Mutation`, not the `autoresearch.create` RPC.** OpenUI buttons can run installed tools, not RPC methods, so the Start buttons call `autoresearch_control {op: start|start_window}` which sends the same `StartDraft {draft_id, start}` message `autoresearch.create` sends. The draft id is the spec's slug; the spec lives at `<root>/drafts/<slug>/spec.json` (the drafts dir §12.6 already defines; "writes nothing" of §12.4 is read as "creates no study" — a draft file beside the setup's scripts, swept with them).
3. **Novelty similarity** is FTS5-candidates + overlap coefficient rather than a bm25 score thresholded directly: bm25 is unbounded and corpus-dependent, `novelty.threshold: 0.6` reads naturally as "60 % of the idea's words recur". Dead-end collapsing in the brief uses in-memory token Jaccard (no FTS round trip per row).
4. **Side calls are tagged `CallKind::Dream`.** `CallKind` lives in `runtime` (not W6's); a `CallKind::Autoresearch` variant is a one-line `runtime` + store change for the closer. Effort per role (§9.3) is not applied: `SideCall` has no effort field.
5. **`brief::Context` gained `gate: GateConfig` and `crash_retries: u8`** (both `Default`): the Noise line needs `z_fast`/`z`, the protocol needs the retry count; W3 fills them from `cfg.gate` / `cfg.defaults.crash_retries` (0 → 2).
6. **`humantime` added to `crates/autoresearch/Cargo.toml`** (workspace dep) for the spec's timeout validation; W1's runner will want it too.
7. **TUI/desktop `/autoresearch`** hand the skill to the model with the words rather than listing/controlling natively: the desktop `Api` has no `autoresearch.*` calls yet (W4) and a native TUI list needs new `Command`s in `crates/tui/src/lib.rs` (not "table lines"). `/autoresearch` bare → the model calls `autoresearch_status`.
