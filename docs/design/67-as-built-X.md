### 3 — `docs(67): as-built X` (this document)

## Deviations (decided alone)
1. **Mesh peers ride the existing `Nodes` map.** Instead of a second resolution table in `Agents`, `serve_mesh` registers every paired engine with `agent::RegisterNode` (a `MeshDialer`), so spawn, resume (`acp_session`), the directory (`PeerKind::Node`/`Acp`), the tool description and `unknown` texts work unchanged. "Mesh first, then 32 nodes" holds per name: a mesh peer with the same name as a 32 node overwrites that entry while registered (the same machine during migration); the 32 entry returns only when the nodes plugin re-registers it.
2. **Registration lives in `rpc::acp`, not in `agent`.** rpc already depends on `mesh`, `replica`, `agent` and `acp` and starts on every engine; putting the watcher in `agent` would have added `mesh` + `replica` to its dependency list for one loop. The resolution itself (`resolve_node`, `canonical_agent`) is in `agent::peers` as briefed.
3. **`replica::GetTransport` / `replica::transport`** (outside my allow-list, ~30 lines): the mesh hands its transport only to the replica actor (`RegisterTransport`) and the replica engine did not keep it; nothing else could reach `Transport::accept`. The replica is the documented "every other plugin reaches peers through that" point, so the accessor went there rather than a new mesh message.
4. **Id-prefix resolution via `Dialer::engine_id`** (a default method) rather than a change to the `Nodes` tuple; a 32 node answers `None`. Two engines matching one prefix resolve to nothing (the model gets `unknown agent` with the node list).
5. **This engine is named by its hostname** in placement (`where`) and in `canonical_agent` (folded to a local child). `mesh.name` is not read on either side: the tasks tool has no config access and `agent` does not know the mesh. An engine with `mesh.name` set to something other than its hostname is still reachable from peers under `mesh.name`; only a task placed *on the hub itself* uses the hostname. Documented gap.
6. **`_meta.theuth.parent_engine` over the mesh is the caller's mesh id prefix** (8 chars), the analogue of the 32 device id; display only.
7. **`Missing` becomes a blocker on the task** (`state: blocked`, `blockers: [engine:<repo:<path>|display|gpu|harness:<h>|<where>|none>]`) — T's tool description already promised this; the update goes through the ordinary `UpdateTask` guard (`todo|doing → blocked` with a blocker entry).
8. **Desk turn = one `Deliver` with `await_reply`** from the calling session to `session:<theuth desk>`, so the desk sees a `<message>` and answers with `send_message reply_to`; 120 s (`DESK_WAIT` const, not config — `roster.decision_wait_secs` is the roster's). Needs the communication switch on in the calling session (`tools::communication::current()`); off → error text, nothing placed. theuth's own desk calling `task_place` gets the prompt back and answers by calling again with `where`/`harness`/`reason` (the args T kept).
9. **`read_only` comes from the owner's roster file** via the new `DeskRouter::tools_of`, not from the registry's cap of the calling session — the brief said "owner agent's `tools` ceiling via roster", and the caller may be another desk.
10. **`DeskRouter` defaults implemented in the roster** (`manager_of`, `agent_for`, `agents`) beyond `tools_of`: the roster's impl had only `desk_for`/`deliver`, so the tasks side saw every caller as `user`. Four small methods, outside my allow-list, disclosed.
11. **`crates/roster/src/desk.rs` test literal** gained `blocks: vec![]` — `cargo check -p roster --tests` did not compile before (T's `Task.blocks` landed after A's test); one line.
12. **Repo matching** is textual (`same_repo`): an absolute path equal to / under / above a git root; `~/x` matches any root ending in `/x` or a parent of it, since home differs per engine. No filesystem access; the brief's "a project whose sessions' cwd is known" is the project's session cwds appended to the mentioned paths.
13. **`cargo check` count**: four runs for commit 1's crates and one extra for commit 2 (`tasks`, `roster`) in a combined command; the brief allows one per commit. The first surfaced kameo's `Result` flattening in `mesh.ask`, a missing `replica` dep in rpc and a missing trait import in the test; the last ran after the `Option` change to `canonical_agent`.
