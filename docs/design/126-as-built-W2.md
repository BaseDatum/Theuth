### §7.2 Tier A → `crates/double/src/train_a.rs`
- Corpus: `load_examples` (train_a.rs:565) joins `examples` × `labels` (embedding required) and the `baseline` `predictions` row for the zero-shot probs (`align_probs`; uniform when the row is missing); `net_target` (train_a.rs:544) sums §6 weights — `direct`/`override`/`timeout` for their choice, `hindsight_*` against it, `excluded` drops the row — clamped at 0. The output space of every card is its options plus `none` (`NONE`, train_a.rs:49).
- Golden: `assign_golden` (train_a.rs:659) marks per class the first `max(5, ⌈10 %⌉)` rows by `asked_at` (`golden_target`, train_a.rs:684); idempotent, the set only grows; golden rows join no fit.
- Features (`Artifacts::features`, train_a.rs:447): per option `[oracle p, k-NN vote, class prior, is none]` × context `[1, requester one-hot ×4, risk one-hot ×4]` (`requester_idx` / `risk_idx`, train_a.rs:63-85) → 36 weights per `Head` (train_a.rs:98). A conditional logit (softmax over the card's options) so the same head serves the global fit and the per-class fits (`PER_CLASS_MIN = 20`).
- Fit: `fit_head` (train_a.rs:170) is L-BFGS (m = 5, Armijo backtracking) from zero, L2 = 1.0, 100 iterations, f64 — plain Rust, no candle (the design asked for deterministic, convex, explainable; 36 parameters need no tensor library). k-NN features at fit time are leave-one-out over strictly earlier rows (`before = asked_at − 1 ms`), i.e. what the live predictor would have seen.
- k-NN: `Artifacts::knn_vote` (train_a.rs:388): cosine, k = 15, weights `exp(−age_days/30)` × label weight, Laplace floor 0.1 over the card's options; the index is `Vec<KnnEntry>` sorted by (class, asked_at, option), serialised as `knn.bin` (`knn_bin` / `Artifacts::read`, train_a.rs:325-383: magic `DKN1`, u32 count, per row `class, option, f32 weight, i64 asked_at_ms, u32 dim, f16 × dim` LE).
- Temperatures: per class, fixed grid 0.50…3.00 step 0.05, NLL on the class's golden rows (held out); 1.0 without any.
- Prediction: `Artifacts::predict(class, requester, options, oracle, knn) -> Vec<f32>` (train_a.rs:424) — the per-class head when present else the global one, divided by the class temperature. W1's predictor calls `knn_vote` then `predict` with the `ActiveVersion`'s artefacts.
- Measurement and gate: `Metrics { n, accuracy, log_loss, brier, ece }` / `metrics()` (train_a.rs:847-905); `gate()` (train_a.rs:933): (a) candidate log-loss < incumbent's on the last-7-days rows (skipped when there are none yet), (b) golden accuracy ≥ incumbent − 0.01, (c) ECE ≤ 0.05 over golden ∪ 7-day rows; `rejected: no golden rows` when golden is empty. The incumbent is the active version's artefacts re-scored offline on the same rows (`score(None, …)` = baseline when nothing is active).
- `run(store, active, base_hash, now) -> Option<Candidate>` (train_a.rs:1009): load → golden → fit → score → `VersionRow { tier a, metrics JSON (`metrics_json`), data_range = "<first asked_at>..<last label at>", active = false }`; the id is `a-<sha256(data_range)[..12]>` (`version_id`) so the same corpus yields the same id and a second run on an unchanged corpus returns `None`.
- Tests: `fit_is_deterministic_and_beats_the_oracle` (byte-identical `heads.json` / `knn.bin` / `temperatures.json` from two fits; golden log-loss below zero-shot), `knn_vote_uses_only_earlier_rows_and_floors_unseen_options`, `gate_accepts_and_rejects_on_synthetic_metrics`, `metrics_are_sane`, `net_target_sums_sources_and_clamps`, `golden_target_is_ten_percent_min_five`, `requester_and_risk_indices`, `run_fits_a_store_marks_golden_and_is_idempotent` (temp store, 30 rows → 5 golden, 25 trained, same id twice, `None` once the row exists).

### §8.1 scheduler → `crates/double/src/sched.rs`
- `Trainer` (sched.rs:60): `steps()` + `step(i) -> Option<Finished { version, verdict }>`; Tier A is one step (`TierA`, sched.rs:671-714, writes the version directory through `versions::write`); W3's Tier B returns one step per epoch. `Factory` (sched.rs:69) = `(Tier, &Resolved) → Option<Box<dyn Trainer>>`; `tier_a_factory` (sched.rs:716) answers Tier A locally and `None` for B/C.
- `run_one` / `drive` (sched.rs:124-290): `eligible → waiting (every 60 s until `precond::check` is empty) → acquiring (Tier B/C take `BuildSlot`; Tier A none) → running (one `step` at a time; `DoubleTrainingState.progress = i/steps`) → evaluating → promoted | rejected`. At every step boundary: the run cap (`training.run_cap_min`, cumulative `running` seconds per night via `tokio::time::Instant`) → `paused`, slot released, sleeps until `Window::night_of` changes; then preconditions → `paused: <blockers>`, slot released, resume through `waiting`/`acquiring`. The fourth night → `rejected: stale` (`MAX_NIGHTS = 3`). Every transition rewrites the `runs` row and publishes `DoubleTrainingState`; `promoted` activates through `versions::activate` and publishes `DoubleVersionActivated`; a trainer error → `rejected: <error>`; `Ok(None)` on the last step → `rejected: nothing new to train on`.
- Triggers (`Triggers::due`, sched.rs:345-385, on the 60 s tick in `start`): Tier A when `labels_since(last A data_range end) ≥ 25` and the count did not move since the previous tick (debounce), or nightly inside the window once per night when any label exists; Tier B when a trainer is wired (`HasTierB`), `tiers.b.enabled`, inside the window, and `triggers.labels` / `triggers.days` since the last B version fire; Tier C never.
- `Scheduler` actor (sched.rs:421, registered as `sched::ACTOR = "double-sched"`): `Train { tier, venue } → Result<RunId, String>` (one run at a time; `off` → error; an explicit unreachable node → error; Tier A always local; B/C without a trainer → `tier b is not available until W3`), `Rollback(version) → Result<DoubleStatus, String>` (publishes `DoubleVersionActivated`), `Export → DoubleExport`, `DeleteAll`, `SetSettings(DoubleConfig) → DoubleConfig`, `Status → Result<DoubleStatus, String>` (what the scheduler knows: enabled, active_version, last_run, next_window, resolved venue; KPIs default — W1's status fills them), internal `HasTierB`.
- `export` (sched.rs:731): `<data_dir>/double/export/double-<UTC>.jsonl`, one object per example (`id, class, question_id, requester, card_text, options, asked_at, labels[], embedding[]`); rows were scrubbed at write (store.rs). `delete_all` (sched.rs:792): one transaction deleting `examples` (cascades labels/predictions/golden), `classes`, `runs`, every `versions` row but `baseline`, `active = 0`; then `models/`, `runs/`, `export/` removed; refused while a run is in flight.
- `persist` (sched.rs:820): rewrites the whole `double:` block of `config.yaml` with `serde_yaml` (2-space indent) through a sibling temp file + rename; the rest of the file is byte-identical. **Deviation:** `runtime::write_config_value` writes one scalar line and would leave a block's children orphaned under a flow value (`training:` has nested keys in the template at crates/theuth/src/main.rs:1116-1125), so the block is replaced whole; comments inside `double:` are lost on the first `double_settings_set`. - `start(rt, store, cfg, factory)` (sched.rs:598): spawns the actor with `runtime::subscriber_mailbox()`, registers it, runs the tick until `rt.shutdown`.
- Tests (paused tokio clock after the store opens; fake sensors): `promoted_path_and_rejected_path` (full state list, pointer + table updated, slot released, rejected version kept inactive), `waits_pauses_and_resumes_on_preconditions` (battery → waiting; a meeting at a step boundary → paused → resume → promoted), `run_cap_pauses_until_the_next_night_and_three_nights_is_stale` (cap 1 min, 61 s steps, one step per night, `rejected: stale` on the fourth), `tier_a_takes_no_slot_but_waits_on_a_foreign_one`, `nothing_to_train_is_rejected_cleanly`, `triggers_fire_on_25_settled_labels_and_nightly`, `persist_rewrites_only_the_double_block`, `next_window_start`.

## Deviations from the design / brief

1. AC power via `pmset -g batt`, not IOKit (no binding in the tree; the brief allowed it, "say which").
2. Load / disk / memory probes live in `platform::power` (brief named only `power.rs` + `idle.rs`; a third file would have been one function each).
3. `double_settings_set` rewrites the `double:` block whole instead of `runtime::write_config_value` per key (see §8.1 above — a flow value over a block key breaks the YAML).
4. Tier A's golden set follows the design literally (`max(5, ⌈10 %⌉)` of every class, min 5): a class with ≤ 5 rows is entirely golden and contributes nothing to any fit until it has a sixth row. The design's "never trained on" is honoured by growing the set only from rows not yet golden; a row trained on by an earlier version can still become golden later when the class grows (prefix rule) — recorded, not solved.
5. `auto` requires `accelerator ∈ {cuda, metal}`; the brief said "accelerator set". C's `Cpu` variant means "probed, nothing training-grade", so it is treated as unset.
6. The gate's (a) proxy compares the candidate and the incumbent re-scored offline on the same rows (the active version's artefacts, or the zero-shot probs). The design's "the rows the active version predicted live" would read the stored `predictions` of the active version; until W1 writes those for a trained version there is nothing to read, and the offline re-score is the same numbers for a deterministic Tier A head.
7. `Status` reply is `Result<DoubleStatus, String>` (kameo's `Reply` is not implemented for arbitrary structs).
8. `TrainResult.manifest_json` / `metrics_json` are JSON text (postcard has no `deserialize_any`).
9. `serde_json`'s default float parser may read a weight back one ulp off (`float_roundtrip` is not enabled workspace-wide); the files are byte-identical, the read-back equal to 1e-12 (`fit_is_deterministic_and_beats_the_oracle`).
10. No `flock` on `~/.theuth/double/train.lock`: one run at a time is enforced by the scheduler (`current`), and across processes by the build slot for Tier B/C. Two engines on one machine both running Tier A at once is possible and harmless (< 2 min of CPU, separate stores).
