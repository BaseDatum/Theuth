## Deviations and decisions

- **`sandbox_terminal` shape**: the brief wrote `→ { job }`; every PTY RPC (`subscribe_pty`, `pty_input`, `pty_resize`, `list_terminals`) is keyed by `(session, job)` and the pop-out route is `/pty/$session/$job`, so `api.ts` declares `{ session: string; job: string }` (as-built E §31 proposed the same). **F2 must return both** — if it returns only `{ job }`, the UI has no session to subscribe with. Flagged for the integrator.
- Terminal is enabled only for a `running` VM; there is nothing to exec into otherwise.
- Memory gauge says "allocated" in the value text rather than renaming the label ("Memory" stays the `aria-label`); the tooltip sits on the meter, as asked.
- `bindings` fix (`number | null`) is outside the letter of the brief but inside the files it names (`vm/mod.rs`, `secrets/lib.rs`) plus `roster/handoff.rs`: one attribute each, no runtime effect; without them `HANDOFFS_SIM` / `SECRET_REQUESTS_SIM` could not carry `null`.
- `packages/apps` needed its own `bun install` for `tsc -b` to pass (its deps were missing in this worktree; not a code change).
- Did **not** edit `79-sandbox-vm.md` §16 / `79-contract.md` (not in the deliverables); the integrator should move "Terminal disabled" and "`secret_requests` list RPC" out of the open list once F2 lands.
