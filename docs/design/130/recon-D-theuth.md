## 1. Desktop shell (Rust, crates/desktop/src)

Files: `DESK/lib.rs` (527 lines), `commands.rs` (97), `launch.rs` (646), `update.rs` (153), `models.rs` (816), `pages.rs`, `island/{mod,macos,windows,linux}.rs`, `point/{mod,machine,macos,other}.rs`, `ios_windowing.rs`. ### 1.1 Builder, plugins, activation policy
- Shared builder: `tauri_plugin_opener`, `tauri_plugin_notification`, the `theuth-page` URI scheme (120) (`DESK/lib.rs:33-38`); desktop adds `global_shortcut` (no Rust handler at build time), `autostart` (`MacosLauncher::LaunchAgent`), `positioner`, `window_state` (denylist `island`, filter `overlay-*`), `dialog`, `update::plugin()` (`DESK/lib.rs:253-270`); `tauri_nspanel::init()` on macOS only (`:275-276`).
- `ActivationPolicy::Accessory` set in `setup` on macOS (`DESK/lib.rs:322-329`), then `setup(app)`, `island::init`, `point::init`.
- Native app menu kept on macOS so ⌘C/⌘V/⌘A/⌘W reach the webview under Accessory policy; Quit is our own `"quit"` item with `CmdOrCtrl+Q` so it goes through the `quit-requested` handshake (`DESK/lib.rs:395-448`).
- Window background painted to the page colour (DARK-FLASH) for every window except island and overlays (`DESK/lib.rs:470-479`).

### 1.3 Window set

### 1.4 Global shortcuts

Meeting PTT/eye keys are registered only while a meeting is live (`UI/lib/meeting-hotkeys.ts`, per 96 §2.1 recon `docs/design/96-point-and-say.md:262-266`; not re-read here).

The UI pushes the chord at boot and on every rebind from `useShortcuts.chords['voice-key']` gated by `useVoiceKeySettings.enabled`; a refused chord toasts and the store falls back to the last bound chord (`UI/App.tsx:300-329`). `Escape` is registered as a global shortcut only between press and send (`DESK/point/mod.rs:38-39`, `:370-383`).
- Rebinding UI: Settings › Shortcuts (`UI/components/settings/Shortcuts.tsx`, see §2.6) over `lib/shortcuts.ts` `DEFS`.

### 1.6 Point-and-say state machine (`DESK/point/`)
- Pure reducer `machine::step(State, Event, now, refused) -> (State, Vec<Effect>)`; `State` = `Idle | Armed{t0} | Holding{t0} | Tap1{t0,released} | Locked{t0} | Sending{t0} | Replying` serialised `#[serde(tag="state", rename_all="snake_case")]`; `Event` = `Pressed | Released | Esc | Tick{now} | PanelDone | Cancel`; `Effect` = `Start | ShowLock | Stop{reason} | Discard{reason,hint} | Conceal | Refuse{reason}` (`DESK/point/machine.rs:20-65`, `:69-131`); constants `HOLD_MS 200`, `DOUBLE_TAP_MS 300`, `MIN_NOTE_MS 800`, `SAMPLE_HZ 60`, `DONE_MS 6000`, `HINT` (`:6-18`); 20+ unit tests (`:147-474`).
- Driver: `Point { tx, state, refused, chord, annotate }` managed state, `drive()` task, 60 Hz sampler, `MAX_SAMPLES` = 120 s of path (`DESK/point/mod.rs:40-42`, `:73-107`, `:240-260`). Events to webviews: `point:start {at_ms, locked, color_hint}`, `point:lock`, `point:samples {display_index, pts, pen}`, `point:stop {samples, duration_ms, reason}`, `point:cancel {reason, hint}`, `point:refused {reason}` (`DESK/point/mod.rs:189-236`; TS mirrors `UI/lib/tauri.ts:111-126`, listeners `:150-155`). Commands: `point_cancel`, `point_done`, `point_state`, `point_refuse(reason)`, `point_configure(annotate: "always"|"mouse")`, `overlay_ensure` (`DESK/point/mod.rs:149-187`).
- Overlays: one `overlay-<n>` per `available_monitors()`, `transparent`, no decorations/shadow, `focused(false)`, `always_on_top`, then `backend::panelize` (macOS: NonactivatingPanel style mask `1<<7`, `NSPopUpMenuWindowLevel` 101) and concealed via `set_revealed(win, false, false)` (`DESK/point/mod.rs:573-630`; `DESK/point/macos.rs:14-17`, `:22-55`). `left_button_down()` reads the mouse for `annotate = mouse` (`:58-60`).
- Island ↔ main window events: `voice-key:place` (main → island) and `voice-key:placed` (island → main) via `emitTo` (`UI/lib/tauri.ts:156-160`).

### 1.7 Notifications
- Rust registers `tauri_plugin_notification` only (`DESK/lib.rs:35`); no Rust code posts or handles a notification (no `notification` symbol in `DESK/*.rs` besides the plugin init — grep over `crates/desktop/src`, unverified for the iOS bridge). Posting is JS: `notifyIfHidden(title, body)` returns early when `document.hasFocus() && isVisible()`, asks permission once, `sendNotification({ title, body })` (`UI/lib/notify.ts:6-12`); `primeNotifications()` asks on iOS at launch (`:14-21`).

- iOS path: the same `notifyIfHidden` runs in the link client (31 §8 per the comment); no engine push exists (see §3.10).

### 1.8 Autostart, updater, sidecar
- Autostart: `tauri_plugin_autostart::init(MacosLauncher::LaunchAgent, None)` (`DESK/lib.rs:256-259`); permissions `autostart:allow-enable/disable/is-enabled` (`capabilities/default.json:37-39`).
- Updater: `update::plugin()` with a never-downgrade / never-cross-major comparator, `FIRST_CHECK` 60 s, `EVERY` 6 h, jitter ≤ 5 min; bytes stay in memory as `Pending { update, restart }` and install at `RunEvent::Exit`; the webview only receives `update-ready` (`DESK/update.rs:1-34`, `:102-138`); endpoint `https://s3.rwx.dev/theuth/releases/latest.json` (`tauri.conf.json:67-72`).
- Sidecar: `launch.rs` probes the running engine (63's `engine.json`, else the configured port) and otherwise spawns `$SHELL -l -i -c 'exec t --headless --data-dir …'` on a `portable-pty`, env `THEUTH_LAUNCH=1`, `THEUTH_RPC__LISTEN=127.0.0.1:<port>`; readiness is the port, the transcript streams as `launch-log` events (`DESK/launch.rs:1-12`, `:304-331`); `data_dir()` = `$THEUTH_DATA_DIR` else `~/.theuth` (`:174-176`); `cli_bin()` = `$THEUTH_BIN` else the bundled sidecar (`:369-372`). Windows: a plain hidden child (`:9-12`, `:264-276`).
- Models sync (`models.rs`): downloads local model checkpoints from `https://s3.rwx.dev/theuth/releases/models/models.json` and emits progress (`DESK/models.rs:30-39`, `:126-165`).

## 3. Engine model and RPC

All RPCs are methods of the jsonrpsee `Api` trait in `crates/rpc/src/api.rs` (`#[rpc(server, client)] pub trait Api`, `crates/rpc/src/api.rs:160-161`; 6 433 lines; 331 `#[method(name = …)]` attributes counted by grep). The desktop reaches them through the hand-written `UI/rpc/api.ts` (`attention_list` at `:540`, `attention_snooze` `:544`, `attention_dismiss` `:546`; allow-list `:854-856`) over one WebSocket the webview owns (25 §0.4).

### 3.1 Attention item model (`crates/roster/src/attention.rs`, 2 126 lines)
- Derived, not stored: "things only the user can decide, *derived* on every `attention_list` from what already exists — permission prompts (subscribed `ApprovalRequested`), pending `ask_user` questions (`tools::PendingAsks`), artifacts an agent showed (`ArtifactShown`, recorded in `attention_shows`), tasks blocked on a `decision:` or a person, tasks in review with the user as reviewer, proposed agents, budgets at 80 % / paused, unreachable mesh peers, unresolved desktop hand-offs and unanswered secret requests. Only dismiss / snooze per item id is stored (`attention_state`, engine-local) … a newer version surfaces again (119). Badge count = the returned list's length" (`crates/roster/src/attention.rs:1-12`).
- `AttentionKind` = `Approval | Decision | Hire | Blocked | Review | Budget | Node | Handoff | Secret | Ask | Show | Resume`, `#[serde(rename_all = "snake_case")]`, ts-rs exported (`:35-66`).
- `AttentionItem { id, kind, title, detail: Option<String>, at_ms: u64, task: Option<TaskId>, agent: Option<String>, session: Option<String>, approval: Option<ApprovalId>, decision: Option<String>, packet: Option<String>, ask: Option<AskRequested> (serde default), turn: Option<u32> (serde default; "No source does yet") }`; id grammar `approval:<id> | decision:<task>:<decision> | hire:<agent> | blocked:<task> | review:<task> | budget:<agent> | node:<id> | handoff:<id> | secret:<id> | ask:<id> | show:<call_id> | resume:<session>:<turn>` (`:68-101`). `agent` = "hire / budget items, the task owner, else the desk the session belongs to (104 A3)" (`:85-86`), computed by `desk_map(sessions)` (`:781-782`).
- `Inputs { tasks, packets, agents, approvals: Vec<(ApprovalRequested, u64)>, peers, handoffs, secrets, engines, asks, shows, desks, task_sessions, resumes }` → pure `derive(inputs, states, now_ms) -> Vec<AttentionItem>` (`:171-220`). The `Attention` kameo actor (`ATTENTION_ACTOR`, `:29-30`, `:617-629`) subscribes `ApprovalRequested`/`ApprovalResolved`/`ArtifactShown`/`AgentEvent` (`:940-1020`) and answers `ListAttention`, `SnoozeAttention`, `DismissAttention`, `ListHandoffs`, `ResolveHandoff` (`:140-169`, `:865-894`, `:1021-1062`). `Shown` rows (`attention_shows`: call_id, session, title, name, kind, mime, bytes, version, at_ms) (`:103-124`, `:800-838`); `ResumeNeed { session, turn, at_ms, detail }` (`:126-138`).
- RPCs: `attention_list() -> Vec<AttentionItem>` ("undismissed and unsnoozed, newest first. Badge = length") (`api.rs:1731-1734`); `attention_snooze(id, until_ms: u64)` (`:1735-1737`); `attention_dismiss(id)` (`:1738-1740`); `resume_turn(session) -> bool` (`:1741-1744`); `packet_get(key) -> Option<Packet>` (`:1745-1748`); `task_decide(decision, answer: String)` — free text, "the owner is re-woken" (`:1749-1751`). There is no `attention_resolve`: each kind resolves through its own RPC (§2.1).
- No "waiting for the user since" per session exists on the item beyond `at_ms` ("when the item arose", `:80-82`).

### 3.2 Asks (ask_user)
- `AskRequested { id: AskId, session: SessionId, questions: Vec<Question> }` (`crates/tools/src/ask.rs:84-91`); `Question { id, question, options: Vec<Choice>, recommended: Option<usize> }` (`:47-59`). Answered by `answer_ask(id: AskId, answers: Option<Vec<Answer>>) -> bool` — "one answer per question, or `None` to dismiss the set, which also cancels the turn. `true` if it was still pending" (`api.rs:575-578`).
- Dedupe with decision packets (105): an escalation produces both a `decision:<id>` blocker and an `AskRequested` card whose question id starts with `decision:`; `derive` skips such pending asks (knowledge `facts/theuth-escalation-raises-decision-and-ask-card-dedupe-105-2026-10-06`; the rule is in `attention.rs derive`, exact line unverified in the time box).
- The first item of every `subscribe_events` stream is `PendingPrompts { approvals: Vec<ApprovalRequested>, asks: Vec<AskRequested>, secrets: Vec<SecretsEvent> }` so a late subscriber still gets every pending card (`api.rs:1865-1881`).

### 5.4 Platform facts that constrain a companion
- Bundle targets macOS 15.0+ (`tauri.macos.conf.json:34-39`); `macOSPrivateApi: true` (needed by `tauri-nspanel` and transparency) (`tauri.conf.json:14`); Tauri 2.11.5 / tao 0.35.3 / wry 0.55.1 / tauri-nspanel 2.0.1 / global-hotkey 0.8.0 per the 96 recon (`96-point-and-say.md:276-278`; `Cargo.lock` not re-read).
- Hardened-runtime entitlements are only JIT + audio-input (`crates/desktop/entitlements.plist:5-10`); TCC usage strings only microphone + audio capture (`crates/desktop/Info.plist:5-10`). Screen Recording / Accessibility consent for point-and-say is carried by the engine's helper processes (96 §6.9; not re-read).
- The app has no Swift source and no SwiftUI/AppKit target; macOS-specific code is Rust over `objc2`/`objc2-app-kit` and `tauri-nspanel` (`crates/desktop/Cargo.toml:63-69`; `DESK/island/macos.rs:1-20`, `DESK/point/macos.rs:1-20`). Adding Swift means a new link rule set (see knowledge `facts/cargo-link-arg-does-not-propagate-rpath-swift-bridges-2026-10-07`: every binary-producing crate needs its own `-rpath /usr/lib/swift`).

## 6. Open seams and risks

1. **Hidden webviews are throttled.** Measured in the meeting phase: a `WKWebView` whose window is off screen "is throttled by WebKit to the point that its RPC client took 30–45 s to connect and, in one run, never did"; the fix was to never `orderOut` the island — alpha 0 + `ignoresMouseEvents`, ordered in at status level (`docs/design/meetings/03-island.md:368-379`; `DESK/island/macos.rs:51-62`). The same holds for the overlays ("an ordered-out WKWebView is throttled", `docs/design/96-point-and-say.md:79`). A rail/inbox panel that must react within a keystroke has to stay ordered-in and visible-ish the same way, or be native. The 96 state machine was put in Rust for exactly this reason: "it must own the timers while every webview may be hidden or throttled" (`96-point-and-say.md:56-61`). An Esc-undo 2 s timer and a 1/2/3 keystroke handler have the same constraint.
2. **Only the main webview registers JS global shortcuts.** `useGlobalShortcuts` returns early `if (AUX || !isDesktop())` (`UI/App.tsx:283`); 03 §0.1 warns a second webview "double-registers" (`03-island.md:24-26`); 96 §0.2 rejects a JS machine because "a second webview cannot register" (`96-point-and-say.md:59-61`). The Rust-side `voice_key_bind` path is the one precedent for a shell-owned chord (`DESK/point/mod.rs:111-147`). A Carbon hot key "swallows its chord in every other app while registered" (`96-point-and-say.md:36`), so 1/2/3, J/K, E cannot be global; they must be window-scoped keys of a panel that is key. The island is a `NonactivatingPanel` with `becomes_key_only_if_needed(true)` and only the request box ever takes key, handed back by `island_resign_key` (`DESK/island/macos.rs:25-27`, `:47-49`, `:92-100`) — a keystroke inbox would make a non-activating panel key while another app is frontmost, which is new ground here (unverified behaviour: whether key events reach a non-activating NSPanel's WKWebView without activating the app).
3. **Notification plugin usage is minimal.** `sendNotification({ title, body })` only; no action buttons, no click handler, no grouping/threading, no per-kind settings; nothing posts for asks/decisions/reviews/shows (`UI/lib/notify.ts:6-12`; `UI/App.tsx:366-378`). Whether `tauri-plugin-notification` 2.4 supports actions/click callbacks on macOS was not checked (unverified). iOS: local notifications only while the app runs; no push (`UI/lib/notify.ts:14-21`; grep `apns|push` over `crates/` empty).
4. **Engine events do not carry what a rail needs.** `SessionSummary` has `running: bool` and no state/since (`crates/agent/src/lib.rs:1492`); `SessionActivity` (on `AgentInfo` from `list_agents`/`list_activity`) has `state`, `last_active`, `turn_started_at`, `asks`, `live` but no "waiting for the user since" (`crates/agent/src/lib.rs:927-944`); `AttentionItem.at_ms` is "when the item arose" and `turn` is never set ("No source does yet", `crates/roster/src/attention.rs:80-82`, `:98-100`). There is no `AttentionChanged` event — the inbox is re-derived on 13 event types plus a 60 s poll (`UI/components/hud/queries.ts:24-43`), and `attention_list` is a full derive over tasks/packets/agents/approvals/peers/handoffs/secrets/asks/shows per call (`attention.rs:171-220`). A rail polling faster than the UI does would multiply that cost. Per-session "awaiting" for root sessions must be assembled client-side from `AskRequested`/`ApprovalRequested`/`TurnFinished` (the `PendingPrompts` snapshot gives the initial set, `api.rs:1865-1881`). The 128 brief names the same hole: "turn-pulse feed" and "session streaming flag engine-side (recency is a proxy)" (`brief-HUD-SCENE-DOC.md:71-72`).
5. **"Finished work" is not an inbox concept.** A root `TurnFinished` becomes a system notification when the window is hidden (`UI/App.tsx:370-378`) and nothing else; only `show` artifacts and `review` tasks are items. Suggested next steps for a finished turn have no engine source (§4).
6. **No undo.** Every inbox action is an immediate RPC that wakes the agent (`task_decide` "the owner is re-woken", `api.rs:1749-1751`; `answer_ask` with `None` "also cancels the turn", `:575-578`); the engine has no un-answer. An Esc-undo must be a client-side 2 s hold before sending, and the UI's `useAction` toasts "already answered" when the race is lost (`UI/components/hud/queries.ts:114-127`).
7. **Multi-engine state.** `attention_list`, `list_sessions`, `agents_list` are per engine; the desktop scopes every store to one active engine (`UI/App.tsx:405-417`, `UI/link/engines.ts:8-40`); `desk_open` is refused off the hub (`api.rs:1680-1682`); replicated kinds (secrets, handoffs) arrive by replication with a 60 s poll fallback (`hud/queries.ts:68-76`). A rail "showing every agent" across machines must fan out N subscriptions and merge client-side, or wait for a hub-side aggregate that does not exist.
8. **Window plumbing to extend.** A new window label must be added to `capabilities/default.json` `windows` (`:5`), to the `window_state` denylist/filter if it is placed by code (`DESK/lib.rs:263-268`), to the `CloseRequested → hide` rule (`:306-314`), to `paint_page_background`'s exclusions if transparent (`:470-473`), and to `App.tsx`'s `AUX` routing (`UI/App.tsx:55-65`). `island_show` keeps the top-left and clamps 300–1200 × 44–800; `island_place` is notch-centred (`DESK/island/macos.rs:76-90`, `:113-150`) — an edge rail needs its own placement. Capabilities lack `allow-set-ignore-cursor-events` / `allow-set-always-on-top` / `allow-cursor-position` (`capabilities/default.json`; `96-point-and-say.md:258-261`), so click-through regions are Rust-side only.
9. **Tray badge is approvals-only** (`UI/App.tsx:386-391`); the HUD/attention badge count is the list length (`attention.rs:12`) — two different numbers today.
10. **Swift/native option has no foothold yet**: no Swift in the tree, macOS code is `objc2` + `tauri-nspanel` (`crates/desktop/Cargo.toml:63-69`); a Swift bridge brings the rpath/link rules recorded in knowledge (§5.4). The Rust side "never proxies RPC" (`25-desktop.md:28-33`) — a native rail that needs engine data either opens its own WebSocket client in Rust (a new convention) or is fed by the main webview over Tauri events (as `voice-key:place` is, `UI/lib/tauri.ts:156-160`).
11. **Lagged streams.** A slow subscriber receives `Lagged` and the desktop reloads every store (`api.rs:1855-1856`; `UI/App.tsx:362-365`); a second long-lived subscriber (rail) doubles the event fan-out per connection.
12. **Design-129 desktop blank/freeze investigation** exists in the knowledge base (WebContent crash forensics, 2026-10-07) but no `129-*.md` is in `docs/design` — unverified whether its findings constrain adding another webview.

## 7. Implications for theuth (short)

- The pieces a companion needs already exist as separate mechanisms: a non-activating, capture-excluded, never-ordered-out NSPanel with notch placement (`DESK/island/*`), a Rust-owned global chord with a pure state machine and timers (`DESK/point/*`), a per-kind inbox with resolve RPCs (`attention.rs` + `KindActions`), and a hotkey→voice→desk router hard-wired to theuth's desk (`UI/lib/voice-key.ts`). What is missing is (a) keyboard answering + a client-side undo hold, (b) a per-session "state since" signal and a finished-work item kind on the engine side, (c) routing to a chosen agent and text entry in the panel, (d) notifications with actions and a settings page, (e) an edge-rail placement and a second shell-owned key scope.
- The two platform constraints that shaped 53/96 — throttled hidden webviews and single-webview shortcut registration — apply unchanged; any timer- or key-sensitive logic belongs in the Rust shell or in a visible panel, as 96 already decided.
