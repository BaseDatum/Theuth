## Deviations from R1.7 (and why)

1. **`Advisory.kind` carries `deserialize_with = "AdvisoryKind::or_review"` beside `default, flatten`.** serde_derive
   ignores `#[serde(default)]` on a flattened field (the generated code is `Deserialize::deserialize(FlatMapDeserializer)?`
   with no fallback, `serde_derive-1.0.229/src/de/struct_.rs:327-345`), so a 0034 row without a `kind` key would
   fail to parse. `or_review` reads `kind` / `question` through the flat map and maps a missing tag to `Review`;
   the wire shape is exactly R1.7's (`"kind":"review"` / `"kind":"consultation","question":…`), standalone
   `AdvisoryKind` keeps the derived strict tagged form, the TS binding is unaffected. Names unchanged.
2. **`ONE_SHOT_SYSTEM` is built by `const fn` splicing**, not by a string-replace at runtime: R1.7 wants a
   `pub const &str` "built from system.md at compile time" and `const_format` is not a dependency of `agent`
   (adding one is outside C's files). ~40 lines of const code (`find`, `split_at`, `splice`), covered by
   `one_shot_system_swaps_the_workflow_and_zeroes_the_cap`. Until W1 appends `<consultation>` to `system.md`,
   the one-shot prompt has no such section (by construction it will the moment W1's file lands).
3. **`ConsultSource` replies `Option<ConsultSourceInfo>`** — R1.7's comment says `Option<ConsultSource>` while
   R1.5 writes `Some(ConsultSource { advised, advisor, model, effort })`; the struct R1.7 actually declares for
   that payload is `ConsultSourceInfo`, so that is the reply type.
4. **`consult::parse` on a missing `question` key** returns `ERR_QUESTION` (R1.3 lists only "empty or over
   2000"); any other decode error is `consult: <serde error>`. `question`/`context` are trimmed; a blank
   `context` is `None`. `QUESTION_CHARS` / `CONTEXT_CHARS` are `pub` for W1's tests.
5. **`block()` prints `(none)` for an empty `partial`** so the paragraph shape is constant (the `<consultation>`
   prompt section names the `_agent's current step_` text).
6. **No clamp of `AdvisorConfig.max_consults` at the type**: the range (0–32) is enforced by the RPC consumer
   (W1's `SetAdvisorDefaults` handler, like `max_notes_per_update`); a hand-edited `config.yaml` value above 32
   reaches the actor as written (the same as `max_notes_per_update` today, which `identity()` clamps at use).
