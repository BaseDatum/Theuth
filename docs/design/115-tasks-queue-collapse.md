## The bug (Sky, 2026-10-06 16:48, iPad)

"There's a bug on the task screen under Agents in the theuth desktop app. Essentially, there's this like activity log that piles up above the task cards, and I can't scroll past it. So once it gets really big I literally can't see the task cards. For one, that should be collapsed by default into an accordion view or something like that. And two, even if it's expanded I should be able to scroll past it to actually get to the tasks." — "I'm experiencing this on iPad, so it's possible that it was fine on desktop and it just doesn't allow scrolling by touch on the iPad app."

Cause: the "activity log" is the 67 §12 `Queue` (blocked tasks whose first blocker is `decision:`/`person:`, reviews where you are the reviewer, proposed agents; one 32 px row each). It sat as a `shrink-0` `<ul>` with no cap directly in the page column (`article.flex.min-h-0.flex-1.flex-col`, which has no vertical overflow) above the board (`min-h-0 flex-1 overflow-x-auto overflow-y-hidden`), so every row was taken out of the board's height and nothing on the page could scroll vertically. Not a touch problem: a desktop window is taller, so it takes more rows before the columns vanish. Sky's real queue on this engine today is 51 rows (10 decisions · 41 reviews) = 1 632 px — taller than an iPad in either orientation.

## What changed

1. **Collapsed by default, one pinned row.** `Queue.tsx::QueueBar` is a full-width `<button>` (`h-8 bg-layer-1 border-b border-border-subtle text-[13px]`, lucide `ChevronRight` turning 90° on `data-state=open`) reading `▸ 19 need you · 16 decisions · 2 reviews · 1 proposed agent` — headline `text-foreground`, breakdown `text-fg-tertiary`. The words come from `helpers.ts::queueSummary({decisions, reviews, proposed})` (pure; zero kinds omitted, per-kind plurals, `1 needs you`, order decisions · reviews · proposed agents). Nothing renders when the queue is empty, as before. The choice is per device: `localStorage.theuth_tasks_queue_open` (`'1'` = open, anything else = closed; `useQueueOpen()` = lazy `useState` reader + writing setter, both in try/catch like `mock.ts::mockOn`). A fresh profile is collapsed.
2. **Open, the page scrolls past the list and the board gets the full height after it.** `Board.tsx` wraps bar + body in one Radix `Collapsible` root carrying the column-flex classes (`flex min-h-0 flex-1 flex-col`, so the height chain stays definite); under the bar a vertical scroller `div.flex.min-h-0.flex-1.flex-col.overflow-y-auto` holds `CollapsibleContent.shrink-0 → QueueList` and then the board, which keeps `ref={scroller}` (drag edge-scroll, horizontal), `overflow-x-auto overflow-y-hidden`, and gains `min-h-full flex-1`: closed, the board is exactly the scroller's height and nothing scrolls (desktop unchanged); open, the scroller's content is list + one full board, so scrolling to the bottom leaves the columns filling the screen from the bar down. The columns' own `h-full` + `overflow-y-auto` still resolve (post-flex sizes in a definite-height flex container are definite). No max-height on the list, no `overscroll-behavior`, no JS scrolling.
3. **`Queue.tsx` split** into `useQueue()` → `{decisions, reviews, proposed, total}` (the same two queries and filters), `QUEUE_OPEN_KEY`/`useQueueOpen()`, `QueueBar({items})` and `QueueList({items})` (rows, icons, links and classes unchanged). `Queue` itself is gone — it was mounted only in `Board.tsx` (`AgentDetail.tsx::TasksTab` has its own columns and is untouched). Option (a) of the brief: the Radix root lives in `Board` because trigger and content must share it; the trigger gets `aria-expanded`, `aria-controls` (while open) and `data-state` for free and `CollapsibleContent` unmounts the list when closed, which is exactly the conditional render option (b) would have hand-written.
4. **Test** `helpers.test.ts` "queue bar wording": the four-kind example, each kind alone (`1 needs you`), two kinds, all zero.

## Rejected

- A max-height on the list, or its own scroll region: Sky asked to scroll past it, and a third nested scroller (list inside page inside board) is the thing that traps a finger on iPad.
- Collapsing automatically past N rows: the choice is the user's and is remembered per device instead.
- `position: sticky` for the bar inside the scroller: a sibling outside it is simpler and collapsing from anywhere while scrolled never shifts the content under the finger.
- A plain `<button aria-expanded>` with a conditional list (option b): works too, but costs the same one div as the Radix root and loses the free trigger/content wiring.
