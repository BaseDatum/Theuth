# 140 as built — F4E CONFINE: a study session cannot touch anything outside its worktree

Branch `feat/140-f4e` from `fix/140-tab-agents` (c96bcf1d). Brief: `~/.theuth/briefs/2026-10-08/140/140-F4E.md`. Live defect: `140-as-built-P.md` defect 4 (the study session edited the user's checkout because file tools resolved relative paths against the engine's process cwd).

## What was found first (changes the brief's premise)

- The schedule file's `cwd:` reached **nothing** in a native session. `schedule::new_session` → `agent::NewSession { cwd }` → `Agents` writes `sessions.cwd` (a column only the external ACP harness reads). `ShellTool::build_shell` seeded every session shell from `std::env::current_dir()`; `start` (pty) and the file tools likewise. The docs (`33-loops.md` D9, `loops.md`, `routines.md`: "the session starts here") described an intent, not the code. So "the directory the shell already uses" did not exist; this wave creates the carrier and seats the shell too (deviation 1).
- No per-session cwd or write-root mechanism existed in `tools`/`agent`; the only path-rooting idiom was the sensor bridge's `Bridge::rooted`.
- Fan-out: `ToolCx {` has ~40 literals in 30 files, `SessionResources {` 13 literals in 10 crates (and its module doc says it is "not a filesystem routing service"). Neither was touched. The carrier is a process-wide session-keyed map, the idiom the schedule's confinement registry (`CONFINED`), `registry::REPUBLISH` and `wave::CHILDREN` already use.

## Built, file by file

**`crates/tools/src/seat.rs` (new)** — `Seat { cwd: Option<PathBuf>, write_root: Option<PathBuf> }` per `SessionId` in a `LazyLock<Mutex<HashMap>>`. `set_cwd`, `set_write_root` (an all-`None` seat is dropped), `seat_of`, `inherit(child, parent)` (copies the parent's seat unless the child was seated first), `forget`. Resolution: `resolve(session, path)` joins a relative path to the seated cwd, else returns it unchanged (the OS resolves against the process cwd — unseated sessions behave exactly as before); `cwd(session)` is the seated cwd else `std::env::current_dir()`; `writable(session, path)` = `resolve` then, when a write root is seated, canonicalise the root and the path's longest existing prefix (the file may not exist yet) and require `starts_with`; `..` into a non-existent tail or an unresolvable path is refused; symlinks are followed on both sides (a link inside the root pointing out is refused; a root under `/tmp` → `/private/tmp` is not). Error: `<path>: outside this session's write root <root> — this session may only write inside it`. Tests: resolution, inheritance, the write-root matrix (existing / new / new-under-new-dir inside; absolute, `..`, `src/../..`, unresolvable, symlink outside; no root → pass).

**`crates/tools/src/fs.rs`** — `read_file`, `write_file`, `list_dir`, `grep` take `cx` and go through `seat::resolve` (reads, `grep` default root = `seat::cwd`) or `seat::writable` (`write_file`, which also creates parents under the resolved path). Arg docs and descriptions say "working directory" instead of "process cwd". Tool-level test `seated_session_resolves_relative_paths_and_confines_writes`: unseated relative read → ENOENT; seated: `a.txt` reads, `list_dir "."` lists the worktree, a read outside the root passes, a relative write lands in the worktree, `write_file ../elsewhere.txt` and `edit <abs outside>` are refused naming the root and the outside file is unchanged.
**`crates/tools/src/edit.rs`** — `edit` resolves through `seat::writable` (the atomic tmp file is a sibling of the resolved path, so it stays inside too). **`glob.rs`** — root through `seat::resolve` / `seat::cwd`. **`shell.rs`** — `ShellTool::session` builds the session shell at the seated cwd (`set_working_dir`) on first use; persistent shell semantics unchanged. **`pty.rs`** — `start` resolves an explicit `cwd` against the seat and falls back to `seat::cwd` when no session shell exists yet. **`registry.rs`** — `SetParent` → `seat::inherit`; `Forget` (tree close) → `seat::forget`. **`lib.rs`** — `pub mod seat`, `pub use seat::Seat`.

**`crates/schedule/src/lib.rs`** — the fire seats the session from the file's `cwd:` on every fire (`tools::seat::set_cwd(session, cwd)`, right after the session is chosen/created, before `SetBudget`). The confinement resolver now returns `Confine { toolset: agent::Toolset, write_root: Option<PathBuf> }` (`ToolsetResolver` output `Result<Option<Confine>, String>`; `Confinement::Confined(c)`); the fire calls `tools::seat::set_write_root(session, c.write_root)` immediately before `agent::SetToolset` — race-free by construction (the R-5/R-115 lesson: confinement is applied by the schedule before the prompt, never after the fact from an event). An unconfined schedule never touches the write root.

**`crates/autoresearch/src/binding.rs`** — `confinement` returns `Confine { toolset(parallel), write_root: Some(worktree) }` for a Running/Paused study; a live study **without** a worktree now refuses the fire (`Err("study … has no worktree yet")`) instead of firing unconfined. New `seat(session, worktree)` / `unseat(session)` (cwd + write root together). Tests: `confinement_resolves_live_studies_only` asserts the write roots and the no-worktree refusal; `seat_and_unseat_round_trip`.
**`crates/autoresearch/src/actor.rs`** — `begin_slot`: after `resolve_env` the slot child is seated in `cand-<k>` (only when the caller is a registered child; the supervisor acting as a slot is not moved). `recover`: `binding::seat` before the re-applied `SetToolset` (the 109-resumed turn runs before the next fire). `set_state_if` to a terminal state and `finalize_task`'s `Finished` patch call `binding::unseat(study.session)`. Finalizing keeps the seat on purpose: the report turn (§11.3) still runs in the study session.
**`crates/autoresearch/src/wave.rs`** — a child's `TurnFinished` unseats it. Test `child_round` (every wave test) asserts the child's seat is `cand-<k>` for both cwd and write root and that the supervisor's write root did not move.
**`crates/autoresearch/src/actor/tests.rs`** — `started` seats the session exactly as the fire does (through the real `confinement` resolver, asserting the write root is `<root>/<slug>/worktree`); `stop_now_interrupts_the_experiment_in_flight` asserts the write root holds through Finalizing and the seat is default once Finished.

**`crates/agent`** — two functions only: `frame::baseline_dated` gains a `cwd: &Path` parameter (the header's `Working directory:` line; `frame::baseline` passes the process cwd, so the supervisor's and the tests' output is unchanged) and `loop_::Turn::new` sets `Turn.cwd = tools::seat::cwd(shared.id)` (was the process cwd) and the turn's baseline call passes `&self.cwd`. Knowledge hints/harvest and the python `/cwd` mount read `Turn.cwd` and therefore follow the seat as well. `advisor_baseline` untouched.

**`docs/design/140-autoresearch.md` §8.3** — the "what this does not stop" paragraph now states the as-built confinement.

## Deviations from the brief

1. **The shell was not seated by `cwd:`** (brief ruling 1 assumed it was). Seating now covers the file tools *and* the session shell / `start`, so `cwd:` finally means what 33 D9 and the routines docs say. Ruling 2's "shell commands are already seated by `cwd:`" is now true; the shell is still not sandboxed, as ruled.
2. **Carrier is a process-wide map, not a field.** Neither `ToolCx` nor `SessionResources` grew a field (40 / 13 literals across crates I do not own; `SessionResources` is documented as not a routing service). `tools::seat` follows the existing registry idiom; the tool registry wires inheritance and forgetting.
3. **The write root is applied by the schedule, not by the plugin on `Fired`.** `Fired` is an event the plugin's actor handles asynchronously — a study measuring in another `Run` would delay it past the new session's first tool call. Extending the resolver (`Confine`) keeps it on the schedule's synchronous pre-prompt path beside `SetToolset`, which is where the brief's "beside `SetToolset`" actually lives. The plugin registers the root itself only where no fire happens (`recover`, slot children).
4. **"Clears at finish/stop"** = when the study reaches a terminal state (Finished / Failed / Discarded) and when a slot child's turn ends. Finalizing keeps the seat (the report turn runs in the study session; nothing should write outside the worktree then either).
5. No schedule-crate test for the seat line: `fire` returns `agent is not running` before reaching it in the crate's harness (no `Agents` actor); the tools and autoresearch tests cover the seat, and `started` exercises the real resolver output.

## Hand-offs

- `agent::NewSession`, `new_root` (ACP `session/new` cwd) and `spawn_subagent { cwd }` for **native** children still only write `sessions.cwd` (native spawn drops `cwd` entirely, `supervisor.rs:4177`). Seating them is three one-liners (`tools::seat::set_cwd` beside each `store.set_cwd`) plus a restart story (re-seat from the row when a session actor attaches); left out to keep the agent diff to the two functions above. Wave slot children do not need it: the plugin seats them at `experiment_begin{slot}`; before that they inherit the supervisor's seat through `SetParent`.
- Other crates' writing tools (`document`, `artifact`, `knowledge`, …) do not consult the write root; the study toolset does not list them. Any future tool that writes a model-given path should call `tools::seat::writable`.
- `advisor_baseline` still prints the process cwd (advisor sessions are never seated).
- Docs `crates/schedule/loops.md`, `routines.md`, `33-loops.md` D9 now match the code; no wording change needed.
