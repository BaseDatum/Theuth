## Executive summary

Ten mechanisms most worth borrowing (techniques only — GPL-3):
1. Clipboard **lease**: snapshot all pasteboard items, write with Transient/Concealed/AutoGenerated + session-id markers, Cmd+V, return at once, settle at 500 ms only if the clipboard is still ours (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L644-L722`, `Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L808-L833`).
2. **Paste verification** by AX value/count/caret at 150/350/1000 ms → "paste not landed" card with the transcript (`Sources/Fluid/Services/PasteVerifier.swift#L72-L121`).
3. **Three-way target assessment** (editable / certainly-not / unknown), refuse only when certain; containers stay unknown for web editors, GPU terminals, VMs (`Sources/Fluid/Services/DeliveryTargetAssessment.swift#L25-L70`).
4. **Automatic dictionary learning**: watch the field 30 s after insertion, single-word non-inflection edits, ask only after 2 repeats in 7 days, 7-day dismiss cooldown, ≤3 ignores/session (`Sources/Fluid/Services/AutomaticDictionaryCorrectionTracker.swift#L5-L10`, `Sources/Fluid/Services/DictionaryCorrectionEditPolicy.swift#L6-L40`).
5. **Acoustic grounding of corrections**: keep the PCM 120 s, map the edit back to the spoken occurrence by context, thresholds 0.70/0.85, negatives may veto never accept (`Sources/Fluid/Services/DictionaryLearningEvidence.swift#L13-L75`, `Sources/Fluid/Services/DictionaryPronunciationDecision.swift#L6-L25`).
6. **Self-expansion guard** for replacement rules (Git→GitHub never yields GitHubHub) (`Sources/Fluid/Services/DictionaryReplacementProtection.swift#L3-L6`).
7. **Spoken "send it"** armed by partials, sticky across re-decodes, near-miss tolerance len/5, auto-stop after 1.5 s settle + 0.35 s silence, never in secure fields (`Sources/Fluid/Services/SpokenSendParser.swift#L37-L99`, `Sources/Fluid/Services/TypingService.swift#L47-L60`).
8. **Context-gated spoken punctuation** + removal of ASR's own punctuation beside spoken symbols; slash-command/@mention formatting with terminal-autocomplete spacing (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L635-L874`, `Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L236-L262`).
9. **Per-app prompt bindings** (bundle id → prompt profile, per shortcut slot) deciding both whether AI runs and which prompt; app name + window title as context (`Sources/Fluid/Services/DictationAIPostProcessingGate.swift#L22-L36`, `Sources/Fluid/Persistence/SettingsStore.swift#L329-L329`).
10. **Hotkey hygiene**: Automatic mode (tap < 0.4 s toggles, hold = push-to-talk) (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L313-L313`), modifier-only keys by physical keycode (fn = 63, left/right distinct), chord-cancels-release, repeats never toggle, other mode key switches mode, overlay on the pointer's screen (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L1682-L1688`, `Sources/Fluid/Services/GlobalHotkeyManager.swift#L1806-L1808`, `Sources/Fluid/Services/OverlayScreenResolver.swift#L9-L12`).

Surprises: command mode is ONE tool (`execute_terminal_command` in zsh, 30 s, 20 turns) with osascript recipes in the prompt and a substring deny-list for confirmation; WebRTC APM is used only for meetings, not dictation; the Local API (127.0.0.1:47733, loopback-only, no token) exposes transcribe/postprocess/history/dictionary but not command mode.


## A1 Capture front-end

- **WebRTC APM is NOT on the dictation mic.** The only references to WebRTC/AEC in Sources are in `Services/Meeting/AEC/` (meeting echo cancellation of system playback vs mic) (`Sources/Fluid/Services/Meeting/AEC/MeetingAECModels.swift#L5-L50`). Dictation capture has no AEC/NS/AGC (Not found: grep `WebRTC|webrtc` outside Meeting/).
- Capture goes through a custom `DirectCoreAudioInput` (1,878 lines) rather than only AVAudioEngine, with an `AudioEngineRetirementDrain`, a `BoundedAudioHardwareQueue`, and `AudioTopologyDiagnostics` for device graphs (file inventory; `Sources/Fluid/Services/DirectCoreAudioInput.swift#L1-L40`).
- **Startup gate**: a single shared gate that defers any CoreAudio/AVFoundation initialisation until SwiftUI's launch work is done, because early init raced AttributeGraph and crashed with EXC_BAD_ACCESS (`Sources/Fluid/Services/AudioStartupGate.swift#L3-L40`).
- **Readiness / silent-device detection**: capture is declared not-ready when 3 consecutive windows have RMS ≤ 1e-5 and peak ≤ 5e-5 (a dead or still-settling route); same-device retries are admitted within a 5 s window and an admitted attempt keeps its full readiness timeout so a settling Bluetooth route is not cancelled (`Sources/Fluid/Services/AudioCaptureIdlePolicy.swift#L72-L105`, `Sources/Fluid/Services/AudioCaptureReadinessGate.swift#L1-L30`).
- Level/spectrum: `AudioSpectrumMeter` feeds the waveform (`Sources/Fluid/Services/AudioSpectrumMeter.swift#L1-L30`); VAD level threshold 0.12 is reused for spoken-send silence (`Sources/Fluid/Services/SpokenSendParser.swift#L39-L41`).
- Latency: `TypingService.recordInsertionLatency` records requested-at → text-ready → command-posted per delivery path and `appBench` lines time AI routing (`Sources/Fluid/Services/TypingService.swift#L689-L714`, `Sources/Fluid/ContentView.swift#L2744-L2746`). No published press-to-first-word numbers found in source (Not found: grep `first.?word|firstPartial` constants).
- Idle policy is about *prewarm*, not unload: an idle-prewarm request reconciles input selection and keeps the engine warm so the next press starts fast (`Sources/Fluid/Services/AudioCaptureIdlePolicy.swift#L46-L60`).

### More capture details
- **Realtime-safe ring**: `DirectCoreAudioInput` registers an `AudioDeviceIOProc` that publishes native hardware-cycle PCM into a fixed single-producer/single-consumer ring written in C; a Swift drainer does resampling, level calculation, logging and ASR buffer mutation away from Core Audio's realtime thread (`Sources/Fluid/Services/DirectCoreAudioInput.swift#L367-L372`). Stop synchronously drains every packet already published before returning (`Sources/Fluid/Services/DirectCoreAudioInput.swift#L493-L494`).
- **Device-change handling**: no HAL calls in the device-list notification path; multiple events collapse into one fresh setup at the next stopped start (`Sources/Fluid/Services/DirectCoreAudioInput.swift#L816-L817`); HAL discovery runs on its own queue and a blocked discovery cannot hold the caller (`Sources/Fluid/Services/DirectCoreAudioInput.swift#L888-L889`).
- **First-PCM readiness gate**: each capture attempt is armed with (session, attempt) ids and waits for the first PCM packet; timeout `firstPCMTimeoutNanoseconds = 2_000_000_000` (2 s); a format invalidation cancels the wait (`Sources/Fluid/Services/AudioCaptureReadinessGate.swift#L29-L44`, `Sources/Fluid/Services/AudioCaptureReadinessGate.swift#L107-L128`, `Sources/Fluid/Services/ASRService.swift#L871-L871`).
- Route recovery delay 300 ms and an **8 s audio-engine standby** after a recording (engine kept alive briefly so a quick re-press is instant) (`Sources/Fluid/Services/ASRService.swift#L2082-L2086`). After stop, the "final transcription" status only appears if finishing takes > 250 ms; the streaming drain may take up to 30 s (`Sources/Fluid/Services/ASRService.swift#L492-L493`).
- **Microphone selection**: user-ordered priority list with migration, suppressed device UIDs, devices unavailable with the lid closed are skipped (clamshell), fallback to system default then first input; a startup notice is scheduled only after the selection settles (`Sources/Fluid/Services/MicrophonePreferenceCoordinator.swift#L61-L71`, `Sources/Fluid/Services/MicrophonePreferenceCoordinator.swift#L293-L310`, `Sources/Fluid/Services/MicrophonePreferenceCoordinator.swift#L385-L420`).
- **Media pause while dictating**: one reconciler owns all media queries/commands; recording events update intent synchronously and never wait on media control or delay first PCM; a slow query cannot issue a pause after the key is released; an older transcription finishing cannot resume a newer recording's media (`Sources/Fluid/Services/MediaPlaybackService.swift#L3-L4`, `Sources/Fluid/Services/MediaPlaybackService.swift#L45-L56`). Query timeout 2.5 s, command timeout 1.0 s (`Sources/Fluid/Services/MediaPlaybackTransport.swift#L47-L48`).
- Live-preview silence threshold 0.04 with a 2-sample history for the overlay level (`Sources/Fluid/Services/ASRService.swift#L7811-L7812`).

- Parakeet realtime: FluidAudio `StreamingEouAsrManager` with a default **160 ms chunk** (`StreamingChunkSize.ms160`); the end-of-utterance model ships as the `parakeet-eou-streaming` model dir (`Sources/Fluid/Services/ParakeetRealtimeProvider.swift#L15-L20`, `Sources/Fluid/Services/ParakeetRealtimeProvider.swift#L62-L62`, `Sources/Fluid/Services/ParakeetRealtimeProvider.swift#L227-L260`).
- Nemotron: chunked decoding where chunk ends are moved to a low-energy point — search radius 32,000 samples (2 s @16 kHz), analysis window 1,280, stride 320, minimum final chunk 16,000 samples (1 s) (`Sources/Fluid/Services/NemotronProvider.swift#L57-L60`, `Sources/Fluid/Services/NemotronProvider.swift#L371-L380`).
- Model catalog: `CompactSpeechModelReleaseCatalog` reads a release manifest, entries carry archive URL + **SHA-256**, rejected manifest hashes are remembered (`Sources/Fluid/Services/CompactSpeechModelReleaseCatalog.swift#L140-L147`, `Sources/Fluid/Services/CompactSpeechModelReleaseCatalog.swift#L212-L212`); `ParakeetSpeechModelCatalog`, `SpeechModelFeed`, `SpeechModelInstallationSnapshot` and `ModelRepository` manage install state (file inventory).
- Vocabulary biasing: Parakeet CTC keyword boosting, ≤ 256 terms (A3) (`Sources/Fluid/Services/ParakeetVocabularyStore.swift#L79-L84`).
- Local LLM residency: the private AI model has an idle unloader and a meeting-residency coordinator so summary and dictation enhancement never load two big models at once (`Sources/Fluid/Services/PrivateAIIntegrationService.swift#L274-L313`, `Sources/Fluid/ContentView.swift#L2721-L2724`).
- File transcription: `FileTranscriptionService` (906 lines) and `POST /v1/transcribe` on the Local API (`Sources/Fluid/Services/LocalAPI/LocalAPIRouter.swift#L28-L29`).

### More engine details
- Nemotron variants are labelled "Nemotron Speech 3.5 - Ultra Fast Low Latency" and map to `nemotron-3.5-asr-streaming320-int8-CoreML` (320 ms streaming chunks, int8 Core ML) (`Sources/Fluid/Services/NemotronProvider.swift#L9-L26`).

## A3 Transcript shaping (between STT and the target)

### Order of shaping
Raw ASR text → spoken-punctuation formatter (if enabled) → literal/slash-command/@mention formatter → dictionary replacements → optional AI post-processing → output plan delivered to the target (see A4). The AI gate is resolved once at stop time into a `DictationStopSnapshot` (route, prompt, usesAI, appInfo) so changes during processing do not alter the decision (`Sources/Fluid/ContentView.swift#L3034-L3036`, `Sources/Fluid/ContentView.swift#L2727-L2743`).

### Spoken punctuation (deterministic, no model)
- Entire pass is skipped unless `autoConvertPunctuationEnabled` (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L4-L16`); user-defined dictionary punctuation rules and "action rules" (line break, paragraph break, tab, single space) are merged with built-ins (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L110-L123`, `Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L184-L212`).
- Built-in table is a phrase → symbol map with a spacing class per symbol (right-attached for `, . ? ! : ;`, left-attached for open brackets/`$`, spaced for `+ = & —`, special handling for `-` and quotes) (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L214-L241`, `Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L250-L290`). ~40 symbols incl. "at the rate", "hash/hashtag/pound sign", "backtick", "tilde", "pipe".
- Ambiguous words are context-gated: "dot" only becomes `.` with dot context (domains, file names: `requiresDotContext`), "slash" only in a path context, operators like "plus"/"equals" only next to short symbol operands (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L261-L266`, `Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L635-L660`, `Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L695-L726`).
- Clean-up of ASR-generated punctuation around spoken symbols: removes the ASR's own commas, sentence periods beside actions, trailing generated periods and leading punctuation (`Sources/Fluid/Services/ASRService+SpokenPunctuationFormatting.swift#L802-L874`). This is the trick that makes "comma" not produce ", ,".

### Literal formatting for developer targets
- Separate pass builds a `DictationLiteralOutputPlan`: spoken slash commands ("slash compact" → `/compact`) only when there is spoken lead-in context and the token is valid, with a rejected-token list (`Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L101-L140`, `Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L263-L318`); @mentions ("at Claude" → `@claude`) with rejected tokens and possessive detection, relaxed lead-ins only in specific apps (`Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L141-L152`, `Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L374-L407`).
- Terminal autocomplete spacing: in apps detected as slash-command autocomplete apps (terminals/agent CLIs by app name, bundle id or window title) the output plan adjusts trailing whitespace so the CLI's autocomplete menu is not dismissed (`Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L236-L262`, `Sources/Fluid/Services/ASRService+DictationLiteralFormatting.swift#L408-L418`).

### AI post-processing layer
- Gate: AI runs only if the resolved prompt selection for the shortcut slot **and the frontmost app's bundle id** is not `.off`, and the route's provider is configured/verified (or the private local model is installed) (`Sources/Fluid/Services/DictationAIPostProcessingGate.swift#L22-L36`). Local endpoints (localhost, 10/8, 172.16–31, 192.168/16) need no API key (`Sources/Fluid/Services/DictationAIPostProcessingGate.swift#L105-L119`, `Sources/Fluid/Services/DictationPostProcessingService.swift#L279-L282`).
- Two paths. (a) "Fluid Intelligence" private on-device model: gets app name, bundle id and **window title** as context, uses a stable-prompt-prefix KV cache, a "boost" mode, a context limit 2048…8192 tokens in 512 steps, and can stream (`Sources/Fluid/ContentView.swift#L2761-L2796`, `Sources/Fluid/Persistence/SettingsStore.swift#L32-L33`). (b) Any OpenAI-compatible provider via `LLMClient`: system prompt + transcript as user content, temperature 0.2 (nil for models that reject it), optional reasoning parameter (`reasoning_effort` / `enable_thinking`), streaming with a non-streaming retry on failure, 120 s timeout on the batch path (`Sources/Fluid/Services/DictationPostProcessingService.swift#L284-L303`, `Sources/Fluid/ContentView.swift#L2876-L2946`). Thinking tokens are stripped by dedicated parsers and only logged (`Sources/Fluid/ContentView.swift#L2955-L2960`, `Sources/Fluid/Services/ThinkingParsers.swift#L1-L40`).
- Context sent for cloud dictation: app name, bundle id and window title are logged as "app context for AI" (`Sources/Fluid/ContentView.swift#L2842-L2843`). Selected text is **not** sent in dictation mode (trace says "<none (dictation mode)>") (`Sources/Fluid/ContentView.swift#L2771-L2771`). No screen capture found (Not found: grep for `CGWindowListCreateImage|ScreenCaptureKit` in the dictation path).
- Every result passes through `applyGAAVFormatting` after the model (`Sources/Fluid/Services/DictationPostProcessingService.swift#L307-L311`). Latency/tokens-per-second are recorded per call (`Sources/Fluid/ContentView.swift#L2803-L2808`).

### Per-app prompt sets
- Prompt profiles (`DictationPromptProfile`) plus `AppPromptBinding` records (mode + bundle id → profile) persisted as JSON in UserDefaults; resolution takes the shortcut slot and the recording app's bundle id (`Sources/Fluid/Persistence/SettingsStore.swift#L271-L271`, `Sources/Fluid/Persistence/SettingsStore.swift#L329-L329`, `Sources/Fluid/Persistence/SettingsStore.swift#L443-L458`, `Sources/Fluid/Persistence/SettingsStore.swift#L748-L748`, `Sources/Fluid/Persistence/SettingsStore.swift#L872-L880`). Multiple dictation shortcut slots (primary/secondary…) each carry their own prompt selection.

### Custom vocabulary and the AUTOMATIC dictionary-learning loop
1. **Observe.** After delivery, `AutomaticDictionaryCorrectionTracker.beginObservingInsertion` watches the target field via AX (value/selection/focus notifications) for up to 30 s, with 20 verification attempts × 50 ms, a 1 s completion signal and a 3 s inactivity fallback; fields over 100,000 chars are ignored; AX probes run off the main thread so they never delay the paste event tap (`Sources/Fluid/Services/AutomaticDictionaryCorrectionTracker.swift#L183-L188`, `Sources/Fluid/Services/AutomaticDictionaryCorrectionTracker.swift#L200-L230`).
2. **Detect.** `AutomaticDictionaryCorrectionDetector` diffs before/after text, requires the change to lie inside the inserted range, expands to a token, and accepts only single-word candidates ≤ 40 chars (≤ 70 combined), with ≥ 2 alphanumerics and a letter on both sides and a real semantic difference (`Sources/Fluid/Services/AutomaticDictionaryCorrectionDetector.swift#L29-L30`, `Sources/Fluid/Services/AutomaticDictionaryCorrectionDetector.swift#L210-L238`).
3. **Policy.** `DictionaryCorrectionEditPolicy.allows`: single word both sides, case-only edits allowed (brand capitalisation), but English inflections (`'s`, `s`, `es`, `ies`, `ed`, `ing`) are rejected so grammar fixes never become dictionary rules (`Sources/Fluid/Services/DictionaryCorrectionEditPolicy.swift#L6-L40`).
4. **Ask, rarely.** `AutomaticDictionarySuggestionPolicy`: the same correction must occur ≥ 2 times in a 7-day window; dismissed pairs cool down 7 days; at most 3 ignores per session (`Sources/Fluid/Services/AutomaticDictionaryCorrectionTracker.swift#L5-L10`, `Sources/Fluid/Services/AutomaticDictionaryCorrectionTracker.swift#L60-L90`).
5. **Acoustic evidence.** The original 16 kHz PCM of the dictation is kept for 120 s (max 15 min) (`Sources/Fluid/Services/DictionaryLearningEvidence.swift#L13-L15`) and the correction is resolved back to the *spoken occurrence* using ±8 context tokens — never by spelling alone (`Sources/Fluid/Services/DictionaryLearningEvidence.swift#L65-L75`). A background service encodes it with the already-loaded ASR models and cancels immediately when the user starts speaking (`Sources/Fluid/Services/DictionaryAudioLearningService.swift#L6-L6`, `Sources/Fluid/Services/DictionaryAudioLearningService.swift#L50-L50`, `Sources/Fluid/Services/DictionaryTemporalEncoder.swift#L6-L6`).
6. **Optional training session.** A guided UI records the word a few times (endpoint detector, 4096-sample chunks), adds variants, can confirm a wrong match, and saves triggers (`Sources/Fluid/Services/AutomaticDictionaryTrainingSession.swift#L138-L296`, `Sources/Fluid/Services/DictionaryTrainingEndpointDetector.swift#L7-L7`).
7. **Match.** Pronunciation acceptance threshold 0.70 for a known observed variant or a profile without original audio, 0.85 for a new heard text, user override clamped to 0.4…0.95 (`Sources/Fluid/Services/DictionaryPronunciationDecision.swift#L6-L25`). Possessives are preserved ("Kubernetes's") unless explicitly taught (`Sources/Fluid/Services/DictionaryPronunciationDecision.swift#L30-L45`). Negative examples (unchanged delivered utterances) may **veto** an acceptance but never create one (`Sources/Fluid/Services/DictionaryExperimentalMatcher.swift#L145-L145`, `Sources/Fluid/Services/DictionaryNegativeExamples.swift#L25-L26`).
8. **Protect.** `DictionaryReplacementProtection` stops a rule from re-expanding a completed occurrence of its own replacement (e.g. "Git" → "GitHub" must not turn "GitHub" into "GitHubHub") (`Sources/Fluid/Services/DictionaryReplacementProtection.swift#L3-L6`).
- Separately, Parakeet vocabulary boosting (CTC keyword spotting in FluidAudio): JSON store in Application Support, alpha 2.8, min similarity 0.72, min combined confidence 0.64, min term length 3, max 256 terms (`Sources/Fluid/Services/ParakeetVocabularyStore.swift#L79-L84`), configured into the ASR manager with CTC models (`Sources/Fluid/Services/FluidAudioProvider.swift#L585-L587`).

### Spoken "send"
- Phrase default "send it" (`Sources/Fluid/Persistence/SettingsStore.swift#L6043-L6044`); saying "literal send it" dictates it normally (UI copy, `Sources/Fluid/UI/SettingsView.swift#L2994-L2994`). User picks the send key (Return variants) (`Sources/Fluid/UI/SettingsView.swift#L3025-L3029`).
- Streaming partials **arm** the send; once armed it stays armed while later partials have no more words (because re-decoding flips "send it"/"sent it"/"send") (`Sources/Fluid/Services/SpokenSendParser.swift#L72-L82`). At the final transcript an armed send also accepts a near miss with tolerance max(1, len/5) for phrases ≥ 5 chars, and none for short phrases ("end" must not pass as "send") (`Sources/Fluid/Services/SpokenSendParser.swift#L84-L99`).
- "Send immediately" mode: an armed phrase starts a countdown that auto-stops recording after 1.5 s settle with ≥ 0.35 s silence (VAD level threshold 0.12, 0.35 s voice-activity grace) and the notch shows a detected/counting-down indicator (`Sources/Fluid/Services/SpokenSendParser.swift#L37-L41`, `Sources/Fluid/ContentView.swift#L3827-L3875`).
- The Return keypress is a post-insertion action, refused in secure fields and only after physical modifiers are released (`Sources/Fluid/Services/TypingService.swift#L47-L60`, `Sources/Fluid/Services/TypingService.swift#L872-L904`).

### Prompts and the data envelope
- Default dictation prompt is one line: "Make the smallest edits needed to turn the supplied transcript into readable writing." (`Sources/Fluid/Persistence/SettingsStore.swift#L1043-L1047`). The older, long prompt (kept only to recognise saved prefixes) listed: remove fillers/false starts, format, spoken numbers to digits, execute "new line/bold/header/bullet", apply self-corrections ("no wait", "scratch that"), expand abbreviations, never answer questions (`Sources/Fluid/Persistence/SettingsStore.swift#L1049-L1075`). The move from rules-in-prompt to deterministic formatters + a minimal prompt is itself a lesson.
- **Prompt-injection envelope**: `DictationPromptRequest` keeps instructions in the system prompt and puts the transcript into the user message as JSON (`{"transcript": …}`) so quotes, newlines or delimiter look-alikes in speech cannot escape the data block; a user prompt containing `${transcript}` is rendered as a template instead (`Sources/Fluid/Services/DictationPromptRequest.swift#L3-L26`).
- Edit-mode hidden base prompt: "helpful writing assistant… Output ONLY what the user requested" (`Sources/Fluid/Persistence/SettingsStore.swift#L1077-L1083`). Prompt modes are `dictate` and `edit` (legacy `write`/`rewrite` decode as edit) (`Sources/Fluid/Persistence/SettingsStore.swift#L161-L165`).

### Per-app session memory and undo
- `DictationAppSession` is event-driven and memory-only: it remembers a per-app prompt choice picked from the overlay, watching app activation even while the overlay is hidden so A → B → A returns to A's choice (`Sources/Fluid/Services/DictationAppSession.swift#L5-L48`, `Sources/Fluid/ContentView.swift#L4893-L4896`).
- **Undo AI**: a notch action restores the latest history entry's raw (pre-AI) text and re-applies it as output, only if that entry was AI-processed (`Sources/Fluid/ContentView.swift#L4884-L4886`, `Sources/Fluid/ContentView.swift#L4204-L4224`).


## A4 Delivery into the target

### Delivery strategy: direct-AX/CGEvent first, clipboard-paste lease second
- Two delivery modes. In "reliable paste" mode (or as fallback) text goes through the clipboard; otherwise a direct insertion is tried first and the clipboard is the fallback path, with a "clipboardFallback" analytics label (`Sources/Fluid/Services/TypingService.swift#L536-L563`).
- Direct insertion order: CGEvent unicode insertion posted to the focused PID first ("most reliable for Terminals, Electron apps") (`Sources/Fluid/Services/TypingService.swift#L826-L833`), then an AX cascade — insert at selected range → set AXValue → set AXSelectedText → insert at insertion point (`Sources/Fluid/Services/TypingService.swift#L1212-L1243`). CGEvent unicode strings are chunked at 200 chars (`Sources/Fluid/Services/TypingService.swift#L905-L905`). Synthesised events carry a user-data tag `0x46565353` ("FVSS") so the app can ignore its own keystrokes (`Sources/Fluid/Services/TypingService.swift#L7-L7`).
- Ghostty gets special PID routing (`Sources/Fluid/Services/TypingService.swift#L379-L410`); Xcode and Notes have AppleScript-based text snapshots because their AX is unreliable (`Sources/Fluid/Services/TypingService.swift#L1332-L1376`).

### Clipboard lease (pasteboard preservation)
- `PasteDeliveryCoordinator.deliver` serialises all deliveries through a single slot, snapshots the full pasteboard (all items/representations, capped at 32 MiB per representation, images ≤16 MiB converted portably) (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L128-L131`), writes the transcript, posts Cmd+V, then returns `.commandPosted` immediately so the UI can finish while a lease keeps the slot (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L644-L722`).
- The temporary clipboard item is marked with the nspasteboard.org conventions — source bundle id, TransientType, AutoGeneratedType, ConcealedType — plus a private session-id type, so clipboard managers skip it and the app can later prove ownership (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L247-L256`).
- Settlement runs after `defaultSettlementDelayNanoseconds = 500_000_000` (500 ms) (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L613-L613`): if the generation is stale or the clipboard no longer holds the session's text (user copied something), it does nothing; otherwise it either keeps the transcript (user setting) or restores the original snapshot (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L808-L833`).
- Every failure is typed: empty_text, accessibility_not_trusted, clipboard_snapshot_failed, clipboard_write_failed, paste_command_failed, target_unavailable, target_restore_failed, no_editable_target, paste_not_landed (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L6-L16`); on failure the transcript is kept as a clipboard backup (`Sources/Fluid/Services/PasteDeliveryCoordinator.swift#L668-L682`).

### Target assessment and policy
- Before delivering, the focused AX element is classified: editable (AXTextField/TextArea/ComboBox/SecureTextField or value settable) / certainly-not-editable (buttons, menus, static text, sliders, …) / unknown. Containers like AXGroup, AXWebArea, AXWindow are deliberately "unknown" because web editors, GPU terminals and VMs report them yet accept Cmd+V (`Sources/Fluid/Services/DeliveryTargetAssessment.swift#L25-L40`, `Sources/Fluid/Services/DeliveryTargetAssessment.swift#L66-L70`). Only a *certain* non-editable target refuses: it copies a backup and returns `noEditableTarget` (`Sources/Fluid/Services/TypingService.swift#L518-L526`).
- Focus policy: ordinary dictation follows the current cursor; rewrite/retry keep the captured destination; an app-owned overlay holding focus is never a destination — the saved field is restored instead (`Sources/Fluid/Services/DictationTargetPolicy.swift#L3-L19`).
- Secure text fields: post-insertion actions (spoken-send Return) are blocked in secure fields, require physical modifiers released and the exact captured focus still active (`Sources/Fluid/Services/TypingService.swift#L47-L73`).

### Paste verification ("did it land?")
- After a clipboard paste, `PasteVerifier` reads the focused element's AX value/char-count/caret before and after at 150 ms, 350 ms and 1.0 s (`Sources/Fluid/Services/PasteVerifier.swift#L72-L74`); if focus moved it says unknown; only if value, count and caret are all unchanged after the final check does it return `notLanded` (`Sources/Fluid/Services/PasteVerifier.swift#L92-L121`). Readable text capped at 60,000 chars (`Sources/Fluid/Services/PasteVerifier.swift#L40-L40`). It also treats user input after the paste as "user acted" (`Sources/Fluid/Services/PasteVerifier.swift#L79-L83`).
- Direct-path deliveries skip verification (the read-back costs an AX read); only clipboard paths verify and only when the setting `showPasteCheckAlerts` is on (`Sources/Fluid/Services/TypingService.swift#L538-L540`, `Sources/Fluid/Services/TypingService.swift#L581-L585`).
- Failure UX: a `DeliveryFailureOverlay` card with kinds incl. noEditableTarget / pasteNotLanded and the transcript; MenuBarManager shows it for paste_not_landed (`Sources/Fluid/Views/DeliveryFailureOverlay.swift#L13-L14`, `Sources/Fluid/Services/MenuBarManager.swift#L497-L497`).


## A5 Command mode

### What it is
Command mode is a **single-tool terminal agent**, not a tool zoo. `CommandModeService` keeps a conversation, calls an OpenAI-compatible chat model with one function, `execute_terminal_command(command, workingDirectory, purpose)`, runs it under `/bin/zsh`, feeds stdout/stderr/exit back as a `tool` message, and loops (`Sources/Fluid/Services/CommandModeService.swift#L827-L850`, `Sources/Fluid/Services/CommandModeService.swift#L955-L966`). Max 20 turns per request ("Reached maximum steps limit…") (`Sources/Fluid/Services/CommandModeService.swift#L18-L18`, `Sources/Fluid/Services/CommandModeService.swift#L511-L522`).

### Flow: hotkey → action
1. A dedicated (optional) command-mode shortcut in `GlobalHotkeyManager` starts recording into the command mode instead of a text field (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L7-L8`, `Sources/Fluid/Services/GlobalHotkeyManager.swift#L290-L302`).
2. The final transcript is handed to `processUserCommand` (follow-ups via `processFollowUpCommand`) (`Sources/Fluid/Services/CommandModeService.swift#L364-L449`).
3. `callLLM` refuses when `commandModeReadinessIssue` is set, resolves provider/model/base URL/API key from the command-mode model selection, builds the messages (`Sources/Fluid/Services/CommandModeService.swift#L827-L846`).
4. The system prompt (paraphrased) prescribes an agentic loop: pre-flight checks (`ls`, `test -e`, `which`) → execute with a mandatory `purpose` ("checking" / "executing" / "verifying") → post-action verification → graceful failure; brief natural-language reasoning; destructive ops must first show the target; end with a summary starting with ✓ or ✗ (`Sources/Fluid/Services/CommandModeService.swift#L848-L905`).
5. Native-app control is done **through osascript one-liners taught in the prompt** — Reminders, Notes, Calendar, Messages (send iMessage), Mail — including a warning about a broken `reminders list 1` syntax (`Sources/Fluid/Services/CommandModeService.swift#L906-L925`). No browser automation, no shortcuts tool, no file-system tool beyond shell (Not found: grep for `tools:` entries other than `execute_terminal_command`).
6. The `purpose` drives a step type (checking / executing / verifying / result) shown as step rows (`Sources/Fluid/Services/CommandModeService.swift#L665-L695`).

### Execution and safety
- `TerminalService` runs `/bin/zsh -c` with the user's environment, PATH prefixed with `/opt/homebrew/bin:/usr/local/bin`, 30 s default timeout (`Sources/Fluid/Services/TerminalService.swift#L70-L105`).
- Confirmation: only when the setting `commandModeConfirmBeforeExecute` is on **and** the command matches a substring deny-list — `rm`, `rmdir`, `mv`, `sudo`, `kill/pkill/killall`, `chmod/chown/chgrp`, `dd`, `mkfs`, `format`, `> `, `truncate`, `shred`, piped/chained `rm`/`sudo`, `xargs rm` (`Sources/Fluid/Services/CommandModeService.swift#L572-L590`, `Sources/Fluid/Services/CommandModeService.swift#L697-L737`). The request then parks as `pendingCommand`; the notch says "⚠️ Confirmation needed in Command Mode window" and the window shows a pending-command view with confirm/cancel (`Sources/Fluid/Services/CommandModeService.swift#L450-L497`, `Sources/Fluid/Views/CommandModeView.swift#L143-L144`). Esc invalidates the voice owner before cancelling the deferred confirmation (`Sources/Fluid/Services/CommandModeService.swift#L481-L497`).
- No sandbox, no allow-list, no dry-run. Safety = prompt discipline + substring list + optional confirmation.

### UI while thinking and after
- Two surfaces: the notch (live step/status messages pushed via `syncToNotchState`, expanded when needed) and a full Command Mode window (`Sources/Fluid/Services/CommandModeService.swift#L341-L363`, `Sources/Fluid/Services/CommandModeService.swift#L656-L664`). Views: `CommandModeView`, `CommandMessageView`, `CommandMarkdownContent` (markdown output), `CommandShimmerText` (thinking shimmer), `CommandSessionSidebar`, `CommandModelPicker` + `CommandModelCatalog` (filterable model list) (`Sources/Fluid/Views/CommandModelCatalog.swift#L3-L14`).
- Thinking tokens are kept display-only on the step (`Sources/Fluid/Services/CommandModeService.swift#L545-L557`).

### Sessions / history
- Chats persist via a store: new / switch / delete / archive / restore / recent chats, auto-save on completion (`Sources/Fluid/Services/CommandModeService.swift#L40-L262`, `Sources/Fluid/Services/CommandModeService.swift#L523-L527`).

### Local API (not command mode, but the only programmatic surface)
- `LocalAPIServer` is an `NWListener` on `127.0.0.1:47733` by default, off unless enabled; every connection whose remote endpoint is not loopback (127.0.0.1, ::1, "localhost") is rejected; **no token/auth** (Not found: grep for `Bearer|X-API-Key|apiToken` in LocalAPI/); request bodies ≤ 500 MiB (`Sources/Fluid/Services/LocalAPI/LocalAPIModels.swift#L4-L5`, `Sources/Fluid/Services/LocalAPI/LocalAPIServer.swift#L18-L41`, `Sources/Fluid/Services/LocalAPI/LocalAPIServer.swift#L97-L110`).
- Routes: `GET /v1/health`, `GET /v1/history`, `GET /v1/meetings`, `GET /v1/meetings/transcript`, `GET|POST /v1/dictionary/replacements`, `GET|POST /v1/dictionary/custom-words`, `POST /v1/transcribe`, `POST /v1/postprocess` (`Sources/Fluid/Services/LocalAPI/LocalAPIRouter.swift#L12-L29`). So other local tools can use FluidVoice as an STT + cleanup server and read its history; it does **not** expose command mode.

### Write / Rewrite mode (A4 cross-ref)
- Shortcut captures the selection via AX `kAXSelectedTextAttribute`, falling back to `kAXSelectedTextRangeAttribute` + value slicing (`Sources/Fluid/Services/TextSelectionService.swift#L77-L100`, `Sources/Fluid/Services/RewriteModeService.swift#L50-L65`); with no selection it becomes "write" mode (generate fresh text) (`Sources/Fluid/Services/RewriteModeService.swift#L66-L77`).
- The spoken instruction is the user message; the selected text is injected into the **system prompt** through a user-editable context template (`runtimeContextBlock`), and the prompt profile is per-mode **and per app bundle id** (`Sources/Fluid/Services/RewriteModeService.swift#L198-L240`). Conversation is multi-turn (refine "shorter", "more formal").
- Accept: hides its own panel, **restores focus to the original field first** (hiding alone races the paste), then types through the normal `TypingService` path (`Sources/Fluid/Services/RewriteModeService.swift#L156-L178`). UI: `RewriteModeView` shows the result for review before accept — explicit confirmation by design.


## A6 Overlay, hotkey and gesture UX

- Hotkey modes: **Toggle** ("Tap once to start, tap again to stop"), **Hold** ("Record only while the shortcut is held"), **Automatic (Both)** ("Tap to toggle, hold for push-to-talk") (`Sources/Fluid/Persistence/HotkeyActivationMode.swift#L4-L20`). Automatic splits tap vs hold at `automaticTapThresholdSeconds = 0.4` (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L313-L313`); release handling per mode (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L1811-L1830`). There is **no double-tap lock** — a comment still reserves a further tap-vs-hold detection for the future (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L396-L396`). - **Modifier-only shortcuts incl. fn**: physical key codes are tracked per modifier group — fn = 63, cmd 55/54, option 58/61, control 59/62, shift 56/60 — so left/right are distinguishable (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L1682-L1688`); `maskSecondaryFn` maps to `.function` (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L932-L932`).

Mouse buttons can be the shortcut (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L2254-L2254`). Pressing another mode's key while recording **switches mode** instead of stopping (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L1593-L1600`).
- Separate shortcuts for dictation (several slots), command mode, rewrite mode, prompt mode (`Sources/Fluid/Services/GlobalHotkeyManager.swift#L290-L302`, `Sources/Fluid/Services/GlobalHotkeyManager.swift#L526-L531`).
- Display: overlays open on the **screen under the pointer** (`Sources/Fluid/Services/OverlayScreenResolver.swift#L9-L12`). Two styles: notch (DynamicNotchKit fork, `NotchOverlayManager`, 843 lines) and a bottom overlay (`BottomOverlayView`, `BottomWaveformView`).

## Map to the three questions

**Q1 better dictation** — theirs, not obviously ours (to be confirmed by the OURS report): clipboard lease with nspasteboard markers + 500 ms settle; triple-check paste verification and typed failure kinds with a failure card; three-way target assessment; automatic correction-learning loop with acoustic grounding and strict anti-noise policy; spoken send with arming; literal formatter for slash commands/@mentions/terminal autocomplete; per-app prompt bindings; Parakeet CTC boost ≤256 terms. Web: see survey report.

**Q2 command mode** — theirs is a minimal terminal agent: one shell tool, mandatory `purpose` that becomes visible step rows (checking/executing/verifying), verify-after-act prompt discipline, ✓/✗ summary, optional confirmation on a destructive-substring list, sessions with archive/restore, notch mirror + full window with markdown and shimmer. Lessons for theuth: the *step-row with purpose* UX and ✓/✗ summaries are cheap wins; their safety model (substring list, no sandbox) is weaker than an approval policy and should not be copied.

**Q3 ask-the-agent-anywhere with visible output** — closest analogue is command mode's notch mirror (`syncToNotchState`, expand-on-need, "confirmation needed in window") plus rewrite mode's review-then-accept panel that restores focus to the original field before typing. Borrow: pointer-screen overlay, notch-as-progress / window-as-detail split, mode switching by pressing another mode's hotkey mid-recording, Esc invalidating the voice owner before cancelling pending confirmations.
