### C. Capabilities beyond SQLite

**C1 Encryption.** Page-level AEAD; ciphers `aes128gcm, aes256gcm, aegis256 (recommended), aegis128l, aegis128x2/x4, aegis256x2/x4` (`pragmas.mdx:518-527`; `core/storage/encryption.rs:413-438`); per-page overhead = nonce (12 B AES-GCM / 16 B AEGIS-128 / 32 B AEGIS-256) + 16 B tag in reserved bytes (`encryption.rs:26-41, 482-505`); page 1 header kept plaintext as AD, magic replaced by `"Turso"` (`:44-67`). Key: raw hex via `PRAGMA cipher`/`PRAGMA hexkey` or URI `?cipher=&hexkey=` (`manual.md:650-668`); reopen requires URI params (`pragmas.mdx:554`); Rust `Builder::with_encryption(EncryptionOpts)` + `experimental_encryption(true)` (`lib.rs:207-215`; `rsapi.rs:165-167`). **No passphrase KDF** (no pbkdf/argon/hkdf in core; grep). Not SQLCipher-readable (different header/layout; no claim of compatibility anywhere). Migration: `VACUUM INTO` from encrypted → plain works (`tests/integration/query_processing/encryption.rs:1082-1139`); plain → encrypted tooling ND. Feature `encryption` default on; `pure-rust-crypto` = aegis pure-rust (`core/Cargo.toml:52-53`). Experimental (`README.md:64`; RFC issue #2447 `manual.md:639`).

**C2 CDC — decisive.** `PRAGMA capture_data_changes_conn('<mode>[,<table>]')`, modes `off|id|before|after|full`, default table `turso_cdc` (`core/cdc.rs:10, 71-88`; `pragmas.mdx:434-458`). **Per connection, not per database:** the setting lives on `Connection` (`core/connection.rs:422 capture_data_changes: RwLock<Option<CaptureDataChangesInfo>>`), is read at statement translation (`core/translate/mod.rs:97-105`), and the docs state "CDC is configured per connection. Each connection can use a different mode and a different CDC table. **Changes made by a connection that does not have CDC enabled are not recorded.**" (`docs/language-reference/book/print.html:8969-8970`; also `cli/manuals/cdc.md:13, 176-189`). So a write via connection B (or another process) does **not** appear in A's capture table unless B also enables it. Table is a normal durable table: `CREATE TABLE IF NOT EXISTS <t> (change_id INTEGER PRIMARY KEY AUTOINCREMENT, change_time INTEGER, change_txn_id INTEGER, change_type INTEGER, table_name TEXT, id, before BLOB, after BLOB, updates BLOB)` (v2) plus `turso_cdc_version(table_name, version)` (`core/vdbe/execute.rs:15483-15497`); "The CDC table is a regular table that can be queried with standard SQL" (`print.html:8870`). Row: change_type 1/0/-1/2(COMMIT), table_name, id = rowid/PK, before/after/updates as binary records decoded with `bin_record_json_object(table_columns_json_array(t), blob)` (`print.html:8897-8911`), `change_txn_id` = change_id of the txn's first record, COMMIT record per transaction (`cli/manuals/cdc.md:86-109`). Transactional: written in the same transaction, rollback discards (`cdc.md:191-212`). Pruning: manual `DELETE FROM turso_cdc`; CDC-table edits are not captured (`print.html:8890-8893`). Limits: journal_mode change refused while CDC active (`execute.rs:18880-18896`); WITHOUT ROWID rejects CDC (`COMPAT.md:155`); schema changes captured only in `full` (`cdc.md:214-226`); labelled "Early Preview"/"unstable" (`manual.md:1047`, `print.html:8789`). The sync engine consumes exactly this log (`sync/engine/src/database_tape.rs` `CDC_PRAGMA_NAME`, `database_sync_engine.rs:29`).

**C3 Sync engine.** Client-side `turso_sync_engine` + `turso::sync::Builder::new_remote(path).with_remote_url(https|http|libsql|turso://).with_auth_token(..)` → `db.push()/pull()/checkpoint()/stats()` (`bindings/rust/README.md:116-236`, `sync.rs:91-293`). Protocol: HTTP to a Turso Cloud–shaped server — `POST /v2/pipeline` (SQL-over-HTTP, pushes local CDC changes as logical statements), `/pull-updates` (protobuf page sets or MVCC logical-log stream, `server_proto.rs:16-144`), legacy `/sync/{gen}/{start}/{end}`, `/info`, `/export/{gen}` (`sync/engine/src/database_sync_operations.rs:3715-3873`); protocol spec `serverless/PROTOCOL.md:1-40`. **Open-source server exists in-tree:** `tursodb --sync-server ADDR [--sync-dir DIR]` (`cli/sync_server.rs:70-171, 1352-1364`; `packages/turso-cli/README.md:40`), limited (no zstd, single-generation MVCC pulls `:602, :1045`). Topology: hub-and-spoke client↔server; no peer-to-peer. Conflicts: "logical statements are sent, and on conflicts the strategy is 'last push wins'" (docs.turso.tech/sync/usage); offline writes queue locally until `push()` (same page). Replication of a remote write into a local DB is pull-driven (page/logical-log replay), not hook-driven.

**C4 Materialized views (DBSP).** `CREATE MATERIALIZED VIEW`, maintained incrementally in the same transaction, no REFRESH (`docs/sql-reference/statements/create-materialized-view.mdx:29-34`); experimental flag `views`/`experimental_materialized_views` (`:9-10`); limits: not all functions, no view-on-view, no TEMPORARY (`:36-40`); operators in `core/incremental/*`; 12 open `dbsp` issues incl. #8641 cross-process panic + lost write.
