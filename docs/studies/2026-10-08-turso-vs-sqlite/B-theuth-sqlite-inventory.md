## Replication (what a Turso CDC/sync would compete with)
- Stage 1 (`crates/replica`): per-table AFTER triggers → `_replica_log` → HLC-stamped postcard `ChangeBatch` in `replica.sqlite.outbox`, per-column LWW apply; needs single-column PK + `hlc TEXT`. Session extension rejected here because it captures only its own connection (`engine.rs:5-12`, `67-agents.md:518`).
- Stage 2 (design 68): one write connection + `sqlite3session` on 20 tables → changeset per commit split per session into `session_log(seq, session_id, epoch, changeset BLOB, hlc)` in the same transaction; replicas apply via `sqlite3changeset_apply` owner-wins; snapshot bootstrap from TEMP twins; epoch fence. MUSTs: commit-ordered log, one writer per session, txn = one log row, epoch-fenced apply, snapshot-first bootstrap, prune below min peer cursor (`68-sessions.md`).
